# 复刻项目工作流优化设计 v1

日期：2026-09-23

状态：Design Draft，供产品/工程评审；不代表本文件列出的模型已接入 iFrame recreation。

本期实现范围：以 MiniMax H3、ASR 1.0、Speech 2.8 和 UniArt 对接 GlobalAI 去字幕为主线。跨帧跟踪/分割与视频补洞模型暂不纳入首期，不阻塞快速复刻和关键帧编辑；首期模型边界见工作流总 spec。

关联：[Recreation Project 工作流总 spec](../specs/2026-09-23-recreation-project-workflow-v1.md)

## 1. 设计目标

将现有“选项目、看视频、确认切点、再向下滚动配置引用/生成/装配”的长页面，优化为可恢复、可跳转、有明确完成条件的复刻项目工作区。

关键任务：

1. 用户能快速知道项目在哪一步、下一步缺什么。
2. 两种运动路线的能力边界清晰：快速 H3 是整体复刻；关键帧/逐帧路线按真实编辑覆盖范围命名。
3. 音频、配音、字幕分别管理；没有确认过的台词不被自动送去生成配音。
4. 付费操作之前能审阅输入、音频/字幕策略和成本；重载页面不丢失任务与项目上下文。
5. 默认视频不带字幕。包装上的真实印刷文字仍是产品外观，不应被“无字幕”误删。

## 2. 现状证据

### Observed（本地代码事实，2026-09-23）

- `RecreationPage` 当前同屏承载项目列表、源视频、镜头切点浏览/编辑、分析状态和联系表；已确认时间线后，`ShotReferences` 会继续在当前长页面中承载镜头引用、关键帧付费任务、H3 计划/生成状态与装配结果。
- 镜头切点操作使用整数源 PTS，并显示前后证据帧；均匀联系表与切点候选已经是不同数据。
- H3 生成目前逐镜头提交任务，支持 `silent`、`generated`、`preserve_source` 三种音频策略；`generated` 映射到视频模型 `generate_audio`，而不是独立 TTS。
- UniArt 源码/契约文档存在 MiniMax `speech-2.8-hd`、`speech-2.8-turbo` 与 `asr-1.0` 的端点适配记录。`asr-1.0` 请求支持 `timestamp_level=sentence|word`，响应格式接受 `json`、`verbose_json`、`srt`、`vtt`；这证明接口形状有代码，不证明 iFrame recreation 已接入或生产 SKU/canary 已启用。
- 当前 ASR 适配层解析 JSON/verbose JSON 时只校验 `duration` 与 `text`，没有建立说话人 diarization 数据契约。SRT/VTT 的逐词/逐句结构也尚未在 iFrame recreation 中标准化。
- 漫剧域已有 TTS 处理与 voice picker；复刻域还没有独立 TTS Run、台词确认、生成语音的时间对齐和多轨混音工作流。

### Direct implication

- 首屏优化重点是项目进度与当前动作，不是再加一段介绍文案或堆叠功能卡片。
- ASR 和 TTS 可作为复刻项目的第一批音频模型能力，但仍要补复刻域自己的任务、素材、时间戳和装配契约。
- 音轨解复用只产生原音轨文件；它不等于人声、音乐、环境声已分离。
- ASR 带时间戳不等于说话人分离、情绪/声线理解、源音乐保留或生成配音的强制对齐。

### Not yet proven

- 未证明 MiniMax 2.8 TTS 的最终音质、按句稳定时长、语言覆盖及语速/情绪控制满足真实样片需求。
- 未证明 ASR 1.0 在本产品样片上的逐词时间戳准确率、中文专有名词准确率或混音/背景噪声下的表现。
- 未证明新分步交互会提高项目完成率；需要用任务完成时间、错误恢复率与用户测试观察验证。

## 3. 信息架构

复刻入口先到项目列表/新建项目。进入项目后使用六个主阶段；素材与资产管理作为支撑能力贯穿各阶段：

```text
视频拆分 → 解析 → 分析 → 替换 → 提交 → 合成
```

素材/资产面板作为可从各阶段访问的项目支撑区，不占用一个主阶段位置。每个阶段显示简洁状态：未开始、进行中、需要确认、已完成、失败。项目工作区保留上方项目名/源视频状态/返回项目列表等全局信息；当前阶段有一个明确主操作。阶段可以回看和编辑，但依赖缺失时下游操作显示具体阻塞原因，不允许点了之后才失败。

当前 UI 切片已实现六阶段导航、项目级源视频预览，以及拆分入口、切点解析、联系表检查、替换配置、H3 提交和合成结果的分阶段展示。资产管理暂由全局素材库入口承载，尚不是内嵌资产抽屉。现有后端把媒体探测/抽帧/切点候选合在一个分析任务中，因此界面会明示拆分与解析共享后台任务；“分析”目前只展示已有视觉素材，不代表 ASR、字幕清理或音频理解已接入。阶段完成状态只在可由现有项目/时间线状态证明时标记。

### 桌面工作区

```text
┌ 项目名 / 源文件 / 当前 revision / 最近任务状态 / 返回项目列表 ───────┐
├ 阶段导航 ─────────────── 当前阶段工作区 ───────────────────────┤
│ 视频拆分  解析  分析  替换  提交  合成                              │
│                           主内容：当前阶段工作区                    │
│ 资产入口                 右侧检查器：选中素材/当前任务              │
│                           底部：阶段状态与唯一主操作                │
└──────────────────────────────────────────────────────────────────┘
```

- 六阶段导航保持稳定；镜头列表属于“解析/分析”工作区，替换配置与提交任务分开呈现，不要在列表、时间线、预览三个区域重复呈现相同状态。
- 中央预览区优先保留视频/帧本身；检查器按当前镜头/轨道变化。避免把页面分成层层嵌套的卡片。
- 确认时间、PTS、片长、模型、成本等数据使用稳定宽度和等宽数字，避免任务轮询造成布局跳动。
- 移动端改为单列阶段页；主操作固定在安全区内的底部栏，次要参数折叠；时间线可横向平移，但页面本身不产生横向溢出。

### 项目列表与创建

- 项目列表以源视频缩略图、项目名、最近阶段、任务状态和更新时间为主要扫描信息。
- `创建复刻项目` 打开文件选择/拖放，创建成功后进入“视频拆分”阶段。
- 空项目状态的主要动作是上传视频；不能先要求写 prompt 或选模型。
- 同一视频多次尝试在同一个项目内形成多个 MotionRun/结果，不自动复制出多个项目。

## 4. 阶段交互

### A. 视频拆分

- 显示原视频播放器与基本媒体信息；后续分解能力接入后，以轨道/素材列表呈现原视频、独立音轨、软字幕、抽帧和 ASR 产物。
- 软字幕标记为可提取文字轨；烧录字幕显示为画面文字候选，不能伪装为字幕文件。
- `拆分视频` 是本阶段主操作。进行中显示探测、解复用等子任务和可恢复的失败原因；抽帧/ASR 属于后续阶段，不能假显示为拆分已完成的步骤。

### B. 解析

- 以源 PTS 为依据生成浏览抽帧、镜头/切点候选和前后帧证据；均匀联系表只负责浏览，不能一键将采样时间变成切点。
- 展示候选边界及精确 PTS，支持人工修订和确认；解析产物保留算法版本、输入资产指纹和证据帧。

### C. 分析

- 以一条可操作时间线为主：视频轨上标镜头边界；切点候选、人工切点、已确认切点同时具备文字状态，不单靠颜色区分。
- 选中切点时并排显示切点前后源帧、源时间和精确 PTS；联系表只负责浏览，不能一键把抽帧时间转成切点。
- 选中镜头后显示镜头描述、主体/位置/动作/运镜和证据来源；模型建议与人工确认在视觉上区分。
- ASR 区域按时间展示可编辑句段，并标出机器转录/源软字幕/人工修订来源。用户必须显式确认或修订台词，才能送入付费 TTS。
- 镜头结构/描述、ASR 转录、字幕候选在本阶段汇总，所有机器结果可修订并保留来源。
- 主要动作：`确认分析结果`。在确认前可以预览替换配置，但不能进入付费提交。

### D. 替换

先用 Segmented Control 选择路线，而不是把两条路线放成大营销卡：

| 路线 | 交互范围 | 明示限制 |
| --- | --- | --- |
| 快速复刻 · MiniMax H3 | 每镜头复用已确认的源视频结构与镜头 reference，选择替换产品、生成时长及音频策略；提供总览 prompt 与逐镜检查。 | 追求整体节奏/运动/构图，不承诺逐帧一致。当前编号沿用 `<Video 1>` 源视频、`<Picture 1>` 镜头 reference、`<Picture 2>` 替换产品。 |
| 关键帧/逐帧重建 | 选择镜头及帧覆盖范围；展示原帧、编辑结果、未覆盖帧及其状态；按明确范围批量提交。 | 关键帧模式只编辑目标帧，不得显示为已替换整个视频；全帧路线需先定义输出帧完整性与连续性验收。 |

- 选择快速 H3 或关键帧编辑，配置产品/主体参考、保留/替换意图、提示词和实际覆盖范围；本阶段只准备替换方案与输入快照。
- 比较视图按同一源镜头并排看源帧/生成结果；不同 MotionRun 保留，不互相覆盖。

### E. 提交

- 提交前展示模型、输入素材角色、镜头/帧数、音频策略、成本/计费单位和项目 revision。
- 用户须明确同意费用后才能提交异步任务。刷新后恢复既有任务；除 provider 支持的 task 查询/恢复以外，不自动新发付费任务。
- 任务状态、失败原因、重试/取消策略和结果资产均绑定不可变 Run；不得静默重发付费请求。

### F. 合成

合成阶段管理输出时间线，声音与字幕是其中独立选择的素材/轨道，不额外占主流程阶段：

- **声音轨道**：原声、视频模型原生声音、TTS 配音、音乐、环境声、音效各自独立。v1 可先支持静音、保留原声、H3 生成音频、TTS 配音四种清楚命名的路径；混音 UI 仅展示当前已有的轨道。
- **台词**：显示 ASR 句段、编辑确认状态、speaker（若后续 diarization 接入）、所选 voice、试听结果和生成任务状态。未确认台词不可直接批量 TTS。
- **字幕**：由 ASR/软字幕/人工稿形成独立 subtitle artifact；显示内容与时间段，支持修订和 sidecar 导出。默认 `不加入成片`。
- 声音与字幕分别显示是否包含在最终导出中。字幕旁明确显示“独立字幕文件”或“导出字幕轨”；不提供默认烧录到画面。
- 产品包装上的文字属于图片内容，不属于字幕轨；`无字幕` 不得提示模型清除产品包装文字。

- 时间线以视频、声音、可选字幕轨分层，只有一个主合成结果预览。
- 导出预检列出：选中的 MotionRun、时间线 revision、每镜头覆盖/时长、音频来源、字幕是否纳入、预计输出规格和待处理 QC 项。
- 默认不纳入字幕轨；用户显式勾选后才将 subtitle artifact 加到交付物。
- 对短片段、缺失音轨、revision 变化或未覆盖帧给出阻塞和可选恢复操作；不静默拉伸、补音、烧录字幕或改用其他音频来源。
- 导出完成后提供视频、独立字幕 sidecar 和单独音频素材（若用户选择）下载；结果保留来源链。

## 5. 模型与能力支持矩阵

以下分为模型角色，而不是要求用户在一个大模型列表中自行拼装。策略层按 `transcription`、`speech_synthesis`、`audio_understanding` 等能力请求模型；实际 model ID 由已发布的能力目录提供。

| 优先级 | 能力/模型角色 | 对工作流的用途 | 当前证据 / 设计建议 |
| --- | --- | --- | --- |
| MVP 必需 | 视频生成：MiniMax H3 | 快速复刻运动与产品替换。 | iFrame recreation 现有 H3 路径；在线画面质量仍需验收。 |
| MVP 必需 | ASR：MiniMax `asr-1.0` | 原音轨转录、句/词级时间戳、后续字幕草稿。 | UniArt 代码接受 `sentence`/`word` timestamp level 和 SRT/VTT 等格式；需在 iFrame 做适配、统一 PTS 映射与样片准确率验收。它不提供本设计所需的说话人分离/音频场景理解保证。 |
| MVP 必需 | TTS：MiniMax `speech-2.8-hd` | 生成最终配音/对白。 | 可作为质量优先的默认候选；确认音色、格式、时长与 UniArt 成本/canary 后才开放付费正式生成。 |
| MVP 建议 | TTS：MiniMax `speech-2.8-turbo` | 快速预听、低成本迭代；必要时用于非最终草稿。 | 作为可选速度/成本档，不要和 HD 混成一个不说明质量/费用的随机路由。最终成片是否允许 Turbo 由用户明确选择。 |
| P1 试验 / P2 产品化 | 镜头视觉理解 VLM/视频模型 | 归纳镜头动作、构图、运镜和画面文字候选。 | iFrame 有 Qwen-VL 图像 prompt wrapper，但 recreation 无连续视频理解契约。可先评估带 PTS 的多帧输入；不得标称视频级理解。 |
| P0 对接与验收 | 烧录字幕清理：GlobalAI `sd2ManxueRemoveSubtitle`（经 UniArt） | 对含字幕源视频生成清理副本，作为 H3/帧编辑参考。 | iFrame 尚未对接；目标是由 UniArt 暴露可调用能力。公开 SKU/价格与真实清理质量未验收。需检测/预览，防止擦除包装文字；不可声称保证生成成片无字。 |
| P2（多人台词时） | Speaker diarization 能力 | 把 ASR 片段分配为稳定 speaker ID，为角色配音和 voice 选择提供依据。 | ASR 的词/句时间戳不足以推出说话人身份；目前没有 recreation speaker schema。多说话人场景再评估独立 diarization 模型或含 speaker 输出的 ASR。 |
| P1 POC | Source separation / stem separation | 分离原人声与伴奏背景，支持替换对白后保留背景。 | iFrame 漫剧配音已有 Demucs `htdemucs` 两 stem (`vocals`/`no_vocals`) 实现；尚未接入 recreation，且不是音乐/环境/音效多 stem。优先验证复用并补显式失败/资产追溯，不先采购第二个分离模型。 |
| 延后评估 | 视频目标跟踪/掩膜传播 + 时序补洞 | 将关键帧编辑扩展为有界帧或全帧连续替换。 | SAM 2、Cutie、XMem、ProPainter、E2FGVI-HQ、STTN 均未接入，不进入本期实施范围。首期只交付 H3 快速复刻和明确标注覆盖范围的关键帧编辑；需求验证后再立 POC。 |
| 后续增强 | Forced alignment / TTS time alignment | 将已确认文本与源或生成语音对齐到词级时间，制作紧贴语音的字幕和对白入点。 | ASR `word` 时间戳可以先提供识别式近似对齐；只有当对齐误差验收不达标时才引入专用 forced aligner。不能凭 TTS 返回的完整音频时长虚构词级时间。 |
| 条件性 | Voice cloning / voice design | 复刻原说话人音色或创建指定人设音色。 | 若只做普通旁白，系统音色已可起步；若承诺保留原角色声线则需要独立授权、同意流程、clone runtime 与费用确认。不能把 TTS SKU 当成已支持 voice cloning 的证明。 |
| 非模型基础能力 | FFmpeg/编码、PTS 对齐、音轨混音、字幕 sidecar、OCR QC | 对视频/音轨/字幕做确定性解复用、剪辑、同步、导出与检测。 | 这些主要是媒体运行时和校验能力，不应全部包装成“还缺一个模型”。OCR 可提示字幕候选，但不能证明绝对无字。 |

### 模型支持结论

本期先基于 MiniMax H3、ASR 1.0、Speech 2.8（HD + Turbo）和 UniArt 对接 GlobalAI 去字幕能力推进；ASR/TTS 的 recreation Run 及 GlobalAI 调用仍须完成集成与质量/费用验收。本期不引入 SAM 2、Cutie、XMem、ProPainter、E2FGVI-HQ、STTN，也不承诺全帧连续替换。Demucs 可作为后续音频分离 POC，不是本期必需模型。说话人分离、音频场景理解和 forced alignment 按样片需求及误差门槛后置。

详细候选与发布门槛见[缺口模型评估记录](../research/recreation-missing-models-evaluation-2026-09-23.md)。

这是能力优先级，不是对任何未审阅 SKU 的推荐或生产可用性声明。每类模型都需过精确 endpoint、能力 profile、价格 owner、失败计费、输入限制和 canary 检查。

## 6. 视觉与交互原则

- 产品是反复操作的专业视频工具，不采用营销 landing hero、装饰性大卡片或多层卡片；首屏直接是项目与当前工作。
- 先呈现视频/帧/时间线等可核对对象，再呈现 prompt 和高级参数。
- 每个阶段一个清晰主操作；取消、重试、刷新、成本确认等根据状态显示，避免同时出现多个同权重 CTA。
- 用图标时沿用项目 Lucide；图标按钮需 tooltip/可访问名称。错误在字段或对应 Run 附近呈现原因与恢复动作。
- 异步任务显示 skeleton/progress、状态文字和取消能力；刷新/离开视图不取消任务。轮询完成后停止，并避免整体布局跳动。
- 至少验证键盘操作、焦点路径、屏幕阅读器名称、375px/768px/桌面视口、窄屏横向溢出及 reduced motion。

UI-UX Pro Max 的通用设计系统搜索对该场景给出“Video-First Hero / motion-driven”等营销/展示型建议，与项目式剪辑工作台不匹配；本设计采纳其异步反馈、键盘可达、表单错误就地恢复等通用 UX 检查，不采用该首页构图/配色模板。

## 7. 实施优先级与评估

### P0：工作区结构优化

- 把当前单页分成项目列表和项目阶段工作区；保留现有分析、时间线确认、引用、H3、关键帧和装配 API。
- 将 Motion 路线清楚标为快速 H3 与关键帧引导，隐藏未实现的“全帧替换”承诺。
- 将音频选择解释成“视频模型生成声音”而不是 TTS；默认输出字幕策略显示为不纳入。
- 不修改后端任务契约的结构重排，应先证明所有现有行为可由新 UI 恢复。

### P1：ASR 与字幕素材

- 用 ASR 1.0 对抽取/解复用的音轨生成持久化 transcript artifact；规范句/词时间戳、源 PTS 转换、失败重试、用户修订与媒体来源链。
- 软字幕独立解复用；与 ASR transcript 可并列比较，不互相覆盖。
- 生成字幕 artifact/sidecar，不把字幕烧录进视频。

### P2：独立 TTS / 音轨混音

- 仅将用户确认的台词送 MiniMax Speech 2.8；HD 用于最终候选，Turbo 用于可选快速预听。
- 生成的音频作为独立 `AudioRun` 输出，支持试听、重生成、文本/音色版本校验、时间位置编辑。
- Assembly 增加独立 voiceover 轨和混音预检；无源音轨和失败 TTS 不得静默回退到模型生成声音。

### P3：理解/分离增强

- 根据真实样本验证音视频理解、diarization、source separation 和 forced alignment 的收益后再接入。
- 新模型接入采用统一能力目录；UI 以“分析模型/配音模型”等任务角色呈现，不以所有供应商 SKU 平铺。

### 评估标准

- 用户从上传到看到可编辑 Story 的完成时间、分析失败可恢复率、时间线修改成功率。
- H3 成功率/拒绝率与成片抽样评分单独统计，不把 mock 请求测试等同于画面质量。
- ASR 字错率/WER 或中文 CER、词时间边界误差、用户修订率。
- TTS 可懂度/自然度人工盲评、句长/时长变化、用户重生成率；费用按模型和字符快照记录。
- Assembly 输出的音画同步误差、PTS/帧缺失、字幕流存在性（默认应不存在）、OCR 候选复核结果。

## 8. 决策请求

评审时重点确认三点：

1. 首版是否按“ASR 转录 + 独立 TTS 配音”纳入，而把声源分离留到增强阶段。
2. 快速 H3 的生成声音、原声保留、静音、独立 TTS 是否作为四种互斥基础输出路径，还是允许明确的“背景声 + 配音叠加”混音路径。
3. Story 镜头描述首版先由用户确认/编辑，还是同时纳入一个已批准的视觉理解模型调用。
