# 主机 Qwen 编排隔离验证

日期：2026-10-29。实现提交 `10b3c34e`、`7f6e57fd`。仅测试，没有切换在线聊天入口。

## Observed

- 主机 `/v1/models` 返回 Qwen2.5-0.5B-Instruct Q4_K_M；元数据 n_params=630167424，模型大小 485452288 bytes。
- `/props` 返回 llama.cpp build `b11913-7aca0d2ea`、当前上下文 2048、两个 slot。没有读取或修改模型权重。
- 现有 `scripts/coordinator_service.py` 对日记、照片等关键词先固定判断；此类结果不证明实际调用了模型。在线服务仍保持原行为。
- 新增 `local_planner.py` 为独立提议器；定义创建/取得编辑任务、保存要求、请求来源、暂停、取消的原子步骤，及委派/澄清结果。完整计划做结构、重复步骤、等待位置、任务前置条件及日记焦点校验。
- 此模块不导入业务执行器、不写数据库、不执行步骤；尚无持久化计划恢复实现。
- 通过容器内部模型地址直接调用 llama.cpp，绕过原协调器关键词判断。仅使用合成文字和合成状态，无照片、实际聊天、云端模型或付费生成。

## Runtime observations

15 个固定单轮场景覆盖开启、复合请求、缺图先记录要求、相册、上传、保留旧约束、暂停、取消、日记焦点、日记请求、相册计数、闲聊、看图、视频和歧义澄清。

| 配置 | 格式与前置条件有效 | 动作及参数符合固定期望 |
|---|---:|---:|
| 受限 JSON schema，首版提示词 | 1/15 | 1/15 |
| 同一 schema，增加明确 JSON 示例与步骤唯一性说明 | 8/15 | 1/15 |

首版大量生成重复来源步骤；第二版仍存在省略 ensure、遗漏 brief、把上传选成相册、取消选成来源、把日记交给普通聊天等错误。第二版单次耗时约 0.30–1.15 秒；有效输出记录的请求总 tokens 约 438–476。不能拿这个速度和格式合规率替代语义正确率。

首版原始重复步骤响应 finish_reason=stop，prompt_tokens=258、completion_tokens=80；未见该次触发上下文或输出截断。明确示例后的有效输出同样远低于 2048 tokens。不是长历史或麦克风测试。

临时结果位于测试容器 `/tmp/local-planner-results.json`、`/tmp/local-planner-results-v2.json`；不是永久归档。可复用测试脚本 `scripts/companion_eval/local_planner.py`；后续版本进一步保留被拒绝的提议及 usage，方便区分格式和业务拒绝。

## Direct implication

当前模型配置加当前完整计划协议，不能承担自主执行入口。校验器能拦截部分非法计划，但不能识别所有结构合法的错误意图，例如上传误选相册，因此不应仅靠 schema 接管线上业务。

47 项相关后端测试通过，覆盖非法参数组合、步骤重复、顺序、前置条件与现有草稿/聊天行为。这是程序边界验证，不是模型理解通过。

## Not yet proven / Hypotheses

没有证明所有 0.5B 模型都不适合编排，也没有证明增大上下文或升级主机能够修复语义。JSON grammar、模型容量、提示词及步骤协议复杂度可能影响结果，贡献尚未分离。

主机 Qwen 承担统一语义协调仍是目标；确定性运行时负责执行依赖和保存回执。是否让小模型直接生成多步计划，或先提取有界意图/参数再由执行器展开步骤，需要对照实验决定。

## What would verify it

1. 使用相同固定语料，比较完整步骤协议与简化意图/参数协议；两者均保留状态焦点和旧约束，不增加关键词路由。
2. 核对本机推理模板及结构化输出模式；用不带 grammar 的原始输出做小范围诊断，明确格式约束的影响。
3. 若当前模型仍不能满足要求，在资源评估后对比更强的本机模型和云端参考，不假设升级硬件必然有效。
4. 通过语义门槛后才增加持久化执行器、等待用户恢复和语音播放事件，再部署测试站。

本次没有安装第三方编排框架，没有修改在线模型配置，没有部署、推送或合并。
