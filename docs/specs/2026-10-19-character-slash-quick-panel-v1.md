# 角色工作台 `/` 快捷面板 V1

日期：2026-10-19。范围：项目角色设计草稿；与图片 Prompt 中的 `@` 资产引用分离。

## Observed

- 角色设计接口固定加载 `character-identity-design` 和 `character-style-routes`，请求没有任意 Skill ID 参数。当前生成草稿已先展示模型输入，再由用户确认调用。
- 平台词条已有面容、皮肤、身材和发型文本；服装没有同类词条。题材与画风当前有四个路由值。MotuArt 的[动漫提示词分类页](https://motuart.com/prompts/anime)列出角色设定稿、动作姿势、漫画、轻小说等任务方向；本版只参考分类方向，独立重写短词条，不导入原提示词全文或效果图。
- 身份和造型各有结构化字段与兼容旧草稿的摘要。存在结构化字段时，当前图片 Prompt 投影优先使用结构化字段。

## Direct implication

V1 的 Skill 菜单只能提供现有双 Skill 工作流的快捷入口，不能声称能分别选择或执行任意 Skill。预设词条只填入可编辑草稿；不调用模型、不自动保存、不附加参考图。

## 交互与数据

1. 在角色设计面板输入 `/` 或点击 `/` 按钮，打开分组搜索：Skill、风格、面容、皮肤、身材体态、服装、发型。支持输入法、上下键、回车、Esc 和鼠标。
2. Skill 项显示实际固定加载的两个 ID；选择后进入现有模型输入预览，用户仍需确认才调用模型。预览展示服务端返回的两个 Skill revision。
3. 词条项显示来源及修订号。选择后写入对应的 route 或身份/造型字段；若用户已经写了旧摘要且尚无结构化字段，则追加到摘要，避免使原文退出 Prompt 投影。界面展示实际写入的字段。
4. 保存角色设计时随草稿记录 `preset_id`、`revision`、`applied_target`、`value`、`source`。手动修改对应字段或接受模型草稿后撤销该字段的词条来源标记，避免将改写后的内容伪称为原词条。
5. 面容、皮肤、体态、发型和服装新增细分的文本测试词条；风格保留四个路由，并增加可编辑的局部风格描述。动漫风格词条参考 MotuArt 的分类方向重新编写，来源标为 iFrame 测试词条，未将该站的模板或图片直接导入。未来效果图需要单独的变体身份和版权信息；选择词条永不自动附加效果图到模型请求。
6. 快捷结果在侧栏文档流中展开并单独滚动，避免被侧栏的滚动容器裁切。

## 验收

- 搜索和键盘操作可用；无匹配、Esc、点击外部不会改变草稿。
- 风格选择只更新角色设计 route；其他词条只更新可见字段或摘要，模型调用计数保持为零。
- Skill 快捷项仅调用现有 preview；确认前不调用 draft 生成接口。
- 保存后的词条来源可追溯；手动改写后不保留虚假的来源绑定。
- 图片 Prompt 的 `@` 引用行为及生成审核不变。

## Not yet proven

- 测试服装词条的生成效果，以及后续效果图的授权与视觉一致性，需要单独验证。
- 任意 Skill 选择需要服务端白名单、投影、预览 token 与提交校验合同，V1 不提供该能力。
