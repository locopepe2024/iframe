# 陪伴版首页与资产入口交互规划 V2

状态：规划确认稿，先验证网页 Demo 交互

## 目标

首页回答“今天做什么”，聊天流回答“怎么一起完成”。顶部计划卡片是可滑动的工作入口，不替代聊天；输入栏的上传和相册入口保持长期稳定，避免老人把新增文件和查找旧素材混淆。

## 本片交付与优先级

本片先交付交互规范和独立可点击线框：`docs/agents/deliverables/2026-10-23-companion-interaction-wireframe.html`。可直接用浏览器打开，无依赖、联网、麦克风或真实数据。图片为代码绘制的示例占位图，不能作为照片理解质量的证据。

上一片上传/视频/相册改动仍是工作区草稿，没有部署，也不作为本规划已经落地的证据。线上 Demo 当前仍是已部署输入框与生成配置预演版本。本规划中的“发送前附件区”优先于上一片“上传后立即进入聊天流”的临时实现；下一实施片需统一调整，不能同时保留两套语义。

示意图只表达区域分工。具体工具栏在窄屏可分两行，上传和相册文字不得隐藏；语音与发送保持清晰分组，不要求将所有控件压进同一行。

### 顶部计划卡片

- 横向滑动，第一张完整展示，下一张露出约 12% 作为滑动提示；同时提供左右按钮和“第 1 / 3 张”，不能只依赖手势。
- 卡片顺序：临近提醒的真实待办 → 待处理的相册/回忆事项 → 助手建议。真实计划和建议使用不同标签。
- 卡片字段固定为：标题、摘要、状态/时间、主动作。主动作进入聊天流并带入一个白名单意图，例如 `open_schedule`、`review_photos`、`start_diary`。
- 完成、稍后提醒、今天跳过都在卡片内完成；涉及提醒或资产修改必须确认。卡片不直接调用模型。
- 没有真实计划时显示“今天想做些什么？”，只给建议卡片，不能编造时间或待办。

## 聊天状态

### A. 初始首页
问候、计划滑动卡片、三张轻量功能卡片、固定输入栏。输入栏默认聊天，外发授权收进展开说明。

### B. 计划已打开
计划卡片收起为一条“正在处理：下午散步”；聊天流显示一张提问卡片，一次只问一个问题。返回按钮回到计划卡片，不丢聊天草稿。

### C. 资产选择
点击“🔍 相册”后在聊天流内展开相册卡片：搜索框、照片/视频切换、分页、缩略图。浏览不会附加或发送；点选后在输入框上方显示附件预览，可移除，发送后才进入消息流。

### D. 生成设置
输入框选择图片/视频后，描述→参考图片→必要参数→完整设置与报价状态→确认。图片/视频生成与已有资产选择始终用不同文案和入口；高级设置进入更多设置。

## 入口契约

- `＋ 上传`：本地文件选择，支持照片和视频；先显示待上传列表，再显式确认上传。上传完成后回到附件预览；失败可重试同一操作，不自动分析、不自动发给 Agent。
- `🔍 相册`：资产库浏览/搜索；支持照片讲述、描述文字和视频文件名的服务端文字筛选与分页。浏览不改变资产；明确点击后才选择。
- 相册选择的照片可用于聊天附件或图片/视频生成参考；生成参考暂只允许照片。
- 输入栏的素材附件与计划卡片互相独立：切换计划不清空未发送附件，开始生成也不自动带入聊天照片。

## 视觉与可访问性

- 沿用 iframe 的背景、面板、强调色和图标；不使用只靠颜色表达状态。
- 计划卡片和入口按钮至少 48×48 CSS px，默认文字 20px 以上；375px 和 320px 无横向滚动。
- 滑动卡片支持触摸、鼠标拖动、左右按钮、键盘方向键和屏幕阅读器位置说明。
- 附件、上传、搜索、发送、录音均有可读标签；处理期间显示文字状态，禁用冲突操作。
- 150–300ms 过渡，仅动画卡片位置/透明度；尊重 reduced-motion。

## 数据与验证边界

计划卡片 V1 使用本地示例数据验证布局，真实提醒/日历接口另行接入；示例数据必须标注“示例”。相册搜索使用现有 photoApi 和独立视频库；不会把查询结果注入 Qwen 上下文。生成确认当前只确认本地配置，不调用生成和报价接口。

## 验收清单

- 首页顶部滑动卡片在 320px、375px/200% 字体和横屏可操作；不依赖 hover。
- 卡片主动作进入聊天，返回不丢草稿；完成/稍后/跳过状态可理解。
- 上传与相册分离；上传确认/重试、相册搜索/分页/显式选择均可验证。
- 选中的资产先显示附件预览，移除后不进入消息流；确认发送后才持久化或进入聊天流。
- 照片/视频、聊天、生成类型互不误触发；没有模型调用或价格假数据。

## 下一步实施顺序

1. 首页卡片底座：仅示例数据和白名单动作，验证滑动、位置提示、返回计划、字号放大。
2. 统一附件草稿：本地文件和资产库选择共用附件区，区分已上传/待上传/失败；先完成稳定发送语义，再继续视频接入。
3. 相册选择页与聊天流：搜索、分页、显式选择、返回保留草稿；聊天附件不自动发送至模型，外发权限和真实多模态接口需分别落地。
4. 创作卡片：描述、参考、必要参数、报价、确认；真实服务缺失时明确停在配置预演。
5. 计划服务与语音：真实计划来源、时区、提醒授权、幂等修改与持久化后单独验证。当前语音仍以听写草稿为已实现基础，不宣称实时语音陪聊。

设计假设待验证：老人能发现横滑提示；计划摘要能帮助启动对话；双行工具栏比单行密集按钮更容易操作。浏览器触摸模拟和尺寸检查只能验证技术可达性，不能证明老年人的理解和操作成功率。
