# 陪伴版首页与资产入口交互规划 V2

状态：规划确认稿，先验证网页 Demo 交互

## 目标

首页回答“今天做什么”，聊天流回答“怎么一起完成”。顶部计划卡片是可滑动的工作入口，不替代聊天；输入栏的上传和相册入口保持长期稳定，避免老人把新增文件和查找旧素材混淆。

## 本片交付与优先级

本片先交付交互规范和独立可点击线框：`docs/agents/deliverables/2026-10-23-companion-interaction-wireframe.html`。可直接用浏览器打开，无依赖、联网、麦克风或真实数据。图片为代码绘制的示例占位图，不能作为照片理解质量的证据。

上一片上传/视频/相册改动仍是工作区草稿，没有部署，也不作为本规划已经落地的证据。线上 Demo 当前仍是已部署输入框与生成配置预演版本。本规划中的“发送前附件区”优先于上一片“上传后立即进入聊天流”的临时实现；下一实施片需统一调整，不能同时保留两套语义。

示意图只表达区域分工。具体工具栏在窄屏可分两行，上传和相册文字不得隐藏；语音与发送保持清晰分组，不要求将所有控件压进同一行。

### 顶部计划卡片

- 横向滑动，第一张完整展示，下一张露出约 12% 作为滑动提示；同时提供左右按钮和“第 1 / 3 张”，不能只依赖手势。
- 卡片顺序：临近提醒的真实待办 → 待处理的相册/回忆事项 → 助手建议。真实计划和建议使用不同标签。
- 卡片字段固定为：标题、摘要、状态/时间、主动作。主动作进入聊天流并带入一个白名单意图，例如 `open_schedule`、`review_photos`、`start_diary`。
- 完成、稍后提醒、今天跳过都在卡片内完成；涉及提醒或资产修改必须确认。卡片不直接调用模型。
- 没有真实计划时显示“今天想做些什么？”，只给建议卡片，不能编造时间或待办。

## 聊天状态

### A. 初始首页
问候、计划滑动卡片、三张轻量功能卡片、固定输入栏。输入栏默认聊天，外发授权收进展开说明。

### B. 计划已打开
计划卡片收起为一条“正在处理：下午散步”；聊天流显示一张提问卡片，一次只问一个问题。返回按钮回到计划卡片，不丢聊天草稿。

### C. 资产选择
点击“🔍 相册”后在聊天流内展开相册卡片：搜索框、照片/视频切换、分页、缩略图。浏览不会附加或发送；点选后在输入框上方显示附件预览，可移除，发送后才进入消息流。

### D. 生成设置
输入框选择图片/视频后，描述→参考图片→必要参数→完整设置与报价状态→确认。图片/视频生成与已有资产选择始终用不同文案和入口；高级设置进入更多设置。

## 入口契约

- `＋ 上传`：本地文件选择，支持照片和视频；先显示待上传列表，再显式确认上传。上传完成后回到附件预览；失败可重试同一操作，不自动分析、不自动发给 Agent。
- `🔍 相册`：资产库浏览/搜索；支持照片讲述、描述文字和视频文件名的服务端文字筛选与分页。浏览不改变资产；明确点击后才选择。
- 相册选择的照片可用于聊天附件或图片/视频生成参考；生成参考暂只允许照片。
- 输入栏的素材附件与计划卡片互相独立：切换计划不清空未发送附件，开始生成也不自动带入聊天照片。

## 视觉与可访问性

- 沿用 iframe 的背景、面板、强调色和图标；不使用只靠颜色表达状态。
- 计划卡片和入口按钮至少 48×48 CSS px，默认文字 20px 以上；375px 和 320px 无横向滚动。
- 滑动卡片支持触摸、鼠标拖动、左右按钮、键盘方向键和屏幕阅读器位置说明。
- 附件、上传、搜索、发送、录音均有可读标签；处理期间显示文字状态，禁用冲突操作。
- 150–300ms 过渡，仅动画卡片位置/透明度；尊重 reduced-motion。

## 附件草稿切片约束

聊天/图片/视频各自保留待发送附件，切换类型不混用。选中相册素材或上传成功只加入当前类型附件区，可预览和移除；上传已保存的文件不会因移除附件而删除。上传前的本地文件仍须显式确认上传，上传过程中锁定新建会话、类型切换与发送，避免结果归入错误草稿。

当前文字聊天协议不接受媒体：附件区显示“本次素材只在页面展示，助手暂时看不到”；有文字和素材时须单独勾选确认后才可发文字，素材不进入模型请求。仅素材可通过发送按钮加入本页对话，无外发请求；此操作不产生虚假的助手回复，不宣称持久化会话附件。文字请求失败保留附件并复用原请求；收到成功回执才清空本轮草稿附件。刷新后本页附件展示不恢复，原文件仍在相册。图片/视频创作只允许一张照片参考；视频或多图必须先移除/更换，不得静默丢弃。生成配置仍是本地预演。

## 相册界面精简

关闭采用右上角 X；搜索采用栏内放大镜提交、输入框和条件出现的清除图标，保留无障碍名称，删除重复标签与“查看全部”。照片/视频缩略图不带按钮边框或固定选择文案，选择图标在桌面 hover/键盘聚焦时显示；触摸设备常显，整张缩略图可选择。搜索命中摘要仅在搜索结果出现。现有接口没有删除或复制素材能力，本片不添加无效操作图标。验证选择、分页、搜索清除与关闭行为，保留其他引用网格样式。

相册采用两列瀑布流：照片使用缩略图实际宽高比，不做固定比例裁切；每张照片与搜索摘要保持为同一个不可跨列的单元。采用 CSS columns，视觉与键盘阅读顺序均按先上后下、再到下一列。

## 功能 Sheet 外壳

相册从聊天流内嵌卡片迁移为可复用的功能 Sheet：背景保留聊天并显示遮罩，移动端从底部展开，桌面端居中显示；顶部提供拖拽提示条、标题和 X，内容区域独立滚动。Escape 和点击遮罩可关闭，关闭后返回原聊天位置并保留草稿。相册、日记、广场共享该外壳，内部继续使用各自的瀑布流或列表布局。相册仍按照片、视频、记忆卡、待讲述扩展分类；本次先实现照片/视频内容迁移，不虚构尚未存在的记忆卡数据。

## 底部一级导航与聊天输入区边界

底部一级功能固定为“日记 / 广场 / 相册 / 我的”。相册只从底部导航打开 Sheet，聊天输入区不再重复提供“相册”按钮；输入区保留上传、聊天/图片/视频、语音和发送。输入区与 Sheet 内的功能图标均采用无边框图标按钮，只在 hover、focus 或 pressed 状态提供反馈，保持至少 44px 触摸区域。日记、广场和我的先复用同一 Sheet 外壳，再逐步替换各自内容。

## 日记生成、确认与日历切片

日记入口改为默认今天的月历，年月可选，点击日期查看当日日记；已保存日期以 ✅ 标记，未保存草稿不标记。无日记日期提供“整理这一天的日记”，将带日期的明确请求填入聊天草稿，不自动外发。完成该请求的文字结果显示日记草稿卡，用户可“编辑”弹出编辑器或“直接保存”；所有持久化均须显式按钮确认。已有日记可编辑保存。日历只读取当前 owner/actor 的真实记录，不用示例记录。以现有 Companion SQLite 独立日记表持久化，按用户/日期唯一，修改采用 revision 冲突检查，保存 operation_id 幂等；首存必须关联属于当前用户的已完成文字 turn。关闭编辑不保存；网络失败保留编辑并复用同一请求。聊天草稿不得因打开日历而丢失，日记生成仍受文字外发确认限制。无历史对话时模型只能询问/使用现有原话，不宣称已拥有当日全部生活记录。

验收：模型结果→草稿→编辑/明确保存→日历标记→按日重读；刷新后仍能读取保存内容。API 验证跨 owner/actor 隔离、日期校验、修改冲突、重试幂等及文字来源；UI 验证默认日期、年月切换、取消不写入与错误保留。部署仅隔离 demo，不推送/合并。

## 日记对话中的日期可见性

日记请求的原始聊天消息包含明确 ISO 日期，显示层将用户标签渲染为“我 · YYYY年M月D日”，正文使用“请把 YYYY-MM-DD 我们聊的内容整理成一篇回忆日记”。旧的“今天（日记日期：...）”格式继续可识别。日记草稿卡、日历选择和保存接口使用同一日期，避免聊天回看时只看到相对日期“今天”。
