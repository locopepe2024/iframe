# iFrame 创作台老人陪伴 Agent Chat Demo 需求 v1

日期：2026-10-07
状态：需求规格，待 iFrame 管理员评审和合并
入口：iFrame 主机的 iframe 版本，创作台（Playground）Agent Chat

## 目标与范围

Demo 让长辈用文字或录音转写自然聊天。录音经 MiniMax ASR 1.0 转成可编辑文本，由用户检查后发送；录音本身不自动作为对话事实或记忆保存。Agent 根据当前对话识别意图，并在同一聊天界面引导完成五件事：延续已确认的往事、记录日程、回答问题、上传并保存素材、把聊天内容整理成可编辑的剧本草稿。对话是入口，最终结果必须能在相应的持久化界面中查看和修改。

本期不建设独立任务体系。日程是带日期和时间的记录，不等于后台任务、闹钟或主动通知。媒体播放、真实提醒、照护者通知和自动发布剧本均留待后续。

## 需求记录

1. 陪伴表达：温和、尊重、简短；允许重复讲述故事，主动接续话题，情绪低落时先回应感受；可做成语接龙、猜谜等轻量互动。不得虚构见闻、强行赞美或替代现实照护关系。
2. 长期记忆：从长辈明确自述中提出带原话来源的候选；经用户确认后保存。支持查看、修改和删除；跨会话引用时不得把推测说成事实。生日、亲属、健康等敏感信息尤其需要确认。
3. 日程：从聊天中识别日期、时间和事项；信息不足时追问；先展示可修改草稿，确认后存入日历，可按日/周查看和编辑。服药信息只记录用户或医生明确给出的内容，不推断剂量。
4. 问答：回答一般问题；对时间敏感或需要外部事实的问题，区分已知信息与尚未查询的信息。医疗和投资问题不做个人决策或诊断。
5. 素材：在谈到老照片、录音、视频、文稿等材料时，给出上传入口；展示文件名、类型和预览；由用户指定用途/分类并确认后保存到资产库。上传临时参考文件不等于资产库入库。
6. 剧本：可从用户指定的聊天片段或已确认的故事记录提取文字，生成可编辑草稿；保留来源会话/消息引用、摘录与生成时间。用户预览、修改、确认后，才创建或写入目标项目的剧本编辑器，并保留编辑器原有版本/保存流程。不要覆盖现有剧本。

## Demo 交互契约

### 意图识别与技能唤醒

- 每轮识别可并存的意图：`reminisce`、`schedule`、`question`、`material`、`script`、`small_talk`。优先依据用户明确表达；不确定时用一句简短问题澄清。
- “唤醒”表示展示相应入口或生成待确认草稿，不授予模型任意后端写权限。聊天回复中应能看到建议的下一步；所有实际写入由受限 API 和用户确认完成。
- 一轮可能同时包含回忆与日程，例如“上次说过孙子的考试，明天下午去接他”；需要同时提供相关记忆和日程草稿，不能因单标签路由丢失另一项。
- 问答是默认能力，无需额外技能开关。历史话题只能依据同一会话上下文或已确认的跨会话记忆；候选记忆不可当作既定事实。

### 日历记录

- 在 Agent Chat 附近提供易读的日/周日历入口和日期导航；日程条目至少有标题、开始时间、可选结束时间、备注、时区、来源消息和 owner。
- 对“明天”“周三”等相对日期，按当前用户时区解析并在确认卡中显示绝对日期；无时间的事项可标为全天或待定，不补造具体时刻。
- 支持手工新建、对话草稿确认、新建后查看/编辑/删除。重复事项和冲突提示可后续扩展；本期不触发闹钟或推送。

### 素材与剧本

- 上传前说明可接受的文件类型、大小与目标用途。Demo 优先使用现有资产库已支持的媒体类型；其他格式可作为聊天参考或待支持项，不声称已入库。
- 成功入库后返回可打开的资产记录和稳定 ID；失败时保留可重试状态，不在对话中宣称成功。
- 剧本草稿应把“用户原话摘录”和“Agent 改写/结构化内容”分开展示。若来源消息已删除或用户撤回授权，不能继续以其作为可追溯的生成依据。
- 写入剧本前选择已有项目或创建新项目，并明确“新建草稿/插入位置”；确认后通过剧本编辑器既有保存机制持久化，返回可打开的文档位置。不得静默覆盖已保存内容。

## 建议的最小演示路径

1. 长辈讲述一段往事；Agent 倾听并提出一条有来源的记忆候选，用户确认保存。开启新会话后，Agent 能准确引用该条记忆，用户可删除。
2. 长辈说“明天下午三点去社区活动”；Agent 显示绝对日期和时间的草稿，用户确认后在日历看到该事项，并能修改或删除。
3. 长辈问一个一般问题；Agent 直接回答。问到个性化用药时，仅复述已提供事实并建议咨询医生。
4. 长辈提到一张老照片；Agent 引导上传，用户确认分类/名称后，在资产库看到对应记录。取消确认则不产生资产记录。
5. 长辈指定刚才的故事“整理成剧本”；Agent 展示带原话来源的剧本草稿，用户确认后在剧本编辑器打开，原有剧本没有被覆盖。

## 数据与安全边界

- 所有记忆、日程、上传记录、资产关联和剧本草稿按当前 owner 隔离；跨服务/项目引用使用稳定 ID 和来源，不以文件 URL 当身份。
- 记忆候选、意图分类和剧本改写是模型或规则的解释性输出；未经确认不得变成用户事实。记录确认动作、来源消息和写入结果。
- 涉及老年人的健康、家庭和生活规律，默认最小化采集；提供可见的删除入口。日程删除、消息删除、资产删除与衍生内容之间的保留/撤回规则须在实施前明确。
- 不依赖 ChatGPT 产品设置中的 Memory 开关；iFrame 的记忆由自身服务端管理。不得用“永久记住”或“已设提醒”描述尚未实现的能力。

## 实施与验收边界

语音输入第一段已在功能分支实现：Agent Chat 显示录音按钮前查询当前用户的 `asr-1.0` 模型可见性；录音最长 60 秒，浏览器转换为 WAV，服务端验证格式与 50 MiB 上限后调用 UniArt `/audio/transcriptions`，返回文字到输入框供用户编辑。当前只完成本地模拟验证，仍需以有权访问该 SKU 的 iFrame 用户做真实中文语音请求、浏览器权限与口音/噪声样本验收；不能据此宣称目标环境已上线。

建议先合并并验收 PR #51 的记忆基础，再分别实现：意图识别与确认卡、日历条目、Chat 到资产库、Chat 到剧本编辑器。每一段都要有失败和取消路径，且后端校验 owner 与来源。代码变更提交给 iFrame 管理员评审、合并；本文件不代表已获得合并或发布授权。

Demo 验收以五条最小演示路径为准，并检查新会话、页面刷新、删除/取消、跨用户访问、模糊日期、上传失败、剧本冲突这几类边界。通过只看模型回复，不能证明日程、素材或剧本已真实保存。
