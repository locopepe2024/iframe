# 故事板与分镜设计：继承、局部优化和表演时序 V1

状态：设计规格；拍摄计划字段逐项采纳为第一实施切片，微表情 Skill 尚未实现。

## Observed

- 代码事实：故事板帧已有景别、机位、构图、运镜、光影、表演、动作、对白和转场字段；分镜卡另有风格与光线覆盖输入。空风格覆盖使用项目风格；风格和光线编辑会同步已采用的可见优化稿。
- 代码事实：已选参考图与结构化视觉投影分开；结构化投影需要用户确认类别。同时间不同地点只可带世界光，同地点同时间才可带空间、相机和连续性状态。未确认连续性 ID 时不自动投影。
- 代码事实：当前分镜优化器可选择模型和现有 Skill，但目录里尚无微表情时序 Skill；角色表情面板只描述单张图可见的静态表现。
- 现有规格将故事板场景/参考准备与 Shot Design 提示词、视频生成分开。结构化场景、图片变体和当前镜头各有版本与来源，已确认镜头不得被上游后来编辑静默重写。

## Direct implication

风格和光线输入现在表达**本镜覆盖**，不等于“已继承的一致性”。若把继承值直接填入覆盖输入，用户无法判断来源，也难以区分主动改动与默认基线。分镜优化应读取用户已确认的有效基线，并提出可审阅的镜头局部修改；优化文案不能反向改写场景资产、参考变体或连续性快照。

## 归属与优先级

| 层级 | 负责的决定 | 分镜中的呈现 |
| --- | --- | --- |
| 剧本与导演计划 | 场次事实、时间地点、叙事意图、镜头任务与状态交接 | 显示来源；不将叙事形容词直接当光照参数 |
| 项目/剧集视觉方向 | 基础画风、色彩语法、画幅 | 默认基线；同一序列保持，明确改版才变化 |
| 场景设计及选定变体 | 固定空间、世界光、局部光源、材质和基础视点 | 读取已确认版本；选参考后可逐类确认结构化投影 |
| 故事板帧 | 当前镜头拍什么：主体、动作、开/结束状态、景别、机位、构图、计划运镜 | 每镜独立结构化行；计划值可编辑，不回写场景 |
| 分镜设计 | 当前镜头怎么呈现：局部机位/运镜、风格/光线覆盖、可见表演与微表情时序、首尾帧/视频提示词 | 保留来源和差异；优化结果是候选，用户应用后成为镜头版本 |

有效值按字段与作用域解析：当前镜头显式值 > 目标场景已确认的对应值 > 用户确认且符合连续性范围的参考投影 > 项目视觉方向 > 计划建议。参考投影只填目标字段空缺，不覆盖目标镜头或目标场景已有的明确值；世界光、局部光、空间和相机分别判断，不能用一个整段文本覆盖全部。剧情事实与角色身份是约束，不参与这个视觉字段覆盖序列。冲突须标出来源供用户审阅；不能把互相矛盾的文本一起追加。空覆盖表示继承，用户清空覆盖后恢复基线。对旧镜头中没有来源的自由文本，只能标为来源未知，不反向猜测字段。

## 每镜结构化行

每镜至少展示镜头任务、主体/当前动作、起止状态、景别、机位/轴线、构图与站位、主运镜及速度、风格、世界光与局部光、表演、对白/声音、画幅、转场和来源。将“镜头”拆清为景别、机位、构图/视线轴线与运镜，避免一个自由文本槽位承担互相冲突的指令。画幅来自项目或明确镜头特例，不应由 Skill 随意重设。

每个可继承字段展示“有效值 / 来源 / 本镜覆盖”；来源可为项目、计划、场景设计、所选变体或用户覆盖。选参考图默认仍是图片本身；可供继承的结构化类别只来自该图的历史设计快照，经用户勾选后形成当前镜头快照。场景当前设计不能冒充旧变体的生成时版本。

## 分镜 Skill 边界

1. **镜头设计**读取当前镜头任务、已确认空间/光线/风格、角色和参考素材；提出景别、机位、构图、主运镜及起落幅。每个改动指出目标字段和理由；不自动改画幅、时间地点、角色身份或场景几何。
2. **分镜连续性**比较相邻镜头的显式 place/time ID、世界光、局部遮挡、轴线、站位和状态交接。跨地点同时间仅建议世界光；同地点同时间才可建议空间/机位/站位。前镜动作、对白及角色描述不作为参考图结构化视觉投影。动作状态交接须来自已确认的本镜计划或状态记录，不能从画面顺序猜测。
3. **微表情时序**属于当前分镜的表演层，以角色为作用对象。静态角色锚点保留面部结构、肤质和服装；当前镜头单独描述情绪意图、可观察的眉/眼睑/视线/嘴/下颌变化、触发、变化、短暂保持和恢复/落点。仅在镜头长度、景别与可见性允许时输出细节；远景或被遮挡时降为可见的姿态/视线变化，不编造不可辨的肌肉动作、固定毫秒或 AU 效果。微表情不得改变基准脸型、唇形、肤色、服装或场景光线。
4. **模型提示词适配**最后根据目标模型输出契约组织已确认字段。H3/Seedance 等模型 Skill 负责格式和能力限制，不重新决定剧情、一致性归属或参考图用途。独立 Skill 可以组合，但同一字段的提案应合并为一个可审阅差异，不能叠加相互矛盾的完整提示词。

首帧是镜头起始时刻的静态快照：可表达当时可见的表情状态，不应在首帧图片提示词中加入“触发→保持→恢复”的完整时序。时序用于视频/表演提示词，尾帧描述其终点；无尾帧时不声称终点已被图像证实。

## 用户流程

1. 在故事板检查每镜结构化行及来源；选择场景/角色参考图时，用户决定是否带入允许的结构化类别。
2. 在分镜设计查看有效风格、光线、空间与相机基线；仅在要改变当前镜头时填写覆盖。UI 显示覆盖前后差异及作用范围。
3. 选择镜头设计、连续性、微表情等优化能力，先预览准确的模型输入与参考图。Skill 返回逐字段建议和完整候选提示词；用户决定应用哪些建议。
4. 首帧生成与视频生成分别审阅最终文本、参考媒体、字段来源和版本。上游确认版本变化后标记已采用稿待审，不静默重算历史结果。

## 尚未证明及验收

- 尚未证明：当前所有首帧、视频及优化入口都共享同一有效值解析与来源展示；需要逐路径核对实际请求。也未证明模型能视觉上遵守微表情或一致性指令。
- 行为验收：空覆盖显示并使用已确认基线；修改本镜覆盖仅影响当前镜；清空覆盖恢复基线；同时间换地点只继承世界光；缺少连续性 ID 不自动继承；所选旧变体保持其生成时结构化版本。
- 隔离验收：仅优化微表情时，角色身份、服装、场景、光线、机位、景别、参考图 ID 和其他镜头保存值不变；首帧无时序，视频有可观察的时序；前镜动作、对白和角色描述不通过参考结构化投影进入本镜。
- 提交验收：用户预览的完整提示词及媒体集合等于提交值；优化候选未应用前不改变已采用稿。视觉一致性需用实际多镜生成和人工比对验证，字段/请求测试通过不能替代该观察。

建议实施顺序：先统一字段来源与有效值预览，再接入镜头设计与连续性 Skill 的逐字段候选，最后加入微表情时序及首帧/视频分流。每一阶段先补失败行为测试或等价复现，再验证保存、重载、预览和提交。

### 第一实施切片：已确认计划字段采纳

输入仅为服务端投影的已确认 `director_shot_context.shot`。对景别、机位、运镜和时长分别呈现“当前镜头 / 拍摄计划 / 采用”；无计划值时不生成建议，同值时不重复建议。采用单项只更新该镜头对应字段，复用现有顺序保存与生成提示词组装；计划原文、角色表演、对白、动作和场景内容不随此操作写入自由提示词。当前值不论是否为空都由用户决定是否覆盖。计划时长超出当前模型范围时显示原因并禁用采用。镜头已有完整优化稿时，景别、机位和运镜暂不可采用，因为当前生成路径会绕过结构化字段；时长仍可采用。测试覆盖单项隔离、同值消失和无效组合；保存映射沿用现有 `updateFrame` 路径。

此切片是来源明确的计划值采纳，并不声称 AI 做出了新的摄影选择；后续模型提出的镜头设计候选须进入同一个逐字段审核合同，并携带建议理由、来源和版本。
