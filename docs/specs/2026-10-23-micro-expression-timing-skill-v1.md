# 分镜微表情时序 Skill V1

状态：独立 Skill 包与结构化合同校验已实现；尚未接入分镜 UI、模型调用或保存接口。日期：2026-10-23。

## 目标

为当前分镜中的指定角色设计可见的表情变化时序。该 Skill 只处理表演层，不重新设计场景、角色身份、服装、光线、景别、机位、运镜或对白。

## 输入边界

- 当前镜头的角色 ID、镜头时长、景别、构图、可见区域和遮挡状态。
- 已确认角色锚点图及版本；只用于保持脸型、五官、肤质、发型、服装和身份。
- 当前镜头已确认的情绪意图、动作起点/终点、对白及对白情绪（如有）。
- 已确认的连续性状态和上一镜交接状态；只读取与本角色当前表演有关的状态。
- 用户明确选择的表演目标，例如“只调整表情”“保持身体动作不变”。

不得把参考图的完整提示词、前镜对白、前镜动作或其他角色描述作为表情设计输入。缺少角色锚点、镜头时长、可见性或连续性依据时，输出待确认项，不猜测。

## 输出合同

输出按角色分组的候选，不输出整段视频提示词。每个角色包含 `character_id`、`emotion_intent`、`visibility`、`timing`、`facial_channels`、`body_invariant`、`uncertainties` 和 `source_refs`。`timing` 的阶段固定为 `trigger`、`change`、`hold`、`release`，并使用镜头时长比例 `relative_start` / `relative_end`，不是模型保证的固定毫秒。

`facial_channels` 只允许 `brows`、`eyes_gaze`、`eyelids`、`mouth`、`jaw`。没有足够近景可读性时，降级为视线、头部方向或整体姿态；不得编造不可见的肌肉细节或 AU 编码。

## 首帧与视频分流

- 首帧只消费 `trigger` 阶段在 0.00 秒可见的静态状态，不写入 change/hold/release 的过程词。
- 视频提示词消费完整时序，并明确动作终点；没有已确认尾帧时，不声称终点已被图像证明。
- 尾帧存在时，只描述尾帧可见的 release/hold 状态；中间变化仍属于计划，不是图像观察事实。

## 不变量与采纳

用户只采纳微表情候选时，角色锚点及版本、服装、场景及光线、景别、机位、构图、运镜、对白、参考媒体、其他角色和其他镜头必须保持不变。候选保存输入快照哈希；相关字段变化后候选过期。用户可逐角色、逐通道采纳或拒绝，未采纳不修改已确认镜头。

## 验收边界

- 只选择微表情 Skill 时，提交预览中不存在新的场景、角色描述、服装、光线、镜头或对白决策。
- 近景可以返回眉、眼、眼睑、嘴、下颌的可见变化；中远景或遮挡状态自动降低细节粒度。
- 首帧提示词不含完整时序；视频提示词含触发、变化、保持和落点，且顺序与镜头时长一致。
- 没有角色锚点或可见性证据时返回待确认项，不猜测。
- 前镜动作、对白和角色描述不会通过参考投影进入当前表情候选。
- 预览文本与提交文本、媒体和版本快照一致；候选过期后拒绝应用。

## 未证明

字段合同和不变量测试只能证明输入隔离与提交边界，不能证明模型生成结果一定呈现准确微表情。需要固定角色锚点、镜头时长和模型的实际视频样本进行人工审阅。
