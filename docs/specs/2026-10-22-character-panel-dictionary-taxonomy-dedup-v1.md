# 角色面板与词典分类去重 V1

日期：2026-10-22。范围：角色设计与角色图片 Prompt 的本地基础面板、词典、Prompt 模板。运行时平台目录未纳入本次计数。既有保存 ID 与配置快照保持可读。

## Observed

运行 `cd frontend && ./node_modules/.bin/vite-node --config vitest.config.mts scripts/audit-character-dictionary.mts`，当前本地包有 578 个候选：457 个预设（其中 14 个配置面板）和 121 个非路由快捷词条。词典定义 16 个大类、95 个子类。没有重复 ID；按同类同名统计有 15 组词条，按词条槽位插入值统计也是 15 组。14 个面板之间有 18 组共享字段，但这不等于 18 处重复数据。

`CharacterDictionaryPreset` 用 `type` 区分词条、配置面板和模板；`categories` 表示浏览位置，`dictionaryStructuredFields` 另决定应用后写入的身份/造型字段。Prompt 模板使用任务、题材、画风三个发现维度。三种分类目前不由同一字段注册表驱动，不能将同名分类当作相同的写入行为。

## 面板分类

| 一级分类 | 基础面板 | 粒度与主要去向 |
| --- | --- | --- |
| 基础身份 | 基础特征 | 性别、年龄、身高，写入身份字段 |
| 面容与身体 | 面容、肤色与肤质、发型、体态 | 面容是组合；其余是局部字段，写入身份字段 |
| 服装搭配 | 古装外套、古装衣裙、现代男装、现代女装 | 整套穿搭组合，写入造型描述 |
| 服饰细节 | 古装鞋履、首饰、配饰、新旧 | 局部造型，可覆盖组合中的相应章节 |
| 表演 | 表情 | 目前写入文本，无独立稳定表情字段 |

本轮将这五组作为基础面板的界面分类，保留原 14 个面板 ID 和具体选项。`面容` 与 `肤色与肤质` 共享两字段；古装穿搭组合内含鞋履、首饰、配饰和新旧；首饰组合内含首饰状态；现代服装和新旧共享衣物状态。这些是“组合面板 + 局部面板”的交叉，应展示粒度区别，不能通过删除局部面板来去重。若要从组合面板移除字段，必须先确定旧配置快照恢复及生成提示词如何迁移。

## 词典与模板

词典大类按描述对象浏览：面部、身体、风格、时代题材、角色定位、服装、鞋履、发型、面部表现细节、表情、首饰、装饰、新旧、场景构图、表演。词典定义文件还含 `templates` 大类，但界面将其排除，模板单独进入 Prompt 模板页签。一个词条可以属于多个适用子类；分类不是唯一身份。

Prompt 模板按**任务**发现：角色设计、风格写真、换装写真、电商主图、UGC、视觉风格、运镜、多视图与推演；古装/现代/仙侠/国风是题材，真人写实/动漫/插画是画风。这些维度不得与面板的“面容、鞋履”等字段分类合并。模板默认追加完整 Prompt，不等同局部词条或配置面板。表情模板虽然共用字段骨架，但默认值不同，不应因文本骨架相同而去重。

## 去重判定

1. **重复 ID**：直接报错；当前为 0。
2. **同名候选**：以作用部位和描述维度作为区分依据，再比较来源、完整描述、槽位输出和保存 ID。当前 15 组不是自动删除清单。例如“丝绸”“黑色”分别可用于衣料和鞋履；“交领长袍”“直裰”在通用古装形制与男装外衣中描述侧重点不同。不同部位或不同维度必须保留独立身份。
3. **同字段面板**：选定唯一字段 owner，组合面板只能复用该 owner 的字段定义；组合仍可保留便捷入口。`面容/肤色肤质`、`首饰/新旧`、`穿搭/鞋履/配饰`是优先核对项。
4. **真正等价的词条**：经人工确认作用部位、描述维度、适用域和输出均一致后，选一个规范 ID；旧 ID 作为显式别名继续读取，合并分类标签与搜索别名。不得按标题或中文输出自动重写旧保存记录。
5. **平台目录**：按平台资源 ID、revision 和审核状态处理；不因与本地词条同名而自动合并。平台条目数及冲突需单独以实际目录响应审计。

## 下一切片

建立字段注册表，以稳定字段 ID 定义所属域、适用主体、**作用部位**、**描述维度**、可用词条类别和写入动作；面板、`[槽位]` 与结构化角色设计共同引用。例如 `嘴唇/形状=微微翘起` 与 `嘴唇/厚薄=上厚下薄` 是两个可共存的字段；`下颌/稳定形态` 与 `下颌/表情状态` 也不能因同名而互相覆盖。先处理面容/肤色肤质和首饰/新旧两组交叉，再处理完整穿搭组合。每次迁移提供旧 ID/中文字段键读取适配和行为测试，比较应用前后保存快照及最终提示词。无法证明等价的同名词条保留并显示所属分类。

## 局部调整：提示词蒙板原则

用户选择“只调整表情”时，先确定本次**可改层**：表情及其必要的眉部、眼睑、视线、嘴部、下颌状态、面部气色。稳定身份（脸型、五官固有形态、肤色肤质、识别标记）、造型（服装、发型、饰物）、场景空间、光影与镜头为**保护层**；除非用户逐项放开，否则不从表情词条回写。表情词条描述的是当前表现，不应将“嘴角上扬”等瞬时状态保存为永久嘴唇形态。

应用动作必须带明确的 `target_layer`、`target_field_ids`、`change_scope` 和 `preserve_field_ids`，由当前工位生成可见的“本次修改 / 保持不变”清单。Prompt 组装时从确认过的结构化版本与所选参考图读取保护层，只替换可改字段；保存新版本并保留父版本、实际输入文本、参考图变体和应用来源。用户可取消或编辑建议，不能用一段新模板覆盖整份角色/场景设计。提示词中的“保持不变”是模型指令，不能保证像素级局部不变；真正的图像蒙板或局部重绘需要相应模型能力、蒙板输入和结果验证。

最小行为验收：给同一角色与场景应用表情词条后，身份、服装、场景、光照、机位和参考变体 ID 的保存值不变；最终请求只增加表情层变化；再次编辑嘴唇厚薄时不会清掉嘴唇形状。若生成结果出现重做场景，记录为运行时失败，不能把结构化字段未变等同于视觉一致性已实现。

## Not yet proven / What would verify it

- 当前运行时平台词典的数量、同名冲突和真实使用频次未核对；本地审计不覆盖线上目录。
- 同名条目是否构成用户可感知的重复，需要看搜索结果、选择率和用户对完整描述的判断；同名本身不足以证明语义等价。
- 面板字段交叉是否造成最终 Prompt 重复，需要对同一角色依次应用组合与局部面板，并比较结构化字段、配置快照和实际生成请求。当前静态审计只证明定义交叉。

## 2026-10-22 第一实施切片

已新增 `characterDictionaryFields.ts`，为全部 14 个基础面板的现有槽位登记稳定字段 ID、语义域、部位、描述维度和词典类别；有结构化写入目标的字段也在同一定义中声明。面容/肤色面板共用肤色与肤质字段定义；稳定下颌/唇形与临时下颌状态/嘴部表现分离。`dictionarySlotCategory` 优先读取注册类别，`dictionaryStructuredFields` 从注册目标写入，旧面板 ID、选项值与 `dictionary_configurations` 格式不变。

词典搜索结果显示分类路径和词条描述，同名的服装/鞋履材质仍作为独立条目展示；面板字段显示所属部位与描述维度。没有按名称合并词条，也没有重写历史保存配置。前端逻辑测试 25 项、词典 UI 测试 44 项、类型检查和生产构建通过。

尚未完成：组合面板与局部面板连续应用的结构化合并、服装段落去重、历史配置重新打开时的逐字段恢复，以及平台词典运行时冲突审计。这些必须以应用、保存/刷新和最终请求的行为测试验收，不能由字段注册表的存在推断已解决。

## 2026-10-22 新旧状态字段切片

衣物状态和首饰状态现在分别写入 `look.features.garment_condition` 与 `look.features.jewelry_condition`；组合面板的结构化服装段落不再重复包含衣物状态。旧 `look.features.condition` 保留读取与展示，不反向解析其自由文本，也不静默覆盖它。若旧综合状态与新字段同时存在，界面仍会显示两者，需由用户审核潜在语义冲突。

本切片验证了组合面板与局部面板的字段合并、结构化文本各出现一次、后端草稿和确认 revision 中的 `design_input` / `design_result` 往返，以及旧字段读取。这里的“去重”限于结构化字段投影；直接在出图 Prompt 文本中先后插入两份完整面板描述，仍可能保留两段原文，后续需要结合实际应用路径处理。平台词典审计和图片生成结果一致性仍未验证。

## 2026-10-22 连续应用修复

角色设计框内输入第二次 `/` 查询时保留已有结构化字段；应用后，若剩余文本与已应用面板快照中的预览原文完全匹配，只剔除该面板预览，保留用户另写的内容。行为测试覆盖面容后接肤色肤质、最终保存 Prompt 和重载后的字段。用户手改的面板文字不会按含义猜测并删除。直接在各出图任务 Prompt 中连续插入面板的文本去重仍待单独设计和验证。

## 2026-10-22 唇形字段补齐

面容面板新增 `[唇形]` 槽位与独立词条，写入 `identity.features.lips`。它与表情层的 `嘴部表现` 分开：唇形描述稳定形状，嘴部表现描述当前状态。没有选择唇形时，面容面板仍不输出该行。

鼻型同样补齐为面容面板槽位，写入 `identity.features.nose`；鼻型词条沿用现有 `nose` 分类。面容稳定字段不再只依赖自由文本保存。

## 2026-10-22 表情面板与稳定字段

**代码事实：**当前角色工作台的三个出图任务 Prompt 只在生成核对界面编辑，未开放面板选择；此前列出的“任务 Prompt 连续插入面板”并非当前用户可达流程。角色设计入口的表情面板原本没有结构化目标，应用时走普通文本编辑并清空身份与造型字段。

表情面板现在作为当前描述保存在补充提示词中，不写入稳定面容字段。后续选择肤色等结构化面板仍保留表情；再次选择表情时，只有与上一份配置快照完全匹配的旧预览会被替换。测试覆盖稳定唇形、肤色与最终 Prompt。这里没有建立分镜级表情状态；分镜微表情 Skill 仍按既定顺序另行设计。

## 2026-10-22 面板选择值恢复

重新打开已应用的基础面板时，按面板 ID 从当前设计的 `dictionary_configurations` 恢复 `selections`；保存并重新加载后同样回显。只将当前面板仍支持的选项填入控件；过期选项在界面回退为默认值，旧快照原文仍保留供追溯。测试覆盖即时重开、保存重载和过期选项。

## 2026-10-22 组合与局部面板冲突提示

**代码事实：**整套古装面板与鞋履、首饰、装饰局部面板写入相同的结构化章节。局部面板后应用时，当前字段更新，但整套面板的历史选择仍保存在其配置快照中。重开整套面板会回显历史选择，再次应用会覆盖当前章节。

有历史配置的面板重开时，界面现在将其待写入字段与当前结构化设计逐项比较；差异会显示中文字段名，操作按钮改为“覆盖冲突并应用”。用户仍可修改选择或关闭面板。比较是基于结构化字段值，不推断两段文本是否语义等价，也不删除历史配置。行为测试覆盖整套古装后局部修改鞋履、重开冲突提示、保存后单段鞋履 Prompt 及重载回显。相关 UI 114 项、独立源码类型检查和生产构建通过；共享 `.next` 指向其他工作树，常规 `npm run typecheck` 仍受其陈旧生成类型影响。

后续补齐了首次选择面板的冲突检查：只要当前结构化设计中已有目标字段且与待应用值不同，就在应用前提示，不要求该面板已有配置快照。首次从局部鞋履转向整套穿搭与整套穿搭后局部修改鞋履均覆盖；空字段不报冲突。这个检查仍不能从自由文本推断字段值。
