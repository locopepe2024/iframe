# 角色档案与视觉设计契约 V1

状态：项目角色工作台按提示词与参考图推进；Avatar 保持独立入口
日期：2026-10-08

## Observed

- 当前 `Character.description` 混合外观和性格；`buildCharacterImagePrompt()` 将它原样放入全身、三视图和肖像提示词。
- 角色工作台的「角色特征建议」来自固定 catalog。点击后保存 facet ID，并把通用说明追加到当前 Prompt；这些说明不是该角色的具体视觉事实。
- 原有 `digital_avatar` 字典存储旧 facet ID；项目角色工作台的设计草稿和版本改由 `character_design` 字段保存。facet ID 不是已完成设计。

## 决定

角色工作台以同一角色 ID 展示两个有边界的区域：

1. **角色档案**：从剧本提取并可人工修订的身份、性格、经历、剧情事实和来源。它是设计依据，不直接充当图像提示词。
2. **角色视觉设计**：用户可编辑并保存的可见特征，包括年龄外观、脸部识别特征、基础发型、体态、基础服装和稳定识别锚点。字段为空即为未指定，不用通用质量短语填充。

AI 可辅助填写视觉设计字段，但没有独立的「待确认提案」实体。填写后的内容是普通编辑草稿，保存时才成为当前视觉设计版本。不能从性格推断出具体五官、发型或服装并自动保存为剧本事实。

## 提示词与版本

- 图像 Prompt 由已保存的视觉设计、当前项目风格和本次图像任务的构图要求组合。性格事实仅在能转成可见表情或体态且用户认可时进入视觉设计。
- 全身、三视图、肖像的视角、背景和画幅属于本次任务，不属于角色身份。镜头动作和瞬时情绪属于镜头设计。
- 用户在 Prompt 编辑器中的改动仅影响本次生成，不回写角色档案或视觉设计。
- 保存视觉设计变化产生新的设计 revision，并保留旧版本内容供追溯；图片是该 revision 下的生成变体。仅改变图片选择或重新生成图片，不应改写设计 revision。
- 生成请求记录解析时使用的设计 revision、风格版本、任务类型和最终 Prompt。下游资产引用按现有约定解析当前确认版本；已生成内容不静默重写。

## 工作台交互

- 将当前「角色特征建议」位置改为「角色视觉设计」编辑区，直接展示具体字段和值。
- 固定 catalog 的“保持一致”“由用户指定”等句子不能作为角色特征值，也不能再点击追加到 Prompt。可保留为字段标签或校验提示，但不作为独立建议列表。
- 工作台显示角色档案供对照；保存视觉设计后，预览本次任务编译的 Prompt。未保存的编辑不能悄悄参与生成。
- 旧 `description` 中混合的外观和性格需要一次明确拆分和人工核对；迁移前不能宣称它已经成为结构化视觉设定，也不能静默复制到新字段。

## 布局与任务流

当前三个完整生成面板并排，各自包含预览、变体、Prompt 和模式控制，底部还有固定高度的约束/建议/计划标签区。窄屏会产生横向拥挤和多层滚动，角色档案也没有稳定的阅读位置。工作台改为一次聚焦一种输出：

```text
顶部：角色名 / 当前设计 revision / 关闭
左侧：角色档案摘要（可展开全文）
      角色视觉设计（可编辑保存）
右侧：标准角色图 | 三视图 | 肖像（任务标签）
      当前任务预览 + 当前任务的图片/视频变体条
      当前任务 Prompt、@参考素材与生成操作
      全身/肖像任务内的静态/动态模式
      折叠的风格、负向提示词等高级参数
```

- 默认打开「视觉设计 + 标准角色图」。档案摘要始终可见，全文按需展开，不与图片生成表单混排。保存视觉设计后，当前任务 Prompt 才能重新从已保存版本编译。
- 右侧只渲染当前任务的完整工作区；切换任务保留各自尚未提交的 Prompt 和已选参考。动态参考沿用当前全身/肖像的模式切换，音频与视频参数仅在动态模式显示。
- 主预览只显示当前选中的素材。变体条只列该任务的生成/确认变体，并标明所属设计 revision；`@` 引用素材属于 Prompt 的参考区，不能混入变体条。
- 拍摄计划约束作为角色档案旁的可展开上下文显示；风格开关、负向提示词置于生成区的「高级参数」，不占据常驻的固定底栏。
- 桌面上左侧信息区约 300–340px，右侧任务区自适应；任务区有空间时预览与生成设置并列。中等宽度改为上下布局。手机端以任务标签切换，预览、变体、Prompt 顺序纵向排列，档案/视觉设计可折叠展开。避免三个最小宽度面板造成横向滚动。
- 模态窗口内部以一个主要滚动区承载当前内容；标题与任务切换保持可见。键盘切换、焦点状态、生成中状态及关闭入口必须完整。

## 验收条件

- 剧本中的“惩恶扬善”等非视觉性格事实不进入图像 Prompt；“素黑劲装”等已确认视觉设定进入全身、三视图和肖像生成。
- 修改并保存发型后，设计 revision 增加；旧版本可读取，旧图片变体保持原版本归属。
- 点击任何特征辅助入口都不会直接修改当前 Prompt；只有保存视觉设计后，重新编译的任务 Prompt 才反映该字段。
- 角色档案和视觉设计的修改及生成任务均能追溯到角色 ID 和对应 revision。

## Not yet proven

- 现有资产更新 API 是否适合作为设计 revision 的唯一写入口，需检查并发控制、系列共享资产写入和版本历史存储后决定。
- 旧数据的自动外观抽取准确率尚未验证，因此拆分须保留人工核对。
- Avatar 独立入口不在项目角色工作台的当前闭环内；两个入口之间的身份绑定在角色工作台完成后另行设计。

## 真人角色设计 Skill 优先

角色视觉设定的顺序是：

```text
角色档案 + 项目风格 + 已选参考图 + 项目内已确认设计
  → character-identity-design Skill 形成逐字段设计草稿
  → 用户编辑、确认
  → 项目角色资产保存设计 revision
  → 读取已确认版本，编译本次图片 Prompt
  → 用文本或明确选定的 @参考图生成角色变体
```

Skill 输入必须注明每项信息的来源和状态：剧本事实、用户明确指定、当前风格、项目内已确认设计值、参考素材已核实内容。Skill 输出脸型、五官、发型、肤色肤质、身材体态、识别锚点及本集服装等**具体候选文本**，并区分“直接来自事实”与“创意设计选择”。无依据又无必要的字段保持空值，不凭姓名、性格、职业或族裔猜测固定外貌。性格可以支持可见的常态神情建议，但不得自动变成永久表情；镜头情绪和视线属于表演。

用户确认的是字段值及其身份/造型归属，不是整段模型 Prompt。Skill 不写项目资产、不生成素材、不自动确认设计，也不把 catalog 中“保持一致”“由用户指定”等通用指导当作设计值。已有项目角色设计是 Skill 的硬边界；若用户要改变稳定身份特征，需要明确创建新的设计 revision。

随后只从项目角色资产已确认的设计版本读取具体字段，组成简短视觉片段；造型另补服装、妆容和配饰。标准角色图的中性表情属于任务要求；其它表情、眼神方向和动作由当前镜头或动态任务指定。生成记录应包含 Skill revision、项目角色设计 revision、选用的参考素材 ID 及最终 Prompt。

首期以文本设计、手工 Prompt 和明确选定的资产参考图完成项目角色工作台；独立 Avatar 设计入口不参与此流程。角色工作台不从图片自动反推身份。
