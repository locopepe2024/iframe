### 古风 Skill 对比

[TangDouOVO/ancient-beauty-prompt-generate](https://github.com/TangDouOVO/ancient-beauty-prompt-generate) 的已读版本为 `83d1f886df12fd6e43ac490723a0ef317273ea7f`，仓库标注 MIT；`.skill` 包含 `SKILL.md`、关键词库、模板和 Python 脚本。代码可按朝代、颜色、发饰、服装、场景等识别输入；宋代词条提供褙子、窄袖襦裙、包髻和低髻等检索线索。这些分类适合成为经人工筛选的古典服饰词条候选，但不能直接确定本剧角色外观。

该脚本会随机选取脸、妆容、服装、光影和后期效果；没有明确气质词时默认补入“美人／高贵优雅／妩媚”，并固定加入 `9:16`。其测试文件主要打印输出，没有对视觉一致性、用户审阅或确定性作断言。因此不把整包 Skill 接入生成链，不复制其完整提示词，也不让朝代词自动推导妆容、镜头或画幅。若借用分类结构，需在 `/` 面板展示词条来源、目标字段和选中后的完整文本，并由用户改写确认；本剧“北宋市井质感参考”仍不得变成真实朝代标识或隐形光影约束。

## Observed

- 当前 `/` 面板能搜索 Skill 与风格、面容、皮肤、身材体态、服装、发型词条；空搜索时把全部词条纵向列出。词条写入可编辑设计字段，保存时记录来源与 revision。
- 剧本和角色描述可提供年龄、性别、身份等事实；词条库只提供创作候选。图片生成请求另有提示词审核与显式 `@` 引用。
- 当前词条库缺少满足本剧古典市井与江湖造型的具体候选；平台效果参考图还没有与这些词条建立逐项绑定。

## 设计边界

1. `/` 打开两列面板：左列 Skill、风格、面容、皮肤、身材体态、服装、发型；右列显示当前分类的词条。输入搜索词时跨分类搜索，并显示所属分类。面板内滚动，不扩张整页。
2. 点击词条只写入目标结构字段，显示已选值、来源和版本；字段允许用户直接修改。不会调用模型，也不会静默加图片。选择 Skill 进入现有审核流程。
3. 古典词条描述轮廓、纹理和材质，不把“苏砚应当如何长相”伪装成剧本事实。职业不自动决定武器或服装。相互冲突的候选由用户编辑后确认，V1 不自动调和。
4. 效果参考图以一张图对应一个可审核的组合示例，而非给每个原子词条各生一张。示例保存词条 ID/revision、完整可编辑 Prompt、生成模型与参数、图片媒体 ID、来源和许可。图片只做预览；若用于模型参考，用户另用 `@` 选择具体变体。
5. 首批样本：青年江湖行旅、老掌柜、市井行人三组。先制作同一中性背景下的正面全身示例；后续可派生脸部特写。样本不是剧中角色的已确认母版，也不替代项目角色资产包。

### `/` 与 `@` 的调用契约

- `/` 搜索并调用 Skill 或提示词预设。选择提示词预设时，将其完整文字插入对应可编辑草稿字段；选择 Skill 时打开现有审核流程。预设附带的示例图只在面板中预览，不随提示词自动成为模型参考图。
- `@` 搜索并显式选择具体素材变体，显示缩图、资产类型、来源和版本；只有被选中的参考图才加入待审核的模型输入。选择参考图不自动把它的示例 Prompt 写进用户草稿。
- 一条平台库案例可以同时有示例图和结构化 Prompt，但二者是可分别选择的两个用途。提交前的审核面板同时列出最终文字、引用素材及其来源；用户可修改或移除后确认。

## 验收

- 空查询可通过左侧分类找到古典词条；搜索词跨分类匹配；键盘上下、回车、Esc 可用。
- 选词条后对应可编辑字段改变；模型调用数为零；保存记录准确 ID、来源与版本。
- 手动修改字段后来源标记撤销；生成前仍能检查完整最终提示词。
- 三张参考图只有在真正生成、人工审核并入库后才标记完成；不得用静态占位图替代。

## Not yet proven

- 文字词条及三组组合能否稳定产出区分鲜明且符合剧集的形象，须以实际图像和跨图匹配验证。
- 同一 Prompt 跨次生成时的脸部、服装一致性尚未验证；单次成功不能证明稳定性。
