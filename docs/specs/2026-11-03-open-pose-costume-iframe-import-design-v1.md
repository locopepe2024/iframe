# Open Pose & Costume 参考库接入 iFrame V1

状态：设计稿，未实施。范围是 iFrame 角色设计、资产参考和分镜出图的现有业务流；3D、视频动作时序及外部图库镜像不在本方案内。用户确认素材图片可用于直接测试；这只说明本轮可验证单张选图与请求链路，不自动授予图库镜像、平台再分发或商用托管权利。

## 已观察

- 上游 `open-pose-costume` 在 `321eae5ba196e2b6ddc250294ff34de2d167a6e3` 提供姿势、服饰、人物三类参考目录。每条目录项有稳定 ID、标题、分类、标签和若干图片视角；姿势深度图是视觉参考，不是标定深度或专用 ControlNet 输入。
- 上游组合生图将人物图用于身份/面容，姿势图用于动作与观察角度，服饰图用于穿搭，并把选中原图作为多图请求提交。服饰提取是一次额外的图片生成调用，结果仍须人工审核。
- iFrame 已有平台参考目录、项目/系列/全局资产索引、稳定的 `asset_id + variant_id`、角色工作台多参考选择、分镜参考包和提交审核。平台参考目录当前的发布入口以平台自有生成结果和权利确认为基础，不等同于外部图库导入许可。
- 上游代码是 MIT；图片不在 MIT 范围。其来源说明对姿势/服饰图片数据的再分发设限，自建图片另限非商业用途；上游维护者取得的仓库归档许可没有转授下游。人物图库的 CC0 标注与其避免再分发请求须一并保留。读取目录不证明 iFrame 可镜像图片或在商业服务中提供下载。

## 产品目标与边界

创作者在现有角色面板的面容、体态和服饰字段中就地查找并绑定图片参考。每个字段同时呈现文字设定、关联图片和来源，作为同一份角色设计；生成审核读取这份设计并展示真实请求。姿势是当前角色出图任务或分镜的字段，不写入永久身份。确认后仍由现有角色资产版本和图片变体承载。

不复制上游站点的完整浏览器、收藏体系或本地密钥配置。iFrame 继续使用自己的登录、媒体身份、模型能力判断、任务和结果审核。上游的“多图提示词”只可作为设计参考，不能替代 iFrame 已有的角色身份/造型优先级和提交快照。

## 导入模式与权利门槛

| 模式 | 目录内容 | 用户动作 | 服务端权限 |
| --- | --- | --- | --- |
| 来源索引 | ID、名称、类别、标签、视角名、来源链接及条款快照；不镜像图片 | 搜索、跳转来源 | 只允许目录展示；不产生可提交的媒体引用 |
| 单张临时参考 | 用户主动选择且来源条款允许的特定视角 | 查看原图、确认本次使用 | 逐次解析来源、校验 URL/内容类型/大小和用途；禁止自动批量抓取与长期归档 |
| 托管平台资源 | 单独取得可证明的托管、展示、模型输入及适用商业范围授权 | 像现有平台图一样选择变体 | 审核发布后进入平台媒体索引；记录许可证明、范围和撤回状态 |
| 用户上传 | 用户拥有或有权使用的图片 | 上传并指定参考职责 | 沿用现有 owner-scoped 媒体上传和提交审核；不自动公开到平台目录 |

V1 先提供来源索引、用户上传和**用户显式选中的单张图片直用测试**。测试记录来源、视角、适用条款、实际取得的图片身份和请求用途；服务端按当前许可状态、来源白名单、内容类型与大小校验后才解析为本次媒体输入，失败时要求用户换图或上传，不暗中转用缩图。测试通过只证明传输与模型请求可行。平台长期托管和图库镜像仍须分别取得授权；不能因为上游 Git 仓库含归档图片就复制到 iFrame 静态包、全局资产库或存储后端。自建素材在没有另行许可前不提供 iFrame 商业生成或下载入口。条款变化时停用后续提交，历史任务保留当时的引用和审核事实。

## 目录映射

- 建独立的 `external_reference` 目录类型，保存 `source_id`、`source_revision`、`source_item_id`、`kind` (`pose`/`costume`/`character`)、中英标题、分类/标签、视角列表、原站 URL、许可状态、可用动作和目录更新时间。不要伪装成项目角色/道具资产，也不要给未导入图片分配 `asset_id`。
- 每个视角保留原始 variant ID 和角度。前、俯、仰、侧、斜等角度缺失时不补造；深度图与线稿是同一姿势的不同表现形式，明确标记 `line_art`/`depth_reference`，不能当成第二个姿势或真实空间数据。
- 搜索可复用现有平台目录入口与工作台就地筛选；结果卡显示来源、参考职责、可用动作和许可状态。无提交权的结果只可打开来源。收藏保存目录 ID 与视角 ID，不复制原图或把外部项转换为已确认资产。
- 确认可用的图片若需长期复用，须走现有用户媒体或平台资源发布流程，生成 owner-scoped 媒体身份和稳定变体 ID。导入保留原始来源 ID、视角、条款/授权版本及内容哈希；同一图片的来源身份和 iFrame 媒体身份分开保存。

## 角色工作台交互

保留现有“参考素材”选择器作为字段内弹出的同一个媒体选择工具；不在角色面板旁增加独立的“人物/姿势/服饰组合面板”。面容、发型、肤色、体态、服装和服饰细节字段各自提供添加参考入口，选图后缩图与字段值出现在同一行/同一组。姿势入口位于当前出图任务的“动作/姿势”，或分镜的本镜动作，不放入角色基础身份。角色已确认锚点是面容等字段的优先图片依据。当前 `AssetLibraryReference` 只有资产/变体身份和应用模式，没有字段职责；职责须由**字段绑定关系**保存，不能从资产类型、提示词或图片内容猜测。

### 一套字段状态

当前面板已有 `基础身份`、`面容与身体`、`服装搭配`、`服饰细节`、`表演` 五组；其结构化 `identity`/`look` 字段与确认 revision 继续是角色设定的权威值。每个适用字段扩充为同一设计记录中的 `文字值 + 图片绑定 + 来源/修订 + 确认状态`。图片可以是该字段唯一依据，此时文字值可为空；文本有明确值时不能被图片隐式改写。现有纯文字设计按原字段读取，图片绑定为空，无需伪造参考。

| 字段作用域 | 图片绑定位置 | 编译用途 | 不迁移的内容 |
| --- | --- | --- | --- |
| 稳定身份 | `identity.face/face_shape/hair/skin_tone/build/recognition_marks` 等原字段 | 约束本角色的面容和身体识别特征 | 图中动作、服装、背景及瞬时表情 |
| 稳定或本集造型 | `look.clothing/palette/footwear/jewelry/decoration/accessories` 等原字段，归属所选造型 revision | 约束衣物款式、材质、颜色及穿戴 | 服饰模特的面容、发型、体型和姿势 |
| 当前图/镜头 | 当前任务或分镜的姿势/动作字段 | 约束本次重心、身体动作和单一视角 | 永久 `identity.build`、面容和造型；静态图不规定视频节奏 |

从图库点选图片时，先选目标字段/当前任务槽位，然后直接更新该字段的图片绑定，形成可见草稿变更；不创建一个与面板平行的“本次参考图清单”。如果在字段中请求 AI 解读图片，模型只能提出该字段的文字候选，差异显示在**同一字段**，用户采纳后才改变文字值。不能暗写 `design_result`、清空其他字段或残留上一预设参数。移除图片只移除该字段的图片依据，文字值保留；用户改文字也不暗中更换图片。确认设计 revision 时冻结文字及图片绑定。生成器从当前有效字段投影出有序图片输入列表，列表是只读派生结果，不另存可编辑副本。

同一字段的文字与图片不一致时，该字段标为“待核对”，在确认/生成前由用户修改文字、换图或明确保留二者的不同用途；不能靠全局优先级隐藏冲突。已确认设计不可因一次选图而原位改写：对稳定身份或造型的变更先创建该角色的修订草稿，确认后得到新 revision；本镜姿势只修改本镜字段。一个参考图可绑定多个字段，但每个绑定必须由用户确认职责。以上冲突是供用户审阅的输入差异，不声称图像模型必然服从字段规则。

用户可对上传的穿搭图执行“提取服饰”，但它是明示费用的独立生成任务。提取结果为候选，需核对衣物、鞋履、配饰以及模型凭空补全的部分；确认后保存为可复用服饰参考变体。不要把提取图默认登记为道具资产，也不要把服饰模特面容带入角色身份。

提交审核列出各字段的文字、图片缩图/稳定身份/来源/使用权限、冲突状态，以及由这些字段编译的完整提示词和有序媒体列表。人物字段的图片仅约束身份/脸/发/肤色/适用体型；姿势字段仅约束身体动作、重心、单一视角和遮挡；服饰字段仅约束可见衣物的版型、颜色、材质、穿戴方式。实际请求与字段投影必须同源；无角色资产绑定的自由 `@` 图不能绕过职责字段进入角色生成。模型不支持所需多图数量或尺寸时禁用提交并说明原因。

生成候选保存三类参考的 ID/变体/媒体身份、职责、资产设计 revision、提示词、模型和请求参数。确认候选才新增角色图片变体或造型 revision；失败或取消不修改角色母版。结果旁提供人物脸部、姿势和服饰的分别对照，状态为“符合 / 偏离 / 无法判断”，不把提示词写入视为结果锁定。

## 分镜使用

分镜默认使用当前角色已确认锚点/造型变体来保持身份和服装。姿势目录提供本镜的静态姿势参考；它只影响本镜动作/观察角度，不改变角色资产。若本镜换装，先确认角色造型变体，或明确建立本镜状态候选，不直接用图库服饰替换已确认造型。

分镜参考包与 `reference_asset_inputs` 只索引**本镜明确选中且服务端可解析的媒体变体**；目录项或 URL 不直接成为视频/图片任务的媒体输入。预览应展示来源图、角色锚点、职责与冲突，提交时冻结实际媒体身份与请求。静态姿势图不能证明视频动作节奏，也不自动生成首帧或带入图中人物、衣服、背景。

## 实施顺序与验收

1. **目录和单张直用：** 导入外部目录索引与权利状态；用用户明确选中的单张图片测试原图读取和模型转送，不批量下载或发布图库。测试 ID/视角稳定、来源失效可恢复、未授权条目无法进入媒体提交。
2. **统一角色字段：** 从面板字段调用现有选图器，把所选变体绑定到该字段；当前任务姿势按相同结构保存到任务/分镜。测试面板字段、图片绑定、预设切换及只读请求投影只有一份有效状态；换图不改文字，改文字不暗换图，确认 revision 后旧版本不变。
3. **服饰提取：** 增加单独任务、费用确认、候选审核和来源记录。测试模型凭空补全的细节可标注，未确认结果不能作为已确认造型。
4. **分镜引用：** 从已确认角色字段及造型 revision 读取身份/服饰图，本镜姿势字段绑定图库视角；沿用现有参考包与提交快照。测试旧任务不受目录/资产更新影响，未授权或失效引用被拒绝。
5. **效果评估：** 固定角色、服饰、姿势、模型及参数做可比样本，由人工分别评估脸、体型、服装细节和姿态；同时记录费用、失败率、素材可用性。单元测试只证明输入和状态闭环，不能证明图像一致性。

预计改动边界：平台目录/外部索引 API，角色设计字段的图片绑定、角色工作台选图器与提交投影、分镜本镜姿势字段和生成快照，以及各层行为测试。现有 `AssetReferenceIndex` 继续只表示 iFrame 自有/已导入资产；外部目录必须先经权限检查和字段绑定，才能成为可解析的媒体输入。实现时先统一当前 `reference_assets`、右侧选图状态和 `@` 的读取投影，避免新 schema 与旧状态双写。
