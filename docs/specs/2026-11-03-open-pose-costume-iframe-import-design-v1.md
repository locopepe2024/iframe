# Open Pose & Costume 参考库接入 iFrame V1

状态：设计稿，未实施。范围是 iFrame 平台共享参考库、角色设计和分镜出图的现有业务流；3D 与视频动作时序不在本方案内。用户确认素材图片可用于直接测试；这只说明本轮可验证单张选图与请求链路，不自动授予图库镜像、平台再分发或商用托管权利。

## 已观察

- 上游 `open-pose-costume` 在 `321eae5ba196e2b6ddc250294ff34de2d167a6e3` 提供姿势、服饰、人物三类参考目录。每条目录项有稳定 ID、标题、分类、标签和若干图片视角；姿势深度图是视觉参考，不是标定深度或专用 ControlNet 输入。
- 上游组合生图将人物图用于身份/面容，姿势图用于动作与观察角度，服饰图用于穿搭，并把选中原图作为多图请求提交。服饰提取是一次额外的图片生成调用，结果仍须人工审核。
- iFrame 已有部署级 `platform_shared` 平台参考库、项目/系列/全局资产索引、角色工作台多参考选择、分镜参考包和提交审核。平台库目前支持图片、视频和提示词资源，但分类主要面向角色；候选提交仅接受创作台已完成的生成结果，外部素材还没有受审核的导入入口。
- 上游代码是 MIT；图片不在 MIT 范围。其来源说明对姿势/服饰图片数据的再分发设限，自建图片另限非商业用途；上游维护者取得的仓库归档许可没有转授下游。人物图库的 CC0 标注与其避免再分发请求须一并保留。读取目录不证明 iFrame 可镜像图片或在商业服务中提供下载。

## 产品目标与边界

参考库是与风格、动效等资源并列的**平台共享库**，不是每个角色或项目单独维护的图库。平台发布的姿势、服饰、人物参考图可在多个工作台检索；选择动作发生在当前角色设计字段或视图生成任务中，不把平台原图复制为角色资产。创作者从已确认角色基准图派生多个可复用**角色视图**：站立全身可为基准，view2 可为坐姿，也可生成正脸、侧脸和哭泣视图。生成结果经审核后保存为角色图片变体，供分镜明确选用。平台原图不能冒充这个角色的视图产物。

不复制上游站点的完整浏览器、收藏体系或本地密钥配置。iFrame 继续使用自己的登录、媒体身份、模型能力判断、任务和结果审核。上游的“多图提示词”只可作为设计参考，不能替代 iFrame 已有的角色身份/造型优先级和提交快照。

## 平台共享与发布门槛

| 平台资源状态 | 目录内容 | 用户动作 | 服务端权限 |
| --- | --- | --- | --- |
| 来源候选 | 来源 ID、名称、类别、标签、视角、原站链接和条款快照 | 平台维护者核对来源与可用范围 | 尚未发布，不出现在普通用户可提交的媒体选择结果中 |
| 已发布参考 | 平台资源 ID、修订、分类、视角、受管媒体身份和来源记录 | 全体用户跨项目搜索；在现有选图器中选择 | 审核通过后由平台媒体端点解析；撤回时禁止新请求，历史快照保留引用事实 |
| 用户私有上传 | 用户有权使用的图片及 owner-scoped 媒体身份 | 当前角色/项目使用，或由有权限的发布者提交平台审核 | 未发布前不向其他用户展示；发布须有独立的权利声明与审核 |

目标体验是平台维护一次、所有项目按权限共用。V1 可先用用户显式选中的单张图片测试读取和模型转送，记录来源、视角、条款与请求用途；测试通过只证明链路可行，不等同于平台发布。外部图片进入共享库前须核对托管、展示、模型输入及适用商业范围的授权，经过平台候选审核后才发布；不能因为上游 Git 仓库含归档图片就直接复制到 iFrame 静态包或存储后端。现有候选提交只接受创作台生成结果，需为外部素材增加独立的受审核导入路径，沿用同一平台资源身份、修订和媒体访问机制。条款变化时停用后续提交，历史任务保留当时的引用和审核事实。

## 平台目录映射

- 扩展现有 `platform-reference-library` 的分类：平台媒体 `kind` 仍为 `image`，姿势、服饰、人物参考是 `category_path`/标签中的用途分类，不把它们伪装成项目角色或道具资产。平台发布资源沿用 `platform_resource_id + revision`；外部来源 ID、视角、原站 URL、条款/授权版本和内容哈希进入 provenance，不以来源 ID 代替平台媒体身份。
- 每个视角保留原始 variant ID 和角度。前、俯、仰、侧、斜等角度缺失时不补造；深度图与线稿是同一姿势的不同表现形式，明确标记 `line_art`/`depth_reference`，不能当成第二个姿势或真实空间数据。
- 搜索复用现有平台目录入口及工作台就地筛选；结果显示来源、用途分类、视角和许可状态。未发布的来源候选只对维护者可见，不进入普通用户的角色选图结果。已发布参考由平台媒体端点提供，不要求用户每次复制到个人库。
- 一个来源项含多个视角时，每张可选图须有稳定的受管媒体身份，并保留来源项与视角的关联；提交快照冻结具体平台资源修订和媒体身份。平台目录项与角色最终生成的视图变体分别归属平台和角色，不共用 ID。

## 角色工作台交互

保留现有“参考素材”选择器作为角色面板内弹出的同一个媒体选择工具；不在面板旁增加独立的“人物/姿势/服饰组合面板”。面容、发型、肤色、体态、服装和服饰细节字段可在原位绑定图片；角色变体区提供“新增视图”，同一处选源角色图、变化维度和可选图库参考。当前 `reference_sheet` 已保存角色图变体，`pose_references` 可保存姿态/手势图；资产包设计另定义了转面、表情和姿态派生类型，但统一的确认和来源版本链尚未完成。当前 `AssetLibraryReference` 只有资产/变体身份和应用模式，没有字段职责；职责须由字段或视图生成任务的输入角色保存，不能从资产类型、提示词或图片内容猜测。

### 一套字段状态

当前面板已有 `基础身份`、`面容与身体`、`服装搭配`、`服饰细节`、`表演` 五组；其结构化 `identity`/`look` 字段与确认 revision 继续是角色设定的权威值。姿势、转面、脸部角度和表情图都是依赖已确认角色锚点与造型的**派生视图**，不是第二套身份或服装面板。每个适用设计字段使用 `文字值 + 图片绑定 + 来源/修订 + 确认状态`；每个派生视图保存源角色图/设计修订、造型修订、本次变化维度、图库输入、生成请求和确认状态。现有纯文字设计按原字段读取，图片绑定为空，无需伪造参考。

视图不是互斥的姿势/角度/表情分类：一张图可同时标记为“坐姿、侧脸、哭泣、半身”，也可只改变其中一项。生成新视图时明确记录要改变的维度和要继承的维度；确认后这些标签用于查找与选择，不能替代图片变体 ID 或证明生成结果符合约束。

| 字段作用域 | 图片绑定位置 | 编译用途 | 不迁移的内容 |
| --- | --- | --- | --- |
| 稳定身份 | `identity.face/face_shape/hair/skin_tone/build/recognition_marks` 等原字段 | 约束本角色的面容和身体识别特征 | 图中动作、服装、背景及瞬时表情 |
| 稳定或本集造型 | `look.clothing/palette/footwear/jewelry/decoration/accessories` 等原字段，归属所选造型 revision | 约束衣物款式、材质、颜色及穿戴 | 服饰模特的面容、发型、体型和姿势 |
| 新视图输入 | 选择已确认角色基准图、造型，指定姿态/观察角度/取景/表情中本次要变化的维度；按需选图库姿势图 | 例如从站立全身生成坐姿 view2，或从面部母版生成正脸、侧脸、哭泣 | 不借用图库人物的脸、衣服、体型或背景；没有指定的维度保持来源设定 |
| 角色视图产物 | 经审核的生成图进入同一角色的可复用视图集合；按类型投影到现有 `reference_sheet`、`pose_references` 或后续资产包条目 | 保存同一个角色的具体姿态、视角、表情图及来源链 | 不把派生图当作新角色身份或自动改写设计字段 |
| 本镜使用 | 分镜选择一个或多个已确认角色视图的具体变体 | 为首帧/关键帧提供匹配本镜要求的视觉依据 | 不反向改写角色视图或身份/造型 revision；静态图不规定视频节奏 |

从图库选择面容/服饰图片时，先选目标设计字段，再更新该字段的可见图片绑定；不创建与面板平行的设定清单。新增角色视图时先选源视图和变化维度，图库姿势图只是候选生成输入，不能直接确认成角色视图。生成后人工核对未改变的脸、体型、服饰以及目标姿态/视角/表情，再显式确认该变体。若 AI 解读设计字段图片，只能提出该字段的文字候选，用户采纳后才改变文字值；不能暗写 `design_result`、清空其他字段或残留上一预设参数。生成器从当前有效字段/任务输入投影有序媒体列表，列表是只读派生结果，不另存可编辑副本。

同一设计字段的文字与图片不一致时，标为“待核对”，在确认/生成前由用户修改文字、换图或明确保留二者的不同用途；不能靠全局优先级隐藏冲突。已确认身份、造型和视图都不可因一次选图而原位改写；重做视图生成新候选/变体，历史分镜继续指向原变体。一个参考图可绑定多个设计字段，但每个绑定须由用户确认职责。以上冲突是供用户审阅的输入差异，不声称图像模型必然服从字段规则。

用户可对上传的穿搭图执行“提取服饰”，但它是明示费用的独立生成任务。提取结果为候选，需核对衣物、鞋履、配饰以及模型凭空补全的部分；确认后保存为可复用服饰参考变体。不要把提取图默认登记为道具资产，也不要把服饰模特面容带入角色身份。

提交审核列出设计字段与视图任务的文字、图片缩图/稳定身份/来源/使用权限、冲突状态，以及由同一状态编译的完整提示词和有序媒体列表。人物参考仅约束身份/脸/发/肤色/适用体型；新视图的姿势参考仅约束身体动作、重心、观察角度和遮挡；服饰参考仅约束可见衣物的版型、颜色、材质、穿戴方式。实际请求与字段/视图任务投影必须同源；无角色资产绑定的自由 `@` 图不能绕过输入职责进入角色生成。模型不支持所需多图数量或尺寸时禁用提交并说明原因。

生成候选保存源角色视图、三类参考的 ID/变体/媒体身份、各参考职责、资产设计/造型 revision、本次变化维度、提示词、模型和请求参数。确认候选才新增角色视图变体或造型 revision；失败或取消不修改角色母版。结果旁分别对照人物脸部、体型、服饰及本次目标姿势/视角/表情，状态为“符合 / 偏离 / 无法判断”，不把提示词写入视为结果锁定。`view2` 是用户可读的视图序号/名称；真正的引用身份是稳定 `variant_id`，不能从序号推断“坐姿”。

## 分镜使用

分镜从该角色**已生成且已确认的视图**中选择适合本镜的具体变体：站立全身、坐姿、正脸、侧脸、哭泣等可以各是一张，也可是一张图同时具有多个属性。镜头需要缺失的视图时回到角色视图任务派生候选，再选生成结果；图库原图不能以该角色的身份直接进入分镜参考包。已选视图仍绑定角色锚点和造型修订。若本镜换装，先确认角色造型变体，或明确建立本镜状态候选，不直接用图库服饰替换已确认造型。

分镜参考包与 `reference_asset_inputs` 只索引**本镜明确选中且服务端可解析的媒体变体**；目录项或 URL 不直接成为视频/图片任务的媒体输入。预览应展示来源图、角色锚点、职责与冲突，提交时冻结实际媒体身份与请求。静态姿势图不能证明视频动作节奏，也不自动生成首帧或带入图中人物、衣服、背景。

## 实施顺序与验收

1. **平台目录与首批参考：** 扩展平台参考库的姿势、服饰、人物分类；用用户明确选中的单张图片验证读取和模型转送。完成授权核对后，将可发布图片作为平台候选审核，发布到现有共享库。测试普通用户只能看到已发布资源、跨项目可检索同一资源、每个视角有稳定媒体身份、撤回后不能新提交，未授权来源不能进入平台发布。
2. **统一角色字段与视图派生：** 从面板字段及“新增视图”调用现有选图器。用站立全身基准图生成坐姿 view2、正脸、侧脸、哭泣四类候选；逐张审核后保存为同一角色的视图变体。测试设计字段与图片绑定只有一份有效状态，预设切换不残留旧值，图库输入不自动成为角色产物，未指定的身份/造型保持来源修订。
3. **服饰提取：** 增加单独任务、费用确认、候选审核和来源记录。测试模型凭空补全的细节可标注，未确认结果不能作为已确认造型。
4. **分镜引用：** 从同一角色已确认视图中选择具体变体并展示姿态、角度、表情和造型修订；沿用现有参考包与提交快照。测试图库原图不能冒充角色视图，旧任务不受后续目录/视图/资产更新影响，失效引用被拒绝。
5. **效果评估：** 固定角色、服饰、姿势、模型及参数做可比样本，由人工分别评估脸、体型、服装细节和姿态；同时记录费用、失败率、素材可用性。单元测试只证明输入和状态闭环，不能证明图像一致性。

预计改动边界：现有平台参考库的分类、外部候选导入/审核与媒体修订，角色设计字段的图片绑定、角色视图派生任务及现有 `reference_sheet`/`pose_references` 的候选与确认版本、工作台选图器与提交投影、分镜视图引用和生成快照，以及各层行为测试。平台库资源是跨项目输入，角色生成并确认的视图才是角色资产；`AssetReferenceIndex` 继续索引项目/系列/全局资产，不能把平台来源候选混入其中。实现时先统一当前 `reference_assets`、右侧选图状态、角色视图容器和 `@` 的读取投影，避免新 schema 与旧状态双写。
