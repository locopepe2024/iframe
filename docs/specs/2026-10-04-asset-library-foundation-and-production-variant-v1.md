# 资产库底座与剧情变体规范 V1

状态：提案，作为后续资产库与 Avatar 素材库对接的边界文档
日期：2026-10-04

## 目标

资产库保存可复用的视觉底座；系列、分集和场景再把底座投影成具体制作所需的角色造型、场景状态和道具使用。资产库不应因为某一集的剧情、季节、地点或镜头需求而被静默改写。

## 分层

### 1. 全局底座资产

资产类型只有：角色、场景、道具。

全局底座必须满足：

- 不依赖某一集或某一个镜头的剧情事实；
- 角色保存基础身份视觉，例如真人脸部、发型基线、肤质、体型和身份参考照；
- 场景保存可复用的空间基线，例如校园、餐厅、街道的基础结构与材质；
- 道具保存物体本身的可识别外观、尺寸感和材质；
- 不把“西安冬季”“大四上学期”“女生寝室夜间”等剧情条件写入底座字段；
- 每个图片变体都保留来源、创建时间、父变体和用户审核状态。

全局底座是候选素材，不等于已被某一部剧采用。

### 2. 系列/分集引用

系列或分集可以引用全局底座，并为本剧建立自己的使用记录：

- `asset_id`：引用哪个底座；
- `identity_revision`：角色身份版本；
- `look_revision`：本剧确认的造型版本；
- `placement_scope`：系列、分集或场景；
- `source_context`：导演确认的时代、地点、季节和风格约束。

引用不复制或修改全局底座。若项目需要独立修改，应创建新的项目变体并保留 `parent_asset_id`。

### 3. 场景/镜头生产变体

生产变体承载剧情执行信息：

- 角色：本集阶段、室内/室外服装、发型、妆容、天气影响和连续性锁；
- 场景：具体地点、季节、时间段、天气、布置、灯光和可见背景；
- 道具：本场是否出现、由谁持有、状态变化、叙事意义和连续性要求。

这些变体只能在系列、分集、场景或镜头范围生效，不能自动回写全局底座。

## 资产库操作定义

### 新建资产

入口：资产库 → 新建角色/场景/道具。

结果：创建一个全局底座资产。资产不是单张主图，而是至少支持 4 张有稳定顺序和职责的基础变体。新建时允许填写基础名称、基础描述和多张基础参考图，不读取某一集的 Director 理解，也不自动加入剧情服装、季节或场景关系。

### 新建资产的多变体要求

资产库新建角色、场景和道具时，初始资产应支持至少 4 个变体：

- 角色：正面身份照、半身/面部照、全身照、备用身份角度或三视图；
- 场景：主视角、侧/反向视角、远景空间关系、细节或材质视角；
- 道具：主视角、背面/侧面、使用状态、材质或细节视角。

这 4 个变体属于同一个底座资产，使用同一个 `asset_id`，每张图有独立的 `variant_id`、职责、来源和审核状态。它们不是 4 个独立资产，也不应通过复制 4 条名称相同的资产记录来实现。

用户可以先保存少于 4 张的草稿，但资产进入“可引用底座”状态前必须补齐至少 4 个变体，或由用户明确确认缺少的变体暂不适用。缺少变体不能由系统静默伪造。

## 变体等级

变体必须标记等级，等级决定它能被哪些工作流继承：

### Level 0：底座多视图

资产库新建资产产生的基础变体。它们描述同一个稳定身份或物体，不表达剧情表演：

- 角色：正脸、侧脸、半身/面部、全身或三视图；
- 场景：主视角、侧/反向视角、远景关系、材质细节；
- 道具：主视角、侧/背面、使用前后结构、材质细节。

Level 0 可以被所有系列和分集引用，是角色身份、场景空间和道具结构的视觉基线。

### Level 1：剧情造型与场景状态

在系列、分集或场景范围生效，继承 Level 0 但增加执行上下文：

- 角色的年代、季节、室内/室外服装、发型、妆容和配饰；
- 场景的时间、天气、灯光、布置和季节状态；
- 道具的本场状态、摆放位置、磨损或叙事用途。

Level 1 不改变 Level 0 身份，可由拍摄计划和 Assets 工作台继续细化。

### Level 2：镜头表演与瞬时状态

只对具体镜头或镜头组生效，描述表演和瞬时变化：

- 哭泣、开心、惊讶、疲惫等表情；
- 眼神方向、姿势、手位和动作；
- 汗、泪、雨水、污渍等镜头状态；
- 镜头景别、光线和运动造成的呈现变化。

Level 2 不能写回 Level 0 或 Level 1。删除一个镜头状态不应重置角色底座或分集造型。

剧情资产从 Level 1 或 Level 2 升级为全局资产时，只能提炼出经过用户确认的 Level 0 基础内容；原剧情变体和表演状态必须保留为来源记录。

## 角色图像生产链

角色在实际剧集中的图像不应从全局身份照直接跳到每个镜头。推荐使用三层引用链：

```text
角色照（全局 Level 0）
  → 定妆照（系列/分集 Level 1）
  → 场景剧情照（场景/镜头 Level 2）
```

### 角色照：全局身份底座

角色照是资产库中同一角色的多视图身份参考：正脸、侧脸、半身、全身或三视图。它回答“这个人是谁”，不回答“这一集穿什么、正在做什么”。

### 定妆照：分集/时代级连续性锚点

定妆照仍然需要保留，但它的职责要收窄为：

- 固定本剧或本集的时代阶段、年龄感、发型、妆容、基础服装和配饰；
- 让多个场景共享同一个阶段的外观基线；
- 作为场景剧情照的首选角色参考，减少每场独立生成造成的脸、发型和体型漂移。

定妆照不是强制每集只有一张，也不是每个场景都必须重新创建一套。一个分集可以有多个命名定妆变体，例如“大学时期冬季校园”“大学时期室内寝室”“研究生阶段”。它们属于 Level 1，不能包含哭泣、开心、奔跑等镜头表演。

主角和具有连续性要求的角色建议必须有定妆照；临时人物、群演或没有外观连续性要求的道具可以只引用 Level 0。短集、单场景或没有造型变化的内容可以由用户明确选择直接沿用角色照，但这是显式简化，不是系统自动跳过。

### 场景剧情照：场景/镜头执行图

场景剧情照由 Assets 工作台根据以下输入生成：

1. 全局角色照和身份 revision；
2. 当前分集/时代的定妆照和 look revision；
3. 拍摄计划的场景、人物、道具、时间、地点、季节、天气和连续性说明；
4. 当前镜头的表演、构图、灯光和动作状态。

它回答“这个人在这一场、这个时间、这个镜头里如何出现”。场景剧情照可以包含哭泣、开心、疲惫、淋雨、手持书包等状态，但不得回写定妆照或全局角色照。

## 拍摄计划与 Assets 的关系

拍摄计划中的人物、场景和道具字段是场景剧情照的前置约束，不是最终图片本身：

- 人物字段指定 `person_id`、`era_variant_id`、可选 `look_id` 和连续性状态；
- 场景字段指定 `scene_asset_id`、地点、室内/室外、时段、季节、天气和布置；
- 道具字段只保留本场重要道具及其状态变化；
- shot 字段提供表演、构图、灯光和镜头执行信息。

Assets 工作台据此生成或选择对应的场景剧情照，保存 `identity_revision`、`look_revision`、`scene_context_revision` 和来源 shot IDs。Storyboard 不应直接读取一份混合的“分集 assets”，而应按以下优先级取图：

```text
已确认场景剧情照
  → 已确认分集定妆照
  → 全局角色照
```

缺少上层参考时可以保存草稿，但不能静默把低层图片冒充高层确认结果；用户需要看到缺失层级并决定继续或补齐。

## 当前问题与切换要求

当前分集 assets 同时混合了实体、定妆信息和场景剧情图，导致：

- 同一角色在不同场景没有明确的服装和季节边界；
- 分镜只能引用分集级资产，无法说明它对应哪一个场景状态；
- 重新生成一个场景可能意外替换其他场景的角色外观。

后续应将分集资产拆成“实体引用 + 定妆变体索引 + 场景剧情变体索引”。现有数据可以迁移为 Level 0/1/2 的兼容投影，迁移过程中不得根据图片内容猜测层级；无法确定的记录标记为 `needs_user_review`。

### 创建图片变体

资产库不再把“生成更多变体”理解为直接生成剧情图。

正确流程：

1. 在资产库选择底座资产；
2. 点击“在图片编辑中创建变体”；
3. 图片编辑读取底座作为身份/结构参考；
4. 用户修改、接受、继续编辑或删除候选；
5. 用户明确选择“保存为底座变体”或“保存到当前系列/分集”。

“保存为底座变体”仍不得写入剧情事实；“保存到当前系列/分集”必须带有项目范围和来源版本。

现有“生成更多变体”按钮属于过渡 UI：它当前对项目资产调用项目级生成管线，对系列资产置灰。该行为不能作为最终规范，后续应改名并接入图片编辑工作台。

### 导入到系列/分集

导入是引用或创建项目副本的明确动作：

- 默认保存 `asset_id + revision` 引用；
- 用户选择“创建独立副本”时，生成新的变体 ID并保留父资产 lineage；
- 导入后可以添加本剧时间、地点、服装和场景约束；
- 导入不改变全局底座。

### “提升到全局”的定义

当前按钮的实际行为是把系列/项目资产 deep-copy 到全局池。这是历史兼容行为，不是理想语义。

最终产品中应改名为“提炼为全局底座”，并要求用户确认：

- 将从项目资产中提取哪些基础视觉字段；
- 删除哪些剧情、地点、季节、镜头和导演执行信息；
- 是否以新的全局资产创建，而不是覆盖已有底座；
- 是否保留父资产和来源项目用于追溯。

如果原资产包含明显剧情造型，不应直接提升；应先进入图片编辑或资产清理流程，生成无剧情依赖的底座候选。

这不限制优秀剧情资产的二次策展：后继如果某个分集或场景中的角色造型、场景设计或道具设计具有长期复用价值，用户可以明确选择“升级为全局资产”。升级流程必须：

- 由用户主动触发并确认，而不是由生成结果自动触发；
- 说明升级的是原剧情变体，还是经过清理后的新底座；
- 保留 `parent_asset_id`、来源系列/分集/场景和原始 `revision`；
- 删除或隔离只对原剧情成立的时间、地点、事件、镜头和导演执行约束；
- 以新的全局资产或全局底座变体写入，不覆盖原剧情资产；
- 升级后仍可回到原剧情资产查看和复用，两个版本互不反向覆盖。

在 Avatar 素材库接入完成后，“提炼为全局底座”必须调用 `AvatarCharacterAssetClient` 或对应场景/道具素材服务。iframe 不应继续把本地 deep-copy 作为生产权威存储。

## 角色、场景、道具示例

| 层级 | 角色 | 场景 | 道具 |
| --- | --- | --- | --- |
| 全局底座 | 沈夏的真人身份参考、基础发型和肤质 | 西安校园的基础空间参考 | 普通书包的外观参考 |
| 分集引用 | 2020 年研究生阶段身份版本 | 研究生院校园，冬季 | 本集确认使用的书包 |
| 场景变体 | 宿舍内家居服、自然发型 | 夜间女生寝室、暖光、室内 | 床边书包、考研书籍 |
| 镜头状态 | 看向周涵、疲惫表情 | 镜头景别和灯光 | 手持书包、放下书籍 |

## 禁止事项

- 不把某一集的服装直接保存为全局角色身份；
- 不把导演 JSON、故事地图或拍摄计划全文复制到资产底座 prompt；
- 不把所有场景道具自动提升成全局道具；
- 不把图片编辑候选自动设为当前生产版本；
- 不用“提升到全局”掩盖资产复制、版本和来源关系；
- 不把“禁止自动提升”误解为“优秀剧情资产不能升级”；升级必须是显式的用户策展动作；
- 不让全局底座变更反向使已确认的分集计划失效，除非用户明确选择重新绑定。

## 当前实现差距

代码事实：

- 资产库支持新建全局角色、场景和道具；
- 资产库详情中的生成按钮仍复用项目级生成接口；
- “提升到全局”仍执行系列/项目到全局的 deep-copy；
- 本地 `Character.digital_avatar` 仍是迁移期数据，Avatar 权威边界已在数字角色规范中定义。

因此本规范落地顺序为：

1. 先调整按钮命名和确认文案，避免继续误导用户；
2. 图片编辑接收资产底座并返回可编辑候选；
3. 增加变体作用域、父变体和审核状态；
4. 将“提炼为全局底座”改为显式抽取流程；
5. Avatar 服务 API 确认后替换本地 deep-copy 持久化。

## 验收标准

- 新建全局资产不携带剧集或镜头上下文；
- 新建资产支持至少 4 个同资产多变体，并为每个变体保存职责和审核状态；
- 角色导入后能够区分 Level 0 多视图、Level 1 剧情造型和 Level 2 表演状态；
- 分镜生成优先使用场景剧情照，其次使用定妆照，最后才回退到全局角色照；
- 拍摄计划的时间、地点、人物和道具约束能够追溯到场景剧情照的生成记录；
- 用户能清楚区分底座变体与剧情变体；
- 图片编辑候选不会自动覆盖底座或当前剧情版本；
- 导入资产后，分集可添加时间、地点、季节、服装和道具连续性；
- “提炼为全局底座”显示来源、抽取范围和确认动作；
- 全局底座、系列引用、分集变体和镜头状态可通过 ID、revision 和 lineage 追溯；
- 不再以本地 deep-copy 作为 Avatar 生产权威存储。
