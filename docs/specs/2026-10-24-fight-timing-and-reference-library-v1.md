# 打斗节奏与参考素材库合同 v1

日期：2026-10-24。状态：设计合同与基准案例；尚未接入 Shot Design 的保存、候选审核或视频提交。

## Observed

- `shot-action-physics` 规定接触、受力、位置和道具响应；`shot-martial-choreography` 在明确的专业武术任务中补充攻防与招式。两者目前作为润色输入的规则文本加载，未生成可保存的镜内动作合同。
- H3 短动作润色要求 3–6 个连续时间段，并检查数量、覆盖及首尾时间。校验不检查每个事件是否发生、接触发生的时刻，或成片是否服从时间段。
- `StoryboardReference` 保存媒体身份与来源，但没有动作、节奏、运镜等逐项用途和从视频测量的事件时间。现有引用不能证明素材中的动作时间。
- `buildAssembledPrompt` 消费动作叙事和已确认摄影字段；尚无已确认的动作事件表。完整润色稿可能承载自行设计的时间线，不能视作 Shot Design 已确认数据。

## 工作分层

| 层 | 所有者与产物 | 不得做的事 |
| --- | --- | --- |
| 剧情事件 | Storyboard：本镜需要发生的事件、起止状态、镜头时长 | 不在节奏设计时加一次打击或新剧情 |
| 动作物理 | Shot Design：施力者、受力者、接触点、方向、支撑、障碍物和终态 | 不决定模型格式、剪辑切点和固定秒数 |
| 专业武指 | Shot Design 可选：武术体系、距离、兵器占用、连续攻防 | 不覆盖角色身份、道具母版或场景灯光 |
| 镜内节奏 | Shot Design：事件表、重叠关系、建议时间窗、允许的终态保持 | 不把摄影机速度推导成人物速度；不把建议秒数写成实测 |
| 参考素材 | 资产库：稳定 ID、版本、媒体类型、来源及许可、可借用属性、可选实测事件 | 不因上传视频就自动借用其中的人物、服装或场景 |
| 模型交付 | H3/Seedance：编译已确认事件表与实际附件，保存请求快照 | 不重新设计动作、隐式拉长跌倒或新增碰撞 |
| 结果审核 | 视频候选：逐帧记录事件实测时刻、遮挡、漏失、顺序与速度感 | 不把文本时间窗当作视频实测 |

一个 Skill 是提出候选的方法；动作合同和节奏表是本镜已采纳数据；素材案例是证据；模型格式是编译结果。词典中的招式名只有在展开成可见身体动作并经审核后才进入当前镜头。

## 动作合同与时间线

普通动作合同至少有 `source`、`target`、`contact`、`force_direction`、`initial_blocking`、`reaction_sequence`、`prop_interactions`、`end_state`、`uncertainties` 和每项的 `source_refs`。专业编排可增加 `style_system`、`weapon_hands`、`attack_order`、`distance_changes`；没有证据的值保持未知。

镜内事件表每项包含 `event_id`、`action_ref`、`actor_ids`、`visible_change`、`predecessors`、`overlaps_with`、`authored_window`、`visibility`、`source_refs`、`uncertainties`。`predecessors` 表示因果触发，允许即时反应与接触尾段重叠；非因果动作可并行。`authored_window` 是设计时间，另有 `timing_authority`（`design_example` / `user` / `skill_candidate` / `accepted`）。时间窗可以相接或重叠，不要求平均分配时长；必须覆盖关键事件，但可以有明确的终态保持。若动作在约 1–2 秒内结束而镜头持续 4 秒，应明确剩余时间是静态观察、别的已授权动作，或建议缩短镜头，不把“继续倒下”拉满至 4 秒。

校验分两层：结构校验检查时间、引用、单次接触、依赖先后和授权碰撞；语义审阅核对起幅可见性、真实受力方向、物体是否在图中、是否转身或越过遮挡。通过结构校验不代表 H3 会按秒执行。

## 素材库合同

素材仍使用现有资产与媒体身份。动作参考用途须作为**本镜引用关系**单独保存，可多选 `identity`、`costume`、`weapon`、`pose`、`scene_layout`、`lighting`、`action_choreography`、`camera_movement`、`rhythm`、`impact_timing`、`weapon_trajectory`。前六项主要针对图片，后五项主要针对视频；同一视频只有被勾选的属性进入本轮设计。参考视频中的演员身份、服装、场景和声音不因选择 `rhythm` 自动迁移。

素材条目建议保存 `media_id`、`variant_id`、`type`、`source`、`license/status`、`duration/fps`、`preview`、`annotation_revision`。视频事件标注分开记录 `event_type`、`time_or_interval`、`visibility`、`observer`、`method`、`confidence`；只有直接看过对应片段或逐帧定位后，才能标为 `observed`。未经观看的文章数值与模型建议只能作为 `authored` 或待核对案例。动作分解图不自动成为首帧；参考图静态姿态不能证明动作速度。

外部武术词典可作为动作术语与骨架候选，但其图片/视频样例的可分发权利、专业准确性和模型效果须逐项审查。桌面文章 `ai打斗编排.md` 的事件链与时间窗可作为方法候选；`ai格斗设计` 中的模型内部机制、物理阈值及成功率没有独立证据，不导入产品规则。

## 4 秒基准案例

固定事实：首帧中匪首在画面右侧，老掌柜居中并面向匪首；匪首踢中老掌柜一次，老掌柜沿受力方向踉跄后退，撞到**首帧中确实可见且位于后退路径上的**木桌，桌子移动或晃动，其上可见物品响应，然后老掌柜倒地。若桌子位置或桌上物品不可见，标记待确认，不用提示词补造。摄影机快速推镜只改变相机距离。

基准数据见 `docs/examples/fight-timing/shopkeeper-kick-4s.json`。其中秒数是**待审核的设计方案**，不代表 H3 实测，也不证明 4 秒是最佳时长。一个重要对照是：动作完成后明确保持终态，避免“持续向地面下沉”把一次跌倒拉到片尾。若保持段过长且不服务叙事，再比较缩短镜头时长，而不是让动作变慢。

## 实施顺序与验收

1. 先核对基准首帧与木桌位置，确认有权使用的参考媒体；冻结剧情事件和动作合同。
2. 建立 `shot-action-rhythm` 模型无关候选：只读本镜已确认动作、时长、起幅可见性和有用途标记的参考；输出事件表、依据与不确定项。预览输入、候选版本与采纳流程沿用现有字段候选模式。
3. 在 Shot Design 显示可编辑事件表，逐事件审核；保存已采纳版本。更改剧情、时长、起幅或参考用途后，旧候选过期；已生成视频保持原请求快照。
4. H3/Seedance 只编译已采纳时间线。未采纳时保留原有视频路径，不把新候选隐式拼进模型输入。视觉、声音事件按同一 ID 对齐。
5. 对固定首帧、模型版本、参数与提示词各生成可比候选，逐帧记录踢击开始、接触、收腿、撞桌、桌上物体响应、倒地完成的实际时刻，记录缺失与遮挡。比较设计与实测误差、动作顺序和可读性；不以一次样片推断模型通用能力。

本切片成功条件：普通动作与专业武指调用边界清楚；素材用途不越权；事件表与 H3 文本可追溯；4 秒案例可记录设计值和实测值；现有短时间段格式校验不能冒充效果验收。运行时字段、界面与生成结果尚未实现，必须另行验证。
