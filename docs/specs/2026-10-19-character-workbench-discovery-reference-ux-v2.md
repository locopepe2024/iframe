# 角色设计台与项目／平台／Skill 检索引用交互 V2

日期：2026-10-19。状态：分阶段实施；`/` 动作首层、角色平台 Prompt 的显式文字插入与分镜通用 `[]` 类型匹配已进入本轮切片，统一跨工位检索及平台图片导入尚未实现。范围：角色设计台的任务入口、就地发现、草稿应用、参考图选择和提交审核；资产库的项目／平台检索与 Skill 管理入口。跨工位符号语义见 `2026-10-19-ai-workbench-command-context-index-v1.md`。此文将 `/` 与 `@` 的交互语义作为后续实现基线，替代 `2026-10-19-character-slash-quick-panel-v1.md` 中“`/` 直接搜索文字预设”的目标定义，以及 `2026-10-19-platform-reference-discovery-in-design-v1.md` 中“带图 Prompt 案例直接出现在 `/`”的目标定义。两份旧文仍记录 V1 的代码与决策历史。

## Observed：当前代码事实

- `CharacterSlashPanel` 将一个固定双 Skill 角色草稿动作与风格、面容、皮肤、体态、服装、发型词条放在同一 `/` 列表。选择词条只写可编辑角色草稿，记录 preset ID、revision、目标字段和来源；它本身不调用模型。
- 角色设计参考图和图片 Prompt 的 `@` 使用项目资产索引及其变体；`AssetReferencePicker` 与 `ReferencePromptEditor` 不读取平台目录。角色工位有模型输入预览和图片提交审核，参考图由用户选择后进入审核。
- 资产库界面分为语义资产、平台参考、工作台模板与创作台媒体四个栏目。平台目录、工作台模板、项目资产索引和 Settings 中的 Skill 清单由不同 API 返回；目前没有统一的工作台检索 API。
- 平台资源包含 ID、revision、kind、分类、标签、payload、状态和来源；Skill 清单另有安装、启用、版本、适用目标和来源。两类对象的生命周期与可执行能力不同。
- 角色资产包的完整四层派生关系和本集多造型使用 ID 尚未全部实现，不能在结果卡中把普通缩图写成已确认锚点或某集状态。

## Direct implication

统一的是**发现体验**，不是把所有条目变成同一种资源或同一个写入动作。列表命中、插入草稿、绑定变体、发送模型是不同状态；每一步须有明确反馈。平台结果可见，不代表它有引用许可、已经导入项目或已进入模型输入。

## 1. 入口与心智模型

| 入口 | 用户意图 | 搜索对象 | 选择结果 |
| --- | --- | --- | --- |
| `/` | 执行动作 | 当前工位可执行的命令／Skill 流程 | 打开任务、预览输入或进入下一步；不因打开菜单调用模型 |
| `@` | 给当前任务提供上下文 | 项目资产变体、已发布平台素材、Prompt 案例或字段片段 | 打开资源预览，由用户选“引用图片”“插入文字”或“查看来源”等允许的动作 |
| “参考素材”按钮 | 不记快捷符号时选择上下文 | 与 `@` 同一可用资源目录，默认媒体筛选 | 与 `@` 相同的引用结果和审核状态 |
| “添加描述词”按钮或 `/插入描述词` | 填充一个结构化字段 | 平台／项目文本词条，按当前字段筛选 | 预览目标字段和插入／替换差异；确认后写入可编辑草稿 |
| 资产库与 Settings | 浏览、管理和发布 | 项目资产、平台资源、工作台模板；Settings 管 Skill 安装／启用 | 打开详情或治理操作；不会暗中改变当前角色草稿 |

Hugging Face Agents Course 的 Action 定义是“Agent 与环境交互的具体步骤”，并强调操作与参数要明确；它未规定 `/`、`@` 语法。这里的符号分工是 iFrame 的产品约定。用户提供的《超越对话：设计人性化 AI Agent 交互界面的完整指南》节选支持任务导向、按需展示、状态反馈、控制与恢复，但也未规定这两个符号。

`/` 的首屏只列动作，如“生成角色视觉草稿”“插入描述词”“应用任务模板”。只有已安装、已启用、适用角色工位且实际可调用的 Skill 可以标成“可执行”；其余 Skill 在 Settings 可查看，不能伪装成可运行命令。V1 固定双 Skill 流程保留真实名称与输入预览；不能承诺任意 Skill 已具备同样的运行入口。

`@` 的首屏显示“本项目”“本集”“平台参考”来源分组，并可按角色、场景、道具、Prompt、图片、视频、当前任务槽位筛选。面容字段优先展示适配词条，图片 Prompt 优先展示图像与案例；“全部”始终可选，不能因为推荐过滤隐藏精确搜索结果。

现有索引的 `global` 是语义资产池来源，**不等于**独立治理的 `platform_shared` 目录；选择器应分别标成“全局素材”和“平台参考”。Settings 的 Skill 清单是能力目录，也不伪装成图片资产。

## 2. 工作台布局与具体操作

宽屏沿用已实施的可展开工作台：档案可收起，当前任务参数在左，大图和变体在右。默认只展示角色名与剧本描述、当前资产包任务、一个主要编辑区、当前已选上下文和下一步按钮；身份／造型细项、模型设置、负向提示词与来源详情按需展开。输入框内的 `/`、`@` 和等价按钮进入同一选择流程，快捷符号不是完成任务的前提。

```text
标题：角色 / 当前任务 / 草稿状态                  [查看资产包] [关闭]
左：当前任务                                         右：图片与变体
  剧本事实摘要〔只读，可查来源〕                      当前大图／无图说明
  设计要求〔可编辑〕                                 变体胶片／确认锚点
  [ / 动作 ] [ @ 资源 ] [添加描述词]                 与当前任务相关的生成结果
  已应用文字与来源；已选参考图及用途
  [查看并确认模型输入] → [生成]
```

每张搜索结果卡至少显示标题、类型、来源层级、适用槽位、revision、许可／可用状态和缩图或“无媒体”。角色资产增加项目 → 角色 → 资产包 → 层级 → 条目 → 变体的面包屑；剧集造型显示本集状态及其项目包来源，不能仅以人物名区分。Skill 显示安装／启用状态和实际工位能力；平台案例展示完整 Prompt 与效果图，但两个使用动作分开。

**带图 Prompt 案例的操作**：点击 `@案例` 先打开详情。用户可选择“插入 Prompt 到当前草稿”或“选此图作为参考”，也可两项分别选择。插入前显示完整文字、目标字段、追加／替换范围；图片引用需选择明确变体和参考用途。只插文字不会附图，只选图不会带 Prompt。插入后的文字允许修改；修改后记录来源和用户覆写，不能继续标成预设原文。图片引用保存稳定资源／revision／variant ID，不保存 URL 为身份。

Prompt 案例应用后在编辑器内留下**实际插入的可编辑文字**，来源以旁侧标记保存；不能把未解析的原始 `@案例名` 当成模型提示词。现有 `@` 图片引用继续以稳定变体绑定，迁移时不得把旧图片 mention 解释为 Prompt 资源。

**示例**：在青溪镇角色设计中，用户通过 `/插入描述词` 找到“粗纺棉麻”并确认写入服装字段；通过 `@平台案例` 预览古典行旅样图并选用 Prompt，改写人物性别；通过 `@项目角色` 选定已确认母版图作为图像参考。审核页分别列出三个来源、最终文字、母版变体和实际发送的媒体。用户删掉任何一项后，审核投影与最终请求同步变化。

## 3. 统一检索的分型合同

检索请求携带 `station=character`、当前任务／字段、项目／剧集 ID、所需模态、查询词和可选来源筛选；服务端按可见权限返回目录结果，不在搜索阶段创建绑定。结果至少包含稳定身份、revision、kind、source_scope、title、tags、preview 状态、rights 状态、可用动作和目标槽位。来源可以是项目索引、已发布平台目录、模板目录或 Skill 清单，但前端以一个选择器呈现并保留原始 owner。

动作能力由后端或适配层明确给出，不以 `kind` 名称推断：

| 对象 | 允许的当前动作 | 提交前的额外校验 |
| --- | --- | --- |
| 项目／本集媒体变体 | 查看、作为参考图；符合资产包状态时选锚点 | 变体仍存在、owner 和项目／剧集作用域正确 |
| 已发布平台图片／视频 | 查看；经许可且已形成可解析绑定后作为参考 | status、revision、许可、用途和媒体访问有效 |
| 平台 Prompt／字段片段 | 查看全文、插入可编辑草稿 | schema／目标字段相容；来源与用户覆写可追溯 |
| 工作台模板 | 查看任务输入槽位、启动该任务 | 模板只定义流程，不自动附图或暗加约束 |
| 已启用 Skill | 查看说明、预览输入、执行当前工位支持的流程 | 实际安装和能力匹配；用户确认模型输入 |

平台候选、审核中、下架及许可不明的条目不提供模型引用动作；可只读显示出处。项目结果与平台结果同名时显示来源和稳定 ID，不合并。若平台资源需要导入项目，选择器明确展示“导入到项目”这一步及目标项目；导入不等于模型引用。索引错误、零结果、失效 revision、无权引用、媒体加载失败各有独立可恢复提示。

## 4. 状态、确认与回退

流程状态：`未选择 → 已预览 → 已应用到草稿／已选参考 → 待模型输入确认 → 生成中 → 候选结果 → 用户确认资产`。UI 用文字标明状态和下一步；在任一步取消，保留用户原草稿。模型生成失败保留 Prompt、引用和已审核快照，允许修改后重试；重试形成新候选，不覆盖旧变体。

设计草稿、图片生成和锚点确认是不同审核边界：`/` 或 `@` 选择仅更新当前草稿／引用列表；设计 Skill 先展示模型输入；图片请求再展示完整正向／负向 Prompt、模型参数、来源图和变体；生成结果须由用户选定才能成为锚点。所有发送给模型的文字和参考图都必须在对应审核面板可见并可由用户修改或移除。已生成任务固定当时 revision；平台资源升级只能提示显式更新。

## 5. 实施切片与验收

1. **目录和动作契约**：核对项目索引、平台资源、模板、Skill 的稳定 ID、许可、可用动作和当前工位能力；提供统一搜索适配结果，不重写各目录 owner。验收同名多来源不会混淆，未安装 Skill 和未授权图不可执行。
2. **角色就地发现**：`/` 改为动作列表，描述词移到明确的“插入描述词”二级选择；`@` 和参考素材按钮共用资源选择器并接入平台 Prompt／媒体。保留已有 `preset_id` 历史可读。验收搜索、分类、焦点、键盘、空结果和取消行为。
3. **预览、应用、审核**：Prompt 案例的文字与图像分开选择；字段差异、来源、引用列表和最终请求同屏可核对。验收只选文字的请求没有图，只选图的请求没有案例 Prompt；撤销、失效与手改后的来源标记正确。
4. **资产包任务内复用**：结果卡定位到项目角色包的层级与变体；本集状态在实现 `use_id` 后接入。验收正常／受伤造型不会串用，历史 revision 不被新选择覆盖。

设计验证任务：让用户在青溪镇角色图里完成“找到一个服装词条、引用一张项目锚点、复用一个平台案例的 Prompt、确认图片请求”。记录找到目标所用时间、错误引用、撤销次数和提交审核与实际请求的一致性。现阶段这些是验收方案，不声称已有可用性结果。

## Not yet proven / What would verify it

- 混合检索是否比现有分散入口更快，需上述任务的实际操作数据和用户反馈；不能从入口数量推断效率。
- 平台图片／Prompt 是否均有可用于模型输入的许可与项目导入路径，需逐资源和后端能力验证。
- 真实浏览器里浮层尺寸、图片可读性、触控命中与小屏无横向溢出，需部署后按 1440×900 和 375px 两种视口检查。键盘 Tab 顺序、焦点返回、ARIA 类型、错误提示及深色界面对比需按 `ui-ux-pro-max` 的可及性要点验收。
