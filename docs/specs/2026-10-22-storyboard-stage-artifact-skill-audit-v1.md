# 分镜生成阶段、产出物与 Skill 归属核对 V1

状态：源码核对与设计边界；阶段 2 待审候选、阶段 3–4 图片候选的已确认场景基线及预览绑定已本地实现；阶段 6 已限制单镜润色目录项，其他目标加载合同尚未实现。日期：2026-10-23。

## Observed：当前执行链

产品界面的“分镜设计”混用了两种含义：从剧本拆出镜头草稿，以及对单镜生成首帧和视频。以下按实际产出物分层，不以页面标题划分。

| 阶段 | 当前入口与动作 | 当前产出物和保存点 | 当前 Skill / 指令加载 |
| --- | --- | --- | --- |
| 0. 上游导演拍摄计划 | 已确认计划的 scene/shot、时空 ID、景别、机位、运镜、时长、动作和对白 | 带 revision/hash 的计划；作为后续约束与来源 | `director-tasks.json` 中 `shooting_plan` 方法：开场吸引力、信息差、节奏情绪、视点调度、声画、连续性等；不属于首帧出图 Skill |
| 1. 镜头草稿 | `StoryboardGenerateDialog` 选“按导演计划生成”或“从剧本设计分镜”；`storyboard-analysis-jobs` 生成预览，用户可修订、应用 | 草稿行含 `shot_id`、scene/character/prop、动作摘要、景别、机位、构图、运镜、时长、对白等；应用后成为 `StoryboardFrame`，替换旧帧 | 按计划：`materialize_plan` 纯转换，不再加载方法卡。从剧本：本次所选四张 `storyboard-*` 方法卡按 ID+revision 冻结并进入 LLM 提示词；不是图片生成 |
| 2. rich-frame 细化 | 草稿应用后前端自动调用 `refine_batch_frames`；单帧也可 `refine` | 生成 `rich_refinement_candidate`，用户逐字段采纳后写入 `StoryboardFrame` 的画面、摄影、站位、对白、声音、光线、转场或时长字段并重算 `assembled_prompt` | 固定 `refine_frame_to_rich` 提示词；读取本帧、角色/场景资产、相邻镜头和导演上下文。当前没有独立 Skill 选择；候选采纳已需显式审核 |
| 3. 首帧图设计与提示词 | `StoryboardFrameEditor` 编辑图像提示词/构图/风格；`storyboard/refine_prompt` 可产生中英双语候选，用户再应用 | `image_prompt`、双语稿、候选和来源快照；场景/角色/参考图另按其已确认版本引用 | 使用 `storyboard_polish` 模板及已确认设计上下文；当前没有 `storyboard-*` 方法卡的首帧专用加载入口，也没有微表情时序 Skill |
| 4. 首帧/尾帧图片生成 | `render-preview` → `render-jobs`/`render` 生成 Storyboard 帧；统一分镜卡的 `render-candidate-preview` → `render-candidate` 可生成独立首/尾帧候选 | 图片及候选、所选图片/参考包；候选路径不直接改 canonical 图字段 | 图像模型和预览合同处理最终文本、参考与上下文 token；生成请求不再选创作 Skill |
| 5. 单镜视频设计 | `ShotCard` 编辑动作文本、景别、机位、运镜、转场、风格/光线覆盖、时长及输入模式；参考包与连续性表提供来源 | 当前 `StoryboardFrame` 字段及镜头工作台状态；尚无独立的表演时序、镜内节奏和逐字段 AI 提案版本 | 上一切片的“拍摄计划字段”仅将已确认计划的景别、机位、运镜、时长逐项采纳；它不是新的摄影设计 Skill |
| 6. 视频提示词适配 | `PolishPanel` 预览完整模型输入、确认后调用润色；`buildGenerationPrompt` 组装未优化稿 | 双语优化结果；应用后完整视频提示词，或保留未优化的结构化字段组装稿 | `catalog.json` 的 H3、Seedance、运镜、连续性、导演风格等复选项当前仍作为**整段指令文本**加载；目标模型筛选和 IR 预览回显已实现，未产出逐字段设计建议 |
| 7. 视频生成与审核 | `video_tasks` 按 t2v/i2v/首尾帧/r2v 模式提交，候选回看并选成片 | 视频任务/候选/选中 take；任务记录 Storyboard 参考 revision | 模型能力与媒体合同参与生成；这里不应再次运行规划 Skill，也不能把任务成功视作视觉一致性证明 |

源码依据：`StoryboardR2V.tsx` 的 `handleSmartGenerate`/`handleApplyStoryboardDraft`/`generateT2I`，`storyboard_workflow.py` 的 `materialize_plan`，`pipeline.py` 的 `preview_storyboard_analysis`/`refine_frame`/`generate_storyboard_render`/`create_video_task`，`llm.py` 的 `analyze_to_storyboard`/`refine_frame_to_rich`，`api.py` 的图像与视频预览路由，以及 `director_skills.py`、两份 Skill 目录。

## Direct implication：阶段与 Skill 合同

| Skill 类别 | 应当读取 | 必须产出 | 允许加载的阶段 | 当前判断 |
| --- | --- | --- | --- | --- |
| 剧本拆镜方法 | 已确认剧情、计划/导演约束、资产身份 | 可审阅镜头草稿及来源；不生成图 | 1，仅从剧本模式 | 四张 `storyboard-*` 已在此加载；按计划模式不重跑 |
| rich-frame 结构化细化 | 单镜草稿、已确认上下游约束、明确的相邻状态 | 对每个变化字段给出候选、理由、来源；用户审核后保存 | 2 | 已有字段候选、原值快照、选择应用与过期拒绝；理由仍依赖模型返回，缺失时明确显示；尚无阶段专用 Skill 选择 |
| 首帧静态画面 | 当前镜头 0.00 秒可见状态、角色/场景锚点图及选定变体 | 静态构图/站位/表情/光照与图片提示词；引用实际来源版本 | 3–4 | 现有模板与预览可用；不能加载视频运镜、对白过程或微表情时序全文 |
| 单镜表演/摄影/节奏 | 当前镜头任务、时长、已确认连续性、首尾图和参考用途 | 动作起止、微表情时序、景别/机位/路径/速度、切点/转场等**独立字段候选及理由** | 5 | 目前无统一候选合同；`seedance-camera` 有方法规则但输出仍是可复制文本 |
| 跨镜连续性审阅 | 显式时空/连续性 ID、已确认帧状态及结果 | 冲突与来源、不确定项和可采纳建议；不改已确认事实 | 1 的草稿审阅、5 的视频设计审阅 | 一致性表与参考投影属数据规则；`sequence-continuity` 目前是多镜提示词指导，不是表格诊断器 |
| 模型编译与校验 | 用户已采纳的字段、模式、媒体映射、模型能力 | H3 或 Seedance 各自的最终文本和预览；语义与来源不变 | 6 | `minimax-h3-director`/`seedance-prompt` 更接近此层；H3 IR 是优化器，不是 Skill；硬格式规则不应靠可选项保证 |

单镜内的动作、微表情、特效、镜头和节奏可以由一个方法联合提出，但每项需落在对应字段；仅扩写成一段“更完整提示词”不构成设计。首帧只消费起始可见状态，视频可以消费时序，尾帧消费已确认终点。模型适配只能编译用户已采纳的设计，不重新决定剧情、身份或连续性。

### 现有条目逐项归属

| 条目 | 当前加载位置 | 正确任务归属 / 当前缺口 |
| --- | --- | --- |
| `storyboard-suspense`、`storyboard-action`、`storyboard-emotion`、`storyboard-dialogue` | 从剧本设计分镜（阶段 1） | 分别处理信息呈现、动作拆帧、情绪可见镜头、说话/反应镜头的**草稿规划**；均不直接加载到首帧图片或单镜视频。`storyboard-emotion` 不是微表情时序 Skill |
| `viewpoint-staging`、`rhythm-emotion`、`audiovisual-strategy`、`continuity-review` 等 | 上游 `shooting_plan`（阶段 0） | 结果经已确认计划和 revision 传给后续阶段，不复制原 Skill 指令重做镜头 |
| `seedance-camera` | 视频润色复选框（阶段 6） | 规则涉及景别、机位、路径、速度、落幅，方法上适合阶段 5；但当前输出合同是一条运镜提示词，尚不能当作逐字段摄影提案。阶段 6 只能用其已采纳决策做 Seedance 表达 |
| `sequence-continuity` | 视频润色复选框（阶段 6） | 说明要求多镜规划和分镜表，作用范围大于当前单镜；应归跨镜审阅，且不能取代按连续性 ID 的数据投影 |
| `director-style` | 视频润色复选框（阶段 6） | 属整体视觉意图/有意变更建议；当前输出含完整自然语言提示词，不能默认覆盖已确认项目风格或光线 |
| `minimax-h3-director` | H3 视频润色（阶段 6） | 混有 H3 格式、媒体用途和分镜设计规则；先拆出硬请求合同与模型编译，再让真实镜头设计输出进入阶段 5 的字段审核 |
| `seedance-prompt` | Seedance 视频润色（阶段 6） | 负责已确认设计的自然语言编译/压缩与参考标记保持，不负责新决定机位、表演或节奏 |

当前目录不存在独立的首帧构图、微表情时序、特效可读性或转场字段提案 Skill；不能用条目名称、`targets` 或整段提示词输出推断这些能力已生效。

## Not yet proven 与当前错位

1. **计划采纳与 AI 细化是两种候选。** 现在 `refine_frame` 先保存待审候选，应用时只写所选字段。上一切片的“拍摄计划字段”面板仍在细化阶段之后，专门审阅计划与当前值的差异，不能冒充 AI 提案。按计划转换本身已携带相同字段；若细化没有改动，计划面板可能没有候选。
2. **已采用完整优化稿绕过结构化视频字段。** `buildGenerationPrompt` 在 `promptIsOptimized` 时直接返回完整文本，因此后来只改景别/机位/运镜不会改变生成文本；当前面板已对这些无效采用禁用。要真正实现逐字段设计，应让已采纳字段重新编译并使旧优化稿失效或要求重审。
3. **两条图片路径合同不同。** `StoryboardFrameEditor` 的 canonical 帧渲染与统一分镜卡的首/尾帧候选都生成图片，但候选路径不改 canonical 图字段。canonical 只补充图像设计所选来源变体；候选图使用确认参考包里的图片条目，包括上传图和效果图，并排除视频条目。canonical 预览 token 绑定负向词。候选图片现在优先读取已保存的图片稿，而非拼装单镜视频稿；服务端补入已确认场景设计的空间、风格、光照及静态约束，场景版本变化使预览失效。草稿回退仍可能描述动作过程，用户须审阅最终预览；尚无可靠的自动静态化判定，也未统一输出图片版本与最终视频输入选择。
4. **现有五个视频选项没有阶段元数据。** `catalog.json` 只有目标模型/类别及文本说明；显式 Skill 选择虽做了目标模型兼容校验，尚未验证阶段、字段作用范围、安装状态或 `id + revision` 冻结。`director-tasks.json` 的阶段冻结合同不能自动套用到这套目录。
5. **相邻上下文有潜在串镜边界。** `refine_frame` 将前后镜的动作、对白、景别等送入模型用于连续性；现在模型 JSON 先进入待审候选。代码仍不能证明模型没有把前镜动作或对白误写入当前镜候选；需要以不同人物、地点、对白的相邻镜做实际输出审核。
6. **视觉效果尚无对照证据。** 结构化字段、预览 token 和图片锚点只证明输入与版本边界；跨镜光影、远景、人物表现是否一致仍需实际生成样本审核。

## 下一轮单镜设计合同

阶段 5 的优化从**当前镜头和已确认来源**开始。输入应冻结当前镜头字段、已确认拍摄计划 revision、场景/角色锚点变体、用户勾选的参考投影、连续性诊断结果、视频模式/时长和目标模型能力；相邻镜头只提供经确认的时空 ID、起止状态及必要轴线关系。参考图的结构化投影仍遵循其独立白名单，不借此传入前镜动作、对白或人物描述。缺连续性 ID 时标记未确认，不按顺序或名称推断。

设计器返回逐字段候选，至少包含 `field`、`before`、`proposed`、`reason`、`source_refs`、`scope` 和 `visibility`。`scope` 区分当前镜头与跨镜审阅；`visibility` 区分首帧可见、视频时序、尾帧目标。镜头任务、景别、机位、构图、主运镜/速度、动作起止、表演时序、光照覆盖、切点/转场各归自己的字段。没有来源或可见依据的建议必须标记待审；微表情只在景别与遮挡允许时细化，不能改角色脸型、服装或基础场景。

候选默认不应用。用户逐字段采纳时核对冻结输入哈希和字段作用域；只更新被采纳字段，并使依赖旧字段的完整优化稿失效或要求重新审阅。跨镜一致性检查只报告冲突及证据，不直接改镜头；同时间异地点比较世界光，同地点同时间才比较局部光、空间和状态，画幅/风格按各自作用域检查。对有意的局部光或风格覆盖保留理由与来源，而不是强制所有镜头数值相同。

阶段 6 只编译已采纳的当前镜头字段、媒体用途与模型硬合同。H3 与 Seedance 从同一冻结设计输入分别生成目标格式；预览回显所选 Skill、完整模型输入、参考媒体与版本，提交必须使用匹配 token。现有 `seedance-camera`、`sequence-continuity` 和 `director-style` 在阶段 6 仍是过渡性的文本指导，不得在 UI 中声称它们已完成逐字段设计。缺省旧请求只能加载目标模型的提示词适配；商品替换等其他同模型工作流不可进入单镜润色。

## 下一步验收顺序

1. 阶段 2 已建立“原值 / 提案值 / 理由 / 来源 / 应用字段”的待审候选；接下来核对真实模型输出、理由完整度和邻镜信息隔离，并保留按计划转换的 `shot_id`、顺序和时长覆盖校验。
2. 阶段 3–4 的图片候选已与视频提示词分开，读取已确认场景版本；图片预览不作为纯 T2V 的前置步骤。下一步为图片稿提供明确的起始/结束可见状态编辑字段与审核，再核对两条路径各自的完整参考集合、图片版本及最终视频输入选择。上一镜尾帧接力保持手动选择，只有上一镜已选视频完成后才可用。
3. 然后为阶段 5 的动作/微表情/特效/摄影/节奏建立字段提案和采纳版本；跨镜 Skill 只做显式连续性范围内的审阅。
4. 最后让阶段 6 的 H3/Seedance 适配读取同一份已采纳设计，分别编译并锁定实际指令文本、媒体与版本；用固定素材的双模型回归验证输入语义，再以实际生成审核视觉效果。

### 阶段 2 候选实施合同

本切片让批量/单镜 rich-frame LLM 只写 `rich_refinement_candidate`，不直接改已采纳镜头字段。候选保存 ID、输入快照哈希、来源标签、原值、模型返回的字段值与理由；UI 每字段默认未选，用户可选择部分字段应用或丢弃。应用时校验 ID、字段白名单和输入快照仍一致；应用成功只更新被选字段，并重新计算派生 `assembled_prompt`。无有效候选字段或模型失败时保持原镜头。前/后镜、资产、计划和本镜内容变化使候选过期。批量细化可以逐帧生成候选，但不能静默应用。该合同仍不证明模型的字段建议在艺术上正确，实际效果需要人工审阅。
