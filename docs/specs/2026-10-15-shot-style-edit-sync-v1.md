# 镜头润色后的风格与光线编辑同步

状态：实现前边界与验收。

依据：10 月 15 日 `2026-10-14-shot-style-lighting-continuity-summary.md` 交互决定及 `2026-10-14-context-lifecycle-optimization-plan-v1.md`。结构化镜头风格/光线是设定源；润色正文是可编辑派生内容。再次润色可选。

## 已确认故障

`buildGenerationPrompt` 在 `promptIsOptimized` 为真时返回旧正文；字段编辑只修改字段。普通组装又会同时输出覆盖光线与计划镜头光影。正文与优化标记分两个 debounce 队列保存，刷新可能读取不一致的状态。

## 本轮行为

1. 编辑风格/光线时，立即同步已采用的完整正文，保留润色状态和用户编辑；普通草稿继续按字段组装。首帧与视频都读取当前可见正文。
2. 采用正文后的字段修改以一条可见“当前镜头设定”描述反映。H3 三段/六段正文放在视觉描述字段内，不在音频段后添加。后续编辑替换同一条说明；移除可定位的旧字段原文。不能声称消除了模型改写的同义旧设定。
3. 正文、优化标记与字段通过同一帧更新请求保存，按帧顺序发送；合并尚未发送的编辑，避免不同延迟的请求反向覆盖。页面离开前排空待保存编辑。
4. 后端字段更新同步独立保存的已采用图片正文，并返回更新结果；视频正文若由客户端显式提交，以当前可见值为准。刷新继续使用所保存的正文及优化状态。
5. 润色 API 可接收界面当前风格/光线（未等待 debounce 的最新值）；没有提供时读取已存字段。显式光线覆盖抑制计划镜头光影，保留匹配地点/时段的连续性基线。无镜头投影时仍传递当前覆盖，遵守字段预算。

## 影响路径与验证

- 前端：提示词同步工具、分镜编辑保存、ShotCard 预览/润色请求、API 类型。
- 后端：帧更新原子字段、图片采用稿同步、镜头润色最小投影。
- 先失败测试：采用→改字段→可见正文/提交；快速正文+字段编辑后保存/刷新；H3 结构和对白保持；显式覆盖与计划光影冲突；未保存字段立即润色。
- 回归：相关 Python/前端行为测试、TypeScript 检查、静态构建及后端 CI 范围。
