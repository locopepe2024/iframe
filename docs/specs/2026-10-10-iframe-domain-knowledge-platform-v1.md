# iFrame 可升级领域知识库与 Agent 检索边界 v1

状态：架构需求，尚未实现。日期：2026-10-10。

实施入口：[行为规格](2026-10-10-iframe-knowledge-platform-spec-v1.md)、[架构设计](2026-10-10-iframe-knowledge-platform-design-v1.md)、[开发计划](2026-10-10-iframe-knowledge-platform-development-plan-v1.md)。

## 目标与范围

为 iFrame 建立可持续采集、清洗、版本化、检索和复核的共享部署知识基础设施。第一组消费者是 AI 漫剧的编剧、导演、美工、剪辑和视频质量分析；金融公司/事件研究是后续使用同一基础设施的另一个领域。个人补充也可属于剑法、拳法、菜系配料等新主题；主题分类可扩展，专业判断规则分别定义。用户仍通过主 Agent 对话，各领域任务调用受控的检索与知识工具。

知识库不是“分镜参考模板”：分镜只是导演/美工知识被使用的一个阶段。库中还要保存编剧方法、导演理论、造型与美术案例、剪辑规则与案例、视频质量指标和失败样本，并支持后续加入论文、标准、教材、官方文档、案例及用户资料。

## Observed

- 当前 `src/apps/agent_skills.py` 的 skill 是 owner 范围的指令快照，不提供持续采集、论文解析或知识检索执行能力。
- 当前 `src/apps/agent_api.py` 的创作 Agent 使用当前消息、skill 指令及用户明确附带的素材；没有通用资料库的检索调用。
- `docs/specs/2026-10-01-long-script-storyboard-context-copy-v1.md` 已要求编剧/导演经验提示标记来源、版本、适用范围与用户决定；`docs/specs/2026-10-01-external-film-skills-review-v1.md` 要求视觉知识与剧本事实、导演解释和用户决定分层。
- GitHub 静态检查显示 Crawl4AI、Docling、Haystack、RAGFlow 等分别覆盖网页采集、复杂文档解析、流水线编排和 RAG 服务。它们的存在不证明其中任何一个已满足 iFrame 的多领域权威与可信度契约。

## Direct implication

共享的是资料生命周期与检索协议，不是各专业的判断规则。编剧、导演、美工、剪辑、视频质量与金融研究应有各自的知识范围、问题模板、适用条件、输出校验和评估集；不能把金融证据自动当作创作规则，也不能把创作经验当作剧本原文事实。

## 资料生命周期

```text
用户提供 URL/文件或启用获准的订阅来源
  -> 来源发现与访问条件检查
  -> 不可变原始快照（正文、图片、附件、时间、hash）
  -> 解析与清洗（段落、图注、表格、页码、OCR、去重）
  -> 可审阅的知识条目/主张（claim）与适用范围
  -> 关键词及语义索引（均为可重建投影）
  -> 任务相关的检索、重排、引用和用户采纳记录
```

同一来源修订或重新采集时创建新 source revision，保留旧版。摘要、图片描述和标签是派生记录，必须带生成模型/规则版本及所依据的原文位置；不得代替原文。论文的图、表、实验设置和结论要分别定位，不能只保存摘要。外部网页图片须保存来源与使用条件；能否用于生成参考图与能否用于研究检索是两个权限。

### 最小数据契约

| 实体 | 必要字段 |
|---|---|
| `Source` | `owner/scope`, URL 或上传来源、标题、作者/机构、发布日期/修订日期、采集时间、来源类型、许可/使用条件、原始 hash、版本、抓取状态 |
| `ContentUnit` | source revision、正文/图/表/视频帧类型、精确页/段/时间戳定位、父子关系、原文片段、派生描述、解析器版本 |
| `KnowledgeClaim` | 陈述、所引 content unit、证据状态、适用领域/任务/条件、相反证据、抽取方式、审阅状态、revision |
| `RetrievalHit` | 查询与过滤条件、source/content/claim ID、分数及检索方式、原文定位、检索时的索引版本 |
| `UsageRecord` | 消费 Agent/任务、使用时的 source/claim revision、建议内容、用户接受/编辑/忽略状态、产物 revision |

库按 `shared-public-reference`、`owner-private`、`project` 三种范围组织；默认检索是已发布公共库加当前用户个人库，进入获授权项目时再加入项目库。每次查询必须先按 owner、项目和权限过滤，再按领域匹配与相关性排名。平台采集的资料经审核才进入公共库；用户补充默认只进个人库，不能因 URL 相同或标签相同而自动公开。公共知识与用户私有文档不能靠标签隔离。历史产物固定引用使用时的库层级及 source/claim revision；知识更新产生“可复核”提示，不暗改已确认剧本、导演方案或金融报告。首版部署使用共享 PostgreSQL、私有 COS 与独立采集 worker，详见架构设计。

## 五个创作知识域

| 域 | 检索触发与知识用途 | 输出边界 |
|---|---|---|
| 编剧 | 剧情结构、人物动机、对白、节奏、类型案例；写作与复核时召回 | 建议/反例，不补写成剧本事实；用户决定后进入可编辑草稿 |
| 导演 | 调度、镜头语言、视点、光线、表演、场面连续性；导演理解与拍摄计划时召回 | 标记理论、案例或当前项目约束；不取代确认后的 Director revision |
| 美工 | 造型、场景、材质、色彩、道具及视觉参考；资产设计时召回文字与获准图片 | 来源图的权利和参考用途可见；风格案例不能伪装成剧本设定 |
| 剪辑 | 镜头衔接、节奏、声音桥、连续性及失败案例；剪辑计划和复核时召回 | 建议具体切点/问题位置；不在未审阅时直接覆盖时间线 |
| 视频质量分析 | 清晰度、闪烁、字幕/口型、动作/身份一致性、镜头连续性、音画同步；成片检查时召回标准及样例 | 区分可计算测量、模型观察和主观审美；记录帧/时间范围，阈值适用条件需明确 |

每个域的 `skill` 只定义何时检索、如何解释命中、如何产出可审阅建议。来源采集、解析、索引和检索由注册工具/服务执行；主 Agent 负责协调并向用户显示证据。域知识版本可升级，但 skill 版本、知识条目版本和产物版本分别记录，不混为一体。

## 来源可信度与论文

不建立一个由“论文/官网/媒体”名称直接决定的总可信分。每个主张至少记录以下独立维度：

1. **来源身份**：作者、机构、出版渠道、原文是否取得、是否为转述、撤稿/修订状态。
2. **证据关系**：原文是否直接支持当前主张，还是仅支持一部分；是否存在相反证据。来源权威不自动等于主张成立。
3. **研究质量**：论文的研究类型、样本、对照/评测、方法、局限、复现状态；同行评审只是元数据，不等于结论已复现。
4. **适用范围**：媒介、类型、目标人群、模型版本、时间/地区、任务阶段。电影剪辑经验不能无条件推广到竖屏漫剧；旧模型论文不能自动证明新模型效果。
5. **时效与使用权**：政策/技术资料的版本和生效时间，以及文本/图片能否存储、引用、导出或作为生成输入。

Agent 输出的建议需标识 `原文事实`、`论文/标准结论`、`案例经验`、`模型推断` 或 `创作建议`。争议、缺失、过时和不适用条目应降级或排除；用户可以查看依据并覆盖建议。内容被引用次数或检索相似度不能提升其可信度。

## 首个演示与验证

演示同一主 Agent 使用两个创作域：导入一篇含正文和图片的公开文章及一篇可合法获取的论文；解析出段落、图、表和来源定位；在“编剧检查”和“导演/美工设计”两个任务中得到不同、有界的检索结果。再加入一个互相矛盾或不适用的资料，确认系统显示冲突/适用条件，而不是合并成确定性规则。视频质量域先用一段有明确时间戳的问题样片验证定位与指标/主观观察分离。

通过条件：跨 owner 不可读；同源重复采集幂等、修订可回看；图文关联和论文图表定位正确；摘要/模型描述不冒充原文；知识命中附引用、可信度各维度及适用条件；用户忽略的建议不自动再次强制应用；旧创作产物引用的知识版本稳定。金融 demo 复用相同采集、清洗、版本、索引和召回接口，再增加财务数据口径和领域分析模板。

预计受影响路径：新增 `src/apps/knowledge/` 与其测试，主 Agent 工具注册，相关创作域的上下文组装与前端审阅界面；金融域通过知识服务 API 接入。具体 RAG 引擎与向量库须根据真实图文/论文检索评测和运行成本选择，不能在静态设计阶段认定为必需。

## Not yet proven / Hypotheses / What would verify it

- **未证明**：单一检索策略能同时满足图文、论文、成片质量和财务数据问题；分别构建带正确来源位置的领域问题集，测召回与引用准确率。
- **假设**：来源分层和多维可信度记录会改善建议质量；用有冲突、撤稿、旧版本和不适用范围的样本，比较人工审阅结果与系统输出。
- **未证明**：各站点、论文和图片许可允许长期保存与生成用途；逐来源验证条款并按用途记录权限。
