# 角色设计台系统优化方案 V1

日期：2026-10-19。状态：实施基线。范围：项目级角色视觉设计、词典和参考发现、生成交互、角色资产包；剧集专属造型只定义衔接，不在项目角色面板中混作基础身份。

本文汇总角色设计台、平台库、`/` 与 `@`、角色资产包的现有规范。实施时以此文确定产品顺序；具体 API 与兼容边界仍以各专题契约和代码验证为准。

- `/` 首层已改成“生成角色视觉设计草稿”“插入描述词”；词条在第二层。快捷词条按分类写入可编辑草稿，不直接调用模型。现有分类是风格、面容、皮肤、身材体态、服装、发型；词条来源包含 iFrame 原创和已记录来源的候选。

## Direct implication：一个角色设计的五种对象

| 对象 | 用户要解决的问题 | 数据归属与边界 |
| --- | --- | --- |
| 角色档案 | 这个人是谁，剧本明确了什么 | 项目角色的事实与来源；年龄、性别等来自剧本或用户确认，不能由词典猜测 |
| 身份视觉设计 | 如何在不同视角认出同一个人 | 项目角色设计 revision；稳定面部结构、肤质、发际线、体态、识别标记 |
| 基础造型 | 默认穿着与配色是什么 | 项目角色设计 revision 或其造型版本；服装与妆容可变，不能与脸部身份混为一项 |
| 任务输入 | 这次要生成什么图 | 当前资产包任务的视角、画幅、背景、光线、Prompt、明确选择的参考图；每次提交前可改 |
| 输出资产 | 哪张图被采纳并如何派生 | 项目角色资产包、条目、锚点 revision、候选变体与来源；本集伤情／换装另建使用状态 |

这五种对象在界面上可以连续操作，但不能仅凭一次 `@` 选择或一次生成就自动确认下一层。项目角色检索主路径是 `项目 → 角色 → 资产包 → 层级 → 条目 → 变体`。剧集路径另为 `剧集 → 角色 → 使用状态／造型 → 本集派生资产`；同一集同一角色可有多个状态，镜头从已确认的状态中选用。

## 一、设计维度：从用户能判断的视觉问题出发

默认只显示“剧本事实摘要”“身份设计”“基础造型”“当前资产包任务”四块。每块提供一段可编辑要求和已选参考，不要求用户先填满表单。逐项编辑按需展开，字段空值表示未指定。AI 提出的值明确标“创意选择”，用户修改和确认后才能形成设计 revision。

| 维度 | 逐项可编辑值 | 不在此处确定的内容 |
| --- | --- | --- |
| 剧本事实 | 角色名、年龄阶段、性别／族裔（仅有来源时）、身份与剧情事实 | 依据名字、职业或性格推断脸型、肤色、武器 |
| 稳定面部身份 | 脸部轮廓／下颌／颧骨；眉眼关系；鼻口结构；肤色与肤质；发际线、发色和发型轮廓；雀斑、痣、疤痕、笑纹、眼圈等识别标记 | 当前镜头表情、景别、主光和妆造情绪 |
| 体态与比例 | 身高比例感、体型、肩背和常态姿态；只保存跨图稳定的特征 | 跑步、坐姿、挥剑等一次性动作 |
| 基础造型 | 默认服装版型、层次、材质、配色、鞋履和必要妆容 | 固定的“配件”“武器外观”必填字段；道具通过独立道具资产按需引用 |
| 本次任务参数 | 正面全身、转面、脸部特写等视图；背景、构图、光线、画幅和模型参数 | 回写成角色永久身份或悄悄影响其他任务 |

首轮数据迁移采用兼容投影：保留现存字段和历史 revision；新界面将 `face` 展开成面部子维度用于编辑，保存时先映射回现有字段，待 schema/API 升级后再独立存储。`accessories/weapon` 的旧值继续可读；新 UI 不把它们当基础身份必填项，用户要引用具体物件时进入 `@道具`。**不得让“整段编辑”在未提示、未可撤销的情况下清空逐项字段。** 首个代码切片应先建立显式编辑模式与转换预览，再调整视觉层级。

## 二、词典：平台候选库，文字与效果图并行

词典提供可观察、可改写的设计候选，不是角色事实，也不是自动约束。首批围绕当前古典剧组织，再扩展现代和其他题材。分类与字段对应如下：

| 类别 | 首批词条方向 | 应用目标 |
| --- | --- | --- |
| 题材／画风 | 古典市井、江湖行旅、电影写实、绘本、动漫设定稿 | 设计路由或本次任务风格；项目风格另有 owner |
| 面容 | 脸型、下颌／颧骨、眼型／眼距／眉形、鼻梁／鼻翼／唇形 | 身份视觉设计的对应子维度 |
| 皮肤与标记 | 肤色、毛孔／细纹／日晒质感、雀斑／痣／疤痕／眼圈 | 身份视觉设计；“消除 AI 脸”只是目标，效果需人工验证 |
| 体态 | 比例、肩背、体型、常态站姿 | 稳定体态；动作资产另归表演层 |
| 发型 | 发际线、发色、头发轮廓、束发与发饰结构 | 稳定身份或基础造型，依角色而定 |
| 服装 | 交领／褙子／短衣等版型，棉麻／丝绸等材质，衣物层次与磨损 | 基础造型；剧情伤损归本集状态 |

每个词条至少有稳定 ID、revision、分类、目标字段、可编辑中文描述、同义检索词、来源、许可和审核状态。图像不是原子词条的必备条件；先用组合案例记录“词条 ID/revision 集合＋完整 Prompt＋模型／参数＋效果图媒体 ID＋人工评价”。当前三组古典角色图只作为待审核组合案例，不能作为已确认角色锚点。后续入库需核对生成记录、版权与可见效果。

词典质量分开记录：术语是否准确、描述是否可观察、与字段是否匹配、参考图是否兑现 Prompt、跨图是否保持身份。一次生成通过只证明该张图可用，不证明该词条具有稳定一致性。外部仓库与文章提供分类和工作流参考，具体条目按许可和来源逐项记录；不因仓库整体标注 MIT 就推断所有图片均可再分发。

## 三、参考：搜索、预览、绑定是不同动作

`@` 和“选择参考素材”按钮进入相同的资源发现层，按当前任务推荐，但保留来源与类型筛选：本项目角色包／本集状态、全局素材池、平台参考库、Prompt 案例。`global` 与 `platform_shared` 必须分开展示。结果卡显示标题、类别、来源、许可、revision、是否有媒体、可执行动作；同名资源不得合并。

- **文字词条／Prompt**：先看全文、目标字段与替换范围；确认后插入可编辑草稿，并记录来源。用户改动后标为“已修改”，不能继续标为预设原文。
- **图片／视频**：先看缩图或预览，再选明确变体与用途。设计阶段的参考只进入设计 Skill 的可见输入；生图参考只有用户在本次图片任务选中后才进入模型请求。平台案例图片需要后端稳定导入／绑定接口及许可校验，目前不宣称已可作为生图参考。
- **项目角色包**：搜索展示层级、条目、候选／已确认、锚点 revision 和变体。已确认锚点可以用于派生任务；普通缩图不得冒充母版。
- **失效处理**：下架、无权、变体删除、revision 变化或同名歧义时保留草稿并要求用户重新选择，不按 URL 或名称偷偷替换。

最终模型审核必须把**实际发送的**正负 Prompt、参数、参考图缩图与稳定身份、来源和用户覆写同屏展示。任何来源项都可在发送前修改或移除；只有用户确认才调用模型。

## 四、交互方式：任务切换决定左侧内容

工作台继续使用可展开的浏览器大视图，右侧保留足够大的当前结果图及变体条；左侧跟随当前资产包任务切换。角色档案是可展开依据，不再固定占一列。一个任务只出现一个主要编辑区，避免“身份字段 → 身份视觉值 → AI 润色 → 图片 Prompt”被误解为四次必填。

```text
角色名 / 设计 revision / 草稿状态      [角色档案] [资产包] [关闭]
任务：定义身份 → 确认正面全身锚点 → 派生所需条目
左：当前任务要求、/ 动作、@ 参考、最终可编辑 Prompt、审核入口
右：当前结果大图、候选变体、与锚点并排比对、确认／重做
```

1. **定义身份**：从剧本事实和用户要求开始。`/生成视觉设计草稿` 预览 Skill 输入，确认后才调用设计模型；结果逐项标来源、可编辑。`/插入描述词` 打开词典二级面板；选择只改草稿。`@` 找项目或平台参考；不自动引用参考图。
2. **确认设计**：展示本次身份与基础造型的变更摘要，用户保存形成设计 revision；未确认草稿不投影到图片 Prompt。字段级编辑与整段编辑之间必须可预览、撤销，且不悄悄丢弃另一种输入。
3. **生成锚点**：当前任务默认为正面全身、自然姿态、中性背景；这是任务模板，用户可改。最终 Prompt、负向约束、模型、尺寸和参考图先进入审核；结果为候选，用户并排比较后选定锚点。
4. **派生资产**：按需选择转面、脸部特写、表情、姿态等任务。依赖锚点的任务显示将用哪一版锚点及具体图，用户可以移除或更换，再审核提交。不能因为勾选任务便隐式生成或自动补参考。
5. **剧集使用**：剧集从项目包引用已确认基础造型，可增加正常、受伤、换装等多个 `use_id`。镜头检索实时显示当前可选状态；切换不改写已生成首帧或视频，重新生成由分镜既有流程负责。

`/` 只列当前工位能执行的动作／Skill，`@` 只做上下文资源发现。两个符号均有按钮替代入口；键盘 Tab、上下选择、Enter、Esc、关闭后焦点返回、空结果、加载失败和窄屏浮层都要验收。Settings 中能找到的 Skill 只有经过安装、启用、适用目标和真实调用能力校验后才显示“可执行”。

## 五、输出资产：按需生成，以锚点为根

| 层级 | 可选输出 | 依赖与作用域 |
| --- | --- | --- |
| 身份锚点 | 正面全身锚点；转面三视图；三视图＋脸部特写；身高比例对照 | 项目角色包；正面全身图先由用户确认，其余记录父锚点 revision |
| 表演控制 | 表情表；姿态／体态库；口型辅音表 | 项目角色包的可选派生；由内容需求决定，不要求首日全做 |
| 视觉规范 | 配色规范卡；服装拆解图；道具独立图 | 配色、服装可归角色包；独立道具有自己的资产身份，角色包保存引用 |
| 环境融合 | 妆造定妆照；破损／状态变化图 | 场景、剧集或镜头作用域的派生，不回写项目级基础身份 |

资产记录至少能追到 `project_id/character_id/pack_id/pack_revision/layer/kind/entry_id/variant_id`、设计 revision、父锚点 revision、来源参考、最终 Prompt、模型参数和确认人。未生成的条目显示“未创建”；生成图显示“候选”；只有用户确认的图显示“已选／锚点”。更换锚点保留历史和依赖来源，并提示受影响的派生条目；不静默批量重生。

“一张图同时容纳三视图、表情、服装拆解、色板和世界观文字”可作为**概念沟通页**模板，但不替代这些独立条目：其中的小图、中文标注和色值需要人工核对，不能自动当作精确的转面、表情或配色规范。

## 实施顺序与验收

| 切片 | 目标 | 完成判据 |
| --- | --- | --- |
| 1. 输入不丢失 | 合并重复输入心智模型；整段与逐项编辑显式切换、预览和撤销；基础界面移走固定武器／配件负担 | 切换编辑方式不会无提示清空已填内容；旧 revision 可读；用户只需一个主要输入区 |
| 2. 任务化左侧 | 按身份设计、锚点、派生任务切换左侧设置；右侧保持大图、变体和比对 | 1440×900 能看清主图及本次 Prompt；375px 无水平溢出；切任务保留草稿 |
| 3. 词典与参考 | 首批古典词条、来源与许可；`/` 动作二级词典；`@` 分来源搜索与预览 | 搜索能找到面部、皮肤、发型、服装词条及已发布 Prompt；只插文字不附图；取消不改草稿 |
| 4. 锚点闭环 | 设计 revision → 审核生图 → 候选比较 → 用户确认锚点 | 请求与审核一致；确认前不得在检索中标“锚点”；历史变体和来源可追溯 |
| 5. 派生资产包 | 分层任务、明确父锚点、按需生成、过期提示 | 转面／表情等条目能追溯所用锚点；锚点换版不会改写历史结果 |
| 6. 剧集状态衔接 | 项目包作为来源，本集多造型和分镜实时检索 | 同一集正常与受伤造型可分别选择；既有首帧和视频不自动变化 |

切片 1 是本轮代码起点。涉及 schema、后端生成和资产包的切片应先写对应数据契约与兼容测试，保持每一步可构建、可回退。实施路径：`frontend/src/components/modules/CharacterWorkbench.tsx`、`CharacterSlashPanel.tsx`、`frontend/src/lib/characterStructuredDesign.ts`／`characterQuickActions.ts`、共享资源选择器、相关前端测试；后续切片再涉及角色资产模型与 API。

## Not yet proven / What would verify it

- 词条和参考图对“AI 脸”及跨视角一致性的改善需要同角色、多次生成、人工并排判读；当前样本不足以证明。
- 任务化左侧和统一搜索是否减少输入次数，需要在真实浏览器上用当前古典剧的一个角色完成“定义身份 → 找面部词条 → 引用项目图 → 确认锚点”的计时与错误记录。
- 资产包四层、多造型和平台媒体导入目前是目标契约；各接口、许可和历史数据迁移必须在相应切片实施并验证后才能标为完成。
