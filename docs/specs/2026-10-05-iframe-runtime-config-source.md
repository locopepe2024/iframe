# iFrame 主机运行配置来源

## 决定

- 生产后端的环境变量以主机 `/srv/lumenx/runtime/iframe-backend.env` 为持久配置源。该文件不进入 Git、镜像或静态资源，目录权限为 `0700`，文件权限为 `0600`，由部署账号持有。
- `scripts/deploy_server_release.py` 必须在构建前校验该文件，并以 `docker create --env-file` 直接读取它。文件缺失、权限过宽或格式错误时停止发布；不得回退为 `docker inspect` 旧容器的环境变量。
- 现有容器仅用于一次性迁移：从其创建环境去掉与镜像默认环境完全相同的项，原样写入受保护文件。迁移工具拒绝覆盖已有文件，也不打印变量值。完成迁移后，以该文件为后续人工修改和恢复的来源。
- 发布脚本仍可从旧容器读取网络、端口和挂载拓扑用于当前兼容部署；这些不是凭据来源。版本检查、健康检查和失败回滚维持现有行为。

## 主机操作

- 一次性迁移：`python3 scripts/server_runtime_env.py bootstrap --path /srv/lumenx/runtime/iframe-backend.env`。仅在文件不存在时执行；不会覆盖已有配置。
- 发布前校验：`python3 scripts/server_runtime_env.py validate --path /srv/lumenx/runtime/iframe-backend.env`。输出只含变量数量和路径，不显示值。
- 正式发布使用仓库更新后的 `scripts/deploy_server_release.py`，其配置路径相对于实际部署根目录推导。历史 `deploy-iframe-*.sh` 是一次性发布记录，不再作为新版本的发布入口。
- 人工修改配置时使用主机上的受控编辑流程，保持目录 `0700`、文件 `0600` 和部署账号所有权；修改后重新校验。不要把配置文件复制到仓库或工单。迁移旧主机前，先通过受控备份渠道保存此文件；不要在确认备份前清理旧容器。

## 成功条件

1. 已有运行配置能一次性迁入主机文件，且变量名集合与去除镜像默认项后的运行容器一致。
2. 发布在配置文件缺失、格式异常或权限过宽时，于构建前失败。
3. 下一次由更新后的通用脚本发布时，新容器的应用配置只来自持久文件；旧容器的 `Config.Env` 不参与部署。
4. 迁移、校验和测试输出都不包含变量值；当前运行容器和静态资源无需替换。

## 边界

此变更不追认最初的密钥来源，也不修改 UniArt、UniFlow、UniRoute。历史一次性部署脚本保留作审计记录，不作为以后发布的入口。配置文件的备份和密钥轮换需要由主机管理流程负责。
