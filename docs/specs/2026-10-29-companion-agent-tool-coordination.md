# 小安统一任务与工具协调

## 已核实的边界

- 云端 Qwen 通过个人 UniArt 渠道提出一个结构化工具调用；服务端校验、执行并持久化结果。当前不是多步工具循环。
- 主机协调器返回只读焦点建议，不执行工具；不是第二份任务状态。
- OpenTalking 使用 `agent_enabled=false`、`render_text=true` 播放主 Agent 的结果，不应再独立理解用户和改写回复。
- 当前缺陷：相册/上传的固定分类会抢先处理活动创作中的回答；工具缺少打开上传/选择素材动作；因此模型即使理解“我要上传”也不能完整执行。

## 本次切片

自然语言由 Qwen 理解，不扩充句式正则。当前活动任务存在时，上传/相册回答同样送给 Qwen，携带服务端任务 ID、revision、step、已有 brief 和素材。工具提供 `open_upload` / `open_album`；点击和工具使用同一上传、选择、保存接口。

工具返回 UI 意图和真实任务回执。`open_upload` 仅打开待用户选择的上传卡片，浏览器文件选择器由用户点击；不能声称上传成功。`open_album` 打开当前任务的相册选择器，选中后通过现有版本化素材绑定接口执行。导航不改草稿 revision；业务修改仍检查版本与归属。

每轮只执行一次工具，返回确定的卡片和简短回执供 OpenTalking 播放。不要为每次导航再调用第二个模型。复杂需求的多步循环另设上限、操作日志与暂停点；付费生成、删除、保存等确认边界继续保留。

## 后续完整编排目标

统一快照应包括：会话最近对话、当前界面焦点/选中素材、活动及暂停任务、待用户确认操作、工具能力和最近执行回执。主机模型只能建议焦点；云端 Qwen 为唯一语义规划者；服务端为任务状态和执行结果的唯一写入方。前端把上传/选图/取消等真实事件回报任务，不能靠模型从历史猜测页面是否成功。

验收分两层：模拟模型工具调用验证运行时确定性；真实 Qwen 多轮语料验证语义理解，分别统计启动、改口、选择来源、素材绑定、补充要求、取消、恢复、过期版本与失败重试。两层通过前不宣称真实语音闭环完成。

## 对话中的能力缺口（下一切片）

新增受限的缺口记录工具，不允许模型自动创建或执行接口。记录字段：当前消息 ID（服务端取原话）、任务 ID/step、用户希望的操作、现有工具不足的原因、建议输入/输出与用户可采用的替代步骤。按用户和操作归并，保留发生次数与来源消息；不复制全库照片或密钥。没有相应工具时明确说明，不能伪装已完成。

工具未注册属于能力缺口；鉴权、版本过期、网络错误、工具参数不合法属于运行失败。两类分别统计，避免因模型调用错误而新建重复工具。此工具本片尚未实现，不能声称已开始自动收集。
