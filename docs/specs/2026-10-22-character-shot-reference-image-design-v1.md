# 角色镜头参考图设计 V1

日期：2026-10-22。状态：设计确认，暂缓实施。先完成角色面板/词典、分镜结构化一致性，以及分镜风格/运镜/机位的优化，再实施本规格的图片编辑入口与蒙板链路。本规格只覆盖分镜中的角色静态参考图；视频微表情时序 Skill 另行设计。

## Observed

- 已确认角色设计 revision 持有稳定身份与造型；图片变体有独立媒体身份。选择一张图片作参考，不等于采用该角色的未确认设计草稿。
- 已确认场景设计 revision 持有空间、环境光、风格和基准视点；当前分镜持有局部机位、构图、动作与首帧。分镜参考包可保存已确认首帧及显式选择的角色、场景和道具变体。
- 现有角色静态表情模板以眉部、眼睑、视线、嘴部、下颌状态、面部气色六个可选字段组成；其配置是词典快照和提示词文字，尚非独立后端表情 schema。
- 本地《AI人物微表情词典》的五层为身份锚定、情绪基调、肌肉运动、时序编排、环境联动；毫米、秒数及跨模型效果主张缺少可复核实验，不能当作静态出图能力保证。
- 共享图片编辑器目前提供裁切、调色、标注等本地像素编辑；标注结果不是 AI 蒙板。UniArt 图片适配器已有 `mask` URL 提交能力，但 Studio 尚无蒙板绘制、保存、与角色镜头编辑请求贯通的流程。

## 目标与归属

为当前分镜生成一张可审核的角色镜头参考图，表示角色在**这一帧**的可见状态。已确认的基础角色锚点图像是脸、发型、识别特征及图中已确认服装的主要视觉依据；配套结构化角色版本说明这些特征的语义和适用造型。空间与背景由场景锚点图像及已确认场景版本负责，不能把角色母版的白底当作镜头背景。景别、机位、站位、姿态、视线、瞬时表情及明确的局部遮挡来自当前分镜。若当前镜头需要换装或伤势，应先选择相应已确认造型/状态锚点，或显式建立并审核镜头状态，不能把变化暗写回角色母版。

一张首帧可能有多个角色。每个角色分别绑定其身份/造型 revision、实际参考图片变体、镜头位置及面部状态；不能用一个角色的表情字段覆盖整镜人物。

## 结构化输入

| 字段组 | 来源与编辑规则 |
| --- | --- |
| 角色锚点 | 每个入镜角色必须显式选择已确认的基础角色锚点图像，或已确认的当前造型/状态锚点图像，并绑定其角色设计 revision 与实际媒体变体。生成镜头角色参考图时缺少该图像应阻止提交，不以文字描述代替，也不暗中附加另一张图。 |
| 场景锚点 | 显式选择已确认场景设计 revision 及用于背景连续性的场景图像变体；显示空间、风格、光线和基准视点的来源。背景有视觉一致性要求时，不能仅凭角色锚点图像或场景文字声称已锁定背景。 |
| 当前镜头 | 当前分镜快照中的景别、机位、构图、角色站位/姿态、视线及局部遮挡；明确的镜头覆盖只影响本镜。 |
| 静态表情 | 情绪标签仅作选择入口；输出当前帧可见的眉部、眼睑、视线、嘴部、下颌和临时气色。空字段不输出；不把瞬时嘴角状态写入永久唇形。 |
| 修改范围 | 每次编辑保存可改字段、保护字段及来源快照。只改表情时，身份、服装、场景、光照、机位和已选参考变体保持原值；用户显式解除保护时记录本次覆盖。 |

词典的“部位 × 描述维度”负责选项归类；五层方法只用于组织输入：身份锚定引用角色版本，情绪基调是意图，可见面部状态是本帧表现，环境联动引用场景与镜头。**时序编排不进入本规格**；“随后落泪”“0–3 秒形成”、呼吸节奏、对白和声音不进入静态参考图请求。

## 预览、生成与版本

1. 用户选择当前分镜及每个角色的基础/当前造型锚点图像，查看场景图像、镜头和角色版本的来源；再选择或修改本帧表情。缺少角色锚点时阻止生成；缺少明确场景来源时显示待选择，不根据名称、相邻镜头或故事语义猜绑定。
2. AI 优化和出图前，组装带来源的可见输入预览：本次修改、保持不变、最终提示词、实际参考图缩图/变体、设计 revisions、冲突与过期状态。用户可逐项决定采用、覆盖或移除。文本中的 `@` 只能解析已加入当前参考列表的素材。
3. 预览确认后提交与预览一致的文字和媒体身份。来源 revision、分镜字段或参考变体在确认后变化，应使待提交预览失效；不静默重写已生成图片或已确认首帧。
4. 候选图片记录父分镜 revision、各角色及场景的已确认设计 revisions、实际媒体变体、结构化字段快照、最终提交文本、模型请求和生成结果。用户审核并确认后，才成为该分镜的首帧/镜头参考图；不反向覆盖角色或场景母版。旧候选保留其原始来源。

## 局部表情编辑

首次合成镜头图时，角色锚点和场景锚点作为视觉参考；此时没有现成的完整镜头底图，不能声称仅凭多图参考已锁住全部像素。得到镜头候选后，用户从该候选发起局部编辑：**候选镜头图作底图，用户绘制的面部区域作独立蒙板，静态表情字段作编辑指令**。角色锚点仍作为身份与适用服装的参考图；其他角色和场景由底图承担保持依据。若只以白底角色锚点作底图，便无法用蒙板保护尚不存在的镜头背景。

角色工作台可以承载这一编辑入口及角色语义，但应复用共享画布能力；镜头候选、蒙板和编辑结果仍归当前分镜。蒙板须与底图尺寸/方向对齐，清楚标出可修改区域；保存底图变体、蒙板媒体身份、目标角色、可改表情字段、保护范围、模型和实际请求。蒙板绘制与普通标注分开，不能把画在图上的彩色笔迹当作蒙板。提交前预览底图、半透明蒙板、角色锚点和最终指令；蒙板为空、超出有效范围、底图/角色版本已变或所选模型不支持蒙板时阻止局部编辑提交。

生成结果作为新候选，不直接覆盖底图或已确认首帧。审核时同时比较蒙板内目标表情是否达成，以及蒙板外脸部其余区域、服装、其他角色、背景和光影是否保持。蒙板与底图能收窄预期修改范围，但模型是否严格保持蒙板外像素，仍取决于具体模型与请求语义，需以实际结果验证。

## 角色工作台图片编辑入口

角色工作台顶部增加“图片编辑”横幅入口。进入后先显示当前所选图片缩图、来源版本和保存归属，并允许在已选角色资产变体与当前分镜镜头图之间明确切换。未选择底图时展示选择操作，不默认取图库中的最新图片，也不根据提示词中的名称推断底图。

编辑区复用共享画布能力，但将两项操作明确分开：

- **蒙板**：用户涂选允许 AI 改动的区域；提供画笔大小、擦除、撤销/重做和清空，并以半透明覆盖预览实际将提交的独立蒙板。仅支持经目标模型验证的蒙板语义与图片编辑模式。
- **标注**：箭头、圈选、形状和文字用于表达修改意见；标注不能自动充当蒙板。用户明确选择“导出带标注图片”时才把笔迹写入图片像素，否则标注作为可审核说明随候选保存，不污染角色锚点或镜头底图。

右侧保留当前参考图列表、可编辑表情/局部指令和最终请求预览。提交按钮须区分“保存本地编辑副本”和“AI 局部编辑”，并根据所选底图启用可用操作。结果先进入候选对比；以角色资产为底图的结果保存为角色资产候选，以当前分镜图为底图的结果保存为当前分镜候选。设为角色锚点或确认分镜首帧均需单独审核动作，不能由编辑器保存动作隐式完成。

## 验收

- 同一角色在两个镜头采用不同表情时，角色稳定身份和造型 revision 不变；每个镜头保存各自的表情与图片候选。
- 在同一镜头只调整表情，保存值及实际请求中的角色身份、服装、场景、光照、机位和参考变体身份不变；临时嘴角状态不会覆盖稳定唇形。
- 多角色镜头只修改选中角色的面部状态；其他角色不受影响。
- 未显式选择、未确认或已过期的来源不得静默进入请求；预览所列文字与媒体和实际提交一致，来源变化使待提交预览失效。
- 每个入镜角色的已确认锚点图像确实进入实际模型请求；背景连续性所选的场景锚点图像也确实进入请求。仅保存变体 ID 或在界面显示缩图不足以证明已提交给模型。
- 静态请求不含视频时段、表情过渡、对白、声音或前镜动作。确认镜头图片不修改上游资产版本。
- 图片审核以实际提交的角色锚点图像检查脸、发型与适用服装，以场景锚点图像检查背景、空间与光影。锚点图像是视觉一致性的主要控制输入；提交了锚点也不能直接证明模型结果零漂移，仍须审核候选。
- 局部编辑请求中实际包含所选镜头候选底图、对齐的独立蒙板、目标角色锚点及本次表情指令；修改底图/蒙板或版本后旧预览失效。审核同时比较蒙板内目标和蒙板外保持情况。
- 角色工作台入口能区分角色图与分镜图；标注不会作为蒙板提交，未选择“导出带标注图片”时也不会被烘焙进底图。两个保存归属各自产生新候选，原图及上游确认版本不变。

## 实施边界与验证

先核对目标 UniArt SKU 的蒙板语义、尺寸/透明度要求和多参考图组合能力，并用一张固定镜头底图验证蒙板内外行为。再以单镜头、单角色完成蒙板绘制/上传、可见预览、局部生成候选与行为测试；随后覆盖多角色与镜头状态。沿用现有角色设计、场景设计、分镜参考包和预览确认机制；不建立第二套角色身份 owner，也不在本切片实现视频微表情 Skill。

实现前核对的路径：`frontend/src/components/modules/CharacterWorkbench.tsx`、分镜参考包/首帧编辑组件、`frontend/src/lib/characterExpressionPrompts.ts`、`src/apps/comic_gen/models.py`、`src/apps/comic_gen/pipeline.py` 及相关 API/测试。行为验证需覆盖上述验收中的请求等价、版本失效和上游不变；真实生成候选需人工对照参考图，不能由单元测试宣称视觉一致性。
