# Atelier Agent Chat 老人陪护技能配置 v0

日期：2026-10-07
状态：v1 记忆扩展待管理员审查

后续 Demo 的完整需求与验收路径见 [iFrame 创作台老人陪伴 Agent Chat Demo 需求 v1](2026-10-07-elder-companion-agent-chat-demo-v1.md)。

## 目标

在 iFrame 创作台（Playground）的 Agent Chat 中提供可选的老人陪护技能配置，覆盖：

- 温和、尊重、简短的情感倾听和主动话题引导
- 经用户确认的跨会话记忆与用户画像
- 日程整理与提醒表达
- 成语接龙、猜谜、新闻/经典内容等认知刺激和娱乐互动

## 当前范围

1. Agent Chat composer 增加“陪护技能”入口，可启用/停用陪护提示词模板。
2. 支持四类技能开关：记忆与画像、倾听与话题引导、日程与备忘、认知与娱乐。
3. 启用的技能 ID 随每条消息发送到后端，由服务端模板追加到固定 system prompt。
4. 在 assistant chat system prompt 中保留现有“只做创作提示词和规划，不执行生成”的安全边界；陪护指令只在陪护模式下追加。
5. 日程功能仅识别整理并输出建议清单，未接入日历、系统通知或闹钟时不得声称已设定/会主动提醒。

## 隐私与能力边界

- 记忆提取只产生候选；生日、健康信息、家人信息等必须由用户逐条确认后才写入跨会话记忆。
- 每条记忆可查看、编辑、删除；只在同一 `owner_profile_id` 下读取和注入。
- 涉及健康或投资问题时，给出一般性、非诊断/非投资建议，并建议咨询专业人士或家人。
- 陪伴表达须温和，但不得鼓励老人疏远现实社交支持。
- 新闻、歌曲、戏曲播放属于对话建议；没有接入内容服务时不得声称已播放。

## 接口契约

- 前端 `POST /agent/sessions/{sid}/messages` 增加可选字段 `companion_skills: string[]`，只能包含四个已注册的技能 ID。
- 后端校验 ID，由服务端固定模板生成 system prompt 附加指令，不作为 user 消息或对话记忆保存。
- 请求缺省或空字符串时维持现有行为。

## 跨会话记忆 v1

- `GET /agent/memories`：列出当前 owner 已确认记忆。
- `POST /agent/memories/extract`：对当前 owner 的已保存用户消息，按明确自述句式（“我喜欢…”、“我叫…”、“我的生日是…”）提取最多 3 条候选；候选必须带原文片段，接口不写入记忆。此规则覆盖有限，不推断隐含事实。
- `POST /agent/memories`：用户确认候选后保存；服务端验证原文片段来自对应消息，并记录来源会话、消息 ID、分类、创建/更新时间。
- `PATCH /agent/memories/{id}` 和 `DELETE /agent/memories/{id}`：编辑/删除已确认记忆。
- 仅普通 Chat 且请求启用 `memory` 技能时，将当前 owner 的有界已确认记忆作为数据上下文送入 system prompt。H3 提示词优化路径不接收陪护记忆。
- 启用记忆技能后，每轮成功回复自动刷新候选，也可手动从最近历史提取；提取错误只影响候选提示，不影响已成功的聊天回复，候选绝不自动保存。
- 删除来源消息或来源会话时，同步删除依附其上的已确认记忆，避免无来源事实继续参与回答。
- 记忆容量限制为每 owner 100 条、每条 300 字；候选只扫描最近 20 个会话各自最近 30 条消息，并验证原文片段确实属于来源消息。

## 验收标准

- Agent Chat 中可访问陪护技能配置，四个技能可分别启停。
- 发送消息时只传当前启用技能的指令；配置状态对用户可见。
- 后端将该指令追加到 system prompt，常规 Agent Chat 不受影响。
- 未知或重复技能 ID 被服务端拒绝，客户端不能注入任意 system 指令。
- UI 明确表示只有经确认的记忆跨会话使用；真实日历/闹钟提醒和媒体播放仍未接入。
- 通过前端类型检查、相关 Agent Chat 测试及后端对应测试。

## 后续版本

日历/提醒和新闻/媒体服务应先明确服务端能力与授权契约，再实现真实操作。记忆 v1 使用明确确认和手动删除；自动到期、批量导出与加密存储待后续评估。
