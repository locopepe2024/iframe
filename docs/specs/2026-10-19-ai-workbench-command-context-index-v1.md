# AI 工位的 `/`、`@` 与分镜 `[]` 语义 V1

日期：2026-10-19。范围：角色、场景、道具、分镜、创作台的 AI 输入交互，以及分镜项目资产索引。此文统一符号语义；各工位的可执行命令、资源类型和模型能力仍需分别声明。

> 当前符号约定以 `2026-10-19-prompt-dictionary-skill-entry-v3.md` 为准：`/` 词典和 Skill，`@` 资产。下文旧案例通过 @ 插入的记录已被替代。

## Observed

- 角色工作台已有 `/` 快捷面板、图片 Prompt `@` 变体引用和模型输入审核。平台目录已有发布资源与 Prompt 文本，但平台媒体尚无直接导入当前项目作为模型参考的 API。
- 分镜前端已识别 `[character:name]`、`[scene:name]`、`[prop:name]` 与旧 `[characterN:name]` 标签；提交时解析项目素材、所选变体和图片序号。此前通用标签仅按名称解析，同名跨类型资产可能串用；本次实现让三种通用标签按类型＋名称匹配。
- Settings 的 Skill 目录与工作台可执行 Skill 不是同一个集合。安装或能被搜索到，不证明当前工位已经支持调用。

## Direct implication：统一语法，保留工位能力边界

| 符号 | 通用意图 | 角色／场景／道具 | 分镜增量 |
| --- | --- | --- | --- |
| `/` | 检索词典和 Skill | 角色词条、组合方案、Prompt 案例及实际可执行 Skill；预览后插入文字或审核 Skill 输入 | 润色分镜、编排运镜、生成首帧／视频等已实现命令 |
| `@` | 检索可引用资产 | 角色、场景、道具和可绑定的媒体变体；不插入词典、Prompt 案例文字或 Skill | 同样可引用平台与项目资源，入口应共享 |
| `[]` | 当前分镜内的**项目资产索引槽位** | 默认不要求使用 | `[character:name]`、`[scene:name]`、`[prop:name]` 明确镜头指向的项目资产类型；`characterN` 暂为历史兼容 |

`@` 是发现和选择资源的操作入口；`[]` 是分镜提示词中已绑定的项目角色／场景／道具索引。二者可以指向同一项目资产，但职责不同：`@` 让用户找到并选择，`[]` 让镜头文本明确引用哪个类型的资产。平台 Prompt 通过 `/` 预览并插入后成为可编辑文字；`@` 只建立资产引用，不能把原始 `@名称` 未解析文本当作模型引用。平台图片只在有明确导入／绑定和审核能力时允许“作为参考图”。

`[]` 的解析必须按类型和项目身份校验。名称只用于显示和输入匹配，最终请求须冻结资产 ID、revision、选中变体 ID 与实际图片顺序；同名跨类型结果不得互相代替。同名同类型多资产若无法消歧，应要求用户选择稳定 ID。`[characterN:name]` 在现有项目中曾作为编号槽位使用，可能引用非角色素材；先保留兼容读取，显示为旧语法，新增输入优先使用类型正确的通用标签。是否迁移历史 Prompt 需以存量数据和提交日志验证。

## 工作台共享选择器的合同

1. 输入位置决定默认槽位和推荐结果，但“全部来源”始终可切换。检索按项目、本集、全局素材、平台参考和可执行 Skill 标明来源，不把全局素材混成平台发布库。
2. 搜索命中只打开预览。资源卡展示类型、稳定 ID／revision、来源、许可、缩图或无媒体、可用动作。用户点击具体动作后才修改草稿或绑定素材。
3. 选择 Prompt 显示全文和插入位置；选择媒体显示变体和用途；选择 Skill 显示即将使用的输入与实际工位能力。最终模型审核同时展示文本、引用、参数及来源。取消不改变模型请求。
4. 失败、下架、失效 revision 或权限不足时保留原草稿，提示受影响项；不得悄悄换用同名资源或旧图片。重新生成形成新候选，不覆盖已确认资产。
5. `/`、`@`、`[]` 均提供按钮／搜索替代入口，支持键盘焦点、Esc 返回、空结果和小屏可操作；快捷符号不是唯一操作方式。

## 实施状态与顺序

- 已有基础：角色 `/` 双 Skill 动作、项目图片 `@`、分镜 `[]` 标签和提交审核。
- 当前切片：角色图片 Prompt `/` 直接检索词条、组合、案例和 Skill；`@` 只检索已有资产引用。侧栏结构化字段选择器保留。分镜通用 `[]` 按类型＋名称解析；平台案例图片只预览，不进入模型参考。
- 后续共享化：把角色以外的工位接入相同的命令／资源发现组件和服务端动作能力表；提供平台媒体导入项目、稳定引用与审查；再把分镜 `[]` 从名称解析升级为稳定资产 ID 绑定。

## Not yet proven / What would verify it

- 当前只有角色工位接入本轮平台 Prompt 选择；“所有 AI 工位都能用同样入口”仍是设计目标，需逐工位确认真实命令与资源能力。
- 平台资源和 Skill 的跨目录搜索尚无统一 API；可用性收益须用角色、场景和分镜任务实测。
- 分镜旧 `[characterN:name]` 的历史使用范围和自动迁移安全性尚未统计，不能仅凭代码命名认定全部指向角色。
