# 场景资产提取 Skill V1

## 状态

后端资产设计草稿合同 V1 已实施。本 Skill 也适用于剧本“提取实体”的初始场景草稿；它不负责当前分镜的人物调度或动作编排。

## 目标

将“长街中段粮铺”提取为可复用场景资产，并把当前镜头的劫掠事件、人物选择、站位、前中后景和镜头构图留在分镜层。

## 强制分层

### 场景资产层

- 场景身份与主题
- 固定空间结构
- 固定物体与地标
- 材质、环境和空间纵深
- 可确认的默认时间基线
- 可确认的世界光影基线
- 可复用构图倾向
- 场景级禁止项

### 分镜层

- 当前镜头事件和动作
- 当前镜头角色、群众和道具选择
- 人物具体站位、朝向和前中后景
- 当前镜头景别、机位、运镜和构图覆盖
- 当前镜头局部光影覆盖
- 当前镜头时长、节奏和声音

## 禁止写入场景资产

- “正在劫掠”“准备劈砍”等当前事件
- 具体角色 ID、附件引用或人物数量
- 近景/中景/远景中的临时人物分配
- 当前镜头的左三分、右三分或中心站位
- 当前动作、受力链、对白和临时道具状态

## 输出要求

场景提取结果必须返回结构化字段和可见摘要。当前后端合同为 `asset_baseline`、`shot_only_content`、`visual_notes` 和 `uncertainties`；`visual_notes` 只能作为兼容摘要，不能重新成为第二套权威值。无法确认的时间、光影或构图应标记为建议或未确认，不得从当前分镜事件推断为场景事实。

初始实体提取在预览、修订和应用时保留这些字段。应用后仅写入 `Scene.asset_design.design_draft`；不得创建 `design_revisions`，因为实体提取确认不等于场景视觉设计确认。`Scene.description` 由基线的地点、固定结构及环境生成，不复制临时事件。场景设计台确认后才生成正式版本，正式分镜投影仍以已确认版本为准。与拍摄计划同步只处理需求、绑定和视觉上下文，不覆盖场景设计草稿。

## 验收样例

输入包含“长街中段粮铺、门前劫掠、百姓退让、黄昏、人物近中远景分配”时：

- 场景资产只保留粮铺、长街、固定物件、黄昏基线和参考光影。
- 劫掠、百姓退让、人物引用和前中后景分配必须留在分镜结果。
- 生成场景资产的复用提示词不能要求固定出现这些临时人物。

青溪镇样例中，用户已确认苏砚所在的梧桐树街角，与江灼惩戒打手、卖艺少女受欺凌的另一处街角是不同物理地点。两者必须分别提取；第二处缺少已知固定地标时只记录地点身份和不确定性，不把打斗、人物或假设的摊位写进资产基线。江灼走入长街后与苏砚交手，复用长街资产。

合并候选场景时应核对人物交集、地标、明确的空间指代、移动路径和时间关系。苏砚与江灼分别出现在两个街角且无同址证据，是禁止仅按“街角”名称合并的信号；人物交集或不交集本身都不是充分条件。

实测四场景草稿仍将“另一处街角”仅放进长街的 `shot_only_content`，并把两个街角是否重合留作疑问。后续规则要求把该处保留为第五个地点候选；用户已确认异址时不再输出相反的不确定性。用户还确认阁楼屋檐能看到粮铺门前的交手区域：阁楼基线记录从屋檐可望见粮铺门前，粮铺基线对应记录从粮铺门前朝阁楼方向可见屋檐。该双向空间视线属于两处地点的稳定基线，不要求每个分镜都拍到对方；具体距离、高度、精确朝向和遮挡仍待核对。地点身份不得包含“探子潜伏”或“匪寇围堵”等事件。

实体提取任务的去重键必须包含当前默认提取模板和场景 Skill 内容的版本；更新规则后，同一剧本可重新生成草稿，不复用旧任务。现有待确认草稿不自动改写，作者可通过界面修订明确两处街角及阁楼视线后再应用。
