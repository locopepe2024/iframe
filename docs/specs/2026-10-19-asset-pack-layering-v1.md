# 角色、场景、道具资产包分层规范 V1

日期：2026-10-19。状态：设计确认，尚未作为独立迁移发布。

## 目标

将角色设计面板中的长文本字段，收敛为可审核、可复用、可检索的结构化资产包。角色、场景和道具使用同一套分层原则，但每类资产只启用适用层级。

## 通用层级

| 层级 | 作用 | 角色 | 场景 | 道具 |
|---|---|---|---|---|
| 身份锚点层 | 确定资产是谁或是什么 | 正面全身、三视图、脸部特写 | 空间母版、全景、主要入口 | 主视图、结构拆解 |
| 结构视觉层 | 稳定外观、结构和材质 | 服装、配色、材质 | 建筑结构、材质、环境色、主光方向 | 材质、尺寸、结构、配色 |
| 控制层 | 说明如何变化、使用或拍摄 | 表情、姿态、口型 | 视角、机位、空间轴线 | 开合、使用姿态、功能状态 |
| 状态变体层 | 表达剧情或使用状态 | 受伤、战损、换装 | 日夜、天气、破坏状态 | 损坏、使用中、收纳、变形 |
| 融合参考层 | 说明如何进入具体画面 | 妆造、动作参考 | 人物占位、局部镜头、气氛参考 | 手持、桌面、环境摆放 |

## 角色边界

角色基础身份只保存稳定身份锚点和基础视觉设计：

- 年龄阶段和体态轮廓；
- 面部、发型、肤色和少量识别锚点；
- 基础服装语言、主色、材质和妆造方向。

服装变化、受伤、战损和换装必须形成独立的造型变体，并通过 revision 和人工确认管理。

配件和武器不再作为默认的角色长文本字段。它们属于道具资产，角色只保存显式绑定：

```text
角色 → 道具资产 → 变体 → 作用域
```

## 妆造定妆照与环境融合图

妆造定妆照、环境融合图不属于角色基础身份，不得写入角色锚点或基础视觉值。它们只能作为：

- 场景作用域的角色融合参考；
- 当前镜头的构图、光影或表演参考；
- 已确认造型变体的派生媒体。

它们可以引用角色身份和造型变体，但不能反向改写角色身份。

## 依赖和提交边界

基准图是衍生资产的生成依赖。系统可以在资产包中显示“基准·自动包含”，但不得因此把依赖图片静默附加到模型请求。最终发送的参考图必须由用户显式选择，并在提交前预览。

## 迁移原则

旧版 `identity.features` 和 `look.features` 保留读取兼容。新界面逐步将：

- `accessories`、`weapon` 迁移为道具绑定；
- 妆造定妆照、环境融合图迁移为场景／镜头派生参考；
- 角色长文本收敛为身份锚点、基础视觉设计和造型变体。

迁移不重写历史 revision，也不自动改变已有分镜、首帧或视频的参考图。

## 角色工作台交互

角色工作台采用资产包驱动的创建流程，不再将完整角色描述固定在左侧并长期占用主工作区：

```text
创建角色
  → 选择或生成身份锚点
  → 确认基础视觉设计
  → 选择资产包内容
  → 生成并审核变体
  → 绑定道具
  → 保存角色 revision
```

布局契约：

- 中间区域显示当前角色资产包和变体卡片；
- 右侧设置面板跟随当前资产包项目切换，显示该项目的参考库、结构化参数和生成操作；
- 左侧只保留可收起的角色上下文，包括原始描述、剧本事实、来源和 revision；
- 顶部显示角色名称、身份锚点状态、视觉设计状态和本集造型数量；
- 完整提示词、参考图清单和提交按钮只出现在当前生成任务的审核视图中。

参考库、上传和 AI 生成是同一资产包项目的三种输入方式。参考库候选不会因为被浏览或被模板列出而自动进入模型请求；只有用户选择并确认后才进入当前草稿和提交预览。生成结果以新变体保存，不能覆盖已确认 revision。

该交互模式可复用于场景和道具工作台，只替换资产包层级和右侧设置内容。

## 外部角色设计工作流对照

用户提供的 Lovart 角色设计文章强调了四类可迁移机制：

1. **角色 brief 合同**：稳定的角色 ID、参考图、视图、表情、服装规范和禁用项；
2. **转面图与表情表**：分别约束角度一致性和情绪变化后的人物识别；
3. **Brand Kit**：锁定颜色、服装配色和标志性元素；
4. **发布前匹配测试**：将新图与基准图并排检查，而不是只凭单张图判断。

这些机制可映射到 iFrame：

| 外部概念 | iFrame 对应 |
|---|---|
| brief 合同 | 角色身份锚点、基础视觉设计 revision、禁用项和来源记录 |
| 转面图 | 角色身份锚点层的多视角资产 |
| 表情表 | 表演控制层的表情资产 |
| Brand Kit | 基础视觉设计中的色板、材质、标志性视觉值 |
| 匹配测试 | 资产提交前的人工审核与后续一致性检查 |

### 需要保留的边界

外部文章将 Brand Kit 描述为每次自动强制应用的系统约束。iFrame 不允许把这些约束静默拼接到提示词后：

- 结构化视觉值必须显示来源、revision 和作用域；
- 用户可以修改或移除当前资产包继承的视觉值；
- 参考图只能在用户显式选择后进入提交预览；
- 禁用项必须在审核视图中可见，不能作为隐藏负向提示词；
- 最终请求只能包含审核视图中展示并确认的文本、参数和媒体。

### 最小可用角色系统

不要求一次生成完整资产包。最低可用系统是：

```text
一张确认的身份锚点图
+ 至少三视角参考
+ 一个基础视觉设计 revision
+ 一个可复用造型变体
+ 一次提交前匹配审核
```

表情、姿态、口型、配色卡和服装拆解按内容需求逐步补充。参考图应少而明确，避免把风格混杂或互相冲突的图片一次性提交给模型。

## 角色字段作用域对照

参考外部角色创建流程中的基础信息、肤色、妆容、面部特征、体型、发型、姿势、服装和场景字段，iFrame 采用以下边界：

| 字段 | 归属 | 规则 |
|---|---|---|
| 族裔／文化背景、性别、年龄阶段 | 身份事实 | 只能由用户明确提供或确认，模型不得从姓名或图片自动推断 |
| 肤色、肤质、面部特征、体型、基础发型 | 身份锚点 | 形成角色稳定识别值，可进入角色 revision |
| 妆容、服装风格、主色、材质 | 基础视觉／造型变体 | 基础值与当前造型状态分开保存 |
| 表情、姿势、动作 | 表演控制／分镜 | 不写入角色基础身份；按表演资产或镜头字段保存 |
| 场景角度、机位、光线、色调 | 场景／分镜 | 不属于角色资产；由场景基线和镜头局部设置提供 |

角色工作台不提供“武器外观”“配件”作为默认长文本字段。相关内容通过道具资产绑定进入角色、分集或镜头作用域。

## 验收标准

1. 用户可以只创建角色身份锚点，不填写武器或配件文本。
2. 角色绑定道具后，分镜可以独立检索和替换道具变体。
3. 妆造定妆照和环境融合图不会出现在角色基础身份引用中。
4. 角色、场景、道具资产包均能显示基准图、派生资产、来源 revision 和作用域。
5. 模型请求只包含提交前用户可见并确认的文本和参考图。
