# 设计过程中的平台参考发现与使用 V1

> 历史设计基线。角色工作台后续的 `/` 动作、`@` 资源引用与带图 Prompt 案例分型操作以 `2026-10-19-character-workbench-discovery-reference-ux-v2.md` 为准；本文件中案例直接列在 `/` 的设计已被替代。

日期：2026-10-19。范围：iFrame 角色、场景、道具、分镜工作台的参考检索与显式应用。参考 `iyi/docs/product/2026-10-18-iyishow-asset-library-2.0.md` 的资源身份和治理模型；两个产品的权限与数据实现分别验证。

## Observed

- IYIShow 文档登记了 Shot.Cafe、Film Grab、Eyecannndy、Melies、AI Camera Movements、Grok Film、YouMind、Motuart 八类来源，并区分 `source`、审核候选、平台资源、媒体变体和 prompt variant。文档状态是设计基线，不代表八站内容已经导入。
- iFrame 当前 `/platform-reference-library` 只读取 `active` 目录，`/workbench-templates` 是另一目录；角色 `/` 面板搜索本地词条与现有角色设计 Skill，工作台 `@` 与参考图选择器使用项目资产索引。
- 外部网站的案例、术语、提示词和图片具有不同的用途及授权条件。网页可访问不证明图片可再分发或可发送给生成模型。

## Direct implication

用户需要在**正在编辑的位置**搜索，而不是先离开工作台去浏览一个大型素材列表。检索可统一呈现结果，但应用动作必须由资源类型和当前输入槽位决定。搜索结果出现不等于模型输入已经包含它。

## 一、统一发现，分型使用

| 结果类型 | 例子 | 工作台允许的动作 | 不能暗中执行的动作 |
| --- | --- | --- | --- |
| 外部案例索引 | Shot.Cafe 镜头、Film Grab 画面 | 打开来源、查看人工标签、收藏为候选 | 将网站图片作为模型参考图提交 |
| 术语/技法卡 | Eyecannndy 特效、AI Camera Movements 运镜、Melies 技法 | 将经审核的短描述填入可编辑字段 | 假装已锁定镜头参数或模型效果 |
| 结构化预设 | Motuart 风格方向、Grok Film 光影或剪辑方向 | 预览字段映射与完整编译提示词，确认后应用当前作用域 | 覆写剧集全局风格或加入不可见约束 |
| 工作台模板 | open-ai-canvas 或独立设计的任务模板 | 选择工位、输入槽位并预览草稿 | 自动附加模板示例图 |
| Skill | YouMind 工作流、iFrame 已安装 Skill | 显示版本和输入预览，按该工位实际能力调用 | 把 Skill 当成 `@` 图片或声称任意 Skill 都能执行 |
| 带图 Prompt 案例 | 平台角色设定图和配套完整 Prompt | `/` 展示缩图及全文，确认后只填入可编辑图片 Prompt；如需图片参考再使用 `@` 选图 | 点选案例就自动上传图片或把案例人物固定为当前角色 |
| 可用媒体变体 | 已获授权的平台图、项目角色锚点、场景图 | 选定具体变体、用途和作用域，进入生成审核 | 因名称匹配而自动上传图片 |

同一来源可以产出不同类型的条目。例如 Motuart 的风格词条、案例链接、获授权图片是三种独立资源，不能用一个“风格素材”卡同时代表三者。来源网站只是 provenance；平台资源有自己的 `resource_id + revision`。

| 来源 | 优先进入的检索槽位 | 第一批可用形态 |
| --- | --- | --- |
| Shot.Cafe | 分镜景别、构图、题材 | 镜头案例索引与经审核的构图术语 |
| Film Grab | 场景色彩、构图、光影 | 影片出处明确的案例索引 |
| Eyecannndy | 分镜视觉特效 | 技法名称和自写效果卡 |
| Melies | 分镜镜头语言 | 含条件与含义的技法卡 |
| AI Camera Movements | 分镜运镜 | 方向、速度、轨迹结构化预设 |
| Grok Film | 场景照明、分镜剪辑 | 光影卡与剪辑技法卡 |
| YouMind | 导演理解与工作台 Skill | 经适配并审核的 Skill/工作流 |
| Motuart | 角色/场景/道具的风格、版式、材质 | 可编辑词条与结构化视觉预设 |

这些是入口与候选形态的设计映射，不表示八站内容已获授权或已导入。

## 二、入口与检索行为

1. **就地打开：** `/` 搜索 Skill、模板、技法与结构化预设；`@` 搜索可引用的语义资产和媒体变体；“参考图”按钮打开同一可用媒体索引的图像视图。保留资产库全页用于浏览、审核和维护。
2. **上下文过滤：** 请求带工位、目标字段、项目/剧集、模态、模型能力和当前作用域。角色面容字段优先显示脸部词条；场景光影字段优先显示照明预设；分镜运镜字段优先显示相机运动。用户可切换“全部类型”，不能因默认过滤隐藏明确搜索结果。
3. **跨源查询：** 同时匹配名称、别名、中英术语、描述、标签、来源、角色/场景/道具、镜头景别和技法参数。字段/类型精确匹配优先，再按文本相关性、授权状态、质量证据和项目使用历史排序；热度不应压过当前槽位相容性。
4. **结果卡：** 标题、类型、可执行动作、来源、版权/许可状态、修订号、缩图或“无媒体”、适用工位与作用域均可见。未知权利状态明确显示“仅查看来源”，不提供图片提交按钮。
5. **预览和确认：** 点击条目先显示要填入的字段、替换/追加范围、编译后的完整文本和实际附带的每张图。用户可编辑；确认后才修改草稿或创建绑定。模型调用沿用工位自己的最终审核。取消不改变草稿。
6. **持续可检索：** 应用后记录资源 ID、revision、variant/prompt variant、目标字段、用户覆写及来源。手改字段后不能继续把新文字标成原预设原文；已有任务固定当时版本，库更新只提示可升级。

示例：在场景光影字段搜索“侧光”时，结果可同时出现一个可编辑光影预设、一张有授权的长街参考图和一个 Film Grab 案例索引。三项的动作分别是“预览并填入参数”“选择图像变体”“查看出处”，用户逐项选择。

## 三、检索索引和审核所需字段

最小公共结果：`resource_id`、`revision`、`kind`、`title`、`aliases`、`source`、`license_state`、`review_state`、`applicable_stations`、`slot_keys`、`actions`、`summary`、`tags`。有媒体时另给 `variant_id`、模态、参考职责、预览 URL 和可用于模型输入的权利状态；有结构化内容时给 `prompt_variant_id`、schema 版本、字段映射和兼容模型。

搜索索引只收录已批准且可发现的资源；候选和下架资源留在审核/历史视图。外部案例索引若未授权媒体，应只索引自写摘要、元数据和来源链接。引用时再次由服务端校验身份、revision、状态、作用域、槽位和许可；前端过滤不构成提交授权。

## 四、实施顺序

1. **目录归一与能力矩阵：** 给现有 Skill、模板、平台词条、案例索引和媒体变体定义资源类型与动作，清理“有缩图就能引用”的歧义。验收：同一结果在不同工位显示相同身份、不同可用动作。
2. **就地检索：** 先接角色 `/` 和 `@`，再接场景、道具、分镜；共享搜索 API、索引和结果卡，保留工位专有字段映射。验收：同名资产和多变体可区分，来源过滤及无匹配状态可用。
3. **应用审核：** 术语/预设/模板先显示字段差异与完整提示词；图片逐变体显示并由用户勾选。验收：审核快照与实际模型输入一致，取消和失效引用均不会静默替换。
4. **质量反馈：** 记录检索词、零结果、打开、应用、撤销和生成后人工评价，分别计算“找得到”“用得上”“结果一致”。使用计数不是质量证明。

## Not yet proven

- 八个来源是否允许批量索引、展示缩图、再分发原图或用于模型输入，需要逐站核对。当前文档没有证明已获得这些权利。
- 上述混合检索的排序能否提升创作效率，需要在角色、场景和分镜任务中做检索成功率与应用后撤销率验证。
- iFrame 当前平台目录、模板目录和项目资产索引尚未形成统一搜索 API；本规范不将设计目标表述为已上线功能。

## What would verify it

- 用“长街侧光”在场景工作台搜索，观察案例、参数预设和可用图片是否被清楚区分，并验证每种动作修改的准确字段。
- 用同名两名角色、多张锚点变体做 `@` 检索和提交，核对保存的稳定 ID、审核显示和模型实际参考图完全相同。
- 下架一条平台预设后验证新应用被阻止、已生成镜头的版本和来源仍可查。
