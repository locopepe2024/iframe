# Unified workbench reference materials

Creation, character image/design, and storyboard workbenches use one reference browser: local upload, owner/project assets, platform references, and recent creation media. A persistent quick-search field searches the active source; platform search runs on the server, is paginated, and never downloads originals until selection. Loading errors have retry states and never masquerade as empty results.

Selection is explicit; closing without confirmation preserves the draft. Image-only hosts admit images only. Existing model reference limits and semantic character/scene/prop membership remain authoritative. Platform pose/depth images are ordinary visual references, not a promise of depth-control model support.

References retain stable asset IDs/revisions, or an owner media-registry ID for uploads. An authenticated resolver validates identity, ownership, revision and image bytes before returning a durable owner media URL. No API keys, arbitrary paths or external URLs are accepted as reference identity. Storyboard supplemental image selections persist on the frame and participate in image generation, R2V, preview and invalidation; they do not create project entities. I2V retains first-frame semantics.

Platform reference semantics travel with image evidence: catalog title, summary, tags, category, view angle and representation are resolved by stable resource ID/revision on the server. Materialized owner media retain an immutable metadata snapshot, with distinct identities for identical pixels carrying different reference meanings. Creation snapshots align metadata with the actually selected input images; image/video adapters receive the description without altering the editable user prompt. Character AI design, character/scene/prop image submission review, storyboard image preview/render and R2V carry the same evidence. Generated context is replaced on reselection so stale/unselected reference semantics cannot survive. Tags describe reference evidence and do not silently replace the target subject, costume or style; depth/lineart describe visual structure rather than a mandatory output rendering style. Selected reference details are visible in the shared browser.

Discovery supports the published catalog's existing categories and tags as explicit filters, combined with quick search. The server returns facets before pagination: categories cover all eligible published resources; tags cover the selected category, independently of search and selected tag. Retired resources, method cards and ineligible media never contribute. Choosing a filter switches to the platform source, resets pagination and clears stale selection; changing category also clears the old tag. Cards show category and tag previews, while selected details remain outside the result-grid scroll area so they are immediately reachable on mobile.
