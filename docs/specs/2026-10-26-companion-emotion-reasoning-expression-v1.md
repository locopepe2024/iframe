# 陪伴助手“情绪小脑—思维大脑—表达层”测试边界 v1

日期：2026-10-26
状态：测试设计，未作为生产架构切换依据

2026-10-26 补充：三层划分是待验证假设，不代表必须部署三个模型。先按 [角色交互测试体系 v1](2026-10-26-companion-character-evaluation-v1.md) 建立现有链路基线，再通过消融比较情绪线索、回应策略与表达控制的效果。尚未完成相关能力评测，不以模型接口打通作为成熟度结论。

## 目标

让陪伴助手能够识别说话中的情绪线索，结合事实和意图作出合适回应，并用 OpenTalking 的声音表达出来。三层必须分开保存、传递和验证，避免把一次语音标签当作用户真实心情。

## 三层模型

```text
语音 / 文字 / 会话行为
          │
          ▼
┌──────────────────────────────┐
│ 感受层：情绪小脑              │
│ ASR、停顿、音量、速度、事件    │
│ 输出：临时线索 + 来源 + 状态    │
└──────────────┬───────────────┘
               │ only as evidence
               ▼
┌──────────────────────────────┐
│ 思考层：思维大脑              │
│ 事实、意图、日期、记忆、工具    │
│ 输出：回复文字 + 行动决策       │
└──────────────┬───────────────┘
               │ explicit delivery plan
               ▼
┌──────────────────────────────┐
│ 表达层：声音与角色             │
│ 人设、关系、语速、停顿、音色    │
│ OpenTalking TTS / WebRTC       │
└──────────────────────────────┘
```

### 感受层：情绪小脑

输入同一段短音频和当前已识别文字，输出：

```json
{
  "utterance_id": "...",
  "text": "今天女儿来看我了",
  "emotion_hint": "happy",
  "audio_events": ["Speech"],
  "confidence": null,
  "source_model": "sensevoice-small-int8",
  "status": "ok"
}
```

`emotion_hint` 是声音线索，不是用户确认的心情；`unknown` 和 `unavailable` 是合法结果。当前 SenseVoice CPU 适配不提供校准概率，因此 `confidence` 保持 null。情绪线索有独立超时，失败不能阻塞文字聊天。

这一层可以提取：开心、低落、生气、害怕、惊讶、平静，以及笑声、哭声、咳嗽等声音事件。它不能决定保存记忆、写日记、提醒、上传、生成或删除。

### 思考层：思维大脑

输入：用户原话、可靠的会话事实、当前意图、工具结果，以及可选情绪线索。思考层需要：

- 先理解用户要做什么，再参考情绪线索调整追问和措辞；
- 情绪不确定时使用温和平静默认回应，不在回复中宣称“我知道你很难过”；
- 只有事实和用户明确确认才能触发记忆、日记、上传和生成操作；
- 情绪线索不写入长期记忆，除非用户明确说出并确认“我现在很难过”等事实；
- 产生 `reply_text` 与独立的 `delivery_instruction`，不能把控制指令混入用户原话或回复正文。

示例：

```json
{
  "reply_text": "听起来今天见到女儿让你很开心。你们一起做了什么？",
  "delivery_instruction": {
    "style": "warm",
    "rate": "slightly_slow",
    "pause": "clear"
  },
  "action": "chat"
}
```

### 表达层：声音与角色

输入回复文字、固定人设和思考层给出的表达指令，输出 OpenTalking 音频/数字人 WebRTC 和文字字幕。表达层不能修改事实、调用工具或自行判断用户心情。当前配置的 TTS 字段是否支持动态语气指令仍待验证；在验证前只允许固定人设默认语气。

## 关键边界

1. **情绪不是事实**：一次 `sad` 标签不能直接保存为“用户情绪低落”。
2. **情绪不是意图**：检测到哭声不能自动进入日记、报警或通知家人。
3. **失败可降级**：感受层超时、模型不可用或标签未知时，继续文字回复和默认语气。
4. **一轮一绑定**：所有情绪线索必须带 utterance_id；晚到结果不得写入下一轮。
5. **不重复采集**：OpenTalking 语音入口优先复用同一段音频；浏览器 SpeechRecognition 只有文字时，不宣称完成语音情绪识别。
6. **可解释**：聊天调试视图显示“声音线索”，不显示成确定诊断或用户标签。

## 测试切片

第一切片只做 OpenTalking 语音入口的旁路分析：现有 `asr-1.0` 继续负责文字，SenseVoice 只返回临时情绪线索；线索通过内部上下文传给 LLM，用户原话记录保持原样。未接入动态 TTS 指令，未改变记忆和日记工具。

验证样本：平静、开心、低落三种说法；轻声、重复、停顿、笑声、哭声、电视背景音；短音频、静音、分析超时。记录：ASR 文字、SenseVoice 原始标签、情绪线索、回复文字、WebRTC 音频是否播放。只比较行为，不把少量样本当作准确率结论。

## 当前未证实

- `asr-1.0` 是否能返回结构化情绪字段；当前适配器只保留文字。
- OpenTalking 当前 `qwen-audio-3.0-tts-flash` 别名是否接受动态表达指令。
- SenseVoiceSmall 对老人语音和真实环境噪声的情绪识别准确率。

## 成功标准

- 同一语音请求可得到原始文字和可追溯的临时情绪线索；
- 情绪分析失败时聊天仍完成；
- 情绪线索不污染用户原话、历史消息、记忆或日记；
- OpenTalking 返回的文字和 WebRTC 表现仍对应同一 utterance_id；
- 当前测试结束后可完整关闭旁路分析，不需要迁移历史数据。
