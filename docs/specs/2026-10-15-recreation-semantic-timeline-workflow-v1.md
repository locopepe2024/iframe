日期：2026-10-15。状态：验证规格，s09 单段试点；不表示产品端已具备全部步骤。适用：以源视频的人物动作、器械关系和播放节奏为复刻目标的镜头。

- [s09 语义时间线](../agents/deliverables/2026-10-15-s09-semantic-frame-timeline-v1.md)已有人工审阅事件：深俯身、回升、举枪、前伸及帧 112 硬切。v2/v3 的深俯身与枪位不等价，不能仅用时间偏移解释。

## 目标与边界

复刻工作流的权威输入是**源片播放时间线**。动作语义说明“画面能看到什么”，时间线说明“在哪一帧可见、保持多久、何时转折”。原拍摄动作的真实速度和武术招式名称只有独立证据时才进入事实层。不同镜头分别建事件链，切点不能作为人体连续运动插值。

工作流先形成一个可审阅的 `ActionTimelineRevision`，再形成 `RecreationPlanRevision`，最后执行生成。LLM/Kimi 只提出候选；源帧复核后才能把候选升为可生成约束。没有等价输出事件时，验收记“动作缺失”，不计算速度误差。

```text
源媒体与镜头边界
  → 源帧证据（frame/PTS、可见姿态、遮挡、切点）
  → 可选前景分离与人物/器械 mask 草稿 → 人工逐段审核
  → 动作候选（可撤回）
  → 已复核的语义时间线（事件、帧窗、节奏、不确定性）
  → 已确认的生成计划（输入指纹、事件引用、提示词、目标时长）
  → 生成尝试（请求、provider task、结果指纹）
  → 同事件验收（语义 → 顺序 → 时点/占时 → 正常速连续性）
  → 选片与装配
```

## 产物契约

| 产物 | 必须保留的字段 | 进入下一步的条件 |
|---|---|---|
| 源帧证据 | 源媒体 SHA-256；`time_base`；源帧索引与 PTS；镜头 ID；可见事实；遮挡/模糊/出画标记；切点两侧 | 所有关键姿态能回到原帧；候选切点经两侧证据确认 |
| 可选 `MaskReviewRevision` | 原视频和前景预览并排；每帧人物 mask、长枪/红缨 mask、遮挡与画外标记；模型/参数、父素材指纹、审核人及修正记录 | 人工核对快速动作、细杆、手与杆接触、遮挡和切点两侧；拒绝断杆、漏手、背景误抠及跨帧身份漂移；未通过则返回源帧复核/重做 mask |
| 动作候选 | 候选语义、证据帧、提出者/方法、不确定项 | 只供复核，不直接进入提示词 |
| `ActionTimelineRevision` | 事件 ID；镜头 ID；首次/峰值/最后**证据**帧；可见身体/器械关系；阶段类型（进入、保持、转折、退出）；边界精度；审阅状态；证据链接 | 关键事件已确认或明确标“不可确定”；事件顺序单调；无跨切点连续事件；每条具体约束有源帧 |
| `RecreationPlanRevision` | 源/人物/参考媒体指纹；镜头与动作标注 revision；事件到 prompt 句子的映射；模型能力快照；seed、时长、比例、音频策略；完整 prompt 与校验结果 | 输入和 prompt 与同一镜头窗口一致；可复现计划指纹；成本/能力/时长预检通过；提交时不得静默重算成另一份计划 |
| `GenerationAttempt` | 计划 ID/指纹；完整提交参数；provider task ID；重试父尝试；输出媒体指纹；运行状态 | 输出可打开且任务与计划一致；完成不等于视觉合格 |
| `EventReview` | 源事件 ID；对应输出帧/PTS 或 `absent`/`unscorable`；语义、顺序、时点、持续时间、器械连贯性、正常速结论 | 关键事件都可评且通过；画面杂质、人物、切点和装配时长另行通过；失败保留为可比较结果 |

帧索引只在所属媒体内有意义。权威时间使用源 PTS/time base；CFR 测试片可以用 `frame/fps` 展示秒数。输出为另一帧率时先确认事件语义等价，再按播放时间比较。抽样帧窗口不得标成精确起止；要给精确边界，须逐帧复核。

重复出现的同类姿态必须有不同事件 ID，并保留中间的回落/转向；输出事件只能按语义和顺序逐一配对，不能把输出第一次出现与源片第二次出现直接计算时差。s09 在帧 69–73 与 82–87 的两次高举就是反例。

去背景只生成辅助视图，**原帧仍是事实来源**。人物和器械应有可分别审核的区域；只做人像抠图容易把细枪杆、红缨及握持关系消掉。mask 缺失不等于画面中该部分不存在，审核不通过的帧记为遮挡或分割失败，不得静默修补成动作。若生成路线明确使用 mask，审核通过的 mask 才能进入计划输入快照；若 H3 路线只提交原视频，mask 仅支持标注复核，不声称 provider 使用了它。

## 阶段闸门与回退

1. **解析闸门**：文件身份、帧 PTS、硬切与镜头归属可信。失败则回到源媒体/切点复核。
2. **mask 审核闸门（采用前景分离时）**：人工审核人物与器械区域及其跨帧连续性，记录通过/需修正/不可评区间。未通过的 mask 不参与生成或确定性动作标注。
3. **标注闸门**：关键事件各有原帧证据和不确定性，候选与确认状态明确。事件缺失或握点遮挡时不得靠知识库或 mask 补完。
4. **计划闸门**：每句具体动作要求回指事件 ID；提示词不要求参考窗外的切后动作；预检输出时长与装配契约。改动标注、参考、mask 或描述须产生新 revision，并使先前计划失效。
5. **提交闸门**：按已审阅计划指纹提交；费用确认绑定该指纹。重试保留旧尝试，不能覆写结果。
6. **验收闸门**：先判断是否做出同一动作，再比阶段顺序与局部时长。只在事件等价且镜头连续时做单调时间映射。动作/枪/人物/UI/切点/时长任一关键项失败，停止扩批并记录失败维度。

## s09 试点顺序

1. 冻结源参考 `[0,112)` 的单镜头输入与哈希；帧 112 后的第二视角独立处理。保留原四秒参考作为对照，不将停帧尾段当成源事实。
2. 如使用前景分离，先在 E2 深俯身、E4a/E4c 两次高举、E4b 回落及帧 111/112 切点两侧审核人物和枪 mask；失败帧保留原帧并标记不可评。把 E1–E5 的原帧证据窗口逐帧收窄；E2 深俯身幅度、E3 回升、E4a 第一次高举、E4b 回落/转背、E4c 第二次高举、E5 前伸为最低可评集。
3. 从已确认事件生成一份单镜头计划，逐句写明事件 ID；锁人物图、参考窗、模型、seed、提示词、时长和输入指纹。预先处理 H3 3.75 秒输出对 4 秒目标的装配问题。
4. 在费用确认后只生成该计划的一次试点；以同一事件表审阅。若 E2 不等价，先归为动作缺失，不以全段倍速修正；若 E2 等价但峰值/保持偏移，再分析局部节奏。
5. s09 联合通过后，分别用 s10 检查枪形/UI、s03 检查遮挡不可评规则，再决定是否推广。

## Direct implication

下一段产品实现应先使动作事件和审阅状态成为镜头的版本化数据，并在生成计划预览中显示事件到 prompt 的引用。随后持久化确认后的计划快照，让提交与费用确认指向同一份内容。结果验收最后接入。可以按这三个薄片分别交付，不需要一次改动整条产品工作流。

前景分离作为独立、可选的证据辅助切片：先验证 s09 人物与枪的双 mask 草稿及人工审核记录，再决定是否接到任何生成模型。当前试点的[mask 复核](../agents/raw/2026-10-11-qiangfa-cut-poc/qiangfa2-gray-full/s09-mask-poc/review.md)显示人物分割在深俯身/转身帧失败，前景实例分割仍漏枪/红缨；因此不把它接入生成。不能因为单帧 `edit_mask` 已存在，就把跨帧 mask 作为已完成能力展示。

## Not yet proven / Hypotheses

- H3 会遵守精确事件秒数，或结构化标注比现有自由文本显著改善复刻质量：尚无受控样本证明。
- 当前后台任务在重启后保留完整 provider 尝试链、独立 collect 阶段和计划快照：本次未做重启验证。
- s09 源片曾删帧或分段变速：导出参考片均匀 PTS 不能证明上游编辑方式。

## What would verify it

- 数据/API：提交过时计划必须 409；修改动作标注后旧计划不可再次提交；任务和结果能回查计划指纹及事件证据。测试事件跨切点、无源帧、重复/乱序和不可确定边界。
- 运行：先在本地演练计划预览、确认、提交快照、任务恢复和结果审阅，不产生付费任务；必要时再用一次 s09 受控生成比较 E2–E5。
- 质量：同一次候选在可评的动作语义、阶段时点、枪几何、目标人物、画面洁净度及装配时长均达标，才进入跨段推广。
