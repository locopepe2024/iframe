# 拍摄计划之后：风格、Assets 与分镜模板路线 V1

状态：需求与实施计划，尚未实现本文件中的新模板能力
基线：iFrame Studio `07954e4b`；承接 `2026-10-04-creative-production-system-canonical-v1.md`
目标案例：《武林传·苍桐》已确认拍摄计划中的第一集场景；具体 scene/shot ID 以实际计划为准

## 1. 目标流程

```text
已确认拍摄计划
  → 确认系列视觉风格（分集可显式覆盖）
  → 从计划同步分集 Assets 需求
  → 图片编辑/资产设计生产候选，人工确认适用场景
  → 选择运镜、动作、人物造型和特效模板/参考素材
  → 按 scene → beat → shot 生成和审阅 Storyboard
  → 用户选择直接参考视频或先做首帧，再生成视频候选
```

风格是跨场景的视觉语言，Assets 是可引用的视觉身份与状态，模板是可编辑的创作建议，参考素材是带用途的媒体证据，Storyboard 是具体镜头的选择和组合。四者不能互相冒充。

## 2. Observed：当前代码事实

- `style_presets.json` 有 5 个分类、16 个预设：日式动漫 4 个，美式动画 3 个，东方水墨奇幻 1 个。`ArtDirection` 已有目录读取、预览、保存及系列继承/分集覆盖入口；尚无专门的中式武侠/玄幻动画风格族。
- 已确认的 `DirectorShootingPlan` 可投影成 `EpisodeVisualContext`，包含 scene 时间/季节/天气、角色阶段、关键道具及 shot 表演、构图、运镜；同步返回新增、复用、变化、过期和未绑定条目。现有 Assets 页面提供手动同步与新建场景资产入口。
- `EpisodeAssetBinding` 现有 `selected_variant_id` 和 `suggested/accepted/stale` 状态。场景资产生成已有入口，但这不证明角色、场景、道具候选已按计划自动生产或被每个镜头准确采用。
- Storyboard 已有 `t2i_i2v` 和 `direct_r2v` 两条路径、图片参考选择、景别、机位、运镜、光影和风格覆盖字段；`buildAssembledPrompt` 会组合这些字段。现有字段不等于有可检索、可审阅的运镜/动作/特效模板库。
- 角色工作台保有身份、造型和连续性边界；图片编辑是视觉设计入口。3D 导演台已有局部动作结构与预演能力，但不把尚未稳定的跨工作流版本化引用列为本阶段前置条件。

## 3. Direct implication 与待验证项

- 先选择风格，再生产视觉候选，才能比较同一人物、场景和道具在同一种视觉语言下是否协调。改变风格不应重写拍摄计划，但需要标记旧风格下已生成的候选待复核；这一失效规则尚需实现和测试。
- 拍摄计划描述的是“需要什么”，不等于资产已经可用。缺少已接受参考图时，Storyboard 必须显示缺口，不能把文本计划当成资产或把 Level 0 底座冒充场景定妆。
- 对首集武侠项目，剑、衣装、街景和交手动作可以做验证样例；哪些效果属于原文事实、哪些属于导演补充，必须逐项从剧本与确认计划核对。
- 外部动画风格资料本轮未能读取：浏览器会话被占用，公开页面请求超时。以下新增风格名是设计候选，不是已完成的行业调研结论。发布前应补公开来源、视觉样图和生成对照；不以现有动画 IP、导演或角色姓名命名预设。

## 4. 风格目录：媒介工艺与题材分开

“武侠/玄幻”首先是题材与世界规则，不能仅凭题材词确定线条、材质、色彩或动画工艺。目录应将 `visual_family`（可观察的画面语言）与 `genre_tags`（适用题材）分开；现有 preset ID 和已保存的用户选择保持兼容。

| 方向 | 当前状态 | 首批处理 |
| --- | --- | --- |
| 中式水墨奇幻 | 已有 `chinese_ink_fantasy`，在 `style_lab` | 评估归入“中国动画”分类；保留原 ID 和已保存选择 |
| 中式写意武侠 2D | 缺少专门预设 | 墨线与留白、克制矿物色、清楚的身法轮廓；不默认加法术光效 |
| 中式彩绘武侠 2D | 缺少专门预设 | 手绘线条、服饰纹样、分层背景、动作关键姿态；与水墨图区分 |
| 中式玄幻绘景 2.5D | 缺少专门预设 | 绘景层次、云雾与发光材质；超自然元素仅在剧本或导演计划允许时启用 |
| 中式风格化 3D | 缺少专门预设 | 角色比例、布料/金属材质、环境深度和可运动的光影；避免塑料感 |
| 日式动画 | 已有手绘、现代赛璐璐、复古都市、时尚战斗 4 项 | 先复用；对战斗剪影、动作分层和背景处理做对照后决定是否新增 |
| 欧美动画 | 已有风格化 3D、图像小说、厚涂 3D 剧集 3 项 | 先复用；验证是否需要单列 2D 电视动画，不复制具体作品造型 |

每个新风格须提供：稳定 ID、中英文名称、媒介/画面工艺、适用与不适用场景、可编辑正负约束、**同一中性测试主题**的预览图，以及角色/街景/动作三项生成对照。预览图说明来源和使用权。系列选中一个基线；分集可以显式覆盖；场景只改天气、时段和光线时不创建新风格。风格快照随每次资产生成任务和分镜候选记录，不能只保存当前全局 preset 名称。

## 5. Assets 生产：从需求到可用参考

Assets 页面按确认计划展示“场景 → 人物造型/场景状态/关键道具”的需求矩阵，每条显示来源 scene/shot、时间、季节、内外景、人物阶段、服装/持物与连续性要求。非关键道具只在拍摄计划明确有叙事或连续性作用时进入待生产列表。

单条生产流程：

1. 用户选择计划需求、风格和有序参考图；参考图分别标注身份、服装、场景、道具职责。
2. 在图片编辑中查看并编辑生成输入；角色身份底座与场景动作、镜头语言分栏显示，不把原始 Director JSON 或多个场景全文塞入 prompt。
3. 生成结果先进入候选，保留 `plan_revision/hash + scene_id + shot_ids + style_snapshot + parent_asset/variant + model/task`。
4. 用户接受后指定适用场景/镜头；同一变体可被多个场景引用，现有默认选图不因新候选生成而被替换。
5. 计划或风格变化只标记相关绑定待复核，给出复用、改图、重新生成三种操作。

角色先保留稳定身份，再选时代/服装造型，最后才做镜头中的表情和动作状态。场景资产与道具可以从图片编辑导入；不要求所有计划条目都变成图。全局 Avatar 身份由外部 Avatar 服务持有，iframe 不扩展本地 Avatar 素材库 CRUD。

## 6. 分镜模板与参考素材库

### 模板不是素材

模板保存可编辑的结构化建议；素材库保存实际图片、视频、3D 或音频及其来源。首版使用只读、随代码发布的策展目录，支持搜索、筛选、预览和“应用到草稿”；不先做一套全局模板 CRUD。用户项目内可保存修改后的模板快照。应用模板不得覆盖已有字段，必须先显示字段差异并由用户确认。

建议的目录契约：`template_id`、`revision`、`kind`、`title`、`medium_tags`、`genre_tags`、`applicable_scope`、`parameter_schema`、`constraints`、`example`、`source_note`、`license_note`、`preview_media_id?`。镜头应用记录 `template_id/revision`、用户参数、目标 `scene_id/beat_id/shot_id`、已改字段和撤销点。参考媒体另存 `media_id`、用途、来源、授权、时长/比例/音频说明；视频默认只提供动作或镜头节奏，不自动提供人物身份、服装或场景事实。

| 类型 | 放置与输出 | 首批模板 |
| --- | --- | --- |
| 人物造型 | 图片编辑/资产设计；输出身份多视图或 Level 1 造型候选 | 正脸与侧脸、三视图、服装/时代变体、表情板、动作起终状态。角色工作台只审核身份与连续性 |
| 运镜 | Storyboard shot；可选 3D/视频参考 | 固定观察、缓推、侧向跟拍、摇镜揭示、低机位上升；参数包括起终景别、路径、速度、焦点、轴线和时长 |
| 动作/表演 | Storyboard beat/shot；可选角色 motion reference | 起始状态、触发、身体过程、结束状态、情绪目的，补重心、接触点、持物状态和镜头配合；先做转身、停步、拔剑、格挡、递物等基础结构 |
| 特效 | Storyboard shot；输出效果意图与可选参考，不生成永久角色属性 | 剑光/兵器接触、尘土、雨水、火花、能量效果；参数包括附着对象、开始/结束、强度、遮挡、物理接触和禁止变化 |

导演 Skill 可根据 shot 目标建议模板与参数，但只返回提案；用户确认后才进入镜头草稿。模板目录先用图片或短样片证明预期效果，不能把“提示词里有运镜字样”当成可复核的运镜参考视频。3D 导演台可在能力成熟后给出占位、机位、深度和运动样片；本阶段允许这些引用为空。

## 7. Storyboard 接入与两条生成路线

一个确认 shot 映射一个可编辑 Storyboard 草稿，保留 scene/beat/shot 和计划来源。镜头面板按顺序呈现：剧情目的与原文事实、已接受 Assets、造型/持物/站位、模板建议与参考素材、分镜画面、生成 prompt。模板选择只影响当前 shot 或用户明确指定的镜头组，不改变全剧资产。

- **直接视频**：已接受角色/场景/道具参考图 + shot prompt + 可选动作/运镜参考；用户选择 R2V 模式并确认素材职责。
- **先首帧后视频**：先用图片编辑或分镜静帧生成含人物与场景占位的关键画面，再由用户选择 I2V 和首帧；首帧候选必须保留所用资产与模板来源。
- 两条路线可对同一 shot 并存比较。系统不根据附件数量自动替用户切换模型模式；生成前展示最终模式、素材顺序、缺失项和可编辑 prompt。

多人场景需要明确左右/前后、入场方向、视线、持物和动作顺序。没有 3D 深度和站位证据时，标注 `spatial_review: pending`；不声称独立角色图能保证四人空间关系。特效和动作参考不得覆盖身份、服装或剧本事实。

## 8. 实施顺序与验收

### S0：风格目录与对照（先做）

- 在现有 `style_presets.json`、风格画廊和相关测试中补中国动画分类及首批 4 个候选；为每个候选做同题预览和可编辑约束。
- 验收：原 16 个 ID 可继续读取；系列/分集选择可恢复；同一角色、街景和交手在四种风格下能看出稳定差异；切换风格不改已确认拍摄计划。

### S1：拍摄计划驱动 Assets 生产

- 在现有 `EpisodeVisualContext` 和 Assets 同步上呈现缺口、参考图职责、候选生成与接受/复用/过期流程；图片编辑负责具体设计。
- 验收：至少一个已确认场景完成主角造型、场景状态和关键道具；候选不覆盖默认图；可复用变体不被复制；计划改动只影响相关绑定。

### S2：四类模板的最小策展目录

- 先做结构化目录和可编辑应用预览；每类至少 3 个可用模板，人物造型在图片编辑、其他三类在 shot 编辑器；可选媒体只按明确角色引用。
- 验收：搜索/筛选、参数修改、应用/撤销、来源查看可用；相同模板在两个 shot 可使用不同参数；应用不改资产身份或其他 shot。

### S3：Storyboard 场景试片

- 从第一集已确认拍摄计划选择一个含两名以上角色的场景，完成 scene/beat/shot 映射、资产选择、模板应用和两条生成路线的对比。
- 验收：每个 shot 显示计划/风格/资产/模板来源和缺失项；人物左右关系、道具持有与连续性可审阅；用户可以接受、重做或保留候选；不因生成成功自动确认镜头。

### S4：3D 精度升级（独立能力稳定后）

- 接入全景、场景占位、机位、深度和运动参考；只为需要严格空间控制的镜头启用，不阻塞 S0-S3。
- 验收：3D 参考可与现有 shot 对齐且可撤销；其空间证据不覆盖身份、造型或导演意图。

## 9. 首个验证场景与风险

以《武林传·苍桐》第一集的一个**已确认计划场景**做纵向验证：街景/天气、苏砚与江灼的造型、剑等关键道具、人物出现顺序、交手前后状态、机位与克制的接触效果。原文中明确的衣装、动作和人物关系必须可追溯；新增的动作设计、镜头和特效必须标为导演选择。具体范围以用户当前确认的拍摄计划为准，不能把小说中的全部事件挤成一个镜头。

主要风险：风格预设相似而不可辨、风格词污染原文事实、资产候选没有场景适用范围、模板变成不可编辑提示词堆叠、参考视频误导人物身份、多人物空间关系被静帧掩盖。S0-S3 各切片应提供行为测试、类型检查、生产构建和一个可见的场景审阅结果；部署前再次核对 Git/镜像/静态资源同一修订及实际 API 路由。
