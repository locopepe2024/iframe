# 分镜工作域与过程交接 V1

状态：流程设计与源码对照；不是已实现状态声明。承接 [Storyboard/Shot Design 产品边界](2026-10-07-storyboard-shot-design-boundary-v1.md)、[阶段审计](2026-10-22-storyboard-stage-artifact-skill-audit-v1.md)和[一致性表](2026-10-22-storyboard-structured-continuity-sheet-v1.md)。

上述阶段审计及其他旧规格含按当时版本记录的自动批量初始化等实现描述；涉及当前执行路径时，以本文件的 `Observed` 和实际源码为准。此文档不追认先前隐藏候选或提示光影的 UI 改动为产品状态定义。

## 目标与边界

从已确认剧本、导演计划及角色/场景/道具设计出发，定义五个互不冒充的交付物：镜头清单、有效连续性、起始画面及参考包、镜内设计、模型请求与结果。同一 `StoryboardFrame` 可以暂时承载多个交付物的兼容字段，但页面位置和数据库同居不等于字段所有权相同。

过程为：**确认输入 -> 提出方案 -> 审核差异 -> 保存当前版本与来源 -> 生成下游输入 -> 审核实际结果**。候选、已确认字段和生成结果是三种不同对象。当前 `rich_refinement_candidate` 仅是每镜一个可覆盖的当前候选槽位；代码没有候选历史或“历史未采纳/采纳”状态，不得用这些词解释已有数据。

## Observed：当前实现

- 从剧本拆镜：LLM 读取 `storyboard_extraction` 基础提示词；`storyboard-suspense`、`storyboard-action`、`storyboard-emotion`、`storyboard-dialogue` 是可选方法，选中快照进入模型输入。按已确认导演计划生成则由 `materialize_plan` 转换，不再调用拆镜 LLM。两条路径产出镜头草稿，应用后为 `StoryboardFrame`，并不产生首帧图。
- 镜头保存有 `action_description`、`visual_description`、`blocking`、景别、机位、构图、运镜、对白、`image_prompt`、`video_prompt`、参考包及图片/视频任务等。`visual_description` 当前混合环境、表演与物理动作；首帧编辑器读 `image_prompt`，缺失时回退到 `action_description`。这些字段尚无唯一的“起始状态”合同。
- 分镜卡的风格/光线输入是本镜覆盖，空覆盖不等于有效值为空。项目风格、场景设计、计划光线、参考投影与本镜光线分散存储；只读一致性表能显示部分有效字段及来源，但并非所有图片/视频请求共用的一份冻结输入。
- 首帧可由当前镜头生成图片、选择参考变体，或在上一镜选定视频完成后手动截取尾帧。尾帧接力目前不是默认分镜规则，也不能仅凭相邻顺序推出连续性。
- 单镜优化目前分散在拍摄计划字段采纳、静态起幅、运镜、微表情、旧 rich-frame 候选及整段视频润色。H3/Seedance 润色会输出完整模型文本；不能据此认定镜头过程字段已得到独立设计和采纳。

## 五个工作域

| 工作域与所有者 | 冻结输入 | 需要确认的产物 | 不得改写 | 当前实现对应 |
| --- | --- | --- | --- | --- |
| A 镜头规划：导演/拆镜 | 剧本事实、已确认导演计划及资产身份 | 镜头清单：镜头任务、场次/时空 ID、角色/道具、事件与起止状态、时长、对白、镜间交接；保留来源 | 角色/场景设计、最终图片与视频提示词 | `storyboard-analysis` 草稿及 `StoryboardFrame`；从剧本可选四张拆镜方法 |
| B 连续性解析：视觉基线 | A 的镜头关系、已确认资产设计及所选变体快照、项目风格 | 每镜有效的风格、画幅、世界光、局部光、场景空间、角色造型与道具状态；逐字段值、来源、版本、覆盖和冲突 | 剧情事件、未知时空关系；不自动采用前镜全文 | 场景设计、`director_shot_context`、`reference_visual_projection`、`continuity_sheet` 的部分能力 |
| C Storyboard：起始画面与参考包 | A 的起点、B 的有效视觉基线、用户选择的图片来源 | 0.00 秒可见布局：主体/道具位置、静态姿态与表情、景别、机位、构图、光影；首帧媒体及其参考、版本；可选尾帧目标 | 镜内动作过程、对白时序、运镜路径；不反写资产母版 | `StoryboardFrameEditor`、静态起幅、首尾帧候选、参考包；现有自由文本仍混用 |
| D Shot Design：镜内过程 | A 的镜头任务与时长、B 的基线、C 的起幅及选定媒体 | 动作起止和可见阶段、对白/反应调度、逐角色表演时序、特效关系、运镜路径/速度、节奏、落幅与转场决定 | 已确认剧情、身份/服装、场景基线；不静默替换首帧 | `ShotCard` 动作/对白/运镜/微表情、视频模式和参数；完整结构化过程合同未齐 |
| E 模型交付与结果审核 | A-D 已确认版本、实际参考媒体及模型能力 | 图片或 H3/Seedance 等目标请求的完整预览、冻结版本与媒体映射、生成候选、人工选择结果 | 不重新决定 A-D 的字段 | 图片预览/渲染、`PolishPanel`、`buildGenerationPrompt`、视频任务与候选 |

工作域是数据与决策的所有权，不要求五个独立页面。产品现有边界仍为 Storyboard 管参考包/首尾帧，Shot Design 管视频设计；镜头清单和连续性是两者的前置输入。UI 可以同屏，但每个操作须显示它更新哪个产物。

## 交接与选择规则

1. **A -> B。** 镜头清单确认后才解析时空和资产版本。计划可提供已有 `place_continuity_id` / `time_continuity_id`；若无明确关系，标记未确定，不能以相邻顺序或场景名称补出 ID。拆镜 Skill 只改善 A 的镜头决定，不承担 B 的视觉继承。
2. **B -> C。** 先显示有效风格、世界光、局部光及来源，再设计起幅。空的本镜覆盖输入可以表示继承；有效值仍空时须显示缺口。参考图默认只带图片；用户可按允许作用域选择结构化字段。同时间异地点只可继承世界光；同地点同时间可审核局部光、空间、机位和站位；时间变化重新定光影。剧情明确的角色换装、道具增减和局部光变化应形成有来源的状态变更。
3. **C 的媒体选择。** 场景图与角色图是生成本镜起幅的锚点，不自动等于分镜首帧。默认候选为基于当前镜头起始状态生成新图；上一镜尾帧仅在有意接力且选定视频完成时可选。切换机位或改变主体时，可把尾帧用作连续性参考并另生起幅。纯 T2V/R2V 镜头仍需结构化起点，但不强制先生成首帧图片。图片来源选择与起始状态均需留版本，不能只保存 URL。
4. **C -> D。** 起幅只规定开始时可见的状态；D 才规定该镜持续期间发生什么。镜头任务可同时包含对白、情绪、叙事、打斗或追捕，不做互斥枚举。按实际任务加载方法：对白调度处理谁说/谁回应，微表情处理指定角色可见变化，动作/打斗方法处理已确认事件的阶段与物理关系，摄影方法处理视点及运镜，节奏/转场方法处理时间组织。每个方法返回字段候选、理由、来源及不确定项；没有字段结果的整段扩写归 E 的表达层。
5. **D -> E。** 图片请求只读 B 与 C 的静态状态；视频请求读 D 的过程和实际媒体。H3/Seedance 适配可使用不同格式，但不能重写剧情、光照或动作决定。优化后的完整文本如不包含后来确认的字段，必须失效或重新编译/审阅；不能把完整文本与新增结构化字段并列保存却只有一方进入提交。

剪辑切镜不等于转场到新时空：同地点同时间可保持视觉基线，但景别/机位可变化；同时间换地点保留适用世界光与项目风格，重新确定局部空间和光源；时间变化重新确定光照。镜间动作状态交接只由已确认起止状态或实测尾帧支持，不通过场景参考投影携带前镜动作、对白或角色描述。

## 版本与状态合同（待实现，不冒充现状）

每个工作域的候选至少记录 `target`、`source_revisions`、`input_hash`、`field_diffs`、`reason/source_refs`、`created_at`；确认操作只更新指定字段及该交付物版本。生成请求冻结 A-D 的消费版本、媒体身份、最终文本、模型及参数；结果记录请求快照。上游变化只使依赖它的下游预览/候选标记待审，不改写已生成媒体。候选覆盖、撤回、部分应用和历史保留必须作为单独产品决策；现有 `rich_refinement_candidate` 单槽位不能承担完整状态机。

## 当前重叠与实施顺序

| 重叠或缺口 | 收口方向 |
| --- | --- |
| `visual_description` 同时像静态首帧、动作叙事和视频正文 | 先定义 A 的事件/起止状态与 C 的静态画面字段；旧文本标记来源不明，迁移须人工审阅，不按词句自动分类 |
| 静态起幅在视频卡内，首帧图编辑另有图片正文 | C 统一展示静态起幅、参考包和图片预览；D 仅读已确认起幅，不再拥有第二份景别/机位真相 |
| 空覆盖值与有效风格/光照混淆 | B 在每镜显示有效值、来源及冲突；图片和视频预览核对是否读取同一冻结基线 |
| 微表情、运镜、旧细化、整段润色并列 | D 先按字段/任务形成镜内设计，再由 E 编译；旧入口在迁移前标明实际作用，不能隐藏当前待审候选充当状态迁移 |
| 场景图、当前首帧、前镜尾帧混为“参考” | C 为每个媒体标注用途：资产锚点、连续性参考、已确认首帧或尾帧目标；提交按用途检查 |

实施按可验证切片推进：先做 A-E 的只读来源与请求映射；再让 B 的有效值及缺口在首帧/视频预览一致呈现；随后明确 C 的静态起幅与媒体版本；再补 D 的动作/节奏/对白调度字段合同；最后将 E 改为只读已确认设计的模型编译。每一片先用同地同时间、异地同时间、时间跳变、尾帧接力和纯 T2V 五类样例核对预览与实际请求。视觉一致性仍需固定素材的真实生成和人工比较。

## 尚未证明

- 图片与视频的视觉基线目前没有统一消费合同；下游模型对已提交参考图和文本的实际保持效果仍未证明。
- 参考图、结构化文本或尾帧接力是否能在目标模型中稳定保持视觉连续；请求正确仅证明输入边界。
- 五域 UI 应呈现为一个顺序向导还是同一工作台的分区；先以交付物及状态行为验收，再决定页面形态。

## 2026-10-23 请求消费核对（代码事实）

| 路径 | 当前预览与提交 | 视觉基线的实际消费边界 |
| --- | --- | --- |
| Storyboard 首帧图片 | `preview_storyboard_render_prompt()` 生成完整正文与上下文令牌；确认后以完整正文提交，令牌校验镜头及资产版本 | 普通草稿会投影本镜场景设计、项目/本镜风格、本镜灯光、计划镜头上下文及已勾选参考字段。已采用的完整图片润色正文可原样提交；场景/角色变化只提示重审，不自动重编译。已确认场景光线存在时，旧计划镜头光线不再额外追加。 |
| Shot Design 视频 | `buildGenerationPrompt()` 在前端组装；`createVideoTask()` 直接接收文本及媒体，后端可能补对白提示 | 未采用完整优化稿时读取项目风格、本镜覆盖、动作文本、机位/景别、运镜、转场与微表情。采用完整优化稿时以该正文为主。两者都不会读取一致性表的场景设计、计划世界光或已勾选参考视觉字段；参考媒体与结构化视觉文本目前是两条独立路径。 |

因此，一致性表是来源诊断，不是图片和视频共用的冻结请求。下一片的验收应分别比较同镜的有效世界光/局部光与**图片完整预览**、**视频实际提交文本及媒体**，并覆盖完整润色稿过期、同时间异地点、时间跳变与仅参考图四种情况。未建立视频请求预览和版本令牌前，不能将表内值称为“已带入视频”。
