# 老年人个人助理：代码架构审查与下一步

审查日期：2026-10-28。范围为当前工作区代码；部分 runtime 文件尚未提交，本报告不将工作区状态等同测试站部署状态。不推送、不合并，本轮只审查与验证。

## 结论

现有照片、日记、记忆存储和语音播放原语可继续复用。可以继续针对性测试和开发，但尚不能按“懂当前焦点、持续记录、跨任务协作的个人助理”验收。应先补任务状态与上下文，暂不增加协调模型或扩张语义规则。

## 已存在的能力（代码事实）

- AgentChat 管理文字、语音句子队列、工具卡片与聊天历史；失败原请求有操作ID。
- chat_store 存储用户消息、模型结果、照片任务；conversation 可恢复两者；claim_turn 给模型取最近20条用户原话，并附最近3个等待中的照片任务及选中照片资料。
- 相册已有上传、软删除、结构化分析、用户资料版本、讲述、描述核对和检索。组合关键词搜索跨最新确认资料/讲述/核对描述，不使用原始AI观察。
- 日记有独立表、按月查询、按日编辑保存、版本检查与重试去重。DiaryEditor/useDiaryDictation 支持持续追加、重启识别及保存确认。
- 个人记忆支持确认式保存、删除、列表与字面搜索；保留来源原话。人格有3个静态行为模板。
- OpenTalkingReply 对普通文字回复使用 render_text 播放通道；该通道关闭 memory_enabled/knowledge_enabled。它不承担主任务状态。

## 缺陷与直接影响

| 优先级 | 代码证据 | 直接影响与边界 |
|---|---|---|
| P1 | chat_store.claim_turn 仅 SELECT id,text，LIMIT 20；model 将其包为 user_messages | 助手前次提问和普通工具结果不进入主模型上下文。单独保存历史不等于模型理解历史；含糊回答缺少承接依据。 |
| P1 | workflow_context 以最新 waiting_input 照片任务为 focused_task；只有最近日记元数据 | 无共同的当前编辑任务、草稿、前端选中照片、收音及待确认状态。最新任务不等于当前焦点。照片资料仅在存在服务端任务时附加，浏览页面不自动建立同一焦点。 |
| P1 | api.chat 先 classify；intent._UPLOAD 为宽泛子串正则，再直接生成 upload_guide | 在输入“还拍了视频/上传照片”等叙事时可能绕过模型进入上传引导。这是代码路径可见的风险，尚未证明每个真实说法都误路由。 |
| P1 | PhotoStory 调用 useCompanionVoice 未设 continuous，回调 setDraft(text)；hook 默认 false | 照片讲述是单轮且替换草稿；日记则独立连续追加。不同入口对“继续说”的语义不一致。 |
| P1 | DiaryEditor、PhotoFactsEditor 草稿均为组件内状态；workflow_context 不读取它们 | 普通聊天无法可靠知道正在编辑什么；切换/卸载后草稿恢复未形成统一能力。录音停止与保存是不同动作，不能混同。 |
| P2 | 普通 model._propose 不加载偏好或检索结果；记忆通过单次工具返回，不能继续调用模型 | 有记忆CRUD，不代表已具备语言习惯学习与自动唤醒；查询后缺少同轮基于结果的自然回答。知识检索桥接存在，但未证明主聊天路径使用它。 |
| P2 | personality 从环境变量选择模板；useContinuousCapture 仅传 result.text；SenseVoice 保留 emotion_hint | 当前是静态人格与文本情境提示，声学情绪未进入主聊天上下文；没有证据证明形成用户专属人格或情绪表达闭环。 |
| P2 | 前端端侧协调器可先澄清；后端独立 decide；正则还可直接分支 | 存在多个决策入口，焦点未统一时可能分歧；尚未证明所有部署配置同时启用。需先记录实际配置再评估延迟与冲突。 |
| P2 | chat_store.turn 的 read 结果会重新 dispatch 读取 | 历史查询展示可能随当前资料变化，而非执行时快照；不宜直接当作过去执行证据。是否采用实时视图需明确。 |

## 开发顺序与成功标准

1. 共同任务状态：建立服务端 session 工作状态，含 focus、task_id、object_id/day、phase、revision、draft_ref、pending_action、last_receipt。前端选择/编辑同步显式事件，服务端校验对象与版本；草稿文本走专用数据，不混作已保存事实。切换需明确保存/保留/放弃语义。
2. 模型上下文：最近完整用户/助手轮次、当前任务状态、相关确认资料、工具结果及来源；长历史按相关性/日期读取。明确字符预算，保持原始日志；日记按目标日期检索事实，不能仅靠20条窗口。模型只提出动作，工具回执才可完成任务。
3. 连续记录：先修照片讲述为追加式持续听写，再统一照片/日记的暂停、继续、容量上限和失败保留。编辑阶段的叙事默认留在任务中，明确切换才离开；废除绕过焦点的宽泛关键词路由。
4. 个人资料与记忆唤醒：记录用户确认的称呼、表达偏好与纠错，按任务加载相关片段，保留来源、修订与删除。照片里的角色不自动当用户本人。需要工具返回后再生成简短自然回复的有限工具循环。
5. 情绪与表达：将声学提示作为短时、不确定线索，与文本/用户偏好共同决定语气；不自动固化为长期人格。之后再验证TTS是否支持预期的情绪控制，不将文字语气等同声学实现。

第一条验收场景：上传照片→选择小安整理→连续讲三句并停顿→暂停后原话完整追加→补充人物/时间→保存且返回回执→文字和语音按相同条件检索→选图继续讲述→按当天已讲事实生成并保存日记→刷新可恢复。过程中出现“拍了视频/上传照片”等叙事不跳走；保存失败不报成功，重试不重复写入；切换照片不串稿。

测试分层：确定性状态与工具集成→假识别事件的UI验证→真实Qwen语义样本→部署后自然语音与移动视口。暂不将提醒、主动问候、端侧新模型或GPU接入加入本条闭环。
