# 场景人工提交与按需连续性投影 V1

状态：目标设计与实施计划，2026-10-13。第一项窄范围投影已实现：已确认计划的光影基线及地点/时段 ID 进入分镜帧快照，当前镜头视频/R2V 润色会读取匹配的有界基线，并保持上下文 JSON 可解析。场景人工提交、跨地点共享世界光、镜头交接和渲染前校验仍未实现。

关联：[现有地点/时段契约](2026-10-11-plan-continuity-and-entity-reextraction-v1.md)、[上下文入口核对](../research/2026-10-13-asset-mention-sync-and-prompt-context-summary.md)、[状态与校验研究摘要](../research/2026-10-13-episode-shot-continuity-state-and-validation-summary.md)。

## 目标与证据

### Observed（代码事实）

- 拍摄计划已保存 `place_continuity_id`、`time_continuity_id` 和每个地点/时段组合的光影基线；镜头默认继承，用户选择独立光影并填写原因后才覆盖非空字段。
- `EpisodeVisualContext` 将确认计划投影到场景与镜头。分镜帧只复制部分当前场景/镜头字段；分镜细化会读相邻帧文字和更宽的导演上下文。图片渲染与视频任务创建没有结构化跨镜头状态校验。
- 项目资产出图不附加 Director JSON，但目前也不自动投影剧集视觉风格；系列资产和各类润色入口采用不同上下文策略。现有数据不能证明提供商输出具有视觉连续性。

### Direct implication（直接推论）

同一段黄昏跨两条室外街道时，仅按地点/时段组合管理基线，无法保证两处引用同一个世界光源。树荫下与树荫外的亮度差异也不能仅凭文字差异判定为冲突。LLM 每次重新解析整集可能提出不同的关系，但提议不应成为已确认状态的自动更新。

## 决策

1. **每场人工提交是确认边界。** LLM 生成场景和镜头草稿；代码从已确认状态投影本场上下文。提交界面展示本场实际会使用的状态、参考素材和提示词，以及定位到字段的冲突。用户确认后，保存不可变的本场输入快照和出场状态。编辑或重新生成草稿不改写已提交场景；重新提交创建新版本。
2. **状态分层，按需读取。** 剧集视觉风格与角色身份、时段世界状态、地点/局部区域状态、镜头交接状态分别持有权威字段。出图请求只获得本次主体、地点、时段与镜头所需的投影。完整 Director JSON 可供分析 LLM 阅读，不作为图像/视频提示词的固定后缀。
3. **LLM 只提议，不确认。** 正常的状态继承、版本比对、输入投影和结构化校验不调用 LLM。只有缺少依据的地点归一、含糊转场或创作判断，用户才可选择 AI 辅助；模型结果仍是待审提议。不要让同一个 LLM 在提交时重新解释自己刚生成的全文作为唯一校验依据。
4. **结构化证据优先。** ID、版本、枚举状态和显式转场事件可以校验；自然语言近义或文字不同不能单独构成冲突。缺少世界方位、人物姿态或上一场状态时报告 `not_assessable`，不猜测也不宣称通过。

## 最小状态契约

| 层级 | 目标字段与权威 | 本场如何使用 |
| --- | --- | --- |
| 剧集 | 已确认视觉风格版本、角色身份/造型版本、系列资产引用 | 角色与场景参考图继承相关视觉设定；剧情事实仍以本集确认为准。 |
| 剧情时段 | `time_continuity_id`、状态版本、日光阶段、太阳世界方位（可未知）、天空光、天气及来源 | 同一连续时段的室外地点共享世界光；时间跳跃或有来源的天气变化进入新状态/转移。 |
| 地点 | `place_continuity_id`、地点版本、空间朝向（可未知）、固定画内光源、遮挡区域 | 跨街切换地点；同街不同机位继续引用同一地点。地点资产 ID 与连续性 ID 各司其职。 |
| 本场 | 计划 `scene_id`、时段/地点引用、局部区域及遮挡、`state_in/state_out`、所用基线版本 | 树荫改变局部受光，不覆盖太阳状态；确认后向下一场传递出场状态。 |
| 本镜 | `shot_id`、机位/景别、人物与道具起止状态、动作阶段、局部创作偏离 | 连续切镜比较相邻镜头边界；机位改变可改变画面左右光向，不改变太阳世界方位。 |

状态字段应带 `source`（剧本事实、已确认导演/计划、用户决定或模型提议）、`revision` 与 `certainty`。未审定的模型提议不可升级为已确认事实。首次实现只结构化能稳定判定的字段，例如时段/地点引用、持剑手、剑出鞘状态、道具归属；姿态和空间位置可以先保留有来源的简短描述与 `unknown`，不强制用户填写坐标。

## 场景提交行为

1. 打开本场草稿：读取已确认的剧集视觉版本、当前时段状态、地点状态、上一场已提交的 `state_out`，合成本场 `state_in`。若是连续切镜，读取上一镜结束状态；若为时间省略、闪回或转场，使用显式转场类型和新的时段/地点引用。
2. 编辑本场：镜头提示词、参考图与局部区域由用户或 LLM 修改。变更只影响草稿。基线继承和明确的结构化冲突由代码实时计算；同一世界光下的树荫/檐下不要求“独立光影原因”。
3. 提交前预览：展示本次图片/视频请求将携带的简短投影、实际选定素材变体、来源版本和差异。`conflict` 定位到场景/镜头及字段；`not_assessable` 说明缺失证据；有意偏离须明确选择并记录理由。只因文字表述不同不阻断提交。
4. 人工提交：原子保存本场确认快照及 `state_out`，固定导演、计划、时段、地点、资产和镜头版本。若依赖版本在预览后变化，要求刷新差异再提交；不静默重算已确认快照。
5. 后续场景：从前一场确认快照继承需要连续的状态。上游重提炼、导演或计划更新后，将受影响草稿标记待重新投影；已提交场景保持原版本，重新提交才接受新状态。

## 输入投影与调用预算

| 入口 | 最小投影 | 常规额外 LLM 调用 |
| --- | --- | --- |
| 角色定妆 | 角色身份/造型、剧集画风、选定参考与用户提示词 | 无；生成设计草稿时才调用设计 LLM。 |
| 场景参考图 | 场景资产、地点与时段状态、局部区域、剧集画风、参考与提示词 | 无。 |
| 分镜图 | 当前镜头、相关人物/道具状态、地点与时段光、前镜结束到本镜开始的交接、参考图 | 无；用户选择细化/润色时才调用 LLM。 |
| 视频 | 当前镜头起止状态、切镜/转场类型、输入图与参考、相关声音/动作约束 | 无；用户选择视频润色时才调用 LLM。 |

代码生成确定性投影并记录字段来源、长度和版本。提交前预览必须与实际发送给提供商的输入来自同一快照；不可展示一份摘要、提交时另行拼接不同的全文。分镜 `assembled_prompt` 的消费者需先确认，再决定沿用或废弃，避免双份提示词权威。

## 校验结果与界面

校验返回 `pass | conflict | not_assessable`，附 `scene_id`、可选 `shot_id`、字段、当前值、继承值、双方来源版本及建议操作。显式转场和用户确认的偏离作为有范围的例外保存，不能豁免整集。界面以本场为单位展示少量差异与预览；继承正常的字段折叠展示，不把所有状态展开成必填表格。

## 实施计划

当前进度：已完成第一阶段中的“基线经 `EpisodeVisualContext` 到分镜帧保存”的投影回归测试，并接通当前镜头的有界视频/R2V 润色上下文；这不等于完成时段世界状态、场景提交或提供商请求校验。

1. **契约与测试夹具。** 在 `models.py` 设计可版本化的时段世界状态、本场与镜头交接状态及校验结果；用“长街夕阳 → 梧桐树荫 → 另一街同一黄昏”编写失败测试。另测换机位、黄昏到夜间、拔剑后持剑手/空剑鞘、缺证据及明确转场。成功标准：同一时段跨街光照继承，局部遮挡不误报，真实结构冲突可定位。
2. **确定性投影。** 在 `pipeline.py` 从已确认计划构建时段、地点、本场和本镜投影，保留来源版本；修复分镜帧丢失连续性 ID/基线来源的问题。先覆盖一个场景的确认与下一场读取，旧数据以 `unknown` 兼容。成功标准：同一输入和版本产生相同投影，无额外 LLM 调用。
3. **提交校验与版本固定。** 在场景提交 API 保存人工确认快照和 `state_out`；加乐观版本校验、差异预览和范围明确的例外。成功标准：LLM 重新生成不能覆盖已提交状态，依赖变化不能静默通过。
4. **生成输入接通。** 分别接入场景图、分镜图、视频任务的投影快照；在适配器边界测试最终 payload 的字段、来源和长度。成功标准：预览与实际请求一致，完整 Director JSON 不进入图片/视频请求，必要状态不会只停留在 `assembled_prompt`。
5. **界面与视觉验证。** 场景提交界面只显示冲突、不可判定项和最终输入预览；用户可确认有意转场。运行前后端流程测试，再用实际跨街/树荫镜头人工评估生成结果。通过契约测试只证明输入一致，不宣称像素结果一致。

主要路径：`src/apps/comic_gen/models.py`、`pipeline.py`、`prompt_assembly.py`、`storyboard.py`、`api.py`、场景/分镜提交前端与对应测试。每阶段保持可运行，先完成窄场景再扩展到全剧；不把提炼器身份归一或视频提供商画质问题混进本次改造。
