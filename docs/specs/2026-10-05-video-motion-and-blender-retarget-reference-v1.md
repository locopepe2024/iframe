# 视频动捕与 Blender 动作重定向参考 v1

## 目的与证据边界

记录用户提供的 Rokoko Video、Plask、Animate 3D、Rokoko Studio Live for Blender 和 Expy Addon 参考，作为动作复刻后续调研与测试输入。

本次仅整理讨论结果，没有访问官网、GitHub 或运行这些工具。下列产品定位属于待权威来源复核的参考信息；免费额度、许可证、导出权限、版本兼容性及实际动作效果均未验证。不得将“免费”“插件开源”“视频提取服务可自行部署”视为同一能力，也不得承诺武打动作能自动完美复制。

## 当前需求与约束

- 优先完成动作复刻，再补电商与动作复刻的字幕、ASR、配音和音频合成。
- media 主机为 CPU 环境，当前使用 Blender 4.5.9 和自定义白模 rig。
- 优先评估 GitHub 上可自行部署的项目，暂不依赖友商在线服务。
- 原始 motion-track 保持只读，人工关键帧修正保存在 review overlay。
- 视频模型参考视频输入，不等于 provider 已开放 pose/depth control 接口。

## 视频动捕产品参考

| 参考 | 讨论中的定位（待复核） | 对本项目的参考价值 | 未验证项 |
|---|---|---|---|
| Rokoko Video | 商业视频动捕服务 | 视频上传、动作预览、骨架输出与重定向的用户流程 | 免费额度、FBX 导出权限、模型是否可自行部署、武术切片效果 |
| Plask | 商业在线动捕服务 | 视频到骨架动画的处理流程与审核方式 | 免费套餐范围、导出权限、许可证、可部署性与动作精度 |
| Animate 3D | 名称通常指 DeepMotion 服务；不应未经核实称为开源平台 | 视频动捕及动作清理流程 | 确切产品身份、商业条款、导出能力与可部署性 |

上述服务目前仅作产品参考，不作为实施依赖。免费服务不等于开源；可导出 FBX 不等于动作复刻准确。

## Blender 插件参考

| 参考 | 拟评估能力 | 与当前缺口的关系 | 未验证项 |
|---|---|---|---|
| Rokoko Studio Live for Blender | 源骨架到目标骨架映射、重定向、动画烘焙 | 可作为标准动画驱动自定义白模的对照实现 | 当前仓库及许可证、Blender 4.5.9 兼容性、离线/无账号重定向、CPU 批处理、自定义骨架适配 |
| Expy Kit / Expy Addon | 已知骨架体系之间的转换与映射，例如 Mixamo、Rigify | 可参考骨架命名、rest pose 对齐和转换实现 | 准确项目名称与仓库、许可证、维护状态、骨架支持范围、自定义白模适配 |

安装插件不等于已具备正确的重定向。是否采用插件，需经过源码审查和运行验证；插件中的映射逻辑也可作为自有编译器的参考，但需遵守许可证。

## 职责分层

```text
源视频
  → 目标人物跟踪
  → 姿态、身体朝向与轨迹求解
  → 人工关键帧复核
  → 动作清理与接触修正
  → 标准骨架动画
  → 骨架重定向
  → Blender 白模动画 / 可编辑动画
  → 视频模型参考输入
```

视频动捕负责从画面恢复动作证据。重定向插件负责把已有骨架动画映射到目标 rig。若源动画已存在肩、髋、腿或转身错误，重定向工具不能被假定会修复它们。

## 风险与假设

- 假设：已知正确的 BVH/FBX 可用于隔离提取误差与 rig 重定向误差。
- 假设：快速转身、腾空、宽松衣袖、持剑、镜头运动和剪辑可能降低视频动捕可靠性；具体影响需逐素材测试，不能直接归因。
- 未证明：任何上述工具能准确还原指定电影中的武侠招式。
- 未证明：标准动画文件能无适配驱动当前白模 rig。
- 武器、手指和御剑视觉效果需独立轨道；不能仅凭人体骨架动画宣称完整招式复刻。

## 下一阶段测试计划

### 1. 权威来源核实

确认准确 GitHub 仓库、许可证、版本、维护状态、Blender 4.5.9 支持、离线重定向与 headless 批处理能力。核实结果需记录来源、访问日期和对应版本；未核实前不安装或认定兼容。

### 2. 标准动画对照线

选择允许本项目使用的 BVH/FBX，记录许可证、文件 hash、骨架定义、FPS、单位和坐标系。动作至少覆盖中立、抬臂、转身、腿外展；跳跃与落地在基础映射通过后加入。

```text
已知正确的 BVH / FBX
  → Blender 导入并确认源动画
  → 插件重定向 / 自有重定向对照
  → 当前白模 rig
  → 单帧投影与连续动画验收
```

### 3. 验收与故障定位

- 验证左右映射、rest pose、骨骼局部轴、单位、root/pelvis、肩臂连接和膝盖方向。
- 检查转身是否保留、动作关键时刻是否一致、脚部接触/脚滑/穿地。
- 保留源动画与目标动画对照、映射配置、警告及测量结果。
- 标准源动画正确但白模错误：定位映射/rest pose/骨架轴/求解器边界。
- 标准动画通过但视频轨迹失败：继续检查检测、深度、身体朝向及轨迹到源骨架转换；不能仅由一组结果断言唯一根因。
- 不设“自动完美复制”验收；量化阈值在坐标及测量口径固定后确定。

### 4. 采用决策

仅在自定义 rig 测试通过后决定直接使用插件、借鉴实现或保留自有重定向。标准动画对照不取代真实视频动作复刻验收。

### GVHMR CPU 姿势能力验证（2026-10-06）

**范围：** 在 media 主机（4 CPU 核、15 GiB RAM、无 GPU）独立运行 GVHMR 上游版本
`ee960bb6e2ea2d381aa97f08e9b71ef320b624b1` 的预处理阶段。实验目录为
`/home/ubuntu/gvhmr-cpu-validation`，未接入 iframe 运行时。GVHMR 许可证限制为教育、
研究及非营利用途；本实验结果不能作为生产集成许可。

**运行观察：** 输入是原片前 3 秒，30 fps、720×854、90 帧，SHA-256 为
`49c73ccaaa2bf36d89c234006417320f7ffd5f9c5d58e6eafd227e38d4fa8602`。
YOLO 人体追踪耗时 120.6 秒、峰值 RSS 约 1.08 GiB；ViTPose 耗时 381.9 秒、
峰值约 5.22 GiB；HMR2 图像特征提取耗时 439.5 秒、峰值约 5.50 GiB。
三阶段均使用 PyTorch 2.3.0+cpu、4 线程，姿势与特征阶段 batch size 为 1。
输出分别为 90 帧人体框、`(90, 17, 3)` 的 2D 关键点及 `(90, 1024)` 的图像特征；
两个张量均无非有限值。2D 关节点置信度中位数约 0.915，1530 个点中有 16 个低于 0.5。

**抽帧观察：** 0、1、2 秒的姿势叠加图在站姿、低重心展开和起身转向时大体贴合人物。
这只是三帧目视检查，不能证明整段连续性、身体朝向、深度、旋转或落地质量。

**未验证：** 主机没有经授权取得的 `SMPLX_NEUTRAL.npz`，因此没有运行 GVHMR 原生
3D 动作推理，也没有生成 SMPL-X 关节轨迹或 Blender 白模重定向结果。前 3 秒是
执行冒烟测试，不覆盖完整 18.53 秒原片的旋转验收。不能据此声称 GVHMR 已具备
本项目所需的姿势复刻能力。

**下一步验收：** 取得授权的 SMPL-X 模型后，以 SimpleVO 处理镜头运动，先核对
原生动作输出的坐标系、左右方向、root 轨迹、跳跃与接触，再记录旋转动作的精确
源时间段，逐帧对照原片。只有原生动作通过复核后，才进入白模骨架映射和连续动画验收。

### GVHMR SMPL-X 解码诊断（2026-10-08）

**运行观察：** 用户提供的 `models_smplx_v1_1.zip` 含 `SMPLX_NEUTRAL.npz`；包内
`version.txt` 写的是 `Version 1.0`，与压缩包名不一致。仅将 neutral `.npz` 安装到
media 独立实验目录，文件 SHA-256 为
`376021446ddc86e99acacd795182bbef903e61d33b76b9d8b359c2b0865bd992`。
SMPL-X 加载与骨架构建通过。90 帧原生动作解码诊断耗时 1.71 秒、峰值 RSS
1,048,772 KiB；`global` 与 `incam` 均导出有限值的 `(90, 22, 3)` 关节轨迹。

**证据边界：** 这次使用了静态相机假设，只验证参数解码及导出链路。实验产物标记
`static_camera_assumed_for_diagnostic=true`、`world_trajectory_validated=false`。
原片相机有运动，而 SimpleVO 在该素材上无法恢复完整相机轨迹。因此当前不能把
`global` 输出当作真实世界轨迹，也未证明姿势、转身、跳跃或落地与原片一致；
尚未做 Blender 白模重定向。下一步需恢复相机观测，或以已核实的固定机位素材
单独测试，再对源帧和 3D 关节做时间对齐、朝向及接触核对。
