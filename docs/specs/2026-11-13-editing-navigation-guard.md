# 剪辑模块离开保护

## 目标

剪辑计划存在未保存修改时，离开剪辑模块必须由用户选择保存、放弃或留在当前页面。浏览器卸载继续使用原生 `beforeunload` 提示。

## 行为与边界

- 仅拦截从 `#/editing`（含 query）离开到其他应用路由；`#/editing?tab=materials` 与 `#/editing?tab=edit` 属于模块内导航，保留草稿且不提示。
- 应用内路由和浏览器历史触发的 hash 变化均先恢复地址栏到剪辑路由，再显示剪辑页自己的离开对话框；取消后地址栏、视图与草稿保持一致。
- “保存并离开”提交当前计划；保存失败时留在剪辑页、保留草稿并展示错误，允许重试。
- “放弃并离开”仅在没有在途操作时启用。放弃后导航到最初请求的目标。
- 如果保存或合成在途时用户请求离开，先阻止卸载并保留目标；操作成功后继续该导航，失败时留在剪辑页并允许用户决定。不得因离开请求清除或替换在途请求状态。
- 用户取消待处理离开后清除目标；后续操作完成不得触发旧导航。
- `beforeunload` 仍保护关闭标签页/刷新；内部素材标签不触发此提示。

## 实现边界

- 在应用 hash 路由处理器与 EditingPage 之间添加轻量的内存导航守卫注册点，不改变其他模块的路由协议。
- 守卫只暴露当前 dirty/busy 状态和请求离开的回调；对话框及保存/放弃操作仍由 EditingPage 持有。
- 采用一次性目标许可恢复用户确认后的导航，避免 dirty 状态异步更新导致二次拦截。

## 验收

- 自动化验证外部 hash 离开受拦截、内部标签切换放行、确认离开只放行目标一次。
- UI 验证取消保持 dirty 草稿与路由，放弃导航到目标，保存成功导航，保存失败保留草稿并可重试；保存/合成中离开不会卸载组件或丢失请求响应。
- 运行剪辑相关 UI 测试、TypeScript 检查及生产构建。

## 当前状态
