# Storyboard 首帧与分镜设计 Skill 盘点及加载 V1

状态：设计规格；不声称新增 Skill 或加载器已经实现。承接 `2026-10-22-storyboard-shot-design-inheritance-and-performance-v1.md`。

## Observed

产品里的 Storyboard 是每个分镜的首帧图。代码里 `storyboard-analysis` 另有一个同名的上游流程：它从剧本生成镜头草稿字段，再由独立的 `render_frame` 路径生成图片。下面将两者明确区分。

当前存在两套独立目录和调用边界：

| 阶段 | 目录及入口 | 当前条目 | 实际作用 |
| --- | --- | --- | --- |
| 上游从剧本拆镜 | `director-tasks.json`；`StoryboardGenerateDialog` | 悬念呈现、动作拆解、情绪特写、对白调度 | 生成镜头草稿字段，不生成首帧图片；按导演计划转换时传空选择。服务端按阶段和 revision 冻结后交给草稿任务 |
| Storyboard 首帧图 | `StoryboardFrameEditor`；独立 `render_frame` 请求 | 当前无这四张方法卡的首帧专用加载入口 | 当前分镜 0.00 秒的可见主体、场景、站位、表情、景别、机位、构图和光线；不承载动作过程、对白调度或声音 |
| 分镜视频/R2V 润色 | `catalog.json`；`OptimizerSelector` | MiniMax H3 导演、Seedance 提示词、Seedance 运镜、连续分镜与风格一致性、导演风格与视觉叙事 | 复选框提交 ID；本地 GPT/Qwen/DeepSeek/GLM 路径按目录文本拼入优化契约 |
| Agent 对话 | 同一 `catalog.json`；`/skills` 安装状态 | 上述条目及角色/短片/图片/商品工作流 | `creative_guidance` 依据 owner 的已启用安装项和请求文字筛选；不是分镜润色复选框的加载规则 |

代码事实：分镜润色显式选择仅验证 ID 存在于目录，没有核对该用户的安装状态、Skill 目标模型或阶段；因此不能称复选框为“已安装 Skill”。`optimization_skills` 缺省时，本地优化器默认载入 H3 导演；显式空数组则不载入。当前前端初始选择固定为 H3 导演，与目标视频模型无关。MiniMax 官方 Context-IR 是优化器，不是 Skill；其当前预览路径只附加“应用所选 Skill”的句子，未将选中 Skill 的目录指导文本展开。目标模型的硬输出契约仍另行存在。

当前目录没有微表情时序 Skill。`storyboard-emotion` 是上游拆镜方法卡，虽可建议用特写呈现情绪，但它不是首帧图片 Skill，也不包含单镜视频内的触发、变化、保持、恢复。其余三张方法卡也只参与拆镜：悬念呈现决定画面揭示范围，动作拆解决定取哪个可见动作状态，对白调度决定说话/回应镜头的位置；首帧只接收其中已确认、在 0.00 秒可见的结果，不接收方法卡全文、台词过程或动作时间线。`sequence-continuity` 是多镜规划指导，不等于已确认参考图的结构化投影规则。`viewpoint-staging`、`audiovisual-strategy`、`continuity-review` 属于导演拍摄计划阶段；短片五阶段、竖屏短剧结构属于 Creative Agent 的整体规划；角色身份 Skill 属角色工作台。它们可提供上游已确认结果，不应在单镜优化时自动全文加载。

`seedance-2-5-fight-director` 及所举“30 秒女刀客对男枪客、古殿到云海、长枪脱手”示例不在当前 iFrame Skill 目录中；这个例子说明的是另一种问题：它以完整创作请求为输入并产出可复制提示词，不能据此认定它有逐镜设计节奏、机位、景别、表情或转场的能力。现有五个视频润色选项中，H3 导演偏向模型结构与提示词编写，Seedance 提示词偏向全文整理，Seedance 运镜确实包含起始景别、角度、路径、速度和落幅的设计规则，连续性偏向多镜规划，导演风格偏向整体视觉意图。它们不能仅凭名称替代各个分镜设计字段的专门决策。

## 分镜设计能力与层级

Skill 的安装、名称和可生成完整提示词，都不证明它做出了可执行的分镜设计决策。准入问题是：给定镜头任务和约束，它是否能提出**可比较、可修改、可保存的字段结果**，并解释这个选择怎样服务叙事。没有字段结果的完整提示词工作流可以留在自由创作或最终编译环节，但不应标为“节奏设计”“机位设计”或“微表情设计”。

| 层 | 设计问题与输出字段 | Storyboard 首帧边界 |
| --- | --- | --- |
| 0. 已确认输入 | 剧情事件、角色/场景身份、参考用途、连续性 ID、画幅、时长、限制和镜头任务；这是设计依据 | 取当前镜头 0.00 秒状态 |
| 1. 表演与画面事件 | 动作的起止状态和关键阶段；微表情的触发、可见变化和落点；特效的出现条件、位置、强弱变化及与主体的遮挡关系 | 只使用起始姿态、静态表情及该时刻可见的效果 |
| 2. 摄影与时间组织 | 景别、机位/轴线、构图、运镜路径、速度、镜内节奏、跨镜切点及转场关系；指出每项如何呈现第 1 层的信息 | 只使用起始景别、机位、构图、视线和站位；无运动路径、切点或转场时间线 |
| 3. 提示词编译 | 将 0–2 层已选字段组织为目标模型允许的格式，并检查参考媒体映射和能力 | 编译图片提示词；不把视频过程写进首帧 |

能力应逐项评估，不必机械要求每个 Skill 只负责一个字段。一个真正的“打斗镜头设计”Skill 可以联动动作、特效、机位和节奏，但必须输出各字段的具体决策及依赖关系，供用户逐项审核；若只把一段打斗需求写成更长的可复制提示词，它属于第 3 层的创作/表达工作流，不是第 1–2 层的设计器。

现有目录的能力判断：`seedance-camera` 已有景别、机位、路径、速度、落幅规则，可作为摄影设计的起点，但目前返回的是一条运镜提示词，尚未形成结构化镜头建议；`sequence-continuity` 可辅助跨镜状态审阅，不能代替节奏或转场设计；`director-style` 可给视觉意图，不负责确定当前镜头的机位和切点；`minimax-h3-director`、`seedance-prompt` 主要负责模型提示词表达，不能因为产出完整文本就当作所有设计层的合成替代。微表情时序、特效与主体关系、镜内/跨镜节奏、转场决策目前没有对应的专门分镜 Skill 或字段输出合同。

验收样例不看提示词是否更长，而看决策是否落地：同一动作给出为何采用远景还是近景、相机从哪一侧观察、何时移动或保持、特效何时遮挡/让出动作、微表情在何种景别可读、哪里切镜及转场保留什么状态。Storyboard 首帧只验收起幅中可见的部分。各建议应能独立采纳或拒绝；未采纳时原字段与提交请求不变。

## 加载原则

1. **先分任务，再分模型。** 上游拆镜、Storyboard 首帧图片、单镜视频、跨镜审阅分别有不同输入和输出合同；Skill 只在声明的阶段、媒体和任务范围可选。模型目标决定格式/能力硬约束，优化器决定调用提供方，两者不作为创作 Skill。
2. **默认只加载必需合同。** 用户可选择创作方法；系统可建议相关项但须显示默认状态和原因。没有显式选择时不得暗中加载全部同目标 Skill。旧请求的自动映射在迁移期保留并标明 legacy，直到调用者传明确选择。
3. **源数据优先。** 已确认剧本/导演计划、场景/角色/参考变体快照与本镜字段是证据和约束，不作为 Skill 文本复制。Skill 只能针对授权字段提出可审阅改动；不能越过用户确认的一致性类别，也不能把前镜动作、对白、角色描述通过参考视觉投影带进本镜。
4. **服务端冻结和回显。** 提交携带 Skill `id + revision`；服务端验证目录、阶段、模型、模式、预算和互斥关系，冻结本次指令文本及来源。预览返回实际加载列表、版本、作用字段和完整模型输入；提交以预览 token 锁定相同内容。变更 Skill、参考或镜头字段须重新预览。
5. **组合顺序固定。** 硬模型/安全合同 → 已确认来源和本镜约束 → 所选任务 Skill → 模型适配 Skill → 用户本次反馈。重复作用同一字段时合并为一个候选差异，冲突显示给用户，不靠后一个自然语言段落覆盖前一个。

## 建议的分镜 Skill 组

| 任务组 | Skill | 默认与边界 |
| --- | --- | --- |
| 上游从剧本拆镜 | 现有四张 `storyboard-*` 方法卡 | 仅生成镜头草稿；用户按需选；导演计划转换不重跑方法卡；不得作为首帧图片 Skill 加载 |
| Storyboard 首帧图 | 当前镜头静态画面规则；后续可提炼首帧构图/可见状态 Skill | 只处理 0.00 秒可见的主体、表情、站位、景别、机位、构图、光线及画面边界；不加载动作过程、对白调度、声音或微表情时序 |
| 单镜镜头设计 | 新的模型中立镜头设计方法；Seedance 运镜仅作 Seedance 视频适配 | 景别、机位、构图、轴线、主运镜和起落幅；首帧不输出视频运动过程 |
| 跨镜连续性 | 现有 `sequence-continuity` 需收窄为审阅/建议；结构化继承仍由产品规则执行 | 显式连续性 ID 和已确认状态；缺 ID 不猜，不自动改前后镜 |
| 单镜表演 | 新的微表情时序 Skill；现有 `storyboard-emotion` 只做上游拆镜 | 视频中按可见性描述触发、变化、保持与落点；首帧只留起始可见状态，不能写入角色身份 |
| 导演风格 | 现有 `director-style` | 需要建立或刻意改变镜头表达时选择；已确认风格/光线默认继承，不自动改写基线 |
| 模型提示词 | H3 导演或 Seedance 提示词；官方 H3 IR 另作优化器 | 只用与目标模型相容的一项格式适配；H3 与 Seedance 适配不同时加载 |

暂不把对白调度、音效、动作物理全部拆成新 Skill。上游方法卡只负责镜头草稿，Storyboard 首帧与视频只读取各自相关的已确认字段；实际测试显示独立优化需求且无法由现有字段表达时再新增。

## 加载界面与迁移

上游从剧本拆镜入口显示“镜头草稿方法”；Storyboard 首帧入口只显示静态画面相关能力；视频分镜入口显示“当前镜头优化”，按镜头、连续性、表演、风格、模型适配分组。每项标出适用首帧/视频、目标模型、作用字段与来源。目标模型或生成模式变化时重新计算建议，只保留仍兼容的用户选择；不可用项解释原因。当前被选中的 H3 导演不应在 Seedance 镜头上保持默认选中。

先修正现有五项的模型过滤、实际加载回显和 IR 路径一致性，再定义第 1–2 层结构化提案合同。按缺口依次评估镜头/节奏、微表情、特效可读性和转场方法；能由现有方法给出合格字段结果的，先适配输出合同，不按名称重复造 Skill。`director-tasks.json` 与 `catalog.json` 可以保留各自存储，但应通过同一只读能力描述和预览契约向前端解释阶段、版本、适用范围；不要把已安装 Agent Skill 状态冒充本次分镜选择。

## 验收

- 按计划转换无可选拆镜方法；从剧本拆镜只加载用户所选、版本匹配的方法，输出镜头草稿而非首帧图片。
- Storyboard 首帧图片请求不加载四张上游拆镜方法卡，不出现微表情时序、对白调度或动作过程；只使用当前分镜起始时刻可见的已确认字段。
- H3、Seedance、首帧和视频各自只展示兼容 Skill；未选中的 Skill 文本不进入模型输入。空选择与缺省旧请求可区分。
- 本地优化器与官方 IR 的预览均显示实际加载指令；若官方 IR 不能承载某 Skill，应禁用该组合并说明，而非显示已选却不加载。
- 仅选择微表情时序时，人物身份、服装、场景、光线、机位、参考媒体、其他镜头不变；首帧没有完整时序，视频包含可见的起止变化。
- 标为“节奏、机位、微表情、特效或转场设计”的能力必须返回相应字段的具体候选及依据；仅返回扩写后的完整提示词，不算通过设计能力验收。
- 预览与提交的 Skill ID、revision、冻结文本、镜头/参考版本一致；任一变化使旧预览失效。行为测试只证明加载和数据边界，视觉效果仍需实际多镜验证。
