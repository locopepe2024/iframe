# 故事板与分镜设计 Skill 盘点及加载 V1

状态：设计规格；不声称新增 Skill 或加载器已经实现。承接 `2026-10-22-storyboard-shot-design-inheritance-and-performance-v1.md`。

## Observed

当前存在两套独立目录和调用边界：

| 阶段 | 目录及入口 | 当前条目 | 实际作用 |
| --- | --- | --- | --- |
| 从剧本设计故事板 | `director-tasks.json`；`StoryboardGenerateDialog` | 悬念呈现、动作拆解、情绪特写、对白调度 | 仅从剧本设计模式可选；按导演计划转换时传空选择。服务端按阶段和 revision 冻结后交给故事板任务 |
| 分镜视频/R2V 润色 | `catalog.json`；`OptimizerSelector` | MiniMax H3 导演、Seedance 提示词、Seedance 运镜、连续分镜与风格一致性、导演风格与视觉叙事 | 复选框提交 ID；本地 GPT/Qwen/DeepSeek/GLM 路径按目录文本拼入优化契约 |
| Agent 对话 | 同一 `catalog.json`；`/skills` 安装状态 | 上述条目及角色/短片/图片/商品工作流 | `creative_guidance` 依据 owner 的已启用安装项和请求文字筛选；不是分镜润色复选框的加载规则 |

代码事实：分镜润色显式选择仅验证 ID 存在于目录，没有核对该用户的安装状态、Skill 目标模型或阶段；因此不能称复选框为“已安装 Skill”。`optimization_skills` 缺省时，本地优化器默认载入 H3 导演；显式空数组则不载入。当前前端初始选择固定为 H3 导演，与目标视频模型无关。MiniMax 官方 Context-IR 是优化器，不是 Skill；其当前预览路径只附加“应用所选 Skill”的句子，未将选中 Skill 的目录指导文本展开。目标模型的硬输出契约仍另行存在。

当前目录没有微表情时序 Skill。`storyboard-emotion` 是故事板阶段的情绪特写方法，负责选择可见信息和镜头，不包含单镜视频内的触发、变化、保持、恢复。`sequence-continuity` 是多镜规划指导，不等于已确认参考图的结构化投影规则。`viewpoint-staging`、`audiovisual-strategy`、`continuity-review` 属于导演拍摄计划阶段；短片五阶段、竖屏短剧结构属于 Creative Agent 的整体规划；角色身份 Skill 属角色工作台。它们可提供上游已确认结果，不应在单镜优化时自动全文加载。

## 加载原则

1. **先分任务，再分模型。** 故事板生成、单镜首帧、单镜视频、跨镜审阅分别有不同输入和输出合同；Skill 只在声明的阶段、媒体和任务范围可选。模型目标决定格式/能力硬约束，优化器决定调用提供方，两者不作为创作 Skill。
2. **默认只加载必需合同。** 用户可选择创作方法；系统可建议相关项但须显示默认状态和原因。没有显式选择时不得暗中加载全部同目标 Skill。旧请求的自动映射在迁移期保留并标明 legacy，直到调用者传明确选择。
3. **源数据优先。** 已确认剧本/导演计划、场景/角色/参考变体快照与本镜字段是证据和约束，不作为 Skill 文本复制。Skill 只能针对授权字段提出可审阅改动；不能越过用户确认的一致性类别，也不能把前镜动作、对白、角色描述通过参考视觉投影带进本镜。
4. **服务端冻结和回显。** 提交携带 Skill `id + revision`；服务端验证目录、阶段、模型、模式、预算和互斥关系，冻结本次指令文本及来源。预览返回实际加载列表、版本、作用字段和完整模型输入；提交以预览 token 锁定相同内容。变更 Skill、参考或镜头字段须重新预览。
5. **组合顺序固定。** 硬模型/安全合同 → 已确认来源和本镜约束 → 所选任务 Skill → 模型适配 Skill → 用户本次反馈。重复作用同一字段时合并为一个候选差异，冲突显示给用户，不靠后一个自然语言段落覆盖前一个。

## 建议的分镜 Skill 组

| 任务组 | Skill | 默认与边界 |
| --- | --- | --- |
| 故事板从剧本设计 | 现有四张 `storyboard-*` 方法卡 | 按剧本需要建议，用户选；导演计划转换不再重跑方法卡 |
| 单镜镜头设计 | 新的模型中立镜头设计方法；Seedance 运镜仅作 Seedance 视频适配 | 景别、机位、构图、轴线、主运镜和起落幅；首帧不输出视频运动过程 |
| 跨镜连续性 | 现有 `sequence-continuity` 需收窄为审阅/建议；结构化继承仍由产品规则执行 | 显式连续性 ID 和已确认状态；缺 ID 不猜，不自动改前后镜 |
| 单镜表演 | 新的微表情时序 Skill；现有故事板“情绪特写”只做上游镜头任务 | 视频中按可见性描述触发、变化、保持与落点；首帧只留起始状态，不能写入角色身份 |
| 导演风格 | 现有 `director-style` | 需要建立或刻意改变镜头表达时选择；已确认风格/光线默认继承，不自动改写基线 |
| 模型提示词 | H3 导演或 Seedance 提示词；官方 H3 IR 另作优化器 | 只用与目标模型相容的一项格式适配；H3 与 Seedance 适配不同时加载 |

暂不把对白调度、音效、动作物理全部拆成新 Skill。已有故事板方法卡和分镜字段可先覆盖；实际测试显示独立优化需求且无法由现有字段表达时再新增。

## 加载界面与迁移

故事板入口显示“故事板方法”；分镜入口显示“当前镜头优化”，按镜头、连续性、表演、风格、模型适配分组。每项标出适用首帧/视频、目标模型、作用字段与来源。目标模型或生成模式变化时重新计算建议，只保留仍兼容的用户选择；不可用项解释原因。当前被选中的 H3 导演不应在 Seedance 镜头上保持默认选中。

先修正现有五项的模型过滤、实际加载回显和 IR 路径一致性，再新增模型中立镜头设计及微表情时序 Skill。`director-tasks.json` 与 `catalog.json` 可以保留各自存储，但应通过同一只读能力描述和预览契约向前端解释阶段、版本、适用范围；不要把已安装 Agent Skill 状态冒充本次分镜选择。

## 验收

- 故事板按计划转换无可选故事板方法；从剧本设计只加载用户所选、版本匹配的方法。
- H3、Seedance、首帧和视频各自只展示兼容 Skill；未选中的 Skill 文本不进入模型输入。空选择与缺省旧请求可区分。
- 本地优化器与官方 IR 的预览均显示实际加载指令；若官方 IR 不能承载某 Skill，应禁用该组合并说明，而非显示已选却不加载。
- 仅选择微表情时序时，人物身份、服装、场景、光线、机位、参考媒体、其他镜头不变；首帧没有完整时序，视频包含可见的起止变化。
- 预览与提交的 Skill ID、revision、冻结文本、镜头/参考版本一致；任一变化使旧预览失效。行为测试只证明加载和数据边界，视觉效果仍需实际多镜验证。
