# 复刻流水线 Summary：可靠证据锁定、时序补全与验收闭环

日期：2026-10-29。用户已确认流程方向；本文是执行与验收约定，不表示整条产品流水线已经实现。目标是源视频约束下可编辑的Blender人物、动作、相机和场景；模糊或遮挡部分允许合理补全，但必须标记为推断。

## Observed

用户质量要求：动作对齐、人物比例正常且与原片动作关系一致、光影接近原片、轨迹稳定；前景遮挡/交互人物需要制作，远景无交互路人和物体简化。外貌无需精细还原。按场景资产、人物资产、动作迁移组织；同一场景输出白模和深度，保留可编辑骨架/相机。

用户确认：先锁定能确定的局部区域，再结合前后帧与锁定帧的清晰部分综合分析；短暂模糊采用姿态/运动插值，不要求先修复图片。自动识别、时序补全、交叉检验后仍无法确定且影响结果的内容，集中交给人工。最终按白模视频质量验收并局部修复。

现有实验：三张稀疏图的LLM接触全unknown；20帧加一个左右身份锚点后形成连贯阶段解释，但五个非锚点接触标签只一致2/5。不能把更多回答当更准确，也不能把流式请求成功当动作理解通过。64双脚腾空、右脚尖更高、左脚尖近地不承重，已由用户复核。根高度对照只证明部分采样几何可满足，未证明动作自然或全片通过。

## Canonical pipeline and gates

| 阶段 | 处理 | 交付与通过条件 |
|---|---|---|
| 0 原始输入 | 保留未经增强/插帧的源视频与逐帧PTS，记录缩放/裁剪/哈希 | 输入和时间映射可回查；重复帧不作为新证据 |
| 1 镜头与初始空间 | 分镜，区分运镜/变焦/裁剪；背景独立验证相机；建立尺度/地面候选与目标rig契约 | 参数来源和未知量明确；不跨切镜直接平滑；不要求先唯一解出真实相机 |
| 2 原图识别基线 | 人物/肢体身份、可见性、姿态、动作阶段；LLM与姿态模型分别输出候选 | 记录清晰可见、可见但模糊、遮挡、画外；关节点误差/命中率/覆盖率与身份错误分开 |
| 3 交叉检验与可靠局部锁定 | 综合背景相机、骨架几何、LLM片段解释、地面及人工事实 | 已确认事实为硬约束，估计为软约束，冲突不强锁；骨长/左右/父空间/坐标与投影可回放 |
| 4 时序联合补全 | 同镜头内融合当前帧可靠局部、前后清晰部位及锚点；补短缺口，分阶段保持峰值/腾空 | 补姿态/根轨迹而非编造清晰图；不全帧弃用、不改可靠区域迁就坏点；补全部分标明来源 |
| 5 异常人工复核 | 将自动分析与补全后仍有冲突的关键帧/短区间集中呈现 | 显示上下文、可靠区域、候选、问题与影响；复用旧标注并去重；不可见允许unknown，不要求猜坐标 |
| 6 可编辑白模 | 固定资产骨长、rest/父空间映射、重定向、相机/场景、分阶段IK | 支撑/滚动/抬跟/蹬离/腾空分开；近地不等于接触；超预算修正回查上游 |
| 7 输出验收 | 源/白模连续播放及事件对照，同场景视频与深度 | 动作/节奏、比例、镜头、轨迹、接触、遮挡、光影与可编辑性分项通过；不能只看RMSE |
| 8 定位修复与回归 | 将问题归属输入、识别、补全、相机、映射、接触或渲染层 | 记录首次失配边界，局部修复；重验相关段及已通过项；保存版本/哈希/来源 |

阶段1–3可交替受限校正；“锁定”是保留证据与约束，不是冻结身体，也不是把未经验证的相机/地面永远固定。片段理解是动作层的基本单元，单帧用于局部证据；提供连续图片本身不证明模型完成时序追踪。

## Direct implication

相同问题主要表现为证据可靠性、时序语义、相机与人体独立约束以及层间验收未形成闭环。旧规范已提出不少规则，此次重点是明确可执行先后关系、可靠局部锁定、剩余异常人工入口和白模回归验收。不能把所有失败归为相机，也不能把所有问题交给LLM或插值。

## Not yet proven / Hypotheses

未有统一原图人工真值集、全片识别准确率、LLM校准或完整A/B产能数据；流程调整是否显著提高效率仍待实测。单目焦距/深度耦合和遮挡的不唯一性仍在。历史经验与Addams相似不足以证明二者共享唯一或最大的根因。

## What would verify it

下一可执行单元：以46–65同镜头片段冻结源图/PTS与既有标注，建立逐关节可见性与证据状态（含来源、确认/估计/推断、版本）；同时保留独立相机证据。先给原姿态识别基线，再仅对低可信短缺口补全，使用未参与补全的清晰帧/事件做检验。人工队列只含去重后的剩余冲突，不重新提交全部帧。

产出版本化源/动作/相机/地面/rig契约、修复列表及可编辑blend；统一验收表逐项pass/fail/不可评。记录人工处理帧数/时间、自动覆盖率、阶段/身份错误、可见点几何、接触与最终白模通过项，才能判定效率是否改善。本轮只记录summary并更新入口，没有实现新产品UI或宣称流水线已上线。
