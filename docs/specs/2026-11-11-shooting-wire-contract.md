# Shooting-plan generation protocol audit and consolidation

An observed job failed on visual_intensity while retaining 8/9 steps. Previous jobs failed on container names, source ranges, information-design shapes and event references. Live raw rejected shot responses are not retained, so the exact earlier fields/repair progression remain unknown.

Before consolidation, the per-beat shot request contained full-scene/full-beat output instructions and a broad stage preset before a conflicting shots-only instruction. Only lighting had a complete schema. A handwritten chunk validator duplicated persisted models and stopped on the first issue. Rejection repair gave a reason without the prior response. Some malformed dialogue was silently dropped before validation; persisted-model constraints such as lengths and duplicate entity IDs were checked later. The consolidation below preserves the previously fixed event admission/cache recovery.

Consolidate generated shot fields as a projection of DirectorPlanShot field definitions, excluding server IDs and user-owned binding/override/crowd decisions. Derive envelope/schema/strict validation from this projection; reuse it for chunk and checkpoint admission. Keep source-covered structure separately owned by shooting_plan_stages. Active beat requests receive read-only scene/beat context and a shots-only schema, never full-scene generation instructions. Full-chunk adapter callers use the same shot contract and an explicit chunk envelope. No routing changes.

Collect bounded field/type/size/uniqueness and inspectable event-reference issues before one existing repair attempt. Repair includes bounded raw rejected JSON in assistant history and safe path/type feedback. Never guess aliases, drop unknown fields, discard malformed dialogue, replace event IDs or expand retries. Return safe owner-scoped diagnostic categories, field paths/counts and response size; no screenplay/ref values in ordinary logs. Stage paths identify the actual chunk/scene/beat rather than local envelope indices.

Preserve protocol v6 identity so the 8/9 checkpoint resumes. Reuse valid details; re-open only cached details failing the shared contract. All production data/keys stay untouched except normal user-triggered work. Verify with targeted failing tests, regression suite, network-isolated mock-provider image, and read-only replay of the live checkpoint; do not initiate paid calls. Deploy only when generation is idle.

## Aggregate admission

Scene questions can recur in every saved beat. Assembly deduplicates identical question strings in first-occurrence order before validating the chunk; it preserves distinct questions and leaves saved details unchanged. This prevents 13 beats carrying the same six questions, plus three structure questions, from exceeding the 80-item chunk limit despite only seven distinct questions. Distinct items beyond the limit still fail admission; no truncation is used to pass the chunk contract.

The pipeline carries all admitted chunk questions into the final plan rather than keeping only the first 20. Aggregate contract failures report a bounded `aggregate_contract` reason and finalization location. A completed checkpoint can be reassembled without generating shots again; a 14/14 saved-step count indicates generation completion, not necessarily final-plan admission. Actual retained-checkpoint replay verifies that the admitted raw shots and checkpoints remain unchanged and makes zero model calls.
