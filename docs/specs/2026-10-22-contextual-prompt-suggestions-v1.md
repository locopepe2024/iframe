## 范围与语义

所有用于撰写**创作描述、结构化设计字段、生成 Prompt、分镜动作或画面要求**的文本框，均可在光标处触发联想。名称、搜索、数字、密钥、文件路径、模型参数等输入框不自动接入；对白是否接入表演词典由对白工位单独声明。每个输入框显式声明 `station`、`task`、`field_id`、可引用资产类型和可执行动作，不通过占位文字、DOM 标签或标题猜测语境。

| 触发 | 候选 | 默认行为 |
| --- | --- | --- |
| `/关键词` | 当前字段适用的词条、配置面板、Prompt 模板及当前工位已实现的命令/Skill | 搜索和预览；确认后按条目声明的动作应用 |
| `@关键词` | **当前输入框参考 list 中已选的素材变体** | 在已选列表内定位并插入可辨认的引用 token；不搜索或添加资产 |
| `[槽位]` | 与槽位字段匹配的词条或选项 | 仅替换该槽位，不覆盖同名其他槽位 |

添加参考素材是输入框之外的独立操作：用户先从本地上传或资产库选择素材及变体，放入当前参考 list，再在输入框用 `@` 引用。`@` 不查询项目资产索引、平台库或上传文件列表，也不因命中而自动加入参考 list。列表为空时提示先添加素材；移出列表后，该变体不再是新的 `@` 候选，已有 token 需显示失效或被明确移除，不能静默改绑同名素材。`/` 可切换“当前字段 / 全部适用领域”，但跨领域条目只能执行当前工位明确支持的动作。中文输入法组合期间不执行 Enter/Esc/箭头选择，也不提交半成品查询。

## 统一条目与应用契约

面板、词条和模板共享发现元数据，而保留不同粒度：`entry_id`、`revision`、`entry_kind` (`term | panel | prompt_template | command`)、`semantic_domain`、`category_ids`、`field_ids`、`task`、`topic`、`style`、`applicability`、`source`、`preview`、`actions`。展示名称不作为存储键；旧条目先经显式兼容映射，未知适用范围显示为未知，不自动开放给所有字段。

应用动作需由调用方选择并向用户显示：`replace_range`（原子词或槽位）、`set_field`（结构化字段）、`merge_fields`（配置面板）、`append_template`（完整模板）、`bind_reference`（资产变体）或 `run_command`（已实现能力）。预览不会修改输入；确认后只修改目标范围/字段，保留光标前后文本、其他结构化字段、约束和引用 token。面板产生的文字快照与字段值同时保存来源；用户编辑后标明已改写。应用模板不得借由自由文本回调清空现有结构化设计。

联想 UI 采用输入法式的轻量候选层：跟随光标或当前输入框边缘定位；前几项显示名称、所属字段、内容类型和来源；方向键选择、Enter 应用、Esc 关闭；需要配置的面板和完整模板再打开现有详情预览。候选层不在输入时自动写入草稿，不在每次按键时全量构建目录或渲染所有结果。编辑器失焦、关闭弹层或切换输入框后丢弃旧查询；异步返回不得覆盖新输入框的结果。

## 实施切片与验收

1. **共享联想契约**：抽出与编辑器 DOM 无关的查询上下文、候选与应用动作类型；将现有角色目录适配到该契约。验收同名但不同类型/来源不合并，字段适用性明确，旧角色入口结果不丢失。
2. **共享编辑器接入**：保留 `ReferencePromptEditor` 的 token 和撤销历史，统一 `/`、`@`、`[槽位]` 的键盘及输入法行为；角色设计应用模板不清空身份、造型和约束。验收替换仅影响触发范围，插入后可撤销，引用身份不因文字编辑丢失。
3. **逐工位迁移**：先接场景结构化字段及图片 Prompt，再接道具和分镜画面/动作字段，最后盘点其他创作文本框。每个工位明确当前输入框的参考 list；资产库只服务独立的“添加参考素材”动作。验收未选入列表的本地上传和资产库项目均不出现在 `@` 中，场景字段不会出现角色服装默认项，分镜引用保留类型和变体身份。
4. **性能与可访问性**：输入到候选更新、目录规模、移动端位置、焦点和屏幕阅读器逐项验证；需要远端检索时使用取消/序号保护，并限制首批结果数量。

受影响路径预计包括 `frontend/src/components/modules/playground/ReferencePromptEditor.tsx`、`CharacterPromptDictionary.tsx`、各工位的输入组件及 `frontend/src/lib` 中的分类/查询适配。每切片运行对应行为测试、typecheck 和生产构建；部署与跨工位联调在实现完成后进行。

## Not yet proven / What would verify it

- 当前尚未统计所有创作文本框的完整清单，也未验证各工位资产候选来源是否能共享一个查询 API。切片 3 先建立入口清单和适用字段表。
- “输入法式”候选层能否比现有大面板更快完成选择，需要在角色、场景、分镜各测查找时间、误选率和撤销率。
- 平台目录的大规模性能与跨工位适用性尚未由线上数据验证；沿用现有规模测量方案，不能用当前本地候选量作容量保证。
