## 数据责任

### 生活故事板边界（2026-10-22 用户同意）

采用“生活故事板”的产品模型：照片是可逐步补充信息的节点，未来关联用户讲述、记忆与生成草稿。当前为设计决定，未实现故事板存储或编辑器；V1-A 仍只交付时间整理闭环。

- `Photo` 是稳定素材实体；未来 `LifeStoryboardNode` 引用 photo_id，并保存故事板内排序与上下文说明。同一照片可被多个故事板引用，节点调整不移动/复制原图。
- 日期与人物事实由照片领域持有，故事板顺序不能冒充拍摄时间或事件证据；节点不复制一套可独立覆盖用户更正的事实。
- 原始证据、机器候选、用户确认事实、主观讲述与生成草稿分层保存。后续生成内容引用照片、确认记录与消息版本；来源更正后标记派生草稿待复核，不静默改写已确认内容。
- 生活相册保持独立 owner、授权、任务和数据状态，不以 Studio project/frame 或分镜生成状态为父级。不新增对 Studio 模块的依赖；中性展示组件的复用另行核验。
- 验证边界：缺日期节点可以存在；手动排序不改变日期；同一照片多处引用共享用户日期更正；移除引用不删除原图。以上跨故事板行为待后续切片实现，不列为本轮已通过测试。

- Photo：owner、id、原图/缩略图内部 object key、内容摘要、上传时间、原始 EXIF、解析结果和状态；不能把原图路径当公开 URL。
- Batch 与 BatchPhoto：批次不可变清单，每个文件有独立上传状态；一个已存在 Photo 可被多个批次引用。
- Consent：owner、batch、scope=time、问题版本、披露的处理位置、granted/declined/revoked、确认方式/时间。人物 scope 不在本期开放。
- TimeTask：owner、batch、consent_id/version、幂等键、状态、逐照片进度/错误、租约和重试次数；重启恢复以数据库为准。
- DateAnnotation：拍摄值、year/month/day/second 精度、来源 EXIF/user、候选/确认状态、原始元数据引用、修订版本；未知就是空值，不补齐月日。
- AlbumRelation 与 Operation：记录此批新增的关系、任务来源和撤销状态；同一 photo/year 关系可有多个有效来源，撤销一批不移除另一批仍有效的结果。

数据库是授权、任务和已确认标注的事实源。原图存储受保护，缩略图按 EXIF 方向生成；日期归档不移动或重写原图。只在授权后进行时间整理，上传阶段仅做文件校验/缩略图和必要元数据保存，不创建相册关系。未获人物授权绝不执行检测、特征或聚类。

## API 候选（命名可在实现时按项目约定调整）

| API | 目的与约束 |
| --- | --- |
| POST /photos/batches | 建立 owner 范围的批次；幂等键防止重复 |
| POST /photos/batches/{id}/photos | 逐文件上传，分别返回成功/失败；重试不重复同一上传项 |
| GET /photos/batches/{id} | 返回上传、授权、任务状态与逐文件错误；跨 owner 一律不可见 |
| POST /photos/batches/{id}/time-consent | 确认当前批次/版本的时间授权；拒绝同样有明确状态 |
| POST /photos/batches/{id}/time-tasks | 必须有有效授权；事务持久化任务后由 worker 领取；返回任务 ID |
| GET /photos/tasks/{id} | 任务状态和真实统计；不得由模型编造结果 |
| GET /photos/albums | 按确认年份/待确认过滤、分页；不将上传年份当拍摄年份 |
| PATCH /photos/{id}/date | 接受年份、年月或完整日期；校验精度和值一致，以 expected_revision 防止覆盖 |
| POST /photos/batches/{id}/revoke | 撤回授权并取消尚未提交项；事务内阻止旧授权版本提交 |
| POST /photos/batches/{id}/undo | 只撤销本批新增关系/自动标注，原图和此前确认结果保留；幂等 |
| GET /photos/{id}/thumbnail | 认证并验证归属后返回；private/no-store，不使用公开 /files 目录 |

原图删除另行设计和确认，不随整理/撤销执行。身份由服务端认证决定，所有模型/客户端传入 owner 字段不被信任。数据存储不可用应明确失败，不静默降级为浏览器本机保存或另一数据源。

## 状态、并发和失败

- 授权与任务分开：任务 waiting/running/pending_confirmation/completed/partial_failed/failed/cancelled；没有日期的照片进入待确认，不算处理故障。
- 先提交数据库任务记录再向 worker 可见；租约到期可重领，逐文件事务提交。对 task/photo/operation 使用唯一键或受约束 upsert，实现至少一次执行下的幂等。
- 每次结果提交与授权核验在同一事务/锁边界中完成；撤回成功后旧授权版本的任务不能再新增结果。不得仅在模型调用前检查一次。
- 用户确认过的日期先于新 EXIF 解析；重跑不覆盖。更正用版本检查并记录来源；日期与相册关系的更新必须一致。
- 撤销按操作来源回滚；部分失败保留已成功部分和重试入口。不得用删除整张照片或整个年份相册代替撤销。
- 照片不因一个文件失败而整批丢失。上传字节上限、图片格式/解码限制和去重键需在实现切片中固定，并以测试覆盖。

## 日期规则

原始 DateTimeOriginal 等元数据保留来源和值，解析失败、相互冲突或日期非法时待确认；无时区值不能伪装成 UTC。上传时间始终另存。人工输入“1980”只保存年精度，“1980-05”只保存月精度；不能为排序存入虚构 01 日。未明确说明时不依据画面服饰/年龄生成日期。

### 结构化信息与用户纠错闭环（2026-10-22）

本节为需求补充，尚未实现。文件时间回退可以作为底层服务的显示/排序行为；它不自动成为本领域的已确认拍摄日期。接入 Immich 等服务时必须区分实际 EXIF 与服务回退值，不能直接将统一日期字段标为 EXIF 来源。适配器应取得可辨别的原始证据；无法辨别时来源记为未知，进入待确认。

- 原始证据：分别保存 EXIF、文件创建/修改时间、上传时间和来源引用；不改写 EXIF 或移动原图。
- 整理标注：日期值、精度、来源、状态、证据引用和修订版本独立保存。文件时间可成为单独辅助候选；缺 EXIF 时当前拍摄日期保持空值，进入“时间待确认”虚拟相册。未知日期不因浏览排序产生年份相册关系。
- 确认流程：先询问老人记得的年份，支持跳过；语音生成带 photo_id、当前 revision 和问题 ID 的待确认提议，确认后才写入。文件年份不作为默认选项；用户需要时可查看，并说明可能是保存/扫描时间。“大概八十年代”保留原话，V1 不转换成虚构年份。
- 用户优先：扫描重跑保留已确认日期，只附加新的来源证据/建议。人工确认年份不能被完整文件时间补齐。显式恢复自动判断前说明后果，恢复后可能无日期且待确认。
- 修改历史：候选 `DateAnnotationChange` 保存 owner/photo、operation_id、前后标注快照（值、精度、来源、状态）、操作者、时间、原因、证据引用及可选 restored_from_change_id；用户语音原话为可选上下文，不替代结构化确认，也不默认保存录音。
- 历史恢复：针对当前照片与目标历史记录检查归属及 expected_revision；在事务中重新校验适用授权，生成递增修订、追加恢复记录并同步相册关系。不能直接回写旧 revision 或清除日志；自动标注的恢复需重新验证适用证据与授权，不能借恢复重新启用已撤回的分析任务。
- 历史恢复和批次撤销分开处理；恢复指定照片的日期不能删除原图或静默影响其他照片。当前未有持久化历史或恢复 API，后续新增前应先验证跨 owner、过期确认、连续修改再恢复、年/月精度、重跑优先级及相册一致性。

## 日期规则基础切片（2026-10-22）

先实现 `src/apps/photos/dates.py` 和 `tests/test_photos_dates.py`。这是无 I/O 的业务规则模块，不注册 API，不读图片、不访问存储、不运行模型。原图读取与 EXIF 提取后续单独实现；调用方仅传入提取到的原始拍摄时间（DateTimeOriginal）及其 OffsetTimeOriginal，各条保留来源引用和原始字符串。不能将文件修改时间、数字化时间或上传时间作为原始拍摄时间传入。

- `PhotoDate` 保存原值、年/月/日/秒精度和可选的显式时区偏移。人工输入仅接受 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`，精度必须匹配；非法日期拒绝，不补全输出月日。秒精度值使用不带时区的 ISO 本地时间，偏移另存；偏移缺失保持空值，不按服务器时区推断。
- EXIF 原始格式按本切片输入契约接受 `YYYY:MM:DD HH:MM:SS`，允许字符串边缘的空白/NUL padding；可选偏移为 `±HH:MM`。不执行宽松的日期猜测。无日期、任一非空条目非法、多来源的有效值或偏移不一致时进入待确认，保留所有输入证据；不以多数票解决冲突。
- 日期状态区分 `parsed`（原始元数据解析结果）、`confirmed`（人工更正）与 `pending_confirmation`。待确认结果无日期值；用户更正后仍保留原始证据。按年份读取时只返回值中已有的年份，不造排序日期。
- 人工更正必须匹配 `expected_revision`，成功产生新不可变版本；重复提交旧版本失败。EXIF 重跑不能覆盖人工确认日期。该函数只检查传入快照版本，未来仓储层必须在同一数据库事务中再检查并写入；本切片不宣称已解决并发写入或 owner 隔离。
- 验证：无值、非法/冲突元数据、有效闰日、未知/显式时区、证据保留、年/月精度、旧版本冲突、人工优先、不变输入及序列化往返。命令：`.venv/bin/python -m pytest -q tests/test_photos_dates.py`。完整上传/授权/任务/浏览验收条件继续保留，未完成项不以此模块代替。
