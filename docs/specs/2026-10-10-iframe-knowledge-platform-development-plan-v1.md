## Delivery target

First demo on a shared deployment: a curator publishes an authorized illustrated article to the public base; two users each add different private material, including a legally usable paper in one account. The Playground Agent combines public and the current user's material for screenwriting and director/art questions without exposing the other user's additions; user review controls whether advice enters a draft. Source revisions and citations survive refresh and restart. Finance uses the same public-plus-personal lifecycle in a later adapter slice, demonstrated with one company/source pair and separate financial fact normalization. No special direction-judgment model is in scope.

It ran the migration twice in one transaction, checked one v1 version row, verified a published public collection plus each owner's own collection, excluded the other owner's collection and an unpublished public collection, then rolled back its fixture rows. This does not verify ingestion, RAG or Agent use.
- The Agent-facing owner import/read/media/search API, local private content-addressed blob adapter, and v2 trigram index migration are implemented in source. ## Sequence and dependency decisions

Build shared storage, authorization and the source/version boundary before RAG: otherwise public/private ownership and index identities can drift. Build retrieval and claim labels before Agent integration: otherwise the Agent can only repeat unverified summaries. Add domain-specific draft handoff after the Agent can cite stable units. Add continuous subscriptions after import idempotency and durable jobs have been demonstrated. Financial adapters reuse that base but their structured facts and research dimensions require separate tests.

For the first demo, choose one source URL that permits capture and one legally usable paper fixture. Use a local HTTP mirror/fixture for deterministic tests. Running a live site smoke test is a separate operational check with URL scope and source-policy review. Data-source license, rate limits, model fees, storage budget and paper/image usage rights are explicit launch checks, not inferred from an open-source crawler's license.

## Commands and review evidence

- Backend: `pytest -q tests/test_knowledge_*.py` plus affected Agent/Studio tests; use disposable PostgreSQL and a COS-compatible test object store with fixtures. Do not rely on external sites in required tests.
- Frontend: `npm --prefix frontend run typecheck` and targeted Playground/knowledge component tests. Run the static production build when routing or shared UI contracts change.
- Data migration: verify fresh PostgreSQL schema, migration rollback/backup and restore of metadata together with object storage; any import from an existing owner data directory is an explicit separate migration.
- Permissions: test owner A/B, project A/B, public read/private supplement, curator-only publication/retirement, same-URL annotations, media preview, denied URLs and source text prompt injection at the API and tool boundaries.
- Shared deployment: run an API and worker instance against the same disposable stores; restart each independently, verify lease recovery, signed preview access, backup/restore and no private result in cross-owner caches or logs.
- Retrieval evaluation: report top-k recall, exact citation/figure locator accuracy, unsupported-claim rate, and domain-specific failure cases. A passing generic RAG test does not establish screenwriting, editing, quality or finance correctness.

## Open decisions before implementation

- Shared target is fixed: TencentDB for PostgreSQL, private Tencent Cloud COS, iFrame API and an independent worker. PostgreSQL is provisioned in Tokyo; COS, worker, deployment credentials and a verified restore procedure remain open. Cost ceiling and retention must be reviewed before ingesting production data.
- Which sources may be captured in the demo, what rights allow storage/quoting/visual generation, and whether any require authenticated access.
- Which public-search provider and source allowlist can support the discovery demo, including its terms, cost and candidate metadata limits; explicit URL import remains available if discovery is unavailable.
- Which creative action first consumes accepted knowledge: script check, confirmed Director draft, or art asset draft. The design supports all, but one should be selected for the first vertical slice.
- Whether the first parser benchmark shows a material need for Docling, Crawl4AI, both, or simpler local parsing; choose from fixture results.
