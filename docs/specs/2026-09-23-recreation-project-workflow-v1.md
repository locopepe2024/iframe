# Recreation Project 工作流总 spec v1

日期：2026-09-23

状态：Draft，项目级边界与验收目标；不是新的 Provider/API 实现承诺。

适用：iFrame Studio「创建复刻项目」。

## 1. 产品定义

复刻应作为一个可持续编辑、可重复尝试、可比较结果的 `RecreationProject`，而不是一次性生成按钮。用户从原视频开始；系统分析视频、音频和字幕等输入素材，重建可编辑的故事/时间线，再选择运动生成方式，最后独立处理声音与装配。

产品共用 `story → motion → assembly` 的生产骨架：剧本项目从剧本进入 story，复刻项目从源视频分析进入 story reconstruction。两者可共用媒体、模型路由、异步任务和导出等 Core 能力，但复刻项目的时间线与状态不应由 Studio 的剧本/分镜状态代管。

## 2. 目标和非目标

### 目标

- 从原视频创建项目，并将原视频、视频片段/帧、音轨、字幕、转录和生成结果登记为有来源关系的素材。
- 给用户一条快速复刻路线（MiniMax H3），和一条逐帧/关键帧路线（抽帧、分析、替换、编码/剪辑）。
- 声音、配音和字幕作为独立、可编辑、可选择是否装配的轨道，而不是视频生成时的隐式副作用。
- 保留可核对的时间线、任务输入快照、成本确认和结果来源，使用户可以修订、重跑和比较。
- 默认输出不含字幕/字幕轨；字幕可作为独立文本素材生成或导出，只有用户明确选择才参与成片。

### 非目标 / 不作保证

- 不承诺生成模型逐像素复刻原视频；H3 路线尤其不承诺逐帧一致、精确切点或精确台词。
- 抽帧采样点不自动成为镜头切点。切点必须有视频证据并由用户确认或来自可核验的精确时间线。
- 从视频流中解复用字幕，不等于能从画面像素中移除烧录字幕。烧录字幕需识别/标注，并由另一个明确的修复步骤处理。
- 本 spec 不确定特定 ASR、音源分离、逐帧修复或视频生成 Provider 的可用性、价格或效果；必须经对应能力契约与运行验收后再开放。

### 首期模型范围

- 首期围绕现有 MiniMax 能力组织：H3 用于快速视频复刻，ASR 1.0 用于转录草稿，Speech 2.8 HD/Turbo 用于独立配音候选。ASR/TTS 仍需接入复刻域的 Run、素材和时间戳契约；UniArt 中存在适配代码不代表 iFrame 已接入、价格已批准或质量已验收。
- 烧录字幕清理由 UniArt 对接 GlobalAI `sd2ManxueRemoveSubtitle`，作为可选的源视频预处理步骤。对接、价格确认、输出限制与样片质量验收完成前，不在 iFrame 中显示为可用能力，也不自动处理所有视频。
- 首期不引入 SAM 2、Cutie、XMem、ProPainter、E2FGVI-HQ 或 STTN。它们不属于现有能力；跨帧跟踪、掩膜传播和时序补洞不作为首期承诺，也不阻塞 H3 快速复刻及关键帧编辑闭环。
- 首期关键帧编辑仅对实际提交的帧产出编辑结果。需要全帧连续替换时，另立技术验证与资源/许可评审，不得把稀疏抽帧结果包装成完整逐帧重建。

## 3. 核心领域对象

| 对象 | 职责与关键内容 |
| --- | --- |
| `RecreationProject` | 稳定容器；owner、源媒体、项目修订号、分析/时间线版本、项目状态。 |
| `MediaAsset` | 不可变文件身份；`media_id`、owner、类型、SHA-256、存储位置、父素材、媒体元数据。URL 是可刷新投影，不是身份。 |
| `DecompositionRun` | 一次媒体探测/解复用/派生任务；保存工具与版本、输入指纹、输出素材、状态与错误。 |
| `SourceAnalysisRevision` | 对原视频/音频的分析快照；候选镜头边界、抽帧、场景描述、音频转录/声音事件、字幕线索及每项证据的时间和来源。 |
| `RecreationTimeline` / `Shot` | 按原始 PTS 顺序排列的镜头区间；切点来源、确认状态、证据和每镜头的保留/替换意图。 |
| `MotionRun` | 一次不可变的运动生成/替换尝试；策略、模型、完整输入引用及指纹、提示词版本、时间线修订、成本确认、任务状态和输出素材。策略为 `quick_h3` 或 `frame_reconstruction`；帧路线可记录 `keyframe`、`bounded_frames` 或 `all_frames` 的替换覆盖方式。 |
| `AudioRun` / `SubtitleArtifact` | 配音/声音设计任务与字幕文本资产；与视频生成分开保存，保留独立时间戳和来源。 |
| `AssemblyRun` | 对明确版本的画面、声音、字幕轨进行剪辑、混音、编码和发布；记录输入清单、时间基准、输出探测结果和 QC。 |

同一项目可以有多次分析修订、多个 MotionRun、AudioRun 和 AssemblyRun。新尝试不覆盖旧结果；失败重试不能隐式重复提交付费 Provider 请求。

## 4. 工作流

```text
视频拆分 → 解析 → 分析 → 替换 → 提交 → 合成
```

这是用户可见的六个阶段；素材/资产管理是贯穿全流程的支撑能力，不单独成为一个阶段。项目创建和源视频登记发生在进入“视频拆分”前。每个阶段只消费有来源关系的资产并产出新的版本化结果，失败或重跑不覆盖源素材及既有结果。

| 阶段 | 主要职责 | 典型产物 / 完成条件 |
| --- | --- | --- |
| 视频拆分 | 探测容器与流，将视频、各音轨、软字幕分离登记；识别烧录字幕处理需求。 | 原视频及派生视频/音轨/软字幕资产，探测元数据和父子来源关系。 |
| 解析 | 抽帧、建立联系表、定位镜头/切点候选、提取可验证的时间结构。 | 有源 PTS 的帧资产、镜头候选及切点证据；抽样时间不自动当切点。 |
| 分析 | 对视频镜头、声音和文字进行理解，供用户修订确认。 | 镜头描述、ASR 转录、字幕候选及其来源/置信度；模型结果不自动视为事实。 |
| 替换 | 配置替换意图、产品/主体参考及快速 H3 或关键帧编辑策略。 | 版本化替换计划和已准备的模型输入；关键帧结果只代表实际覆盖帧。 |
| 提交 | 审阅输入/策略/费用并明确授权后提交异步生成任务，跟踪结果或失败。 | 不可变 MotionRun、provider task、成本确认及输出视频/帧资产。 |
| 合成 | 选择画面、音频和可选字幕轨，按时间基准剪辑、混音、编码并 QC。 | AssemblyRun、探测/QC 结果、成片及可选字幕 sidecar。 |

阶段职责需保持区分：“替换”负责定义并准备要改什么，“提交”负责付费授权和执行模型任务；不能把二者压成一个不可审阅的生成按钮。

### 4.1 创建与分解（Decompose）

1. 登记不可变源视频；校验容器、流、时长、尺寸与 SHA-256，按 owner 隔离。
2. 探测所有音视频/字幕流。视频、每条音轨、内嵌软字幕和派生片段可各自成为有父素材关系的资产；保留 codec、channel layout、time base 等探测信息。
3. 如字幕烧录在视频画面内，将其记为带时间范围和置信度的 OCR/视觉注释；不得伪装成可直接解复用的字幕文件。
4. 所有处理命令需限制协议、资源、超时和输入路径；原媒体不可被派生流程覆盖。

### 4.2 视频/故事分析（Understand → Story Reconstruction）

- 生成两类不同资产：用于浏览的均匀抽帧/联系表，以及切点候选前后帧证据。抽帧是采样；切点需定位到源视频的真实帧 PTS 并可人工确认。
- `Shot` 时间用整数 `start_pts/end_pts` 加有理数 `time_base` 表示；秒数仅用于展示。变帧率素材不能先转浮点秒再作为权威时间。
- 生成按镜头顺序排列的场景/主体/构图/动作/运镜描述，并附可追溯证据与置信度。模型描述不是已确认的源视频事实。
- 从音轨运行 ASR，输出带起止 PTS、文本、语言、说话人（若可用）、置信度的 `TranscriptSegment`。机器转录、源软字幕、人工修订分别保留来源；可对齐比较但不互相覆盖。
- 单独记录声音事件/环境声/音乐等理解结果。ASR 文本不等于声音风格分析，也不等于分离出独立 stem。
- 时间线编辑必须保留确认状态和 revision。修改源文件、分析输入或时间线后，旧 MotionRun 只能继续作为旧版本结果查看，不得冒充当前版本输出。

### 4.3 Motion 路线 A：快速复刻（`quick_h3`）

目标是较快复刻整体构图、镜头运动、主体动作节奏和场景结构，并进行用户指定的主体/产品替换；不以逐帧无损为目标。

H3 引用职责必须无歧义：

- `<Video 1>`：只参考原视频中实际可见的构图、运镜、动作节奏、场景变化和时间结构。
- `<Picture 1>`：镜头/主体的静态参考图，锚定被替换主体原有的位置、姿态、场景关系和可见细节；不取代 `<Video 1>` 对动态镜头结构的职责。
- `<Picture 2>`：仅在需要替换产品时提供产品图，参考包装形状、配色、正面图案和可辨识包装文字；不从产品图推断功能，不编造广告语/卖点。没有产品替换时不提交 `<Picture 2>`。
- `retention_analysis`：明确保留原视频哪些可见结构，哪些主体由产品图替换/覆盖；明确哪些东西不得新增。
- `detailed_description`：按已确认的真实镜头顺序描述主体位置、产品朝向、动作、构图和运镜。联系表的采样时间不能直接用作切点；若要求严格复刻，应引用已核实区间。
- 声音策略由单独的音频选择决定，不从视频/图片引用职责推断。H3 原生生成音频、复用原音轨、静音、独立 TTS 后混音是不同策略。
- 视频画面默认为 clean plate：不生成字幕、标题、贴纸、营销文字或 UI 文案。产品包装上原本可见的品牌/印刷属于产品外观，应尽力保留；它不是字幕。

引用编号沿用现有 H3 契约：`<Video 1>` 是源视频，第一张镜头 reference picture 是 `<Picture 1>`，有产品替换时产品图是 `<Picture 2>`。提示文本标签、图片提交顺序和持久化输入角色必须一致；不要为“产品替换”另建一套 `<Picture 1>` 编号约定。若将来确需更改编号，应作为版本化契约变更处理，而不是同一工作流内隐式差异化。

### 4.4 Motion 路线 B：逐帧重建（`frame_reconstruction`）

目标是以源时间轴为锚点逐步修复/替换画面，而不是只让视频模型大致跟随源视频。

1. 按确认后的镜头/区间从源视频抽取目标帧，资产记录原始 PTS、time base、帧索引及父视频 ID。关键帧应区分镜头证据帧与将被编辑的目标帧。
2. 分析并指定每帧/区间要保留与替换的对象。关键帧替换调用图像编辑能力，输出仍是独立图片素材；单张成功不代表整个镜头已完成逐帧替换。
3. 对逐帧模式，明确实际覆盖的帧集合、缺帧处理和相邻帧一致性策略。未编辑帧如何处理必须显式定义，不得静默丢帧、重复帧或把抽样帧误当完整帧序列。
4. 以源 PTS 顺序编码画面并按独立音频策略装配。输出需核验帧数/时间戳、区间边界、画幅、帧率策略和 A/V 同步误差。
5. 若只能做稀疏关键帧编辑或关键帧引导的视频生成，UI/结果需标为关键帧引导，不得描述成全帧替换。

帧编辑的遮罩追踪、光流传播、跨帧身份一致性和任意烧录字幕消除均属待验证能力；能力未接入前不能由普通抽帧代替。

### 4.5 音频、转录、配音与字幕

`audio_policy` 必须为显式、可审计选择，至少区分：

| 策略 | 行为 |
| --- | --- |
| `silent` | 最终视频不含音轨。 |
| `preserve_source` | 按确认时间线从原音轨截取/拼接；源无音轨时阻止提交。 |
| `native_generated` | 请求视频模型生成声音；最终装配核验返回音轨存在，但不据此声称语义准确。 |
| `tts_voiceover` | 用户/工作流确认的文本独立送 TTS，按时间线定位配音，再按混音配置与其他音轨合成。 |

首版不得默选或静默降级。原声、仅参考声音风格、静音、模型生成声音与新配音含义不同。TTS 文本可以来自修订后的 ASR、人工台词或另行撰写；未确认的 ASR 结果不得自动成为付费配音内容。

字幕/字幕文本单独形成可修订的 `SubtitleArtifact`，可来源于源软字幕、ASR 转录或人工编辑，并支持 SRT/ASS 等独立导出。默认 H3 画面不烧录字幕，默认最终视频也不 mux 字幕流；只有用户明确选择时，才将独立字幕轨加入交付包。禁止用烧录字幕作为生成 prompt 的画面内容要求。自动 QC 对残留字形只给出候选与人工复核，不保证 OCR 能证明“绝对无字”。

背景音乐、环境声、效果音、语音分别作为音频素材/轨道管理；第一阶段不假定已有源音频 stem 分离能力。

### 4.6 装配与 QC（Assembly）

- 装配只消费明确选中的 MotionRun、AudioRun 和 SubtitleArtifact 版本，不按任务创建顺序猜测输入。
- 按源 PTS 区间排列镜头，验证每段长度。短于目标的生成片段不能静默拉伸、循环或补帧；需要报错或经用户选择有记录的策略。
- 画面、声音、字幕分别作为轨道处理。默认成片无字幕流；字幕 sidecar 可独立下载。
- 输出前探测容器/流/时长/画幅/帧率/音频布局，并记录真实切点偏差、A/V 同步、缺失/重复帧和 OCR 字幕候选。机器 QC 结果和人工签核分开标记。
- 输出以新的 `MediaAsset` 注册，并追溯到源文件指纹、项目/时间线 revision、MotionRun、音频/字幕版本和 AssemblyRun。

## 5. 状态、版本与任务不变量

- 每个异步 Run 有 `pending → processing → completed | failed | cancelled` 状态；用户离开页面不等于任务取消。
- 所有付费任务在提交前展示输入/策略并要求明确成本确认；任务保存不可变的 provider、模型、输入 media IDs/fingerprints、时间线 revision、提示词及其 hash、参数、成本同意与 provider task ID。
- 浏览器重载可恢复项目及任务；不自动重发没有已知 provider recovery contract 的付费请求。重试语义需区分查询原 provider task 与新付费 attempt。
- 输入指纹或项目 revision 不匹配时，旧任务可查看但禁止写入当前修订。
- 产物 owner-scoped；签名 URL 可刷新，不能替代稳定 media ID。任一跨 owner 的媒体/任务引用必须失败关闭。
- 生成视频的音频状态、单独 TTS 状态、最终混音状态彼此独立，只有装配后才有“最终声音”事实。

## 6. 首轮交付顺序

以风险优先做小步可验证切片，不一次性实现所有生成能力：

1. **项目工作流骨架**：梳理现有 Creation → analysis/timeline → keyframe → H3 → assembly，实现状态/版本呈现与策略命名一致；文档列出的当前功能不能反推部署状态。
2. **媒体分解 + 分析**：登记独立音轨和软字幕，补 ASR/字幕 artifact 的时间戳、来源和修订；烧录字幕仅检测/标注。
3. **H3 提示与输入契约**：落实 Video1/Picture1 角色、no-caption 视频约束、准确 retention/detailed description、音频策略显式化；先用离线 contract/mock 验证，再做单次成本受控在线预检。
4. **配音与声音装配**：接入现有 TTS 能力为独立 `AudioRun`，做台词确认、时间对齐与混音；与 H3 原生声音对照验证，不暗中择一。
5. **逐帧路线**：先交付关键帧编辑闭环，再确定有界帧覆盖和时间保真验收，最后扩展全帧/掩膜追踪能力。

每个切片必须有独立成功条件和回归验证。不能把 provider mock 通过、catalog 里存在能力、或提示词中写了要求当作生成质量/线上可用的证据。

## 7. 成功标准

1. 用户可创建、重载和继续编辑一个复刻项目；分析、任务与输出均有稳定 ID 和来源关系。
2. 视频、音频、软字幕、抽帧、转录和生成素材可独立访问；烧录字幕与软字幕有不同数据类型/操作。
3. 镜头切点可以回到真实源帧 PTS 核对；分析采样从不自动变为确定切点。
4. UI 清晰区分快速 H3 与逐帧重建，以及逐帧路线中关键帧/有界帧/全帧的真实覆盖范围。
5. H3 请求的输入职责和图片顺序通过 contract tests；付费请求快照不可变且需成本确认。线上请求及输出质量另做受控验收。
6. 音频策略在生成计划和装配中一致，无隐式默认切换；TTS 文本需确认，配音是独立素材/任务。
7. 默认成片不含烧录字幕或字幕流；机器 OCR 告警标为辅助 QC，不冒称绝对无文字保证。
8. Assembly 按确认时间线排列，拒绝不匹配版本、来源变化、缺段及未声明的时长处理；导出后保存探测与追溯信息。
9. 所有源媒体/任务/资产都有 owner 范围、SHA-256 来源校验和跨 owner 拒绝测试。

## 8. 当前证据与既有 spec 边界

### 当前代码事实（代码检查，2026-09-23）

- `src/apps/recreation/analysis.py` 对本地源视频做 ffprobe/FFmpeg 分析，使用真实 PTS/time base，产生镜头候选、候选前后证据帧和均匀采样联系表；probe 只记录音轨数量，当前没有 ASR 或软字幕解复用流程。
- `src/apps/recreation/service.py` 已有 owner-scoped 复刻项目/媒体记录、关键帧图像编辑任务、H3 计划/生成任务与最终本地装配。当前视频策略名为 `silent`、`generated`、`preserve_source`；`generated` 是视频模型 `generate_audio` 路径，尚非独立 TTS/混音轨道。
- `src/apps/recreation/prompt_contract.py` 已校验 `<Video 1>` 的 H3 Ref2V 合约；当前 `<Subject 1>` 从绑定的第一张镜头 reference picture 定义，有替换图时产品在 `<Picture 2>`。第一张图可使用源帧，但代码并未强制其只能是源帧；本 spec 沿用该编号契约。
- Studio 漫剧代码另有 CosyVoice TTS 接口/语音配置；它的存在不代表复刻项目已能按 PTS 使用该接口或完成混音。
- `docs/specs/2026-09-20-recreation-assembly-v1.md`、`2026-09-20-recreation-generation-submit-v1.md`、`2026-09-20-recreation-async-lifecycle-v1.md`、`2026-09-21-recreation-h3-ref2v-source-video-v1.md` 和 `2026-09-20-recreation-task-recovery-and-cost-consent-v1.md` 仍是既有局部契约，本文件补充上层工作流，冲突时需先更新相关局部契约再实现。

- H3 对引用职责的实际视觉遵循、文本/字幕抑制、音频同步及产品包装印刷保真，尚未由当前代码或在线视觉质量数据证明。
