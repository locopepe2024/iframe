# 聊天中的日记保存闭环

代码事实：此前注册能力只有日记打开、查询、阅读，没有保存工具；模型因此只能回复手动保存说明。运行观察：报告会话对应日期日记条数为0，最近保存请求先完成文本回复、后一次失败。服务日志记录 Invalid text reply，尚无当时原始返回形状，不能推断是额度、超时或渠道断开。

实现 9f3fa9b5：增加 diary.save_draft(source_turn_id)，只接受同用户、同actor、同会话中已完成且原请求明确按日期写日记的文本结果。正文与日期由服务端源记录读取，模型不能提交或改写。保存与回合完成共用事务；同草稿再次保存只报告已保存；当天已有其他版本或当前日记编辑焦点包含不同正文时，提示用户在编辑器核对，不覆盖。此工具不通过通用 tools POST 暴露写入，必须有已认领聊天回合。

交互约定：用户明确要求保存既有草稿时调用；只是提到日记、继续写或没有明确草稿时不调用。当前仍不支持通过该工具保存尚未同步到服务端的编辑器变更；需编辑器确认。

验证：先复现缺少保存工具的失败测试，再实现。33项相关测试通过，包括隔离、原文保存、重复保存不升版本、已有内容保护和编辑草稿保护。已备份并部署4个后端模块，保留远端已有模型日志增量，未推送。

真实 UniArt/Qwen：独立测试身份预置已生成的测试日记，完整聊天入口输入“我看了把日记保存一下吧。”，返回 HTTP200 / diary.save_draft / “2026-10-28 的日记已保存。”；数据库重新读取正文一致、revision=1，随后历史接口200。没有替用户原会话保存日记。
