# GVHMR输入准备：源时基存在271ms间隔，严格时序验收未通过

2026-10-23。完成可执行输入准备及像素验证，没有运行GVHMR网络，没有修改生产链路。

## Observed

**runtime observation**：对SHA256为`6614a5f7afdc5dd7342058e99027f2f42eee19594dcfd90c46017ddcfce114c0`的原视频逐帧ffprobe读取308个递增PTS。首末帧跨度10.006677s；第11/12帧PTS分别0.331547/0.602812s，间隔271.265ms。这里只证明相邻解码帧时间间隔大，不证明编码丢帧、原始动作缺失原因或生成器行为。

**code fact / arithmetic implication**：官方GVHMR demo按源解码顺序把所有帧写成30fps（未显式依据原PTS重采样）。同序号时间相对源PTS：第17帧提前250.322ms、第197帧推迟113.387ms、末帧推迟226.656ms。该数值来自源码写法与真实PTS的计算，没有执行官方完整demo；不能据此指认旧实验已有同样错位。

本轮另生成**真实时间格上的最近源帧版本**，规则为从源首PTS起每1/30s取最近帧，相等选较早帧，格点截至末PTS。不是插帧，不生成缺失动作：

## Direct implication

下游时序模型必须知道“模型格点时间”和“画面源PTS”两个口径。按序30fps重写改变动作速度分布；真实时间重采样会在大PTS间隔处重复画面，两种输入都不能无说明地验收足点速度/接触时段。

本输入包**严格时序验收失败**：源间隔超过两模型时间步，且源17未保留。不能把像素完整性检查通过当整体输入合格。后段197的原图腕点塌缩在本轮之前已存在，不因新发现时基问题就改判为焦距或时间错位导致。

## Not yet proven

未运行三维网络，没有新的姿态/接触准确率、骨盆校准或焦距结果。没有确定原始271ms间隔是否包含静止画面持续显示，也没有证明补齐/插帧会改善识别。有效K仍是候选，静态机位仍是假设，不能仅靠输入准备恢复绝对高度或深度。

## Hypotheses

若在重复源帧区间直接计算模型逐帧足点速度，可能虚增静止证据；跨大源间隔的位移也可能把未知过程简化。此为时间采样带来的可能影响，须用相同网络、受控输入版本实测，当前不宣称是旧接触失败根因。

## What would verify it

完整网络具备运行条件后，分开保留两类对照：原308帧按序输入只评价精确源帧上的二维/三维姿态，并明确时基改变；301帧真实时间格输入评价可用区间时序，标记重复/大偏移区间，不将其自动判接触。源17需单独原图姿态对照，不伪装成源18。不能通过缩短片段躲开第11/12间隔后宣称全片通过。
