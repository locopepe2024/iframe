# 枪法_2 复刻：问题聚类与验证计划 v1

日期：2026-10-13。范围：更新版《枪法_2.mp4》，先以 s09 为试点。现有 H3/Kimi 实验多经旁路脚本完成，不能直接视为 iFrame 产品端到端验收。

## 流程及真值边界

| 阶段 | 应沉淀的产物 | 当前状态 |
|---|---|---|
| 源片解析与分镜 | 文件哈希、原帧/PTS、切点及两侧源帧；源帧是动作事实的权威 | s09 为原帧 [1085,1205)，局部帧 112／3.733 秒是硬切；全片其余边界尚待逐段复核 |
| 源帧证据与动作识别 | 可见姿态、握点/枪端、遮挡、对焦；模型提出动作和切点候选 | s09 有抽帧证据；Kimi 视频解析能提出候选，关键帧姿态、红缨方向和切点有误 |
| 动作标注与知识 | 经源帧复核的阶段、方向、节奏、人与枪关系；无法辨认处标不确定 | s09 有初版；握点和枪尖完整路径不可见，不能凭武术知识补造；可执行枪法动作库完整命中为零 |
| 镜头约束与生成 | 每条动作要求回指源帧；锁人物图、动作视频、prompt、模型参数、seed 与输入哈希 | s09 v2 人物和画面洁净度改善，动作相位、枪形与硬切仍失败 |
| 同点审阅、选片、装配 | 事件对齐、正常速复核、质量结论及技术可装配性 | 批量已停止，无合格全片；产品装配代码只有任务/覆盖/指纹等技术前置核验，未见视觉质量闸门 |

产品设计稿的“视频拆分→解析→分析→替换→提交→合成”是目标交互，不应当成每项复核已自动实现。当前代码确实通过 `ref_video_urls` 传源视频给 UniArt（`src/apps/recreation/service.py:955-1007`）；旧规格的相反描述不适用于当前代码。

## Observed：问题聚合维度

| 优先级／维度 | 已观察的失败及证据 | 尚未证明的原因 |
|---|---|---|
| P0 源帧与时间轴 | s09 一个 4 秒窗口跨 3.733 秒硬切；源帧只支持可见阶段，不能证明被遮挡握点或完整枪尖轨迹。Kimi 对帧 45、87 等关键姿态有实质误读 | 全片各切点、变速及动作边界还未逐段确证 |
| P0 动作相位与节奏 | v2/v3 均未重现 1.3–1.8 秒深俯身，约 2.17 秒已提前举枪；此前批量因节奏问题停止 | 不能归因于单一措辞、尾部 8 帧或服务端机制 |
| P0 长枪几何 | v2/v3 枪尖与红缨偏大，长杆方向/画面占比偏离；s10 亦有枪长问题 | 模型表征、参考输入、裁切、透视各因素尚未隔离 |
| P0 切镜、时长、装配 | H3 请求 4 秒却返回 90 帧/24 fps/3.75 秒；s09 未复现硬切 | H3 精确遵守切点的能力及这些旁路输出能否进入产品装配，尚无端到端证据 |
| P1 人物与画面杂质 | 初版 s09 沿用原演员且生成录屏 UI；v2/v3 抽样改善；s10 人物正确但仍有 UI | 旧 prompt 文件哈希与任务记录不符，具体措辞效果及随机性未分离 |
| P1 识别、标注与可追溯性 | Kimi `kimi-k3-video` 可提出候选，但误述深俯身、枪角度；其响应模型为 `kimi-k3` | 实际上游模型身份和跨段可靠率未证实；候选不能直接升格为标注 |
| P1 验收治理 | 技术完成不等于视觉合格；s03 景深遮挡时脸部不可评 | 产品操作中有无独立人工质量闸门，尚无代码或运行证据 |

**代码事实与既有表述修正：** `service.py:1262-1278` 若输出时长比目标短超过 0.02 秒就报错，其后是 `-t` 按目标截取，没有自动将 3.75 秒拉长到 4 秒的逻辑。若已探测为 3.75 秒的 s09 输出进入目标恰为 4 秒的这条装配路径，按当前条件会被拒绝；实际端到端拒绝尚待本地复现。旧质量审阅所写的“assembly would retime each”与当前实现冲突。

## Direct implication

当前优先瓶颈是**源帧/事件真值、生成动作及枪几何失配、时长与装配契约**。s09 的人物/UI 改善不代表整体复刻通过；动作、道具和切镜仍不合格。Kimi 可作为动作识别候选生成器，不能代替源帧复核后的动作标注。

## Not yet proven / Hypotheses

- 单靠更详细的提示词、短窗口或移除末尾切镜能否修复动作，未获证明。停帧尾段 v3 否定了“末尾 8 帧是前段失败唯一原因”，但它重编码前段，且提示词仍要求已从输入移除的切镜，不能用来否定所有分镜方案。
- **假设：** 单镜头连续动作参考可能减轻深俯身和枪角度的时序混淆；需要新样本验证。
- **假设：** 录屏 UI 可能受构图或提示词影响；目前没有隔离裁切、画面输入和措辞的实验。
- 30 fps 源片与 24 fps 输出不证明统一 1.25 倍速。源片可能有剪辑/变速，应按动作事件作分段单调对齐，切点两侧独立比较。
- 相同 seed 是实验控制，不证明服务端确定性；单次差异只称观察，不能强作因果归因。

## What would verify it：执行顺序

| 步骤 | 产物和实验 | 判读及 Go/Stop |
|---|---|---|
| 0. 锁定证据与协议，零生成成本 | 记录源片、人物图、参考片哈希/fps/PTS；逐帧复核 s09 的 30、40–55、65、75、87、99、110–119，纠正争议方向；产出证据表/阶段标注 v2 及每条 prompt 的帧段引用 | 握点、枪尖遮挡写“不确定”；帧 112 两侧不能拟合成连续动作；预登记源/输出事件锚点与可评项 |
| 1. 本地复现装配边界，零生成成本 | 用现有 3.75 秒输出与 4 秒目标隔离测试 duration guard；核对真实产品任务的 PTS/目标时长，形成可执行时长方案 | 首先证明拒绝边界。若要重定时或补帧，应明确实现与画质影响，单独验收；不可假称已有自动能力 |
| 2. 动作优先小样本 | 取不跨切且包含深俯身/回升的连续参考窗；让 prompt 与此窗一致，保留既有目标人物及洁净画面要求；完整保存请求、响应、文件哈希 | 对照源、v2/v3 的同一动作事件及正常速视频，检查深俯身、低位横枪、回升高举的顺序与时相，以及长杆刚性、可见接触。不得只以等比例时间截图判通过 |
| 3. 分辨输入与措辞作用 | 第 2 步若有改善，分别只改一个因素（参考窗/裁切或动作措辞），固定其余输入、模型、seed、参数；保存 prompt 原文；必要时同配置重复运行估计波动 | 逐项记人物、动作、枪、UI 和“不可评”；单次改善不声称确定原因 |
| 4. 独立处理切镜 | 在剪辑层测试保留原尾镜头或两镜头装配与帧 112 精确切点，然后再决定是否测试单次 H3 生成切点 | 尾镜头仅 8 帧、约 0.267 秒，不假设可由最短 4 秒生成直接替换；两侧姿态各按其源帧评估 |
| 5. 跨段推广及最终合成 | s09 联合验收后，用 s10 检验 UI/长枪、s03 检验景深遮挡的“不可评”规则，再逐段选片并跑端到端合成 | **Go：**同一次候选通过可评人物、动作顺序/相位、长枪连贯、无 UI、切点方案及装配时长；代表段也过关后再批量。**Stop：**关键阶段/道具仍错、装配仍拒绝、证据无法追溯时不扩批 |

每项验收记录使用链：`源帧/PTS → 标注与遮挡 → 提示词约束 → 任务及产物哈希 → 输出帧/事件 → 正常速结论`。身份遮挡时记“不可评”；枪在画外时评再入画连续性，不能用固定像素长度推定物理长度。
