# 来源卡真实 Qwen 验证：第一轮发现

## 观察结果

使用现有测试工作区的 UniArt 渠道和 `qwen3.8-flash`，在测试容器临时目录运行已提交后端。每轮创建临时数据库，仅发送合成口语，不读取实际聊天或照片，不上传文件、不提交生成。渠道密钥由现有配置层读取，未写入结果。

每个版本执行 20 个组合场景、各 3 次，共 60 条三轮链路：5 种启动表达 × 4 种来源选择，最后补充“把背景换成海边，人物保持不变”。这只覆盖编辑来源链路，不代表完整 spec 的跨任务、日记、取消、选图和失败恢复验收。

原始判定：修正前 54/60 通过；工具 schema 修正后 49/60 通过。**不能据此认定修正改善或退化**：样本较小、模型输出存在随机性，而且原脚本把合理澄清和部分要求也算为失败。

## 直接发现与已改代码

- 首轮出现 `choose_source` 缺卡片 ID：模型可见 schema 混入了按钮专用动作。现已从模型工具目录排除此动作；HTTP 按钮入口仍保留。
- 首轮出现任务 UUID 拼写错误：现已在每轮 schema 中使用当前 task ID/revision 的单值枚举；服务端归属和版本校验继续保留，不替模型静默纠正。
- 两轮均出现导航动作替代 brief 更新。导航不会保存要求，所以本轮修改内容确实可能未进入草稿。已在 action schema 中说明“缺少照片时仍可先记录 brief”；第二轮仍有一次，尚未收口。
- 第二轮出现额外参数（例如 `bref`、`b`）和文字形式的伪工具 XML。运行时严格校验拒绝额外字段；伪工具文字仍可能展示，需单独修正输出边界。不能以放宽校验来提高通过率。

## 测试口径修正

“处理照片”有编辑和整理歧义，提出澄清问题合理；脚本应回答“修改画面”后继续，问题质量另留人工核对。“换背景”包含部分真实要求，可以保留，不应强制 brief 为空。已修改脚本，但**修正后的口径尚未重跑完整 60 条**，不回溯改写原通过率。

临时原始结果位于测试容器 `/tmp/card-live-results.json`、`/tmp/card-live-results-v2.json`，不是永久归档。可复用脚本：`scripts/companion_eval/source_cards_live.py`。初始渠道配置错误发生于隔离进程未继承数据库环境变量，补齐后测试正常调用模型；不属于渠道失效。

## 当前结论和下一步

代码校验：38 项后端测试通过；此前 60 项 UI 测试、类型检查通过，本轮静态构建也通过。前端构建仍包含既有工作区修改，不是干净提交独立构建证据。

真实语义稳定性尚未达到设计目标，因此此次卡片切片**未部署**，测试站继续保留原版本。下一步先隔离工具 XML 与参数错误的输出边界，评估更细粒度业务工具 schema，再按修正后的口径复测；达到门槛后再做测试站自然语音验证。不能宣称统一语音闭环已完成。
