# Companion 图片与视频对话任务需求 V1

日期：2026-10-29。状态：需求与实施边界已整理，待按切片实现；本文不代表功能已经上线。

## 1. 问题与目标

老人始终把输入框理解为“和小安说话”。目前切换图片/视频后，输入被直接用作生成描述。例如“我们编辑一张图片吧”是任务意图，却进入提示词和设置确认，且允许不选照片，造成误解。

目标：简洁版始终使用一个聊天输入框。图片、视频通过自然对话、功能卡片或快捷指令进入同一任务；小安帮助补齐素材、要求和参数，用户核对后才提交生成。专业创作台保留现有专业交互，本次不修改。

用户不需要学习提示词或模型名。界面明确区分“修改已有照片”“生成新图片”“生成视频”；不把修改照片等同于修改姓名、日期等相册资料。

## 2. 现状证据与缺口

以下为代码事实，不是浏览器运行结论：

共享能力代码事实：src/models/uniart.py 的H3 V2实现已有text_to_video、image2video、first_last_frame、omni_reference分支，并接收首帧、尾帧和图片/视频/音频参考素材。上述限制来自Companion demo入口裁剪，不是UniArt或共享适配器缺少能力。execute虽然调用共享适配器，却没有透传素材与生成模式。需求是复用并接通这些已有能力，不另造生成适配器。具体模型组合、报价、相册保存和上游取消仍需按已有能力契约核对；不能据本次静态检查声称完成全部运行验证。

## 3. 范围与入口

简洁版移除输入框“聊天/图片/视频”持久切换。上传、语音、发送保留统一语义；底部日记/广场/相册/我的导航保持现有职责。

| 入口 | 行为 |
|---|---|
| 自然文字/语音 | “编辑一张图片”“把这张照片调亮”“做一段小狗奔跑的视频”，Agent结合焦点和现有素材决策 |
| 功能卡片 | “修改照片”“生成图片”“生成视频”；可从欢迎区或功能入口调用，活跃聊天中不重复铺开 |
| /图像编辑 | 打开修改照片任务，不生成图片 |
| /图像生成 | 打开生成新图片任务 |
| /视频生成 | 打开视频任务，根据描述和素材确定文字生成或照片生成视频 |
| 输入单独 / | 展示可键盘、触摸选择的中文指令菜单；用户不必记住指令 |

快捷指令是输入开头的显式命令，可附描述；正文引用“/图像编辑”或日记内出现该文字不触发任务。未知指令提示可用选项，保留输入。快捷指令开卡本身不调用计费生成。自然语言使用模型与结构化工具解释，不扩展为大量关键词路由。

## 4. 交互流程

### 4.1 修改已有照片

用户：“我们编辑一张图片吧。”

小安：“好呀，想修改哪张照片？”配“上传照片 / 从相册选 / 取消”卡片。

选择后展示缩略图：“想怎么修改？”用户：“调亮一点，其他不变。”

卡片更新为“修改要求：整体调亮，保留其他内容”，允许继续说“再暖一点”、直接编辑要求、换照片、返回上一步。用户未给具体要求前，不进入参数和提交确认。

用户已经明确选中当前照片时复用该照片，并在卡片显示以便核对；只是浏览过或历史里有照片不构成选择。有多张候选时询问选哪张；第一版编辑以单张为界。

“修照片”默认指画面修改；“改拍摄日期”“把人物姓名改成小明”进入已有相册资料流程。仅说“改一下”且上下文不明确时只问一个澄清问题。

### 4.2 生成图片

“生成一张图片”只进入等待内容状态，询问“想画什么？”；“画两只在草地奔跑的小狗”可直接提炼要求，已有细节不重复询问。可选参考图只在所选能力实际支持时展示。

### 4.3 生成视频

先明确用户要表现的内容；有明确参考照片则询问或确认“让这张照片动起来”，无素材则提供文字创作路径。时长、比例使用模型支持的推荐值，必要时一张卡片问一个主要选择。

V1必须覆盖共享适配器已支持的文生视频、图生视频（首帧）、首尾帧、全能参考。首尾帧卡片分别标记两张图的用途，全能参考按模型契约选择图片/视频/音频；用户不必记专业模式名，小安根据目的与素材推荐并展示核对。已有视频剪辑、复杂镜头编排不是由这些模式自动推导出的能力，另行核对。

### 4.4 统一确认与结果

最终卡片展示：任务类型、素材缩略图、用户可理解的要求、必要参数、所选渠道模型，以及可用报价。模型等专业设置收进“更多设置”。无报价则明确“费用按渠道结算，暂无预报价”，不得显示免费或虚构金额。

使用一个明确主操作“确认生成（可能计费）”；不再先“确认设置”再到另一块重读模型、重做确认。确认前可修改；进入任务、选择素材、用推荐设置和普通“嗯”均不提交生成。

V1付费提交使用可点击确认按钮；语音可完成选图、描述、修改、预览等步骤。若后续支持语音付费确认，应另定义明确措辞与版本校验，不用含糊“同意”触发。

结果卡片按真实任务回执显示提交中/生成中/完成/失败/状态待核对。完成可预览、继续修改；“保存到相册”只有接通持久化后才提供，并以保存回执确认。已有用户原照片不覆盖。

## 5. 任务状态与对话焦点

这是实现约束，不是新增第二个聊天Agent：主Agent提出结构化操作，服务端校验和保存任务，前端渲染卡片，OpenTalking播放同一回合回复及结果。

| 状态 | 进入条件 | 允许的下一步 |
|---|---|---|
| choosing_kind | 意图不足以分清修改或生成 | 选择类型或取消 |
| awaiting_asset | 图片编辑缺参考照片 | 上传/从相册选择；不能跳过素材提交 |
| awaiting_brief | 缺少具体画面或修改要求 | 文字/语音补充；不能拿启动指令当描述 |
| configuring | 内容与必需素材已齐 | 推荐参数、更多设置、返回修改 |
| ready | 类型、素材、内容、模型能力均通过校验 | 展示完整确认卡片，等待明确提交 |
| submitting / running | 确认后发起同一操作 | 查进度；可回聊天，禁止重复计费提交 |
| completed / failed / unknown | 收到真实回执或响应不确定 | 预览/修改/原请求查询或安全重试 |
| paused / cancelled | 用户暂停或取消尚未提交的草稿 | 恢复或明确新建；不自动提交 |

任务至少包含task_id、session_id、owner/actor范围、revision、类型、状态、素材ID、用户原话来源、用户可见要求、执行描述、模型/能力、参数、作业ID、operation_id。最终字段与现有存储模块对齐后实现，不在此假定已有schema。

服务端是任务与作业状态真相来源，不能仅保存React state。一次素材/内容/模型/参数变更使revision递增，并使此前确认失效；提交必须携带用户所见revision。重试同一不确定提交保留operation_id；确认新的创作版本才分配新操作ID。

同一会话V1仅一个前台创作草稿；已提交作业可后台运行。开启其他类型前，提供保留并切换/返回当前任务，不静默覆盖草稿。卡片流保留关键阶段回执，当前只有一张可操作主卡片，历史卡片不得误提交旧版本。

日记/相册编辑焦点优先：在日记里说“今天完成图片生成开发”是日记内容。用户明确切换任务时保留草稿再切换。退出创作后恢复正常聊天；闲聊不会自动成为新版本要求；语义不明确时简短询问，不擅自清空或追加。

语音队列每段绑定捕获时task_id与revision。等待中的语音若属于旧任务或已提交版本，不得写入新任务或静默丢弃；提示用户确认是否应用。朗读打断只停止播报，不取消已提交生成、不清空创作草稿。

## 6. 语义与执行契约

发给主Agent的上下文应是有界任务快照：当前焦点、草稿状态/修订、已选素材ID、用户已明确要求、最近操作实际结果及必要聊天上下文。照片ID与任务ID只可取自真实可访问数据。

建议工具职责：启动任务、读取状态、更新草稿、选择素材、准备生成、提交生成、读取作业、暂停/取消草稿。具体工具名在实施切片中确定，复用已有相册、上传、生成服务，避免并存第二套写入路径。

Agent可以整理用户要求的语句，不能擅自加入未提出的人物身份、场景替换或风格；用户补充覆盖相应要求，保留其他明确约束。模型只提议操作，缺素材/缺内容/能力不支持等门禁必须服务端校验，不能只靠prompt。

参考照片传输必须核对当前用户归属、素材状态与渠道授权，以实际adapter能力提交；不能传浏览器blob地址给远端，不能把图片ID当已传输成功。模型不支持编辑时禁用并说明可用选择，不自动降级成文生图。

生成超时不等于失败。未知状态先查原作业或原operation_id，不能自动创建第二个作业。取消已提交作业仅在上游支持且收到回执时称取消成功；否则说明已返回聊天、任务仍运行。

## 7. 移动端交互约束

沿用iframe色系、现有组件与图标体系。输入框始终有“和小安说话”的稳定无障碍标签；placeholder可随任务提示“说说想怎么修改”，卡片标题持续标明当前操作，不能只靠placeholder说明模式。

优先一张主卡片、一个问题和一个主操作；高级设置渐进展开。素材放缩略图，点开可全图查看。返回保留数据，取消和返回聊天区别明确。普通用户界面不显示内部prompt、revision或路由细节。

图标按钮具可读名称、焦点和足够触摸区域（至少44×44 CSS px），不依赖hover；320/375/390宽度及文字放大200%无横向溢出，软键盘不遮住主操作。弹层支持返回、Escape、焦点管理，关闭后回到触发位置。

设计skill仅采用渐进披露、触控、导航和可访问性规则；自动推荐的展示页网格、超大字体、字体和配色不适用于本产品，不替换已有iframe视觉规范。

## 8. 分期实施与可验证出口

1. 统一入口与空意图引导：移除简洁版模式切换，功能卡片与/指令统一开任务。必须验证启动语句不落入生成描述、不调用生成API。
2. 多轮状态与焦点：主Agent接任务工具，服务端版本化草稿、恢复与取消；文字和语音同路。必须验证跨任务语音不会覆盖草稿，日记内容不误路由。
3. 文生图/文生视频闭环：接现有能力与模型选择，合并确认，实际提交/结果/幂等重试；验证费用提示和状态不确定场景。
4. 参考图编辑闭环：复用已有UniArt图片适配器，补齐Companion入口的素材字段、归属、传输和结果；不重新实现adapter。能力未通过时不能宣称“图片编辑完成”。
5. 视频参考模式及结果入相册：接通共享H3 V2已有图生、首尾帧、全能参考的模式和素材参数，分别验收，不只开放文生视频。接相册持久化后再提供保存。最后自然语音与移动端浏览器验收后部署整体切换。

不以卡片能打开、单元测试数量或文生图成功作为所有切片完成的证据。各切片独立提交并记录部署版本，不混入其他工作区改动。现有未部署的“我们/咱们”正则补丁只算临时防误触，不作为新方案完成。

## 10. 实施进度（2026-10-29，本地分支）

代码事实：统一聊天入口、创作工具和服务端版本化草稿已实现。当前卡片已接模型筛选、比例/时长修改、一次明确付费确认、作业轮询与结果预览。修改比例/时长增加草稿版本；提交事务核对用户/操作者、版本、类型、描述、素材、参数，并原子记录job_id与submitted状态。修改已提交草稿被拒绝；刷新后读取原job_id，不重新生成。

代码事实：Companion单张相册照片现可作为图片编辑或图生视频输入。服务端读取本用户原图，在任务期间创建临时文件，由共享UniArt适配器既有的托管素材上传路径转换为HTTP(S)地址。没有直接发送blob/data URL，没有另建适配器。视频保持generate_audio=False。当前参考素材链路的实际成功仍依赖部署主机的托管存储与渠道配置。

验证：后端29项测试、相关前端72项测试、前端类型检查通过。测试覆盖旧版本/参数拒绝、模型能力门禁、同操作重试与重复付费阻止、提交恢复、原图临时文件传入及清理、超时保留原操作；渠道和适配器生成使用桩，未进行真实计费生成、自然语音或移动浏览器验收。本轮未部署、未推送。

待完成：首尾帧与全能参考的多素材卡片和入口映射、结果保存到相册、Agent读取生成进度与结果的工具、所有任务历史结果展示、上游状态不确定性的恢复、真实渠道/移动端/自然语音联调。当前异常统一标failed的旧执行器仍需区分远端已接单后的超时；本轮不会自动重提失败任务。不能据当前测试声称整个V1收口。
