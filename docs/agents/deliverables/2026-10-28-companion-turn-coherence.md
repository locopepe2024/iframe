# 语音与操作共用回合状态

代码事实：主入口 OpenTalkingReply 创建 agent_enabled=false 的会话，只播放 Agent 文本；不是两个独立 LLM。SenseVoice 前端只按能量分段，服务只排除近乎全静音，噪声仍可能被识别成文字。The. 的真实声源未采样，不能断言是静音幻觉或回声。保存结果虽保留文字，但丢失结构化工具回执，旧照片任务仍在上下文里。

目标：非人声不进入聊天；日记保存回执作为共享上下文输入，保存后等待新明确指令，不延续此前照片追问。OpenTalking只播放同一回合结果，不新增语言生成。

实施边界：服务端使用现有 sherpa-onnx 的 Silero VAD，先检查是否有足够人声，再调用 SenseVoice，不维护英文词黑名单。人声检测是估计，不能保证消除所有噪声；保留有效的英文短句。模型文件仅在服务器部署，缺失时启动失败，不能静默退回能量检测。8–48k输入先转换为16k供VAD，ASR仍读取原采样率原音频。无需存储录音。

回执：记录 saved/already_saved/needs_review/needs_date，不把失败当成功。上下文保留最后操作及状态，旧照片工作域不删除；明确告诉模型可见照片不代表用户要继续讨论。保存成功的播报由实际回执驱动。未识别到人声不发送消息、不调用LLM、不播放寒暄。

验证：先测旧保存回执丢失，再验证新上下文；服务测试噪声/静音不执行ASR、人声样例通行、中英文短句保留、异常释放锁。真实服务用官方中文/英文样本、静音和合成噪声；自然麦克风由用户验收。必要部署仅后端与SenseVoice，不改前端视觉。

SDK依据：sherpa-onnx官方 python-api-examples/vad-remove-non-speech-segments-from-file.py，核对VadModelConfig、silero_vad参数、VoiceActivityDetector的accept_waveform/flush/empty/front/pop；模型下载官方asr-models发布的silero_vad.onnx。

## 已部署与实测（2026-10-28）

代码提交：661a9198（操作回执）、c69d60a5（人声检测）。已部署到现有 companion-demo 后端和 SenseVoice 服务；未推送分支。后端部署只覆盖四个相关模块，model.py 保留测试站已有渠道诊断与协调器配置。服务启动正常，VAD及上下文文件校验值与本地一致，变更前文件已备份。

运行观察：独立测试身份经已配置真实渠道发送“把刚才写的日记保存一下”，返回 diary.save_draft / saved；随后问“保存了吗？”，返回“已经保存啦，2026年10月26日的日记在日记本里了。”未转回照片追问。下一回合实际输入包含 last_operation / saved / 2026-10-26。本次未改动用户实际会话。

线上SenseVoice HTTP验证：官方中文、英文音频均返回非空识别及 speech_detected=true；两秒静音、合成白噪声返回 no_speech、空文本、inference_ms=0。另用实际VAD对官方中英粤日韩五种样本以及48k重采样中文验证通过，静音、白噪声、440Hz纯音均未判人声。这些只验证所列样本，不能证明自然麦克风中的 The. 已消除，也不能证明所有英文短句均可保留。

验证结果：后端53项pytest通过，远端服务9项unittest通过。服务venv没有pytest，使用源文件注明的unittest入口完成；未增加依赖。

待自然语音验收：保存日记后保持安静，观察是否出现无意义新消息；再发出明确新指令，检查上下文和语音回复连续性。0.25秒人声门限可能漏掉很短或很轻的应答；VAD不能分辨用户、其他人和播放回声。操作执行前的语音确认尚未增加，仍由真实保存结果触发完成播报。
