# UniArt 音色 HTTP 上下文修复与旧入口收口

Observed / code fact：用户报告 `Failed to fetch voices` 且页脚显示旧绑定 `longcheng_v2`。迁移后的 TTS 依赖 `require_studio_user()`，但 Studio 中间件 protected 路径没有包含 `/voices` 和 `/voice/*`。即使请求包含有效身份，处理函数也缺少上下文，返回 401。现有适配器进程内验收手动设置上下文，因此不能证明 HTTP 入口可用。

失败重现：FastAPI TestClient 发出已认证 `/voices` 请求，模拟身份解析与真实上下文读取；修复前返回 401，修复后返回所属用户目录。相同测试覆盖 `/voice/preview` 及未认证拒绝。

边界：将音色目录、试听及音色管理路由纳入现有 Studio 用户中间件；不新增身份来源、不扩大权限、不回退全局密钥。前端显示后端明确错误，保留非 JSON 错误 HTTP 状态。

历史音色：只读统计当前 projects/series 持久化文件，发现两个 `longcheng_v2` 字段、零条 custom_voices 记录。当前版本不批量删除持久化记录或音频。移除新建角色的硬编码旧音色下拉；工作台旧绑定显示“旧音色已停用 · 需重选”，选择器页脚只显示当前目录实际条目。旧绑定不计入可用音色数量，也不允许旧绑定发起试听/新对白生成。用户选择并应用后，用 UniArt 绑定覆盖原字段。保留已有音频及历史生成快照。

验证：已认证 HTTP 路由携带请求用户上下文；两用户间隔离；目录/试听复用当前用户凭据；旧标识不再显示为可用选择；失败后错误明确可理解；未应用前不写入角色。部署前检查任务状态，版本同步后用实际 ASGI HTTP 请求和当前用户配置复验，不能只测处理函数或手动注入上下文。

运行证据：修复部署前在服务器读取当前系列现有身份标识，以真实 HTTP 请求 `/voices`，复现 `401 Missing authenticated Studio context`。该请求未手动设置 ContextVar、未模拟身份解析，不打印身份标识或密钥。
