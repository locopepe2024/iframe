# 单目视频到 Blender：公开方案对照与当前偏差

## Sources checked

| 来源 | 可确认的方案要点 | 与当前问题的关系 |
|---|---|---|
| [World-Coordinate Human Motion Retargeting via SAM 3D Body](https://arxiv.org/abs/2512.21573) | 固定人物身份和骨架尺度；低维滑窗平滑；软脚-地面接触；接触感知全局根轨迹；两阶段IK重定向 | 最接近我们需要的工程分层。脚接触和世界根轨迹在重定向前后都有独立约束 |
| [ProxyCap](https://arxiv.org/abs/2307.01200) | 以人中心代理学习世界坐标动作；接触感知运动下降，处理手持移动相机和脚-地面接触 | 说明相机运动、人体运动和接触不能靠逐帧2D点单独解决 |
| [HTD-Refine](https://arxiv.org/abs/2605.26879) | 用速度、加速度等高阶时序约束优化世界轨迹，减少抖动和过度平滑 | 对我们“关键帧迁移后平滑”的方向有支持，但不是逐帧独立拟合 |
| [MoCaNet](https://arxiv.org/abs/2112.10082) | 将结构、视角、动作分离并做 canonicalization | 支持先把源动作转换为规范骨架表示，再映射到目标rig |
| [Neural Kinematic Networks](https://arxiv.org/abs/1804.05653) | 用FK层和IK/cycle consistency处理不同骨长的动作迁移 | 目标rig比例适配应由FK/IK闭环完成，不应直接追源网格像素 |

## Observed

公开方案的共同结构是：

`源视频 → 2D/3D人体估计 → 规范人体/世界轨迹 → 目标骨架FK/IK → 目标脚底与地面接触 → 镜头重投影`

当前实验已经有2D检测、GVHMR原生SMPL-X、目标骨架重定向和Blender回放，但曾把源鞋底代理点直接与白模脚骨端点比较。这一步混合了源网格语义、SMPL关节语义、目标骨骼语义和目标鞋底语义。

## Direct implication

当前方案需要改成四个明确的真值面：

1. **源观测面**：源2D点、动作阶段、支持脚区间、脚尖方向；只描述视频证据。
2. **人体运动面**：规范SMPL/MHR姿态、固定身份与骨架尺度、相机/世界根轨迹；负责恢复人的运动。
3. **目标资产面**：目标rig rest pose、骨长、父空间、mesh包络、heel/forefoot/toe代理和canonical sole plane；负责定义“脚落在哪里”。
4. **接触求解面**：目标rig自己的脚底代理 + 场景ground plane + 支持脚时间窗；通过局部IK、脚锁定和根轨迹优化完成。

源鞋点不应作为目标rig端点硬约束。它们只能帮助推断支持脚、脚尖朝向和接触时段；目标脚底位置由目标资产和场景坐标决定。

## Current deviation

- 把人工膝踝/鞋点统一当作同一种骨关节真值。
- 以逐帧2D RMSE作为主要优化目标，没有先锁定人物身份、骨架尺度和世界根轨迹。
- 接触修正发生在目标脚底代理尚未canonicalize之前。
- 白模相机和源相机的误差被混入动作迁移误差。

这解释了为何脚尖方向修正能把角度对齐到约0.1°，但端点误差仍有43–53px：方向是源观测约束，端点属于目标脚掌/地面体系，不能由源像素直接决定。

## What would verify the revised plan

1. 在目标rig rest pose保存左右脚的heel/forefoot/toe和sole plane，并把ground plane写入场景资产。
2. 固定人物身份、骨架尺度和源相机候选，联合优化姿态、根轨迹和时序，而不是逐帧独立拟合。
3. 将源右脚支撑标签转为时间窗；用目标脚底代理做接触/脚锁定IK。
4. 分别报告源2D重投影、人体世界轨迹、目标脚底滑动/穿地和镜头匹配，不把它们合成一个RMSE。
5. 最后再导出Blender动作和镜头，检查目标mesh外观只作为验收结果，不作为源骨关节真值。

## Limits

上述论文摘要确认了方法结构，但没有证明它们能直接处理当前卡通视频、白模资产或 Blender 4.5.9。尚未运行这些论文的完整官方代码；它们只能作为架构证据和候选实现方向。
