# 剧本分析、导演理解与生成提示词的上下文生命周期摘要

日期：2026-10-14
状态：系统梳理与目标契约；本文件不表示所有入口已实现。

关联：[提示词优化与生成提交契约](2026-10-14-llm-prompt-optimization-contract-summary.md)、[系列/单集导演理解结构](../specs/2026-10-09-series-episode-director-understanding-structure-v1.md)、[场景提交与连续性投影](../specs/2026-10-13-scene-submission-continuity-projection-v1.md)。

## 1. Observed（代码事实）

- `Script` 分别保存来源、事实账本、单集导演草稿/确认版、拍摄计划草稿/确认版及 `EpisodeVisualContext`；`Series` 保存全剧资料与系列导演草稿/确认版。草稿保存序号和确认版本号是不同计数器。确认的拍摄计划带来源版本、导演确认版/hash 和自身内容 hash；同步后投影出场景、人物、道具、镜头及光影基线。
- 系列导演预览目前把投稿前言和各集正文拼成一个 `source`，再调用导演分析；返回的 `story_map` 被清空。单集导演预览读取本集原文、提炼实体、风格及系列资料/已确认系列导演理解作为只读背景；不能据此断言全剧分析已经建立了逐集来源身份或完整跨集状态交接。
- 单集确认后 `episode_understanding` 可是 `compatibility` 摘要；只有满足已有带来源 handoff 的条件才沿用 `confirmed` 入场/出场状态。不能把兼容摘要称为已证明的跨集连续性状态。
- 拍摄计划生成使用已确认单集导演 `story_map`、当前来源、风格和可见资产。长文本分片时会把上个片段的场景末态简述交给下一片段。确认计划后，`EpisodeVisualContext` 可供分镜分析读取；分镜帧可保存匹配镜头的 `director_shot_context`，但没有完整、结构化的上一镜 `state_out` 到本镜 `state_in` 交接。
- 视频/R2V 优化可读取当前镜头的有界投影及 I2V 已选首帧；图片润色可读取当前镜头投影和风格。采用的优化结果在已接通路径原样用于生成。未优化的分镜图片路径仍可调用 `append_projected_shot_context` 在正文后增加条款；这与本文件目标的统一组装顺序不一致。

## 2. Direct implication（直接推论）

分析 LLM、导演计划 LLM、图片/视频优化 LLM 和生成提供商需要不同粒度的上下文。保存了全局导演 JSON，不代表当前镜头的首帧、动作起点、光影与转场状态进入了某次模型请求。只凭文字摘要也无法验证跨镜头物理状态；必须保留可定位的来源、结构化引用和版本。

## 3. 上下文层级与权威

| 层级 | 内容与所有者 | 典型消费方 | 不能承担的职责 |
| --- | --- | --- | --- |
| L0 来源与事实 | 系列投稿资料、各集剧本、用户明确决定；原文版本、区间、证据状态；事实账本 | 提炼、系列/单集导演分析、争议回查 | 模型解释不得自动改写原文事实 |
| L1 系列上下文 | 世界规则、画风、人物身份与跨集故事线；系列导演确认版和集别索引 | 单集导演解读、共享资产设计 | 系列梗概不能证明某事已在本集发生 |
| L2 剧集上下文 | 本集事件顺序、人物关系/认知变化、入场/出场状态、禁用项；单集导演确认版 | 拍摄计划、本集资产设计、分镜分析 | 不直接充当每一镜的完整生成提示词 |
| L3 场景与时段 | 计划场景、地点/时段连续性 ID、世界光、地点遮挡、场景起止状态及资产绑定；计划确认版 | 场景图、分镜与跨场景交接 | 场景换地点不等于时间自动跳跃；树荫不等于太阳换向 |
| L4 镜头与交接 | 计划 `shot_id`、分镜帧、景别/机位、人物与道具起止状态、已选素材变体、必要的上一镜末态 | 首帧、分镜图片、视频/R2V 优化 | 切镜不能自动重置持物、姿势、运动方向 |
| L5 生成输入快照 | 本次目标模型、模式、用户草稿、参考图/首帧、L1-L4 的最小投影、模板版本及用户采用状态 | 一次优化调用和随后一次生成提交 | 不能成为新的剧本事实或第二套长期导演版本 |

层级是**投影范围**，不是把五层全文逐层拼接。每一条摘要事实至少区分 `source_kind`、来源 ID/区间、`evidence_status`（事实/用户决定/导演解释/未知）、适用范围、来源 revision/hash。稳定 ID 用于引用；可读摘要用于阅读；两者不能互相代替。跨镜头状态先保存可确定的持物、位置区域、朝向、动作阶段和光照来源；未知项标为 `unknown`，不由模型补成既定事实。

## 4. 分析与制作流程

| 环节 | 提交 LLM 前检索/投影 | 模型输出、审阅与下游边界 |
| --- | --- | --- |
| 实体提炼与事实账本 | 当前本集原文、来源 revision、必要的系列人物身份索引；保留原文区间 | 提议实体与事实，用户确认后形成有来源的本集状态；重提炼不自动覆盖已确认导演与资产身份 |
| 系列导演解读 | 版本化投稿资料、各集有集别的原文/局部摘要、跨集冲突与覆盖清单；长文先按集再跨集归并 | 全剧草稿经审阅确认系列 revision；不得把拼接后的连续文字冒充具有集别来源的事件链 |
| 单集导演解读 | 当前本集原文/实体/事实账本、已确认系列版的有界只读投影、风格和上集已确认 handoff（若有） | 本集事件、时间线、场景线与人物状态草稿；确认后固定本集 revision、系列来源版与事实来源；未知/冲突不升级为事实 |
| 导演拍摄计划 | **同一**当前单集导演确认版/hash、来源版、相关实体/资产身份、已确认视觉风格；长文仅传上一片段必要末态 | 场景→节拍→镜头提案；确认计划 revision 后投影 `EpisodeVisualContext`。浏览历史计划不改变当前下游输入 |
| 分镜分析与优化 | 当前计划场景/事件/镜头及必要相邻交接、相关资产、剧集视觉风格和原文窗口；按 `scene_id/shot_id` 匹配 | 镜头草稿、视觉动作与结构化镜头字段；用户应用时保存来源 lineage，不能从其他场景借镜头上下文 |
| 首帧设计/图片优化 | L1 画风、L3 地点/时段/局部光、L4 本镜 **0.00 秒**人物姿势/道具/构图、已选角色/场景变体；有连续切镜时加上一镜末态 | 优化为完整图片正文后供人工采用；生成可换出多个候选，选中的首帧 ID/版本成为随后 I2V 的视觉锚点；不能把整张角色三视图当作首帧画面 |
| 视频/R2V 优化 | 当前镜头动作起止状态、首帧或角色参考、目标时长/模型/对白、机位及转场类型；只取本次可见的连续性投影 | 返回完整目标模型提示词，结构校验后供采用；已采用正文原样提交，参考图、负向词和参数仍走独立字段 |
| 场景/道具/角色资产设计 | 资产身份与设计版本、剧集画风；只在有唯一已确认绑定时附加当前场景/时段，不附整集剧情 | 设计提案与图片提示词分别审阅；共享资产不被单集的黄昏或局部镜头永久改写 |

另外需要检查配音/声音、字幕与对白、转场或多镜组合视频、重生成/变体、独立视频创建器、历史计划恢复、系列资产生成等入口。它们可能有自己的 LLM 或生成路径；本次源码抽查不能证明全部遵守同一上下文契约。

## 5. 检索与转场规则

1. **按精确身份检索。** 从 `series_id → episode_id → confirmed director revision/hash → plan revision/hash → scene_id → shot_id → frame_id` 定位；再按 `place_continuity_id/time_continuity_id` 取光影，按资产 ID 与选定 variant ID 取视觉引用。文本地点名只作展示或待归一候选，不作唯一关联键。缺少精确绑定时返回待核对，不以语义相似自动借用别场状态。
2. **连续切镜。** 同一剧情时刻继承上一镜 `state_out` 到本镜 `state_in`，只增加机位、构图和允许的局部受光变化；需要核对持剑手、空剑鞘、人物所在区域、动作朝向及道具归属。首帧必须表达本镜起点，不把上一镜末帧机械复用为新镜头画面。
3. **同一时段换地点。** 更换地点资产与局部遮挡，继承有来源的时段世界光和天气。街道朝向未知时，不从“画面右侧夕阳”推导真实东西向。树下、檐下是局部阴影，仍可与阴影外夕阳同框。
4. **时间跳跃、闪回、跨集或有意不连续。** 明确记录 `transition_type`、旧/新时段、桥接状态、来源和适用范围；不默认继承旧镜末态，也不在未声明跳跃时任意重置。转场提议由 LLM 生成时仍需用户确认。

## 6. 摘要生成、修改与 revision

- **生成**：来源切片先保留原文引用与覆盖清单，再做场景/事件级摘要、剧集级归并、系列级归并。摘要不是权威副本；每层记录 `schema_version`、生成策略/模板版本、输入 refs 与 hash、覆盖范围、缺失/冲突、输出 hash。长文本缓存仅在来源、模型、模板、策略与上下文版本全部匹配时复用。
- **检索**：由服务端从已确认版本按消费入口投影，控制完整请求预算（系统契约、草稿、摘要、参考、反馈和预留输出）；保留摘要条目的来源 ID 以便回查。生产请求记录使用的版本和字段来源，避免“预览一份、提交另一份”。
- **修改**：模型只生成待审提议；用户改动在对应层的草稿中保存。局部修改只影响明确字段/范围，不能把旧全文重新解释后覆盖其他确认内容。确认后追加不可变 revision；历史只读，恢复历史应形成新的草稿和确认动作。摘要若需修订，应从其权威来源重投影并产生新摘要版本，不直接改旧 hash。
- **失效**：上游来源、系列/单集导演、计划、风格、素材变体或转场状态变化时，按依赖图标记受影响的摘要、首帧和优化候选 `stale`；不静默换成最新版本，也不把草稿保存序号当确认版。用户可看差异、重新生成并再次确认。未受影响的旧确认历史仍可复现。

目标生成输入快照可记录为 `{source_revision_id, series_director_revision/hash, episode_director_revision/hash, plan_revision/hash, scene_id, shot_id, continuity_state_revision, style_revision/hash, asset_variant_ids, first_frame_media_id, target_model, optimizer_template_version, context_digest}`。这是一份建议契约，不代表这些字段目前已被统一持久化。

## 7. LLM 优化前准备与正文边界

调用顺序固定为：**选择目标 → 固定来源版本 → 检索精确范围 → 计算连续性/转场 → 解析参考与首帧 → 构建有界上下文快照 → 选择目标模型输出模板 → 调用 LLM → 校验结果 → 人工采用 → 原样提交正文**。确定性投影、版本比较和引用校验不另调用 LLM；创作性歧义才选择模型辅助。

上下文是优化调用的独立输入或明确的模板槽位，不是模型返回后的尾注。优化器必须把必要条件组织进目标格式：H3 的固定字段、时间戳和引用标签保持结构；普通图片/视频也只保留一套动作、光影和镜头指令。生成适配器不得在已采用正文之后补加导演 JSON、角色长描述、风格质量词、镜头约束或对白。未优化的手写正文也应在提交前形成**可见、可确认的完整预览**；现存的隐藏式后置追加路径应迁移，不能把它当作统一规范的例外。结构化参考、负向提示词与模型参数继续分字段传递。

## 8. 验收与证据缺口

- 用“同街切机位 → 树荫 → 另一街同一黄昏 → 时间跳跃”及“拔剑/持剑手/道具归属”建立跨层夹具；确认摘要检索只命中正确集、场景、镜头和版本，未知状态不伪装为通过。
- 分别捕获系列/单集导演、计划、分镜、首帧、视频、资产设计的**实际 LLM 请求**与生成提供商 payload：检查上下文覆盖、请求预算、首帧图像输入、目标模板及最终正文；采用优化结果后的正向正文应与确认文本相同。
- 测试上游改版使受影响候选失效、旧版历史可读、草稿与确认版不混淆；再以真实图像/视频人工检查人物、空间、光影和动作连续性。格式与请求测试只证明输入边界，不证明模型输出画面一致。

**Not yet proven**：统一摘要检索、结构化转场交接、全入口的输入快照和依赖失效尚未完整落地；本文件是后续实现与审计的基线，不把设计目标写成当前运行事实。
