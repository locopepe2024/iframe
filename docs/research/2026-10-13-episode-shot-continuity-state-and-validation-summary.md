# 剧集与跨镜头连续性：状态模型和校验边界

日期：2026-10-13

范围：剧集视觉设定、拍摄计划、分镜、图片和视频生成。本文是代码核对后的设计摘要；已完成一个窄范围投影，完整状态契约及跨场景测试样例尚未实现。

## Observed（代码事实）

- 拍摄计划场景已有 `place_continuity_id` 和 `time_continuity_id`；每个地点/时段组合可保存一条 `DirectorPlanLightingBaseline`，包含剧情时间、日光阶段、天气、阴影方向及主光、色温、反差、画内光源。镜头默认继承该组合的基线。用户明确选择独立光影并填写原因后，非空镜头字段才覆盖基线。见 `src/apps/comic_gen/models.py`、`pipeline.py` 的 `normalize_director_shooting_plan_lighting` 与 `project_episode_visual_context`。
- 现有基线以 `(place_continuity_id, time_continuity_id)` 为键；共享 `time_continuity_id` 但地点不同的两场，可保存互不关联的两条基线。代码没有独立的时段级太阳/天空/天气权威状态，也没有校验两条室外基线是否表达同一太阳方位和日光阶段。
- 已确认拍摄计划投影为 `EpisodeVisualContext`，包含场景、镜头、人物、道具和地点/时段光影基线。分镜抽取匹配 `shot_id` 后，将当前场景的地点/时段 ID、匹配的光影基线及计划版本复制进 `StoryboardFrame.director_shot_context`，并把计划镜头光影映射为帧光照。该快照尚无结构化的上一镜结束/本镜开始状态，也无独立时段级世界光来源。
- 分镜细化会读取当前帧的 `director_shot_context`、相邻帧文字简述和更宽的导演执行投影；视频/R2V 润色已提取当前帧中匹配地点/时段的基线，并按字段优先级删减到可解析的 1200 字符以内。`assembled_prompt` 会记录计划条款，但目前未找到图片/视频提供商消费它的路径。
- 分镜图片渲染把调用方提示词原样传给生成器，后者补角色描述；没有从 `director_shot_context`、`assembled_prompt` 或上一镜重新投影连续性状态。视频任务保存调用方提示词、媒资与帧引用版本，可补对白提示；创建路径未见计划基线或相邻镜头状态校验。LLM 读过某个约束，不证明最终生成请求或画面遵守它。
- 现有测试覆盖同一地点/时段的基线继承、用户独立光影、计划到分镜帧的基线投影及润色上下文的基线匹配；未覆盖跨地点同一时段的共享室外光、局部遮挡与切镜状态交接。见 `tests/test_director_shooting_plan.py`、`test_storyboard_analysis_jobs.py` 和 `test_asset_prompt_binding.py`。

## 外部参考的证据边界

- [AutoMovie 的状态交接规范](https://github.com/samchon/automovie/blob/b4fba4f4a702d6caf64636ec4d1898a519738612/docs/requirements/staging/state-handoff-and-continuity.md)要求在镜头和场景边界传递人物位置、姿势、道具、环境与光照状态。[剪辑连续性规范](https://github.com/samchon/automovie/blob/b4fba4f4a702d6caf64636ec4d1898a519738612/docs/requirements/editorial/continuity-and-film-grammar.md)区分同一剧情瞬间切镜、时间省略和有意不连续；缺证据应标记为不可判定。
- [AutoMovie 的光照时间规范](https://github.com/samchon/automovie/blob/b4fba4f4a702d6caf64636ec4d1898a519738612/docs/requirements/lighting/temporal-state-and-continuity.md)提出按剧情时间取光照状态，并将场景光源与摄影机曝光区分。以上是需求文档；已查看的[场景覆盖校验代码](https://github.com/samchon/automovie/blob/b4fba4f4a702d6caf64636ec4d1898a519738612/packages/production/src/production/productionScreenplayValidation.ts)不能证明这些光影和状态交接规则已经实现。

## Direct implication（直接推论）

同一条街切换机位时，地点与时间基线可以沿用，但镜头构图、景别和画面左右的主光方向可能变化。跨到另一条街但仍是同一段黄昏时，地点状态应切换；太阳方位、日光阶段和天气等世界状态应延续。树下阴影是同一世界光照下的局部遮挡：树冠内人物可以处于阴影，树冠外仍有夕阳直射。这不应被判成整场换光，也不应要求用户为每个树荫镜头填写独立光影原因。

## 目标状态模型（未实现）

| 层级 | 权威状态 | 切镜/转场规则 |
| --- | --- | --- |
| 剧集/时段 | 视觉风格版本、`time_continuity_id`、剧情时间阶段、室外太阳世界方位、天空光与天气 | 同一时段的室外地点共享；时间跳跃或天气事件需显式状态转移。剧集风格约束表现形式，不代替剧情事实。 |
| 地点 | `place_continuity_id`、空间朝向、建筑/树冠遮挡、固定画内光源、地点资产版本 | 跨街更换地点状态；同街换景别继续引用同一空间。不同地点对同一太阳的可见程度可以不同。 |
| 场景/局部区域 | 当前人物和道具状态、树荫/檐下/室内等局部光照区域、场景入场与出场状态 | 局部遮挡改变受光，不改变太阳世界方位；进入室内可新增室内光源。 |
| 镜头 | `shot_id`、景别、机位/朝向、动作阶段、开始与结束状态、允许的局部表现偏离 | 连续切镜继承上一镜结束状态；摄影机相对光向由世界光向和机位计算/描述，不直接作为跨机位相等字段。 |
| 生成素材 | 实际引用的场景/人物/道具变体、选定参考图、上述状态的版本快照 | 提示词只投影与本次出图相关的字段；完整 Director JSON 留在分析/血缘层。 |

`time_continuity_id` 只证明同一连续剧情时段，不自动证明天气或太阳状态已经审定。世界光照状态需要显式版本和来源；地理方位若未知，应标记待核对，不能凭“画面右侧夕阳”推断街道东西向。

## 校验边界（目标）

1. **计划确认：**校验引用的时段/地点/场景状态存在，室外地点共享同一时段世界光状态；同一时段的两条地点基线若太阳世界方位或日光阶段冲突，指出场景与字段。文本近义不作字符串冲突判定；证据不足返回 `not_assessable`。
2. **分镜绑定：**按 `shot_id` 绑定已确认计划的场景、地点、时段与基线版本。镜头切换时比较上一镜 `state_out` 与下一镜 `state_in` 的人物位置/朝向、持物、动作阶段及环境状态；允许显式时间省略、离画变化和有理由的创作例外。
3. **出图/视频前：**解析最终提示词与参考图后，只检查结构化输入是否引用当前版本、是否缺失必要状态或与明确状态冲突。局部阴影是遮挡状态，不能覆盖世界光。不要仅凭自然语言文字不一致阻断生成。
4. **生成后：**图片/视频是否真的保持人物、空间与光影一致，需要视觉审阅或专门的图像测量；通过输入校验不等于结果正确。

## 可执行测试样例（待加入）

| 样例 | 预期 |
| --- | --- |
| 青溪镇长街两个连续镜头，机位从顺光切到逆光 | 继承同一地点/时段和世界太阳；允许画面相对光向改变；人物持剑手、位置及动作阶段按交接状态检查。 |
| 长街切到另一条室外街道，仍为同一段黄昏 | 地点 ID、遮挡和场景资产改变；时段 ID 与世界日光阶段/太阳方位保持一致；不同建筑造成不同局部亮度。 |
| 梧桐树下人物在阴影中，旁边路面受夕阳直射 | 局部遮挡与直射区域同时成立；不触发整镜独立光影或天气/时段冲突。 |
| 同一时段另一街道基线写成相反太阳世界方位，且无转场事件 | 返回定位到两场及字段的冲突；不通过改写镜头文字掩盖。 |
| 黄昏切到夜间，或明确经过一段时间 | 需要新的时段状态或有来源的时间转移；不能静默沿用旧日光状态。 |
| 上镜拔剑、下镜剑仍在鞘中且未回鞘 | 返回持物/动作状态冲突；明确回鞘或时间省略后可接受。 |
| 缺少街道朝向、太阳世界方位或镜头交接状态 | 返回待核对/不可判定；不猜测，不宣称连续性已通过。 |

## Not yet proven / 下一步

- 先设计可版本化的时段世界状态、地点遮挡与镜头 `state_in/state_out`，并定义何处由用户确认、何处可由计划模型建议；再扩展确认校验与分镜投影。避免先把所有状态都展开为用户必填表格。
- 以“长街 → 梧桐树下 → 另一条街，同一黄昏”建立最小测试夹具，分别验证计划确认、分镜切镜、渲染前输入；记录实际发送给图片/视频提供商的投影及来源版本。
- 尚未验证真实生成图像、视频或上游模型是否遵守状态约束；不能把契约测试结果等同画面质量保证。
