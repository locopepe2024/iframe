# LLM 提示词优化与生成提交契约摘要

日期：2026-10-14
范围：iFrame Studio 中面向图片、资产和视频生成的 LLM 提示词优化。关联：[场景提交与按需投影](../specs/2026-10-13-scene-submission-continuity-projection-v1.md)、[上下文入口核对](2026-10-13-asset-mention-sync-and-prompt-context-summary.md)。本文区分目标契约、已实现代码与待验证效果。

## 核心规则

**优化前投影上下文，采用后保留完整结果。** 用户请求 LLM 优化时，由代码从已确认状态构建与本次生成相关的最小上下文，并连同草稿、目标模型及选定参考交给优化器。优化器返回的是一条可供目标模型使用的完整候选提示词。用户采用后，生成阶段不得再向其正文添加风格、角色描述、运镜、对白、光影或连续性文字。H3 的字段、标签和时间线尤其不能被后置文本打断；同一规则适用于普通图片和视频提示词。

这条规则只约束**提示词正文的组装顺序**。模型参数、负向提示词、参考图 ID/URL、音频选择及安全校验仍按各自的结构化字段传递；不应为了保持正文原样而跳过引用权限、素材有效性、版本或模型格式校验。

## Observed（代码事实）

- 当前视频/R2V 润色入口能读取当前 `frame_id` 的有界导演镜头投影；视频工作台在首次润色前提供已组装的风格、镜头、连续性和对白，采用结果后以 `workbench_prompt_is_optimized` 保存来源状态。`buildGenerationPrompt` 对该状态直接返回优化结果。
- 分镜图片润色在调用 LLM 前加入当前镜头投影、视觉风格和光照；采用结果后，图片渲染在提示词与保存的英文优化结果一致时跳过镜头投影及角色描述追加。独立视频创建器在润色输入里提供运镜，采用后提交结果正文；运镜或主体动作设置变化时要求重新优化。
- 场景/道具资产工作台的优化请求带资产描述、现有提示词、已选风格及有限的计划上下文。采用建议并保持正文未变时，资产生成任务携带 `preserve_prompt`，生成器不再追加默认质量、背景及风格后缀。
- 以上是提交路径的代码行为；相关本地测试和类型检查通过。没有提供商最终 payload 抓样或真实图片/视频质量对照，不能据此断言生成结果已经保持视觉一致。

## 目标流程

1. **确定输入快照。** 固定本次草稿、目标模型/模式、用户明确选择的素材、有效的视觉风格版本，以及当前场景或镜头所需的地点、时段、光影和动作连续性。通用角色定妆图不读取整集镜头；场景参考图读取相关场景；分镜与视频读取当前镜头及必要的交接状态。完整 Director JSON 留在分析或血缘记录，不作为固定尾注。
2. **一次性优化。** 将快照和目标模型输出契约送给 LLM。要求模型整合约束并返回完整候选正文，而非返回一段供后续拼接的局部描述。H3、R2V 等结构化模式应校验必需字段、标签、顺序和已确认对白。失败或格式不合格时不应用结果。
3. **人工采用。** 优化结果与其输入快照形成一组候选；用户可预览、修改或再次反馈。采用时记录来源及相关版本。未经采用的候选不得覆盖当前生成提示词。
4. **生成提交。** 已采用且仍有效的完整正文原样送往生成适配器；结构化参考和模型参数独立传递。普通手写草稿可以沿用原有组装规则，但界面和后端必须能区分它与已采用的完整优化结果。
5. **变化处理。** 用户改了运镜、对白、风格、素材引用或上游确认版本，且该变化会影响优化结果时，将结果标为待复核，展示差异并提供重新优化或明确采用当前版本的操作。不得静默把新约束追加到旧结果，也不得静默继续使用旧约束。仅编辑提示词正文时，保持编辑后的文字，不通过字符串包含关系猜测它仍代表旧的优化快照。

## 责任边界

| 边界 | 应做的事 | 不应做的事 |
| --- | --- | --- |
| 上下文投影 | 从已确认状态选择本次相关字段，记录来源版本，控制长度 | 把整集导演 JSON 或所有历史对话塞进生成提示词 |
| LLM 优化 | 将风格、参考、连续性和格式要求整合成完整候选 | 只生成局部正文，依赖生成阶段补齐关键约束 |
| 用户采用 | 明确记录采用、编辑及过期状态 | 把模型返回视为自动确认的剧情事实 |
| 渲染前校验 | 检查结构化引用、权限、版本和目标模型格式 | 按自然语言近义或字面差异自动改写正文 |
| 生成适配器 | 原样传递有效的优化正文，并独立传递参数和素材 | 再加风格、质量词、角色说明、对白或镜头尾注 |

## 当前限制与验证

- 目前各入口的“已优化”来源状态并不统一：视频工作台有持久化布尔值；分镜图片依赖保存的英文结果与正文相等；场景/道具使用当前面板会话中的采用快照。目标是统一显式的 `prompt_origin`、输入版本/摘要与失效原因，避免刷新、手动编辑或异步任务期间误判。
- 系列资产生成与独立的角色视觉设计入口尚未按本摘要逐一验证最终提供商 payload。`preserve_prompt` 当前接通的是项目资产任务；不能据此宣称所有资产入口已遵守同一契约。
- 需要以每个入口的适配器边界测试证明：LLM 收到必要投影；采用后最终正向提示词字节等于用户确认正文；结构化素材和负向提示词仍正确传递；版本变化会使旧结果过期；H3 输出校验失败时不会生成。再以真实生成请求和人工画面审阅验证效果。通过输入测试不等于画面一致性已获证明。

## Direct implication（直接推论）

把约束放在优化前，可让模型在同一结构内安排动作、运镜、光影和对白；采用后保持原样，可避免后置文本改变语义或破坏格式。一次优化通常只需一次 LLM 调用；状态投影、版本比较和提交校验由代码完成。只有用户选择再次优化，或必要的创作判断需要模型参与时，才增加 LLM 调用。

## Not yet proven（尚未证明）

该顺序能降低提示词结构破坏风险，但尚未证明上游模型会遵守所有视觉约束，也未证明画面质量、连续性或成本必然改善。需要真实提供商请求与生成结果的对照验证。
