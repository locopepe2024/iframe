# martial-arts-director-cy 词典结构评估

日期：2026-10-19。读取公开仓库 `locopepe2024/martial-arts-director-cy` 的 `main`，commit `65c7c1dd35fcf4a01bfc1372ab506b60e2d0d26d`。仓库 API 显示 `private=false`、许可证 `Apache-2.0`。本次只阅读 README、SKILL、四份 `references/*.md` 文本；没有读取样例图片或视频的具体内容，也没有执行 Skill。以下“效果”不由代码或样例存在性推断。

## Observed：仓库提供了什么

| 文件 | 代码／文本事实 | 可迁移的数据单位 |
| --- | --- | --- |
| `references/martial-arts-systems.md` | 四大类：传统武术、现代格斗、兵器套路、影视武指风格；每条给特征、招式词和视觉特征 | `system → moves → visible_traits`，适合检索和任务筛选 |
| `references/choreography-beats.md` | 按 4／9／12／16 格和徒手／兵器给动作骨架；每招写朝向、重心、发力或肢体位置 | 可编辑的动作序列候选；原文要求改写，而非照抄 |
| `references/style-references.md` | 按作品或团队列调性、镜头偏好、节奏偏好、推荐词，并列风格互斥与组合建议 | 影视参考卡及镜头／节奏词典，需标明来源与版权边界 |
| `references/poster-template.md` | 徒手、兵器、对打三种变量模板；角色描述、动作、场景、镜头和版式分块 | 结构化提示词模板；变量须预览并由用户确认 |
| `SKILL.md` | 信息收集 → 招式编排 → 海报 Prompt → 视频 Prompt → 自检；还定义角色替换和白模预演路径 | `/武术指导` 的候选工作流，而非角色基础字段 |
| `assets/` | 八组编号样例，每组 PNG、GIF、MP4；README 用于展示 | 可能成为平台效果案例的候选，需逐项审核来源、媒体权利和质量 |

`martial-arts-systems.md` 实际列出 10 种中国传统武术、8 种现代格斗、9 种兵器套路和 8 种影视武指风格标题。它是主题词和姿态语料，**不是**面容、皮肤、发型等角色基础身份词典。README 把“单句输入、图片 Prompt＋视频 Prompt”作为产品主张；本次没有独立运行或统计证据证明出图质量、跨格一致性或平台兼容性。

## Direct implication：iFrame 词典应按作用域分层

| iFrame 目录 | 从此仓库可采纳的内容 | 应用于何处 |
| --- | --- | --- |
| 角色身份词典 | 几乎没有可直接用的面部原子词条；仅可借鉴“人物三锚点集中成块”的组织方法 | 项目级角色身份设计仍由自身词典与确认锚点提供 |
| 角色表演词典 | 流派、常态动作语言、起势／收势、姿态、重心和发力方向 | 角色资产包的姿态／体态库；不自动写入脸部身份 |
| 道具与兵器词典 | 兵器种类、持握与运动轨迹词 | 道具资产及动作任务中的明确引用，不设角色固定“武器外观”必填项 |
| 分镜动作词典 | 招式骨架、攻防关系、可见 keypose、空间位置变化 | 分镜／武指任务；与 `[character]`、`[scene]`、`[prop]` 的项目资产索引连接 |
| 镜头／调性词典 | 景别、角度、运镜、速度、节奏和影视风格卡 | 分镜和导演台；不能在选择流派时暗中锁定服装、场景和灯光 |
| 任务模板／Skill | 徒手、持械、双人对打的输入槽位与输出结构 | `/武术指导` 能力验证后接入；输出先成可编辑方案，再审核模型输入 |

词典条目应表达 `id/revision/type/category/label/aliases/definition/visible_cues/compatible_tasks/source/license/status`，动作条目另有 `stance/orientation/weight_shift/limb_path/target_relation`；风格卡另有 `camera_preference/rhythm_preference`。这些是建议的 iFrame schema，不代表源仓库已有 JSON 或 API。来源文件和 commit 要随导入批次保留，词条文本与样例媒体分别审查。

## 与现有交互契约的映射

1. `/` 负责动作：只有实际可执行的武指 Skill 才显示 `/武术指导`。打开后展示当前角色、武术体系、场景、兵器、格数和拟用参考，用户可改、可删，确认后才调用模型。
2. `@` 负责上下文：可检索“咏春”体系卡、“起势抱拳礼”动作卡、已有角色锚点图和已审核效果案例。选词条先看解释和将插入的位置；选图片另行确认是否作为模型参考。
3. 分镜的 `[]` 负责项目内明确指向角色、场景和道具。武术流派名称本身不应冒充项目资产 ID；动作卡是检索到的设计候选，落到分镜时要展开为可编辑文字或独立结构化动作节点。
4. N 宫格海报是沟通和预演产物。它可作为动作参考案例，但整张图的编号、箭头和字幕不能自动当作视频模型要生成的画面内容；是否使用海报作为视频参考由用户选择并审核。

源文档里的“流派不在词典时先让用户确认”可借鉴为**未知值提示**，不能在 iFrame 中阻止用户自由输入新流派。源文档要求骨架至少改写三分之一、强制姿态配额及固定字数，属于该 Skill 的工作流约束；iFrame 应在任务详情中明示并允许用户修改，不能成为用户不知情的结构化限制。

## 不宜直接整包接入的原因

- **文档内版本冲突**：`SKILL.md` 开头 v9.0 写具象角色为默认、白模只在特定情形使用；同文件 Step 1 与 `poster-template.md` 仍写白模为默认。不能据此定义 iFrame 默认行为。
- **自动联想与用户控制冲突**：源风格库有“风格 → 服装／场景锁定”和 Step 1 缺项自动补默认调性的说法；iFrame 规定所有实际模型输入和约束须可见、可改、由用户确认。
- **作用域冲突**：源 Skill 将角色、动作、镜头、场景、视频提示词串成一份流程。iFrame 的项目角色身份、道具、场景、分镜和视频任务各有独立 owner；不能把动作 Skill 输出回写为角色基础身份。
- **质量与权利尚未逐项验证**：仓库级 Apache-2.0 信息不证明样例图视频每项的原始权利链；流派词条的专业准确性与视频模型效果尚未由本次审查验证。

## 建议的首批导入与验收

以当前古典剧为 case，先挑 3 个流派／兵器体系、每体系 5–8 个可见动作词、2 个动作骨架和 1–2 张经核对的样例图。先作平台**候选**，分列“表演动作”“道具持用”“镜头调性”，保存源仓库 commit、文件路径和 Apache-2.0 归属说明；经审核再发布。角色台仅在“姿态／体态库”任务中推荐动作词，基础身份编辑不会被武术词典挤占。

验收案例：同一个已确认角色分别选择徒手和持剑任务；两次结果都引用同一角色锚点，但动作、道具与镜头变化只出现在当前任务草稿。删除动作词或参考图后，最终审核与实际提交同步变化。若输出多宫格，不能仅凭整张海报生成成功就标记每个单格为已确认的姿态资产。

## Not yet proven / What would verify it

- 词典能否降低提示词输入时间、改善动作差异性，需要同角色同任务的实际操作和结果对照。
- 影视参考卡的名称和“推荐词”用于生产时是否合适，需要逐条来源与授权审核；不能直接把特定作品的服装、场景固定给用户角色。
- 八组图视频样例是否可在平台库公开分发，需要逐项媒体权利、质量和 WebP 衍生预览检查。
