# Character style routes

适用：在 `character-identity-design` 形成字段草稿时，将用户选定的题材、时代、画风和年龄阶段转换为可编辑的视觉设计约束。这里只写角色可观察的身份或造型，不生成图片、不调用图片模型、不写项目资产，也不把路由说明直接拼进 provider Prompt。

## 工作台顺序

1. 用户用一段话提供角色档案或指出参考素材；不要强迫用户按字段逐项填写。
2. 将内容拆成 `stated`（用户明确说出）、`inferred`（从素材可观察但仍需确认）和 `default`（工作流默认）三种状态，并为每个字段记录 `basis`。
3. 展示可编辑的身份和造型确认表。`inferred`、`default` 和创意设计选择必须清楚标出，不能静默写成剧本事实。
4. 用户可以用已确认设计和手工 Prompt 从文本生成正面全身图；也可以通过 `@` 从资产索引明确选参考图。参考图不自动变成当前角色资产的图片变体。
5. 派生大头、侧面、背面和细节视图时优先使用用户选定的正面身份图；当前系统尚未记录完整父锚点关系，不能声称多视图已经自动锁定身份。
6. 只有确认后的具体设计字段才能进入默认图像 Prompt；未确认草稿只能用于编辑预览。用户手工 Prompt 与显式参考图选择仍可独立用于生成。

外部工具的 `asset.json`、文件夹和出图命令不属于 iFrame 数据契约。当前项目角色工作台在角色资产内记录设计 revision、图片变体 ID 和参考素材 ID；独立 Avatar 入口不参与。

## 输入和证据

输入必须区分：剧本事实、用户指定、项目内已确认设计值、已核实参考素材和创意设计选择。没有依据的脸型、肤色、身材、族裔、阶层和服饰保持未决。年龄阶段只描述可观察的年龄表现，不从姓名、职业或性格推断。

## 路由

### `realistic-modern`

适用于当代、近现代、都市、校园、职场和写实真人方向。优先确认：年龄阶段、性别表达、脸型和五官比例、发型轮廓、肤色与肤质、体型和体态、现代服装的版型、面料、鞋和固定配饰。妆容、发型整理、伤势和湿污属于 look；镜头表情、视线和动作属于 shot。

### `historical-costume`

适用于古装、历史、武侠、宫廷和朝代造型。先确认时代或用户允许的架空程度，再确认服装层次、领型、袖型、腰线、面料、发饰、妆面和鞋履。服装结构和材质可以成为 look 的连续性锁；烛火、山水、飞檐、战场和运镜属于场景或分镜，不写入永久身份。

### `xianxia-fantasy`

适用于仙侠、修仙、东方幻想和超自然角色。先把真人身份与幻想造型分开：脸、发型轮廓、肤质、体态和识别锚点进入 identity；法器、衣饰层次、材质、符印、发光边缘和境界标记进入 look。法术粒子、能量光、受伤状态和战斗姿态是镜头状态，除非用户明确确认其长期存在。

### `anime-stylized`

适用于动漫、国漫、漫画、卡通、Q 版和其他非写实比例。明确媒介和比例（写实比例、动画比例或 Q 版），再确认脸部简化方式、眼睛比例、发型轮廓、线条和色块逻辑。不要把某个外部作品名称当成已确认风格；用户未指定时记录为创意设计选择。动漫路由不改变资产、revision 或参考图职责。

## `age-stage`

- `child`: 只使用剧本或用户确认的年龄范围；描述身高感、体态、脸部成熟度和服装适龄性，不能自动添加性化妆容或成人化体态。
- `teen`: 保持少年或少女的年龄表现，具体五官、肤色、身材和服装仍需依据；不把“青春”当成视觉事实。
- `young-adult` / `adult`: 由用户或剧本确定成年阶段；可分别确认成熟度、体态和造型，但不凭职业推断外貌。
- `older-adult`: 只有在有依据时描述白发、皱纹、肤质、体态和动作节奏；这些是可见设计值，不是衰弱或疾病的默认含义。

年龄阶段与性别表达是身份输入，不是风格路由的替代品。跨镜头锁定的是已确认的可观察字段，不锁瞬时表情、动作、光线或镜头角度。

## 变更与过期

- 当前确认身份或造型字段会追加项目角色的 `design_revision`，旧设计文本保留。
- 换画风、修改造型、标记派生视图过期及绑定图片父锚点是后续工作；当前不能宣称已经自动完成，也不能覆盖历史图片。
- 单独重出一张派生视图只增加该视图的变体版本，不改变身份字段；同一组图片始终能追溯到一个锚点和一组已确认字段。
- “过期”是派生关系状态，不是删除命令。已生成内容不能因为当前设计变化而静默换绑。

## 输出

输出 `identity`、`look`、`unresolved` 三部分。每个非空字段带 `basis`，值只写具体、可编辑的设计文本。把路由名称、通用质量词和“保持一致”等说明留在元数据，不作为角色字段。用户确认后才可编译图片 Prompt，并记录本 Skill 的 revision。
