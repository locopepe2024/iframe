# MiniMax H3 模式化提示词编写

适用：用户明确要求为 MiniMax/H3 编写或优化视频提示词，或请求分析 H3 IR。依据官方 MiniMax-AI/MiniMax-H3 的 h3-prompt-writing 及 base-en/ref-en 指南，版本 d21241f0a4b3acbb34c97dae47fa417b7065e438。以下为 LumenX 独立整理的操作指导，不是执行官方托管 IR，也不赋予生成权限。

## LumenX 引用语法与分镜板预解析

在优化阶段先把 LumenX 本轮真实附件 @N 映射到 H3 原生媒体标签：图片、视频、音频各自按该类型在附件中出现的顺序从 1 编号。例：@1 是视频、@2 是分镜板、@3 是人物图，则依次映射为 <Video 1>、<Picture 1>、<Picture 2>；文本文件不是媒体槽位。映射以实际附件类型为依据，不能把跨类型 @N 的数字直接照搬到 Picture／Video／Audio。

最终可提交的 H3 提示词统一使用带尖括号的 <Picture N>、<Video N>、<Audio N>。不要夹带 @N、@文件名、[Picture N] 或裸 Picture N，也不要把双语法映射表写入正文。映射在内部完成；用户要求检查映射时，可在独立说明中展示，明确与可提交正文分开。<Subject N> 是主体编号、[Shot N] 是镜头编号，不是媒体槽位。用户旧稿混用语法时，先根据真实附件消歧再统一；类型或对应关系不明时询问，不猜编号。不得声称格式整理已验证上游生成成功。

收到分镜板、九宫格或连续画格时，在提示词优化阶段先解析实际图片，再写最终正文，不能只写“严格按分镜板生成”把解析推迟给视频模型：

- 先判断是连续剧情分镜还是同一人物的多视图／设定拼图。多视图不等于多镜头。读取可见格数、格号、箭头和字幕确定顺序；没有明确标记时，可按从左到右、从上到下作为待确认阅读顺序，歧义影响剧情时先问。
- 内部逐格记录可见主体、外观、场景、景别、人物位置与朝向、动作起态／终态、道具归属、相机线索以及可辨识文字。将用户要求、图中事实和需要补足的过渡分开；静态格不证明动作速度、镜头时长、声音或格间发生了什么。
- 合并属于同一连续动作的画格，识别真正切镜；用户明确逐格切镜时遵从。将解析结果写入 detailed_description（参考模式）或 integrated_multimodal_description（基础模式），描述每镜具体内容、必要过渡和连续性。已给总时长时安排完整时间线，但不把自行分配的时长说成图中标注；未给时长时不捏造精确切点。
- 一张分镜板仍只对应一个真实图片槽位。用“<Picture 1> 的左上格／第2格”描述图内区域，不创建额外附件槽位；Shot 数量和 Subject 数量也不增加附件数。只有确实裁剪、上传并收到新附件编号后，才能使用独立附件引用。本 skill 不执行裁图，不声称已裁图。
- 除非用户要求画面保留分镜板样式，否则提取每格内容重建全画幅连续画面，不把网格边框、格号、箭头、说明字幕带入成片；用户指定的场内文字另行保留。分镜板不自动成为实际首帧。
- 图片未提供、不可读或局部文字辨识不清时，指出具体缺口，请用户补图或文字；不得凭文件名、历史猜测或“已解析”措辞补全内容。只要求提示词时解析在内部完成，输出仍为一份可复制正文；要求分析时才展示逐格结果和待确认项。

## 先确定素材用途，再决定模式

- T2VA：无关键帧，按文本建立视听时间线。
- I2VA：图片就是 0 秒实际首帧，保留画面锚点并向后发展。
- FL2VA：两图是实际首尾帧，描述连续变化路径并在片尾落到尾帧；默认单镜头，除非用户指定切镜。
- L2VA：图片是实际尾帧，从合理前态发展并在末尾到达它。创作语义不代表当前 UniArt SKU 已开放该模式。
- Ref2VA：参考人物、服装、环境、动作、风格、运镜或声音，不要求将图片直接作为首帧。一张拼接人物图也可以是 Ref2VA；不能因为只有一张图片就强制按 I2VA 写作。只借用视频运镜不等于编辑原视频，只借声音音色不等于复用原始台词。

若素材用途与用户选择的模式矛盾，指出差异并建议匹配的创作模式，不自动改提交参数。不要从官方模型总能力推断 UniArt 当前 SKU 的能力。

## 直接优化请求的输出纪律

动作优先：把可见的动作与状态变化写清，再用必要的形容词限定画风。不能用“凌厉、震撼、电影级、力量巨大、身份稳定”代替动作说明。以下动作和远景规则是 LumenX 的创作与验收策略，不是官方模型硬限制，也不是生成效果保证。

“优化适合 minima/minimax H3”默认要求最终模型提示词，而非导演教学说明。只输出当前模式的一份结构正文，不额外叠加中文整体设定、逐秒脚本、镜头要求、声音时间表和长篇负面清单。不从其他已启用技能继承冲突的格式；用户明确要求分析、分镜表或中文稿时才调整。

先将原稿归纳为少量有因果联系的关键事件，再决定有信息增量的切镜。不要机械套用固定三镜或六镜：一次闪现、侧踢命中、倒飞落地通常不需要把准备、蓄力、踢击、命中、倒飞、收尾各自拆镜。每个信息只在最适合的位置描述一次；短片提示词不是反复复述视觉、声音和负面约束的文档。

仅使用用户本轮明确给定或明确沿用的时长。未给时长且需要精确切点时，先简短询问总时长，不自行设定“约8秒”，不照搬示例的4.5秒、9.2秒切点。可先提供无精确时间戳的创意草稿，但不能称其为完整定时官方稿。未提供附件的纯文本请求使用 T2VA，不因为写了“身份保持”就虚构参考图片。

同一事件只发生一次。慢动作特写可以接续同一次接触过程，不能前一段已踢飞、后一段又重新接触和开始倒飞；若确实需要回放，必须是用户授权的明确回放。人物在空中时不能同时描述支撑腿压地。妖兽已出画后，落地可通过画外撞击与入画尘浪表达，不必擅自增加人物收腿、落地站稳和双主体定格结尾。

保留纯 CG、强透视、红底黑剪影和慢动作等明确风格，不用通用“物理写实”消除用户要求的夸张。剪影段与正常材质段分清即可，不重复要求所有镜头都可见五官。不要把“无实景拍摄”扩写成“场景没有任何地面”并又要求尸体落地。对原稿未指定的妖兽形态、命中位置、饰品材质谨慎补充；不把合理补充说成用户原文，也不写与已知造型相冲突的金／银等细节。

## 动作展开与远景连续性

每个关键动作按需要落实：主体与活动部位 → 起始姿态 → 方向和路径 → 幅度及速度变化 → 接触或终点 → 可见结果。将这些内容写入镜头正文，不另加动作分析表。只补足原动作的必要过渡；“动作更多／更有力”不自动授权增加招式、人物或剧情。无需每句都填满全部要素，不凭空指定精确角度、距离或受击部位。

例如侧踢应交代踢击腿收膝、髋部带动伸腿、脚部沿既定方向到达接触点，以及受击者的弯折与位移。未指定左右腿时可称“踢击腿”，一旦选定不得跨镜互换。地面动作说明支撑与重心转移；空中动作说明身体旋转和肢体配合，不再要求踩地发力。接触只发生一次：若先拍命中，下一镜从接触后的压缩、冲击扩散或脱离继续，而非重新拍脚接近并命中。

分别写人物运动、相机运动和特效响应。推进镜头、衣袖飘动、粒子爆炸不能替代主体完成动作。力度用加速、肢体伸展、身体位移和受力反应表达；不要只叠加 powerful / dramatic 等词。保留用户指定的超大透视：写前景肢体如何因镜头距离显得巨大，而不是一面要求强透视、一面禁止任何视觉比例变化。快动作与慢动作分配到具体事件，不把整段“有力动作”写成持续摆姿或全程慢动作。

远景中优先描述实际能辨认的身份线索：同一发型轮廓、服装主要色块、衣袖与裙摆外形、身材比例、显著配饰及持物侧。中近景再承接面部细节；不要求极远景或黑色剪影也清晰呈现全部五官。镜头切换继承人物位置、朝向、动作阶段和道具归属，出画再入画仍引用同一主体。不要为了稳定而擅自把远景全部改为近景或冻结动作；如需改变景别或增加参考，应作为建议而非已执行的改动。

有真实素材时分工绑定：身份图负责外观，服装或全身图负责造型与比例，动作视频只提供指定的运动、节奏或轨迹，不借用其中人物身份。无附件时保持文本主体定义，不虚构人物图或声称已锁脸。密集粒子和遮挡按用户风格保留，关键动作的轮廓、接触与位移应在适当时刻可读；不能通过删掉用户要求的特效来伪装一致性改善。

原稿及后续补充共同确定最终任务。用户回答“15秒、允许切镜”时，只更新时长与切镜许可，不把历史助手自行添加的翻滚、落地摆姿或服饰变化视为已批准。输出前直接删除正文中的重复命中和越权动作，不能靠末尾写“不要重复”来补救。

补全动作不补写新场景和新事件：原稿只指定纯CG、粒子空间时，不擅自增加废墟山谷、建筑或战场；“倒飞”明确路径和位移即可，不自动加翻滚、旋转或碰撞更多物体。风格未要求环绕时，不为展示力度额外增加复杂环绕运镜。

## 基础／关键帧输出

T2VA 从三个字段开始，固定顺序：integrated_multimodal_description、overall_soundscape、non_diegetic_music。

关键帧模式先写一行对齐说明，空行后再写这三个字段。I2VA 说明首帧图片（如 <Picture 1>）在 0.00 秒属于 [Shot 1] 并作为实际首帧；FL2VA 说明首帧图片（如 <Picture 1>）对齐 0.00 秒、尾帧图片（如 <Picture 2>）对齐最后 [Shot N] 的总时长 S.SS 秒；L2VA 说明尾帧图片（如 <Picture 1>）对齐最后 [Shot N] 的 S.SS 秒。S.SS 为用户总时长且保留两位小数。关键帧模式不能误用全参考六段模板。

## 全参考输出

固定六个字段，顺序如下：
1. subject_definitions：逐行定义需要追踪的参考内容和来源。
2. summary：以方括号内任务关系开头，简述目标；如 reference generation、keyframe completion、video editing、video continuation、audio reference、audio reuse，只选实际成立者。
3. retention_analysis：按定义的用途说明保留、转移或复用策略及出现镜头。
4. detailed_description：按播放顺序描述实际可见、可听的全过程。
5. overall_soundscape：全片环境与物理声音。
6. non_diegetic_music：仅观众能听见的配乐。

<Subject N> 指可复用内容单位，不等于文件：人物、服装、道具、环境甚至动作都可以是主体。同一主体可以来自多份素材，一份素材也可以定义多个主体。所有来源使用已经按真实附件映射的原生媒体标签；如 @1 为视频、@2 为图片，分别使用 <Video 1>、<Picture 1>。

若图片仅提供身份，在主体定义中注明来自真实图片槽位（如 <Picture 1>）即可，不必额外定义独立图片条目；图片作为首帧、尾帧、关键帧、构图或分镜锚点时才单独分析其作用。视频标签用于原视频编辑、续写或时间结构参考；视频里的可复用人物仍定义为主体。同步视频音轨只有实际被提供并启用时才能定义为音频来源，不凭空添加音轨。

视觉参考关系：fully_preserved、partially_preserved、attribute_transfer、weak_reference。音频关系：fully_copy、partially_copy、reference、weak_reference。按已定义的参考用途判断：只参考身份时，新背景或动作不自动意味着身份部分丢失；明确把原服装纳入主体定义又要求换装时，应说明改了哪些特征。这是目标策略，不是成片检测结果。

## 镜头、声音、语言与验收

官方模型提示词的结构正文用英文；对白、歌词、可见文字保留原语言。用户明确只要中文时按其要求输出中文稿，不声称它是严格官方英文格式。解释与交流可用中文。

交付前检查三／六字段正文中的意外语言混入（例如声音描述里出现无来源的俄文单词），改为英文；不要改写用户指定的对白、歌词或画面文字。

[Shot 1] 不附切镜时间戳；后续真实切镜按 [Shot N] At MM:SS.mmm, ... 书写，切点严格递增且在片长内。一个连续镜头可包含多个动作阶段，但不能因此增加 Shot 数量。最后一镜明确延续到用户总时长；最后切点不等于片长。

每镜写清构图、主体可见特征与位置、环境光线、动作状态变化、相机运动、当前声音以及参考内容生效的时刻。运镜描述运动类型、必要的幅度与速度。Ref2VA 的 detailed_description 官方建议通常约350–500英文词，但不能为凑长度增加剧情，也不能擅自套用2000字符截断规则。

发声者才分配稳定 (S1)、(S2)，跨镜不重编号；<Subject N> 与说话人编号不是同一个体系。对白用 <d>[Language] 原台词</d>；跨切镜对白使用 <scenetrans> 且说明持续，片尾截断使用 <cutoff>。仅参考音色时不能把参考音频的原台词带入新片。无对白请求不生成对白或说话人标签。

现场音乐属于镜头内声音；角色听不到的配乐才放 non_diegetic_music。overall_soundscape 只在要求全片完全静音时用 N/A；non_diegetic_music 无配乐时用 N/A。用户要求配乐时落实节奏、乐器与动作节点，不能填写N/A；“无对白”不等于“无配乐”。不要把所有音乐都当成后期配乐。

最后对照当前原稿核验身份、造型、场景、剧情、时长、画幅、镜头数量与禁用项，检查双手／支撑腿／道具占用和运镜相对关系。仅允许用户授权的改编。对比 IR 时先确认输入是不是同一个故事；不得用结构更精细掩盖输入错配。
