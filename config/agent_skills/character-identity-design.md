# Character identity design skill

适用范围：根据项目角色档案设计可复用的角色外观与造型。输入包括剧本已知事实及出处、用户明确要求、当前项目风格、项目内已确认的角色设计版本，以及已核实的参考素材内容。先区分这些来源，再提出可编辑的具体视觉设计。不要把剧本描述或本 Skill 指令原文直接复制成图片 Prompt。

设计时按需覆盖：

- 真人 / 动漫 / 概念设计倾向；
- 年龄阶段和真实感；
- 脸型、五官比例、眼神和常态表情；
- 笑容强度、发型、发际线、发色；
- 肤色、肤质、可识别面部特征；
- 身材比例、身高感、肩宽和体态；
- 角色识别锚点；
- 正面、侧面、背面和多表情视图的一致性。

分层规则：

- Character 身份保存长期识别特征；
- Look 保存本集服装、妆容、发型整理、伤势、湿污和时代造型；
- 瞬时表情、姿势、视线、手位、景别和灯光变化留给分镜与表演；
- 连续性锁只锁跨镜稳定且可观察的最小短语，例如服装主色、材质、发型轮廓或固定配饰；不锁瞬时状态。

参考图职责必须分开：身份图负责角色身份，服装图负责造型变体，动作视频只负责动作、节奏或轨迹。没有用户证据时，不从族裔、职业或姓名猜测脸型、肤色、身材或阶层等身份事实。对于缺少但可创作的细节（例如领型、袖型、腰线、面料、鞋履、发式和固定配饰），Skill 应依据已有的角色档案、题材、画风、年龄阶段和参考素材提出一套具体、可编辑的创意设计选择，并把依据标成“创意设计选择”，不能只把这些字段列成待核对。时代未明确时，可提出不冒充具体朝代规制的架空造型方案。例：角色档案只有“少年剑客，素黑劲装”时，可以设计交领短襟、收紧窄袖、束腰、哑光棉麻、黑布靴和束发，并将其明确标为可修改的造型提案。

输出应按字段组织：`identity`（年龄外观、性别表达、脸型、五官、眼眉鼻唇、基础发型、肤色肤质、身材体态、识别锚点）、`look`（服装、妆容、发型整理、配饰及生效范围）和 `review_items`（仅关键设定歧义，每项提供可采纳建议）。每个非空字段附 `basis`，只能是剧本事实、用户指定、项目内已确认设计值、已核实参考素材，或明确标为“创意设计选择”。不要把创意选择写成剧本事实。只有会改变人物身份、年龄阶段、项目画风，或存在相互冲突证据的事项进入 `review_items`；年龄或画风建议还应给出与建议一致的选项值。无关且无需确认的字段保持空值，不用“保持一致”“由用户指定”等泛化句子填充。

性格只可启发可见的常态神情或体态候选，不决定具体五官、肤色和身材。常态神情不等于永久固定表情；镜头中的情绪、视线和动作留给表演设计。已确认的项目角色设计字段不得被新候选静默改写，冲突要列入 `unresolved`。

项目角色工作台把输出作为可编辑草稿。草稿可以由用户明确点击“应用到图片提示词”进入当前工作区的出图预览，但不会写资产或创建 revision；只有用户确认后，设计才保存为项目角色资产的 design revision。Skill 不调用图片生成模型、不写资产、不确认设计，也不决定图片模型、尺寸或路由。独立 Avatar 入口不参与当前项目角色工作台的设计与生成链路。风格基线负责整体画面质感，通用负面词负责质量缺陷；本 Skill 不重复承担这两类职责。
