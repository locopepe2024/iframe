# 创作优化共同约束

这些约束用于已启用的创作 skills。具体 skill 的表达格式服从本轮用户任务；不强制把每个视频拆成多个镜头。

## 先明确本轮优化对象

区分忠实润色、改编、对比分析、续写。仅要求优化时，默认忠实润色。用户在本轮贴出的待优化稿优先于历史方案；历史助手回答不是用户已批准的事实。用户明确要求沿用、改编或续写时，才继承对应内容。若同时给出互相冲突的完整方案而未指定优化哪一份，先列出差异并问一个定位问题，不把两份合成新故事。

在组织输出前记录不可擅改的创作条件：主体与素材用途、服装和道具、场景、剧情因果与结局、总时长、画幅、单镜头或多镜头、主要运镜、音效与禁用项。只允许修改用户授权的维度；补充假设与可选创意明确标为建议，不混入可复制的正式提示词。

## 素材与主体

使用本轮附件说明中的 @1、@2 等真实编号。编号只在本轮附件内有效；历史消息里的同一编号可能指向另一素材。将主体身份、造型、构图、环境、动作和音色的参考用途分别说明。一张拼图中的半身与全身可以是同一个主体的两个视图，不因此虚构两张附件或两名人物。

不把文件名中的签名、过期时间、URL 参数写入创作提示词。未收到实际附件时不能声称看到了素材；用户描述和图中可见内容需要区分。素材可见特征用于描述依据，“严格保持身份”是生成要求，不是已经验证的结果。H3 官方结构中的 fully_preserved、partially_preserved 是目标参考关系分类，不是成片验收声明；不能仅因出现这些标记就判定输出错误。为 H3 优化时，先按本轮真实附件的类型与顺序，将跨类型 @N 映射为各类型独立编号的 <Picture N>、<Video N>、<Audio N>。例如视频 @1、分镜板 @2、人物图 @3 分别对应 <Video 1>、<Picture 1>、<Picture 2>；文本文件不占媒体槽位。最终可提交正文只使用这些带尖括号的原生媒体标签，不夹带 @N、@文件名、方括号或裸媒体标签，不把双语法映射表放进正文。映射有歧义时先确认；用户要求看映射时放在独立说明中。<Subject N> 和 [Shot N] 只用于主体和镜头。这项单一语法交付规则优先于旧版 skill 的混合映射示例；不改 URL 传输字段。

## 分镜板先解析再优化

针对 H3 的分镜板输入，在优化阶段先读取实际画格、阅读顺序、主体与场景、景别、动作状态和格间连续性，再把每镜的具体画面与动作写入最终正文，不能只交给视频模型“按图生成”。一张板只占一个实际 <Picture N>，图内格用位置或格号描述，不虚构多张附件、不声称裁图；区分剧情分镜与人物多视图，动作阶段不自动等于切镜。静态画格不能证明时长、速度或声音；不清楚的格或顺序要标明并询问。保留用户剧情和总时长，默认不把边框、格号、箭头和说明文字带入成片。仅要提示词时内部完成解析，仍只输出一份正文。

## 时间、镜头与动作

时间段从 0 连续覆盖用户总时长，标明每段结束时间，不能以最后一次切镜时间代替总片长。区分同一连续镜头内的动作阶段与真正的切镜；用户要求不切镜时，全部阶段属于同一镜头。动作复杂度必须匹配可用时间，不为塞入更多细节擅自增加时长。

核对主体和相机的相对运动：距离不变的同速跟拍不会自动把全身景变为近景；需要景别变化时说明距离或焦段如何改变，且遵守用户禁止变焦等要求。区分场景时间冻结、主体例外动作与相机继续运动。逐阶段核对左右手、支撑腿、道具归属及位置、接触点、动作先后和终点；同一只手不能同时执行互斥动作。遇到无法兼容的核心动作要求，应提出最小修改建议，不静默删改剧情。

## 输出前验收

逐项比较原稿与成稿的不可擅改条件，消除意外换装、换场景、改剧情、增切镜和时长变化。将配乐、环境音、动作声按视觉事件同步，不能用泛泛的电影感替代动作和镜头关系。减少重复负面词，保留关键连续性要求。

一般创作交流沿用用户语言；明确为 H3 编写模型提示词时遵循 H3 官方 skill 的英文结构与原语言对白规则，用户明确要求中文稿时优先满足并说明是中文创作稿。只要提示词时只给一份可复制正文；要求方案或分析时再给简明主体定义、保留／修改清单、时间线与问题说明。官方英文格式是兼容性依据，不是效果一定更好的证据；不能声称生成已成功、身份已保留或某模型一定能完成。
